# UNO 编译重构与验收

本文规定 `unit-cards-v3` / `uno-unit-compile-v3` / `review-publish-repair-v2` 的验收边界；契约细则见 [单元编译实施](UNO-单元编译实施.md)，运行状态见 [当前实现与验证](UNO-当前实现与验证.md)，阶段性实现记录见 [图书编译重建](UNO-图书编译重建.md)。新卡只写一个主类型 `type` 与零到三个既有领域 `domains`，不写 `tags/topics`。已保存的 v2 任务按其原契约恢复，不改签或混写；更早入口只保留历史记录。

## 成品要求

　　图书编译应把授权范围内的材料整理成有结构、有关系、可回查且可以独立阅读的知识卡。读取了全部文字、保存了卡片或程序全部通过，都不能单独证明达到这个要求。

- 一张卡回答一个明确、可复用的问题；相互依赖的解释链保留在一起，独立对象不因同属一章而混成容器。
- 正文保留作者立场、关键概念、具体证据、案例过程和成立条件；来源没有的机制、引语、数字或反例不补造。
- 跨章补充融入原有解释；跨作者立场与条件差异可辨认。无“见前波”、批次报告、重复追加段和通用空话。
- 关系能用两端具体内容说明类型和方向；导航与来源支持分开。未确定的关系可不建立。
- 每项产出有真实来源定位。未经读取、提取受损、预算不足或解释尚未闭合，应列为未完成或延期。

　　模型实际使用 [判断方法](design/book-compile-method.md) 与 [正反例](design/book-compile-examples.md)。这些说明引导判断，不是程序能够自动证明语义正确的检查表。

## 程序必须守住的边界

| 场景 | 可验证行为 |
|---|---|
| 新建与旧入口 | 按钮、斜杠和 API 创建相同 `unit-cards-v3` 任务；v2 仅恢复已保存任务，更早编译只显示历史 |
| 服务标识 | 健康接口与准备接口同时声明 `compile_profile=unit-cards-v3`、`compile_version=uno-unit-compile-v3`、`compile_review_policy=review-publish-repair-v2`、`uno_relation_repair=1`；源码标识不能代替正式进程核验 |
| 图书范围 | 冻结用户选定原件及版本；不能悄悄把整书改成选读 |
| 原文保全与归档 | 未完成时原件留在 Inbox；原件哈希与提取哈希分别入路径，重提取不覆盖旧单元；整本已处理、无延期或提取缺失且归档原件哈希核验通过后，由 Gateway 移出 Inbox，崩溃后可恢复 |
| 分段与上下文 | 原文和其余上下文独立计量，按任务冻结的模型能力上限检查；缺少快照的历史任务沿用各 60,000 Unicode 字符限制。切分同时遵守冻结的字节上限，先段落／句子边界再硬切，保留 continuation；具体模型档位见单元编译契约 |
| 宿主提交 | 每单元一次完整 Markdown 生成请求；无模型补读工具、无原生多轮工具循环、无历史正文叠加、无阅读组 |
| 分类契约 | 一个 `type`、零到三个目录内 `domains`；允许空领域，不允许父子领域重复；新卡拒绝 `tags/topics` |
| 提示词 | 生成与审核都注入类型、领域、正文骨架的说明和正反例；允许领域目录与 Gateway 使用同一冻结快照 |
| 检查与修复 | Gateway 预检后只用候选卡做常规审核；问题必须分成 `card` 与 `relation`。卡片修复不含原文、兄弟卡或历史；关系修复只加入已完整核对的明确端点并只能改 `relations`。两类分别最多两次，端点变化后按当前版本重新判断旧问题 |
| 来源引用与查看 | 模型保存来源只填 ref；程序为完整交付单元生成 source_spans；界面可打开真实归档文本、原书页章定位及原书链接 |
| 授权与隔离 | 从持久任务核对运行状态和本库来源；伪来源、别库回执及停止后写入被拒绝 |
| 旧卡与关系 | 参考卡只在本库确定性匹配，最多 3 张完整卡与 5 张导航摘要、总计 22,000 字符；只有完整卡可修改或成为新关系依据；改旧卡须当前 revision；旧来源和原关系语义保全 |
| 思考与输出 | 对话深度不进入编译或建构；环节策略和输出上限按已支持模型能力保存到任务，受模型实际能力约束；旧任务按其原值恢复，不在途中改签 |
| 截断恢复 | 制卡达到输出上限时保留完整闭合候选；启用隔离的任务按校验和审核结果保存通过卡，未解决范围留池，其余任务暂停。恢复只请求剩余内容，不覆盖保留候选或自动重发相同请求 |
| 原子写入 | 每次事务最多 100 张卡，允许合法同批关系；先保存通过卡，后修复问题卡，不要求整单元只有一次事务。单次事务失败不留下该事务的部分卡片 |
| 幂等与崩溃 | 相同操作返回真实收据，改变内容不能复用操作号；事务成功而任务未保存时可恢复成果 |
| 结束与恢复 | 先核对收据，再继续未完成范围；恢复不能清空修复计数或重做已成功单元；延期、提取不完整和失败不计完成 |
| 成本 | 累计实际外发预算覆盖失败和适配器重试，不通过换会话重置；适配器不可计数时阻止新建或外发 |

　　新流程没有 `compile_review`、五个 `book_*` 工具、逐字引文登记、聚合档案登记或固定独立二审。必要的机械检查始终存在，不换名引入另一套语义审核关卡。

## 单元制卡初期程序验证记录

　　单元制卡程序验证见 [单元编译实施](UNO-单元编译实施.md)：新编译及受影响回归 65/65；Python 边界 18 通过、1 个可选样本跳过，类型／切分／清洗 6/6；前端 219/219，TypeScript 与构建通过。隔离 Web API → 宿主 → 模拟供应商 → Gateway：两个约 57,000 字符单元、4 次请求、2 张合成卡、完整归档。浏览器已核验材料类型选择、两个 6 万字符上限说明和空 Inbox 状态。没有调用付费模型。

　　这些检查证明源码路径和标识，不证明真实模型质量，也不证明正式 3093 进程已经加载本版。现场是否上线须核对应进程的健康／准备接口，不能沿用 v1 部署声明。

## v1 历史验收（已被取代）

　　以下数字和加载声明属于 `book-reading-v1` / `uno-book-compile-v1` 时点，不作为 v3 通过声明。

　　程序验证当时为：图书专项 45/45、来源查看 5/5、前端 217/217；正式源码目录完整后端重跑共 715 项：703 通过、0 失败、12 跳过。真实浏览器已从新卡进入来源、打开归档正文。原生本地模拟以 4 次请求、2 章节、2 卡完成归档，当时仍使用五个 `book_*` 工具。

　　正式 3093 当时已加载该 v1 路径：健康接口为 `uno_compile_entry=4`、`uno_book_compile=1`，准备接口为 `book-reading-v1` / `uno-book-compile-v1`。该记录只说明 v1 时点；当前源码 v3 的标识与正式进程加载情况须分别核验。

### 真实模型实验（v1，11/12 次请求）

　　真实 Kimi 实验已使用独立授权预算 **11/12 次请求**，第三章材料为 **7,088 字符**，底座为隔离复制的 **2,669 张金融卡片**，新增 **4 卡**；没有写入正式知识。剩余 1 次不使用，旧实验账本不重置。该实验针对阅读组与 `book_*` 工具，不是单元制卡 v2 的重测。

　　记录用量为 input **34,209**、output **8,575**、cacheRead **104,448 tokens**。最大请求为 **115,366 UTF-8 字节**，不是字符数。

　　三次工具拒绝及处置：要求重读刚保存的卡、不能结算提前处理的下一单元，当时已按 v1 规则修复；将前言来源错误关联到正文章卡触发 `RECEIPT_REQUIRED`，属于正确拒绝。抽查 3 张卡发现引用区间不完整、`example` 关系方向反向、可能的因果强化，以及遗漏例外。程序后来取消模型手填 offset；原实验 4 卡保持原样。

　　最后的方法调整没有额外真实重测。当前不能声称语义全面通过或完成整书验证。v2 也没有追加付费重测。

## 撤回

　　单元制卡修改前快照位于 `%TEMP%/uno-unit-compile`。更早阅读组快照位于 `%TEMP%/uno-book-rebuild/before/`，基线记录位于 `%TEMP%/uno-book-rebuild/baseline.json`。

　　撤回前先让新任务停止并确认底层执行退出；按对应一轮差异恢复程序文件和前端构建，核对运行工作区后再加载。保留全部图书版本、卡片、历史、任务、收据和实验记录；新协议任务不可删除标记后交给旧编译恢复。撤回程序不撤销已经确认的知识写入，也不触碰 DSH 或其他知识库。
