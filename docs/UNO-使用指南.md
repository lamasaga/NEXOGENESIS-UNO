# UNO 使用指南

本指南从空白知识库开始，说明如何导入资料、编译卡片、整理知识和提出问题。环境准备及启动命令见 [项目介绍](../README.md#安装与启动)。

## 1. 选择知识库和模型

知识库是资料和知识的保存单位。开始操作前先确认当前选中的库；不同库有各自的卡片、原件和任务记录。项目可以关联多个库供对话读取，但不会把它们的文件合并。

在「设置 → 模型连接」保存供应商、密钥和模型。连接测试只读取模型目录，实际生成是否可用还取决于账户权限、模型适配和额度。不要把某个供应商套餐的密钥填入另一个接口；详见 [模型连接](UNO-模型连接.md)。

「设置 → 知识处理」用于保存当前库的用途、共同处理要求、组织偏好和默认建构选项。这些要求应说明你希望怎样使用知识，不要要求模型省略来源、抹平观点差异或把推测写成事实。

## 2. 导入材料

点击「导入材料」添加文件。常用格式为 PDF、EPUB、DOCX、Markdown 和 TXT。材料进入当前库的 `00-Inbox/`，等待编译。

- 图书优先按章节组织；短文章通常作为整体处理，长文章按内部结构拆分。
- 扫描 PDF 不会自动 OCR。先检查是否有可提取文本；必要时在外部完成 OCR，再导入并核对结果。
- 提取图片并保存原件，不等于已经理解图片、公式或复杂表格。提取警告需要人工核对。
- 加密、损坏或结构异常的文件可能无法提取；不要把提取失败当作已经读完。

初次使用宜先选一份可以人工对照的小材料，确认提取和卡片来源都符合预期，再处理大批图书。

## 3. 编译为知识卡

打开「编译」，选择待处理材料，填写本次要求并检查选项：

| 选项 | 如何选择 |
|---|---|
| 材料类型 | 通常保持自动识别；结构判断不合适时明确选图书或文章 |
| 标准编译 | 生成候选并审核，保存通过卡，局部处理具体问题 |
| 高质量编译 · 逐卡精修 | 每张候选增加一次结合原文的精修，再走正常审核；请求量、输入量和耗时更高，不保证一定更准确 |
| 请求预算 | 限制本轮可用模型请求次数，不是卡片数量，也不是金额上限；审核、修复等请求同样计入 |
| 连续处理全部所选内容 | 开启后按顺序继续；关闭则完成当前单元后暂停 |
| 允许编译自行决定领域 | 仅授权本任务自动批准通过校验的新领域；未开启时由你逐项确认 |

处理单元大小和输出预算由宿主根据已支持的模型能力确定，并随任务保存。大上下文不意味着程序会一次发送整本书或整个知识库。

编译生成的是可复用的知识对象。一章可能形成多张卡，也可能与已有知识整合；卡数不是完成指标。程序和模型检查通过后，正式卡由统一写入接口保存，并留下收据。

### 如何看待处理结果

- **已保存**：正式卡片已经写入，可以阅读和检索；仍需核对知识质量。
- **待修复**：候选、响应或关系还有问题，不应算作正式成果。按界面的具体修复入口处理。
- **未组织**：正式卡已经存在，但还没有合适领域；它与未发布的待修复候选不是一回事。
- **部分完成／未完成**：还有未处理范围、失败或缺口，不能理解为整本完成。

系统优先保存通过卡，局部问题可以留待修复；认证、预算、版本冲突等问题也可能暂停任务。原件在整本完成并核验归档之前仍保留在 Inbox。正文处理完成和领域组织完成分别结算，等待领域确认不等于正文丢失。

## 4. 阅读卡片与整理领域

打开卡片，依次检查标题、摘要、正文中的适用条件、来源和关系。对重要结论点击来源，核对实际提取文本和原件；模型摘要不能代替原作者的证据。

每张卡只有一个主类型，领域则可以为空或包含最多三个既有领域。领域记录说明核心问题、纳入范围和排除范围，帮助判断哪些卡应该放在一起。书名、作者和章节目录不直接等同于知识领域。

编译会在检查点整理未组织卡。已有领域可以在合法范围内挂靠，新领域按你选择的授权方式确认。对正式的无领域卡，也可使用界面的领域整理或人工建域入口；人工建域需要填写名称、摘要、核心问题和纳入／排除边界，再明确确认。

图谱用于浏览卡片之间的语义关系。仅同属一个领域、标题相似或图上相邻，不足以说明存在有依据的关系；用于导航的关联也不能被当作原作者已经给出的论证。

## 5. 建构已有知识

当库中已有卡片时，打开「建构」，先选主要侧重，再核对允许执行的操作。切换侧重不自动扩大权限；「按主要侧重配置」会明确替换本次操作选择。

可以从全库、某个领域或指定卡片开始。关系发现以范围内卡片为焦点，也可能从当前库的其他领域检索只读比较对象；所选范围并不等于只允许读取范围内的卡。

开启连续处理会在预算内逐轮执行，关闭时先处理一轮。可选择审核通过后保存，或由你确认发布；未发布草稿不算正式成果。取消全部修改权限则只诊断，不改卡。

建构可以修订已有卡片、调整关系、挂靠已有领域或合并重复卡，但不负责新建卡片、生成新理论、创建或拆并领域。没有足够依据时保留原样是有效结果，不应为了减少孤立卡而制造联系。

操作权限和领域调整边界见 [建构侧重与允许调整](UNO-建构侧重与允许调整.md)。

## 6. 用知识回答问题

新建对话并明确问题。可以问“这个观点在什么条件下成立？”“这些材料对同一问题有什么分歧？”或“库中有没有反例？”。有明确研究范围时，说明涉及的材料、领域和判断标准。

普通对话默认只读。系统按当前问题决定是否检索，以及怎样收集相关卡片和原文片段；不会因为你聊到一条知识就自动把它写回知识库。资料缺失、未检索到和事实不存在是不同情况，应结合引用核对。

顶部「提示词」显示当前库最近 60 次模型调用的只读快照，可核对实际输入、任务归属和已报告用量。记录不含连接密钥，但可能包含你的问题和材料正文，不宜公开分享。

麦克风按钮用于本地转写，文字追加到草稿后由你检查并发送。安装方法见 [语音输入](UNO-语音输入.md)。语音识别在本机进行；之后发送文字对话仍可能调用在线模型。

## 7. 暂停、继续与停止

- 暂停任务后，等待界面确认底层请求已经退出；发出暂停意图不等于已经停稳。
- 继续时沿用已保存成果、检查点和请求账本，不把成功阶段从头重做。预算用尽后的明确继续会补足新一轮可用额度，历史消耗仍保留。
- 刷新网页、切换会话或暂时断开页面连接，不等于暂停后台任务。要停止处理应使用任务控制。
- 编译和建构绑定创建任务时的知识库。同一库同时只运行一项这类知识任务，其他会话仍可交流。
- 停止整个本机服务时，使用启动窗口的 `Ctrl+C` 或根目录 `stop-nexogenesis.cmd`。更新后台后要重新启动服务；只刷新网页不会重载后台代码。

恢复时如果提示来源或卡片版本冲突，先检查变化，不要通过删任务状态或重置计数绕过保护。历史任务能否继续取决于其保存的协议，界面只提供历史查看时不能强行按新任务恢复。

## 8. 备份与分享

知识库目录中的原件、卡片、提取版本、历史和任务记录共同组成可追溯的工作成果。`05-Buffer/books/` 会被卡片来源引用，不能仅因名称含 Buffer 就当作缓存清理。

备份前暂停任务并停止服务，再复制完整 `knowledge-bases/` 和根目录 `.nexogenesis/`。后者包含工作区运行配置和会话等私有数据，应保密保存；跨电脑恢复仍需重新准备运行环境，不应直接照搬正在运行的进程或依赖目录。

分享程序用干净发行包，不用私人备份。Git 忽略规则和发行白名单会排除具体知识库、密钥、会话、运行状态，以及根目录的编译中间产物和实验输出。本地被忽略文件不会因此被删除，也不会自动获得备份。

完整开发仓库的打包方式见 [运行与分发](../deploy/README.md)。

## 常见问题

**打不开页面。** 先看启动窗口是否报错，确认已准备依赖并能调用 `dsh.cmd`；默认地址是 `http://127.0.0.1:3093`。端口被其他程序占用时不要直接结束不明进程。

**连接测试成功，但编译仍不可用。** 测试只说明模型目录可读，不证明生成权限、计费额度或请求计数适配都可用。阅读面板给出的具体原因，再检查模型配置。

**长时间没有新卡。** 查看任务是否正在提取、审核、等待确认、暂停或达到预算，并检查已记录的请求和错误。不要通过反复点击开始创建重复任务。

**图谱连线少，或卡片没有领域。** 这些情况不直接证明编译失败。先确认卡片内容与来源是否完整，再决定是否需要建构或领域整理。

**想把服务开放给别人访问。** 当前发布面向本机单用户，不包含成熟的服务器认证和多用户隔离方案。不要直接把 Web Host 暴露到局域网或公网。
