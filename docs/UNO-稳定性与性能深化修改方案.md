## 1. 实施原则与优先顺序

优先解决数据被覆盖、界面与实际写入目标不一致、局部故障阻断整个知识库的问题，再处理恢复入口和资源上限，最后优化重复计算与界面等待。上一轮已经完成的任务版本检查、凭据端点隔离、基础上传流式化和主包拆分继续保留。

证据级别：

- **已复现**：在临时合成目录或内存替身中直接调用当前代码，观察到指定行为。
- **源码确认**：调用链与条件在源码中明确存在，尚未进行完整故障注入或浏览器交互复现。
- **待测量**：确认存在计算或 I/O 成本，但尚未测得实际规模下的延迟、内存或吞吐影响。

P1 表示优先处理的完整性、隔离或主要流程可用性问题；P2 表示局部恢复、资源控制和性能问题。这里的优先级不代表已经发生线上事故，也不代表漏洞已被利用。

## 2. 数据完整性与故障隔离

### F01：元数据损坏后会被默认项目覆盖

**位置**：[meta.js](D:/UESR/Desktop/NEXOGENESIS-UNO/packages/nexogenesis-web-host/lib/meta.js:43) 的 `readMeta`、`writeMeta`、`ensureDefaultProject`；[projects.js](D:/UESR/Desktop/NEXOGENESIS-UNO/packages/nexogenesis-web-host/lib/projects.js:128) 的默认项目初始化调用。

**触发与影响**：`readMeta` 将文件不存在、读取被拒绝和 JSON 损坏统一捕获并返回空元数据。后续 `ensureDefaultProject` 会把空对象创建为默认项目并写回原文件。合成试验中，写入一个截断 JSON，读取返回空项目，调用默认项目初始化后原字节被覆盖。这里受影响的是项目、会话归属、置顶和删除标记，不能将其描述为卡片正文已被删除。

**修改要求**：

1. 只有 `ENOENT` 可以走首次初始化。解析错误、权限错误、I/O 错误分别返回稳定错误码，阻止基于空默认值写回。
2. 原文件完整保留；最近一次已验证快照可以支撑只读展示，并明确标识状态过期。
3. 默认项目初始化必须要求“确认不存在”，不能从“读取失败”推断。
4. 提供“重试读取、导出诊断、从已验证备份恢复”入口；恢复前展示目标、备份时间和覆盖范围。没有备份时保留原件，进入诊断流程。

**验收**：截断 JSON、非法字段、权限拒绝、临时 I/O 错误均不改变原文件哈希；调用项目列表及创建入口也不能覆盖损坏文件；首次启动且确实无文件时仍正常创建默认项目。

### F02：离线的非当前实例会阻断列表，也无法通过现有入口移出登记

**位置**：[registry.js](D:/UESR/Desktop/NEXOGENESIS-UNO/packages/nexogenesis-tools/lib/instances/registry.js:33) 的 `canonicalDirectory`、`normalizeRecord`、`readInstanceRegistry`、`unregisterKnowledgeInstance`；[instances.js](D:/UESR/Desktop/NEXOGENESIS-UNO/packages/nexogenesis-web-host/lib/instances.js:21)。

**触发与影响**：实例记录读取会对每个目录执行存在性、真实路径和清单验证。登记过的移动硬盘拔出、外部目录移动、清单损坏，即使当前库正常，也会让整个登记表读取抛错。移出登记同样先读取全部记录，因此用户无法直接移出导致故障的离线项。两条路径均已复现。

**修改要求**：分离“登记表结构有效性”和“各实例当前可访问性”。逐项返回 `available / unavailable / invalid_manifest` 及原因，保留原始记录。正常实例继续可用；不可用实例禁止激活和写入。移出非当前实例只要求登记身份有效，不要求其磁盘当前在线。重新定位目录需核对稳定 ID，避免把同名目录当成原库。

**用户兜底**：重新检查、重新定位、移出登记三个选项；移出登记保留磁盘内容。当前库不可用时允许选择其他正常实例，不能自动挑一个库接收后续写入。

**验收**：A 正常、B 离线时能列出 A/B 状态、继续使用 A、移出 B；B 恢复后重新检查可用；B 清单 ID 与原记录不符时拒绝绑定。

### F03：后端切库成功，后续刷新失败时界面仍可能显示旧库

**位置**：[App.tsx](D:/UESR/Desktop/NEXOGENESIS-UNO/web/src/App.tsx:332) 的 `changeKnowledgeInstance`；[registry.js](D:/UESR/Desktop/NEXOGENESIS-UNO/packages/nexogenesis-tools/lib/instances/registry.js:118) 的发布订阅；[work.js](D:/UESR/Desktop/NEXOGENESIS-UNO/packages/nexogenesis-web-host/lib/work.js:27) 的实例操作准入。

**触发与影响**：前端先完成切库请求，再 `Promise.all` 等待实例、图谱、项目和流水线四个读取请求，全部成功才更新当前实例。后端已经切到 B 后，只要其中一项失败，界面就进入“切换失败”，可能仍显示 A 的身份和内容。旧请求迟到也需要一并处理。现有后端已串行保护切库与已准入写操作，问题主要在提交后的身份核对与显示恢复，不应重新增加另一套并行锁。

**修改要求**：

1. 切换成功响应中的实例 ID 立即成为前端已确认身份；图谱和列表作为独立可重试资源加载。
2. 使用实例 ID 与切换代次隔离缓存、查询结果、旧轮询及迟到错误；未核对完成时暂停会改变知识或会话归属的操作。
3. 切换响应丢失时先读取当前实例，再决定显示结果；不得直接声称切换未发生。
4. 对实例发布订阅补故障注入：有订阅者抛错时，磁盘登记、运行根目录和会话元数据选择必须有明确结算，不能只向用户返回笼统失败。

**用户兜底**：显示“已切换到 B，图谱加载失败”，提供重试图谱与重新核对当前库；用户仍能访问已成功加载的 B 资源。明确切回 A 应执行新的切库操作。

**验收**：四个后续请求逐个失败、切库响应丢失、A 的迟到请求覆盖 B、连续 A→B→C、双标签页切库均纳入浏览器测试。任何可写状态下显示身份必须与实际目标一致。

### F04：单张损坏卡可中止全库扫描，部分目录异常又被视作空库

**位置**：[cards.js](D:/UESR/Desktop/NEXOGENESIS-UNO/packages/nexogenesis-tools/lib/cards.js:126) 的 `cardInventory` 与 `scanCards`。

**触发与影响**：遍历中 `parseCardFile` 没有逐文件隔离。合成库包含一张正常卡和一张 YAML 损坏卡时，`scanCards` 整体抛错，正常卡也无法返回。另一个方向上，目录枚举发生错误会被统一转换为 `files=[]`，可能向上层呈现空结果。文件在枚举后被移走时，后续 `statSync` 也会整体失败。

**修改要求**：

- 建立快照状态：`complete / partial / unavailable`，附无内容泄露的损坏文件诊断。
- 展示和只读检索可返回正常卡或上次完整快照，并清楚标明缺口；禁止把部分结果用于“全库无重复”“全部处理完成”等判断。
- Gateway 的版本、来源与关系端点校验保持严格。未知端点来自损坏文件时，写入应拒绝相关操作，不能自动删除关系或假定对象不存在。
- 路径不存在、访问被拒绝、枚举期间变更分别处理；短暂变更可有一次有界重读。

**用户兜底**：损坏对象清单、重新读取、查看原始文件或恢复历史版本。原文件保留；不自动移动卡片，因为路径变化可能影响来源与引用。

**验收**：一张损坏卡不阻断其他正常卡阅读；全库统计标记不完整；正式写入不能借降级模式跳过损坏目标、版本或端点验证。

### F05：写锁存在无法自行恢复的窗口，提交后的清理失败会模糊结果

**位置**：[uno-storage.js](D:/UESR/Desktop/NEXOGENESIS-UNO/packages/nexogenesis-tools/lib/harness/uno-storage.js:54) 的 `transaction` 与 `recover`。

**触发与影响**：创建锁目录与写入 `owner.json` 是两个步骤。如果进程在中间退出，或者属主文件写入失败，锁目录会保留。当前代码遇到无属主文件直接拒绝新写入；该行为已在合成库复现。只记录 PID 也不能区分 PID 被后续进程复用的情况。另有一个独立窗口：收据已经写入后，事务文件或锁清理失败仍可能抛错，使调用方看到失败但数据实际已提交。

**修改要求**：

1. 属主记录增加进程启动身份、事务 ID 与创建时间；锁建立失败要有确定性收尾。
2. 缺属主／损坏属主不能按年龄自动删除。提供诊断与安全恢复路径，结合服务执行状态、事务日志、收据和目标版本判定。
3. 提交结果以实际收据为准。提交后的清理失败返回“已提交、清理待处理”，记录诊断，不引导重复生成或重复发布。
4. 恢复遇到外部修改时保持暂停，展示冲突文件和恢复选项。不能绕过日志直接删锁继续。

**验收**：锁目录刚创建、属主写入、各文件替换、收据写入、事务清理与锁清理各阶段注入错误；明确区分未提交、已提交和待核对。相同幂等键重试必须返回同一收据。模拟 PID 复用及并发锁竞争。

## 3. 长操作、取消与资源上限

### F06：流式接收之后，最终发布与异常收尾仍存在缺口

**位置**：[inbox.js](D:/UESR/Desktop/NEXOGENESIS-UNO/packages/nexogenesis-web-host/lib/inbox.js:96) 的 `receiveMultipart` 和 `handleInboxUpload`；[client.ts](D:/UESR/Desktop/NEXOGENESIS-UNO/web/src/api/client.ts:1060) 的上传分批逻辑。

**触发与影响**：文件接收到临时路径后，使用 `copyFile(..., COPYFILE_EXCL)` 直接写最终 Inbox 文件名。排他创建能防覆盖，但不保证复制期间最终名字不可见，也不保证进程退出后不会留下部分目标文件。异常路径中，接收管线失败后直接尝试删除临时文件，没有先等待所有已启动文件写管线结算；Windows 上句柄尚未关闭时删除失败被忽略，存在残留风险。前端批量上传没有取消信号，某一批长期无响应会阻塞后续批次。

**修改要求**：采用同目录暂存与经过 Windows 验证的“原子发布且不覆盖”机制；不要直接把普通 `rename` 当作具有排他语义。最终名称只在完整字节、长度和摘要检查通过后出现。异常时先终止并等待所有写流，再清理自己创建的临时文件；保留清理失败记录。

为批次增加中止、进度和结果核对。停止后不启动下一批；已经成功发布的文件保留。“未收到回执”归入待核对，不自动记为未保存。清理只处理可证明无活动属主的临时文件，不能按扩展名批量删用户材料。

**用户兜底**：停止剩余批次、只重试失败／待核对文件、导出逐文件结果、同名异内容改名导入。不要为了重试重新发送全部已确认文件。

**验收**：复制中终止进程、磁盘不足、断开上传、写流出错、两批同时写同名文件、收到文件但丢失响应。Inbox 列表与编译入口只能见到完整文件，残留临时文件可安全诊断与清理。

### F07：上传与预处理能力不一致，子进程和解压成本缺少完整边界

**位置**：[preprocess.py](D:/UESR/Desktop/NEXOGENESIS-UNO/packages/nexogenesis-tools/lib/uno/preprocess.py:85)、[knowledge.js](D:/UESR/Desktop/NEXOGENESIS-UNO/packages/nexogenesis-tools/lib/uno/knowledge.js:41) 的 `preprocessSource`。

**源码事实**：

- 上传允许 256 MiB，预处理直接拒绝超过 50 MiB 的文件。上传成功不代表材料可编译，但当前两个能力没有在统一准入中表达。
- 预处理宿主有 AbortSignal 和 40 MiB stdout 上限，没有明确总执行期限；stderr 使用数组无限追加。stdout 大小不能约束 Python 内部解压和解析前的峰值资源。
- EPUB 有清单总量检查；DOCX 媒体只有逐文件上限，缺少同等的条目数和累计展开预算。`asset(z.read(...))` 在资产保留额度判断前已经解压读入，超过保留额度后仍可能继续读取后续媒体。
- PDF 重复图片会再次提取；资产去重命中后，又逐项 base64 解码并重新计算哈希来寻找原资产。这个成本随重复次数和资产数量增加。

**修改要求**：由准备接口给出上传可保存与可编译限制，并按格式解释原因；大文件可以保留为原件，但开始前应提示无法直接处理。预处理增加执行期限、stderr 有界尾部、统一终止与等待退出机制。所有压缩格式共享条目数、单项、累计展开和读取预算，预算检查尽量放在实际解压之前。图片使用摘要到资产对象的 Map；PDF 优先按 xref 复用提取结果，并合并定位信息。

**用户兜底**：取消预处理、保留原件、缩小范围、拆分材料、转换为可提取文本后重新导入；保留未提取图像和章节缺口，禁止用静默截断满足预算。

**验收**：50 MiB 边界、低压缩大小但多媒体展开量大的 DOCX、重复 PDF 图片、子进程不退出、stderr 持续输出、取消后迟到输出。记录峰值内存与实际退出时间，不能以 stdout 已限额替代资源验收。

### F08：共享安全令牌请求悬挂，会拖住所有等待它的写操作

**位置**：[client.ts](D:/UESR/Desktop/NEXOGENESIS-UNO/web/src/api/client.ts:191) 的 `getLocalRequestToken` 与内部 `fetch` 包装。

**触发与影响**：首次写请求先等待全局共享的 `/api/security/session` Promise。这个请求没有自己的期限；调用者的 AbortSignal 只传给后续业务 fetch。在安全会话读取一直不结算时，业务操作即使自身设置了超时，仍可能卡在令牌等待阶段；后续写请求复用同一个悬挂 Promise。语音转写已有额外取消包装，但未统一覆盖其他操作。

**修改要求**：共享令牌获取设置有界期限；各等待者独立响应取消，不能因一个等待者取消就中断其他等待者。等待结束与外发前检查取消状态。旧令牌请求晚到不能覆盖新的代次。对 403 的重试应依据明确的令牌失效错误码，且只在已确认业务尚未执行的准入拒绝上重发。

**用户兜底**：显示安全会话连接失败、重试连接、保留表单和待提交请求 ID。对已外发但结果未知的写操作先查询结果，不能仅因超时生成新请求 ID。

**验收**：令牌接口无响应、取消发生在取令牌阶段、多个写请求同时等待、服务重启后旧令牌失效、旧请求晚到。所有等待必须能够结算，已取消的调用不得新增业务请求。

## 4. 界面恢复与长时间使用

### F09：浏览器存储异常及切库时的存取顺序会影响主界面和恢复记录

**位置**：[App.tsx](D:/UESR/Desktop/NEXOGENESIS-UNO/web/src/App.tsx:281) 的最近阅读／收藏 effects；[recovery.ts](D:/UESR/Desktop/NEXOGENESIS-UNO/web/src/conversations/recovery.ts:9)。

**触发与影响**：收藏和最近卡片的 `localStorage.setItem` 未捕获异常；配额不足、存储被禁用等情况会抛入 React effect。切换实例时，写入 effects 排在加载新库收藏的 effect 前面，同一轮 effect 可能把旧库的列表先写进新库 key，再读回这个已覆盖值。恢复模块的 `prepareStart`、`completeStart` 和 `rejectStart` 也直接写 sessionStorage，存储失败可能阻断启动，或者在后端已成功后使前端完成结算报错。以上为源码路径判断，需真实 React 挂载测试确认表现。

**修改要求**：偏好状态携带所属库 ID 和是否已加载标记；只持久化与当前库一致、完成读取的状态。普通偏好读写失败使用内存回退并提示无法持久保存。待提交操作的幂等 ID 必须保留；可采用内存登记加服务端查询，不允许简单吞掉存储异常后在每次点击时重新生成 ID。

**用户兜底**：继续当前页面、复制未提交要求、重试保存；无法跨刷新恢复时明确提示。现有请求可核对后继续，不自动创建另一任务。

**验收**：A、B 收藏不同，连续切换十次后双方记录不互相覆盖；读写存储分别抛错时页面仍可操作；后端任务已创建但客户端存储失败时，不产生重复任务。

### F10：异步模块只有等待占位，没有加载失败边界

**位置**：[App.tsx](D:/UESR/Desktop/NEXOGENESIS-UNO/web/src/App.tsx:1224) 及后续异步面板；[main.tsx](D:/UESR/Desktop/NEXOGENESIS-UNO/web/src/main.tsx:6)。

**触发与影响**：提示词查看器、设置、卡片管理和知识工作台使用 `React.lazy` 与 `Suspense fallback={null}`。源码中未发现 ErrorBoundary。模块慢加载时没有反馈；动态块 404、断网或发布后旧页面引用已失效块时，模块加载异常没有局部恢复界面，可能影响整个 React 树。

**修改要求**：每个异步业务区域具有可关闭的加载状态与局部错误边界，保留外层对话和草稿。模块重试必须验证实际重新发起了加载；仅重新渲染同一 lazy 对象不应视作已实现恢复。整页刷新作为最后选项，刷新前保留尚未提交的用户输入。

**用户兜底**：重新加载面板、关闭面板返回、保留草稿后刷新页面。模块异常不能自动重发模型请求或写入操作。

**验收**：逐个动态块模拟延迟、404 和恢复；阻断加载时可关闭；重新加载能恢复；主对话和其他已加载面板保持可操作。

### F11：多个固定间隔轮询缺少共享在途控制和响应顺序约束

**位置**：[App.tsx](D:/UESR/Desktop/NEXOGENESIS-UNO/web/src/App.tsx:355) 的 `syncJob`、`syncFollowUp`、认知状态同步；[client.ts](D:/UESR/Desktop/NEXOGENESIS-UNO/web/src/api/client.ts:1028)。

**触发与影响**：页面同时存在 3 秒、1.2 秒与 1.5 秒的轮询，其中两条路径会读取同一会话的认知状态。`setInterval` 不等待前一次请求结算；慢响应会重叠，较旧响应可以在新响应后更新同一个会话。部分失败分支把认知状态直接清空，可能让待选择项或执行信息暂时消失。`refreshWork` 已有在途请求与 epoch 保护，可作为现有实现的参照。

**修改要求**：按库、会话和资源种类合并在途读取；结束后再调度下一次。每次读取有期限、代次与取消处理。同一资源使用单调版本或请求序号拒绝倒序响应。断网退避，隐藏标签页降低频率，重新连接立即核对。读取失败保留最后有效状态并标记过期，控制是否可用依据后端状态及明确的连通性要求。

**用户兜底**：显示上次成功同步时间、手动刷新和重连；停止按钮的回执丢失时显示“停止结果待核对”，不能宣称执行已停止。

**验收**：请求延迟大于轮询间隔、乱序响应、断网恢复、切库和切会话、多标签页。相同资源同一时刻最多一个有效在途读取；终态不能被旧响应改回运行中。

### F12：SSE 缺少背压处理，回放游标和内存释放不完整

**位置**：[events-bus.js](D:/UESR/Desktop/NEXOGENESIS-UNO/packages/nexogenesis-web-host/lib/events-bus.js:9)、[pipeline.js](D:/UESR/Desktop/NEXOGENESIS-UNO/packages/nexogenesis-web-host/lib/pipeline.js:172)、[client.ts](D:/UESR/Desktop/NEXOGENESIS-UNO/web/src/api/client.ts:342)。

**证据**：

- `res.write` 返回值未处理。慢响应替身每次返回 false，连续广播 1,000 帧仍发生 1,000 次写调用；这证明没有背压处理，未测得真实 socket 内存增长量。
- 每个会话历史限制为 96 帧，但 `histories` 和 `sequences` 没有全局容量或空闲淘汰；退订只移除 subscriber。
- 帧包含 seq，但服务端未输出 SSE `id:`，前端也未维护 `after` 游标。后端缺省查询参数经 `Number(null)` 变为 0，重连可能重复回放最近帧。前端连接打开后已有状态同步，因此不能据此断言正式任务一定丢失；风险主要是重复事件与动画、增量更新的不一致。

**修改要求**：每连接设有界队列与暂停／drain 策略；低价值动画可以合并或丢弃后重新同步快照。慢客户端超出队列界限时断开该客户端，不能阻塞任务结算。历史按会话空闲时间和总字节淘汰。游标使用连接代次与序号，过期游标走完整快照校准，防止服务重启后新旧 seq 混用。

**用户兜底**：图谱事件流不可用时仍可读卡、查看任务及手动刷新；界面显示实时连接状态，重连后以快照对账。

**验收**：一个慢客户端不影响其他客户端；频繁断线不重复业务增量；创建并结束大量合成会话后缓存回到预算；服务重启后游标重新建立。

## 5. 计算与 I/O 性能

### F13：稀疏检索缓存命中仍遍历文件，变更后全量同步重建

**位置**：[knowledge.js](D:/UESR/Desktop/NEXOGENESIS-UNO/packages/nexogenesis-tools/lib/uno/knowledge.js:73) 的 `index`、`searchKnowledge`。

**源码事实**：每次索引查询先枚举 Buffer 引用和卡片文件状态，构建并排序全量签名。签名改变后，所有卡片与 Buffer 文本重新组装、分词、统计并序列化写盘。关系解析没有传入已加载的卡片集合，会反复调用默认 `loadCards`；它通常能命中快照，但仍造成额外查找，且与当前活动卡集合不是同一份显式快照。索引写盘失败直接导致本次检索失败，即使完整索引已在内存中算好。

**修改要求**：

1. 将文件版本、每文档词频和库级索引代次分开；优先增量更新受影响的卡片及原文文档。卡片 Gateway 写入可精确失效，外部 Markdown 修改仍需有界扫描校准。
2. 在一次重建中显式传递同一份卡片快照；保持包含退役卡的跳转解析语义，不能为了省调用而破坏旧 ID 解析。
3. 缓存文件只是加速层。保存失败时返回当前有效内存结果及诊断，后续重试持久化；来源正文读取失败则必须报告证据缺口。
4. 根据基准决定是否迁入 worker。若迁移，worker 产物必须带输入代次，旧代次不能覆盖新索引；不立即引入数据库或另一套知识事实源。

**用户兜底**：索引重建进度、重试检索、只读浏览可用卡片；旧索引结果必须标明版本并在交付正文前重验对象，不能伪装为当前完整检索。

**验收**：合成 1k／5k／10k 卡与不同 Buffer 规模，测冷检索、暖检索、单卡修改后首查、连续发布中检索；记录文件扫描数、分词文档数、事件循环延迟、CPU 与内存。同一查询在相同快照下保持排序和来源语义。只读缓存目录时检索仍可用。

### F14：请求查看器在增量输出时重复写入完整输入

**位置**：[prompt-inspector.js](D:/UESR/Desktop/NEXOGENESIS-UNO/packages/nexogenesis-web-host/lib/prompt-inspector.js:50) 的 `write`、`save`、`registerPromptInspector`。

**触发与影响**：模型产生可见输出时，每隔至少 2 秒可能保存一次记录。每次 `save` 都同步序列化和写入完整输入、累计输出及索引。输入在同一请求期间通常不变，长输入和长输出会被重复写盘；同步 I/O 位于流式中间件中，可能推迟下一块向用户交付。代码已捕获保存异常、允许模型继续，这是应保留的降级能力；本项针对性能和诊断持久化质量。

**修改要求**：不可变输入一次保存；输出和轻量状态独立检查点，采用按时间与新增字节双阈值触发，终态明确落盘。写盘任务合并、单队列有界，积压时报告记录延迟，不能无限堆积。保留现有 60 条记录与可见信息过滤，并为单条记录和全目录制定字节预算；不能把请求查看器中的截断内容当成失败修复所需的完整原始响应。

**用户兜底**：显示记录保存延迟／失败，仍允许查看已保存部分、导出已有记录、检查磁盘空间。任务审计账本、正式收据与诊断记录分别管理。

**验收**：使用大输入和持续模拟输出，比较实际写盘字节、序列化耗时、首字与块间延迟；慢盘、磁盘满、取消和记录淘汰时不得改变模型结果或恢复已淘汰记录。
