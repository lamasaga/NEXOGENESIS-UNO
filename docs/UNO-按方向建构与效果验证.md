# UNO 按方向建构与效果验证

> 本页记录历史 `direction-driven-v1` 契约，只用于已创建任务的追溯与恢复。新建构使用 [策略建构服务](UNO-策略建构服务.md) 的 `strategy-driven-v2` / `uno-construction-v1`，两类任务不在中途改签。

2026-09-16。当前为本地源码、程序回归和隔离样本验证；本轮没有重启正式服务，也没有改写真实金融底座。

## 用户给方向，系统安排局部工作

新建构入口要求说明希望改善的主题与用途，可以选标签缩小范围，不要求手选卡片 ID。请求使用 `construction_profile=direction-driven-v1` 和 `orchestration_profile=bounded-workflow-v1`，沿用已有任务、原生会话、请求账本与 Gateway，不另建一套任务调度。新任务同时冻结 `card_classification=ordered-single-type-and-domains-v2`；作者、独立审核、工具 Schema、类型指南与阶段证据包都读取该字段。已在途且没有该字段的建构任务继续使用 `single-type-and-domains-v1`，不在任务中途改签。

当前分类按 `conflict → entity → case → concept → method → mechanism → model → claim → phenomenon → undetermined` 顺序检查，取第一个满足全部最低条件并符合整卡主要知识功能的类型。`phenomenon` 必须有观察对象与依据；其他九类都不成立但知识单元仍完整可复用时才使用 `undetermined`。建构调整类型时遵守同一顺序，审核不能用旧九类顺序重新裁决新任务。

程序按目标词、标题、摘要、有限正文和已有联系提出相关比较组，每组最多 6 卡、约 30,000 字符，本次最多选取 24 张候选。完整目标随每组交付，模型根据证据决定具体修订、合并、导航或保留。未入选范围单独列出，不能计作全库检查完成。当前使用本地词面与联系候选，不声称具有全库语义问题发现能力；笼统方向或词面差异大的主题仍可能漏选，需要修改方向或缩小范围。分组上限为可调整的试验参数，不是知识对象数量配额。

授权写入范围冻结为本次候选集合；其他卡片可以作为只读对照和导航目标。确有依据的跨组合并仍可进行，发布后再按真实收据重算剩余工作。领域层和自动新建综合理论不在本次新增能力中。

## 一致性修复

- 合并发布原子保存正式卡、旧卡历史、退役去向及精确版本。后续组只有在磁盘发布收据、退役文件版本和有效承载卡相符时才跳过；异常退役、缺失文件、变更去向都保留待办。
- 普通编辑不能重新激活 `superseded/archived` 卡片；恢复必须走单独的显式历史恢复入口。修改保留原有 `origin`，不把系统推断改称文档来源。
- 同一次发布不能既退役又写入同一 ID。整批成功与对象成功分别记录，失败发布不清待办。
- 原卡未变的局部检查结论绑定自身与实际关系/来源依赖；本组另一张卡合法发布不会无故重开所有结论。来源或端点缺失不能形成“无需修改”的缓存。
- 发布依赖按审核实际使用的版本确定。目标已有正式卡时，默认基于该正式版本，不因目标另有坏草稿而连带阻塞。明确依赖目标新稿时须同批发布或验证它已发布的精确版本。人工确认前版本变化会拒绝沿用旧审核。

## 减少重复工作，但区分不同结论

普通整理中，作者完整读回后可登记具体 `unchanged` 依据；这表示对当前目标无需修改，`source_verified=false`，不代表独立事实核验。没有实际完成的对象登记 `deferred`，保持部分完成且能够恢复。

相同目标、模型、长期偏好、规则、范围清单、卡片版本及来源/邻接依赖版本的无修改组可复用检查，不调用模型；来源变化、新卡进入范围、规则变化均会失效。缓存只是 `.nexogenesis/construct-checks/` 的可重建运行记录。用户勾选“重新检查”会绕过缓存。当前只复用无修改组，不冒称已能对所有历史修改安全增量执行。

明确要求事实核验、来源核对、数字核查的方向，即使未改卡也保留独立审核：完整卡片、当前来源证据、具体命题与引文、发布时来源版本均要匹配。引文匹配只证明定位；是否支持判断仍由审核人负责。

## 按实际改动审核

| 实际改动 | 本轮必要证据 |
|---|---|
| 标题、类型、主题等元数据 | 变更前字段及当前正文依据，不重复发送相同旧正文与全部来源 |
| 阅读导航 | 两端具体正文、比较维度与成立边界；默认读取正式目标，导航不能认证因果 |
| 正文、摘要、边界、来源或来源论证关系 | 修改前版本与差异、完整新稿、支持具体变动的来源引文 |
| 合并 | 上述要求加完整旧卡双方、新稿中的保全依据，以及独有条件、作者立场、反证与来源锚点 |

类型由程序比较实际草稿计算，不接受模型自行降级。审核会话只登记结论和具体问题，不自行扩写。首包区间只在真实发送且模型开始响应后记作已交付，字段预览和替代版本目录不能冒充完整阅读。审核问题最多自动退回作者一次；未解决对象保留待修。

## 固定案例结果

固定合成资料位于 `tests/fixtures/construction-effects/cases.json`，用真实 Gateway 执行预定修订、真实 `collectThinkingContext` 收集前后资料。反向对照还故意漏掉条件、混用来源关系、合并不同作者，验证效果检查可以发现这些坏结果。程序写入合法并不保证知识正确。

| 案例 | 检索变化 | 同模型回答观察 |
|---|---|---|
| 重复合并 | 同一对象由两份变为一个当前检索入口，旧 ID 跳转且两处来源与观察窗口保留 | 没有明显整体质量优势；修改前回答更明确区分登记与实际供给，但多写了一个错误的假想加总数字 |
| 反例导航 | 找到词面检索原先遗漏的反例候选 | 修改后能具体比较触达名单与窗口，且没有把反例直接当成证伪 |
| 观点冲突 | 保留双方独立对象，补入原先遗漏的另一方 | 修改后可区分一年存量承租者收益与八年新增供给风险，没有强合为无条件结论 |

真实请求使用同一 `deepseek-v4-flash`、关闭思考、无历史、相同问题和参数，两次请求分别批量回答三题，不额外运行意图判断。修改后输入 1,696 / 输出 758 tokens；修改前输入 1,303 / 输出 920 tokens；本轮总计 **4,677 tokens**。有效信息变多可以使输入增加，不以单次 tokens 更少为效果目标。

不知道 A/B 条件映射的独立子代理按固定五维标准读回答，得到 A/B 30/25；揭示映射后 A 为修改后。该分数只是这三题的描述，不能证明统计显著、普遍优于旧流程或形成确定的节省比例。一次批量三题不等于三个独立实验。

特别边界：上述建构修订与批准由案例预先设定；真实模型只负责前后回答。因此它证明这些正确修订对检索和回答有实际帮助，**没有证明模型已能自主发现、执行并正确审核所有修订**。大型真实知识库和自动建构端到端仍须另作受预算约束的实验。前一轮原书选章试验的失败记录未改写。
