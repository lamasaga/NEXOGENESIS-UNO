# UNO 对话积累与思考技能设计

> 2026-09-16。基于当前 UNO 源码、现行开发基线和会话恢复实测问题制定。本文为待实施设计；没有接通新工具、启动研究任务、写入知识卡或启用自我改进。接口名称和预算中注明的建议值均需实现与验证。

UNO 应允许用户在同一段对话中，自然地从理解问题走到形成判断、保存知识、修订认识和产出报告。积累的价值是以后更容易找到并正确使用这些认识，不是聊天结束后增加了多少张卡。

建议保留六种已有思考路线，增加五类可按本轮请求激活的成果能力。思考路线回答“怎样分析”，成果能力回答“要留下什么”。两者组合使用，不把每种组合做成新 Agent、新会话或一套独立调度器。

配套：[技能调用与提示契约草案](design/conversation-skills/skill-contracts.md)；[验收场景数据](design/conversation-skills/acceptance-cases.json)。后者是待实现的验收输入与预期，不是已经通过的测试。

## 1. 先说明当前能做什么

| 环节 | 当前事实 | 对这次设计的影响 |
|---|---|---|
| 普通对话 | 新会话使用 quick；意图只接受 answer/retrieve，模型请求不带工具 | 目前能回答、检索，不能因为存在旧 Skill 文件就执行沉淀、精修 |
| 知识利用 | 六种路线按需收集卡片和 Buffer 摘录；支持所选知识库的有限检索 | 可复用取证能力；关系仍是线索，检索结果不是全库核验 |
| 制卡底层 | UNO-v3 已有草稿、版本检查、事务、历史和收据 | 可复用机械能力；不能直接复用整条编译工作流 |
| 对话来源 | 当前草稿只接受本库 Buffer/Archive 来源；内容写入强制标为 document、uno-compile-v3、active | 直接接入会把模型推断或用户贡献伪装成文档编译，必须先修改来源契约 |

## 2. 用户可以自然激活的五类能力

| 能力 | 用户说法示例 | 主要交付 | 什么时候进入知识库 |
|---|---|---|---|
| A 沉淀知识 | “把刚才这个判断记下来”“这几张卡之间能否形成新认识？” | 一张或少量可独立阅读的候选卡，也允许判断暂无值得落卡的增量 | 明确保存要求后准备草稿；用户审阅具体版本后提交 |
| B 定向修订 | “这张卡遗漏了反例，补进去”“只把这一段说清楚” | 指定卡的局部修订、完整差异与保留说明 | 绑定真实卡片和版本，确认具体差异后提交 |
| C 专题研究与研报 | “深入核查后在这里回答”“把讨论整理为一份研报” | 有来源、时点和局限的研究回答或报告 | 研究可仅在对话交付；要求报告时进入 OutBox，拆卡和改卡另按明确请求处理 |
| D 判断复盘 | “对照后来的变化复盘上次判断”“当时为什么漏掉这个条件？” | 原判断、后续证据、偏差原因与需要修订之处 | 复盘本身不自动改卡；用户可继续要求沉淀或修订 |
| E 方法与知识利用改进 | “以后遇到这类问题先检查什么？”“为什么总漏掉那张反例卡？” | 可复用方法候选，或具体检索/回答失败案例与改进试验 | 方法知识可按 A 保存；行为改变经对照和批准试用后启用 |

“涌现”和“沉淀”在 A 中有不同含义：涌现是提出已有材料之外的综合认识或假说；沉淀是把有价值的认识保存为知识。涌现不必立即写卡，保存也不要求每次发现新理论。只让 UNO 探索新认识时，先交付认识和依据，不擅自写库。

这些能力可以连续发生，但不自动串成固定流水线。用户要求一份研报，不默认触发复盘、写卡、整理全库和方法学习。用户只问一个简单问题，五类成果能力都不用激活。

用户在一句话中明确要求“复盘、修订原卡，再形成简报”，应记录这一个请求里的三个成果及必要依赖，逐项完成，不让用户重复发三次指令。共用一个累计预算，不能每切换一个技能就重置。需要确认的知识修订可以先停在草稿；报告若引用未提交版本，必须说明草稿状态。

## 3. 六种思考路线继续服务整个对话

| 路线 | 重点 | 可用于哪些成果 |
|---|---|---|
| 解释原因 | 机制、成立条件、替代解释 | 沉淀机制判断，修正因果误读 |
| 比较选项 | 对称维度、不同约束、取舍 | 决策卡、比较报告 |
| 检验判断 | 支持证据、最强反例、何时失效 | 修订边界、提出待检验假说 |
| 寻找类比 | 可迁移的结构、重要差异 | 方法提炼，跨领域启发 |
| 追踪变化 | 当时可知信息、后续变化、时间顺序 | 专题研究、判断复盘 |
| 综合判断 | 目标、约束、可行选项、风险与行动条件 | 研报结论、条件性建议 |

选择路线是帮助找对证据，不是给每个回答强加六段格式。“综合判断”也不意味着串行执行前五条。切换话题时重新判断，追问则保留本轮真正需要的对象和条件。

## 4. 每项能力应怎样工作

### A. 沉淀知识：保存值得复用的对象

首先确定要保存的是哪项认识，以及它来自用户、材料还是本次综合。卡片至少要讲清对象、主要判断、依据和适用条件；模型提出的新解释明确保留为假说或待验证判断，不改写为来源已经证明的事实。

围绕该对象集中检索一次，阅读最相近卡片的必要正文。比较对象身份、真实增量、解释完整性和旧卡的承载负担，再选择新建、丰富或不写。不能只因关键词相近就塞入旧卡，也不能因为“没有一模一样的标题”就新建。

默认一次展示 1–3 张紧密相关的候选，便于阅读和确认；这是交互建议，不是知识产量配额。用户明确要求较大范围时，按内容展示可独立审阅的批次，共享原目标和累计预算，不把“每批必须三张”写成模型指标。

候选正文直接面向以后使用它的人。只保留必要的对话来源片段、真实材料锚点、支持与反证；不先生成长篇中间笔记再由主代理重新读一遍。用户可以编辑候选、改为修订已有卡、保留对话或取消。

**成功标准：** 下一次相关问题能够找到这张卡，正确使用其条件和反例；卡片数量、篇幅与关系条数都不是成功的替代指标。

### B. 定向修订：清楚知道改变了什么

卡片阅读器提供“在当前对话修订”，携带知识库 ID、卡片 ID 和版本。自然语言里只说标题时，宿主解析目标；若存在两个合理对象，询问目标，不能猜一个就写。

读取当前卡片必要全文一次。用户只要求措辞或结构调整时，保留判断、来源、关系、对象 ID 与生命周期；要求补证据或改判断时，只针对变化部分取证。较大卡片可分节读取，但关键限制段不能只因排在后面被丢弃。

优先采用局部编辑。预览展示完整新正文、可切换的原文/差异、实际改动的字段，以及新增或撤回的证据。撤回错误说法不等于删除原始来源：通过历史保留原文，并明确哪些来源不再支持当前判断。

提交时检查目标版本、草稿版本和来源版本。如果别人已经修过，保存这份草稿并重新计算差异，不覆盖新版本，也不把旧确认套在新内容上。关系调整另列清楚，不能因一次措辞修订隐式连边或批量改动邻居。

**成功标准：** 指定问题被修好，未要求改变的事实和边界得到保留；刷新、重复确认和并发修订不产生重复写入或丢失更新。

### C. 专题研究与研报：区分整理和新研究

研究深度与交付形式独立判断。“深入核查，但直接在这里回答，不要报告”也能使用有界研究，结果只留对话；“整理成研报”也可以完全不新增研究。两者使用同一个 C 能力，不再增加一个“深度会话”入口。

“整理刚才的讨论成研报”复用本次已经提供的证据和结论，一次生成报告，不重新研究同一问题。历史只剩摘要、缺少原依据时，取回确实相关的原消息或来源；取不到的部分明确标为未复核，不能把历史回答当原始证据。

“研究这个问题并形成研报”才进入有边界的取证：确定问题、受众、资料范围、时间截点和输出深度。能够合理推定的条件直接说明并开始；只有会改变结论或研究范围的缺口才追问。以尚未解决的关键问题驱动下一次读取，不按卡片列表逐张走完。

研究可使用多个路线，但只在当前证据提出具体需要时切换。例如比较报告发现双方数据口径不同，才查口径；存在一个足以改变建议的反例，才补读它。每次继续应能说明准备填补哪项缺口，已读同版本内容仍在窗口时不重复取回。

报告按任务组织，通常包含结论、机制或比较、关键依据、替代解释、风险和成立条件；投资用途再增加观察指标与决策情景。方法和数据不足时明确影响了哪个判断，不堆“仍需进一步研究”的空话。

当前 UNO 普通对话没有实时外部检索能力。现阶段可交付“基于所选资料、截至所给时点”的研究，不能称为已经核对最新行情或政策。用户明确要求实时材料而工具未接通时，说明具体缺口；可以在已有资料范围完成机制分析。

用户明确要求生成/保存报告，授权形成对应的 OutBox 产物；无需再询问一次“是否允许生成文件”。用户只要聊天中的分析，则留在对话。保存采用受控的产物写入，返回真实文件路径与版本，不自动把报告观点拆成卡、更新 Profile 或覆盖旧报告。

**成功标准：** 回答了用户的研究问题，证据可追溯，重要反例未被省略；报告保存和结论可靠性分别验收。

### D. 判断复盘：改善认识，而不改写过去

冻结“原判断当时的文字、条件、依据和时点”，再与后续提供的观察比较。区分：信息后来才出现、原材料被误读、已有证据漏检、假设不成立，以及结果本身具有偶然性。

结果正确不能证明推理正确，结果不佳也不能单独证明当时决策不合理。对当时无法获得的信息，不倒推为“本来就应该知道”。无法确认当时信息集时，收缩结论，不伪造完整复盘。

交付一份简洁对照：原判断哪里保留、哪里应撤回或增加条件、依据是什么。只有形成可迁移的教训才提出方法候选。保存复盘、修卡或试用新方法，都复用对应成果能力，不自动全库重建。

**成功标准：** 能定位具体认识错误或知识利用问题，并区分偶然结果；不会通过重写原判断制造“始终正确”的历史。

### E. 方法与知识利用改进：让“变好”有证据

这项能力分开处理三种内容，避免把所有反馈塞进长期记忆：

| 内容 | 合理处理 | 不应做的推断 |
|---|---|---|
| 明确表达的个人偏好 | 当前对话立即遵守；明确要求“以后都这样”时直接按所述范围保存，并给出撤销入口 | 用户喜欢短回答，不代表所有问题都应该省略条件 |
| 可复用分析方法 | 提炼输入条件、关键检查、反例和使用边界，按普通知识候选保存 | 一次好答案不代表通用方法已经有效 |
| 检索或回答失败 | 保存可复现问题、实际检索/引用、正确依据和预期改变，先定位原因 | 一次没搜到，不等于知识库没有；程序读卡失败也不是“模型不会思考” |

可以从“论证方法”和“知识使用方式”两方面试验：前者例如在比较政策影响时先区分政策动作与预期变化；后者例如某类问题需要保留原卡的反例段、将一个已知别名用于检索，或者纠正旧卡摘要使其更容易被找到。

语气、篇幅等明确表达偏好不需要跑方法评测，也不需要在原请求之外再批准一次。若范围不明确，只补清是否长期适用或适用于哪类输出；不能把“简短些”理解为允许省略决定性风险。改变检索和判断方法的提案才进入后述对照试验。

优先修正具体原因：坏摘要修摘要，缺失术语补合法别名，读取错误修代码，材料确实不足则记录具体缺口。只有多个案例支持可迁移的变化时，才考虑调检索排序、路线提示或上下文选取。不要用越来越长的系统提示遮盖工具错误。

方法知识和执行策略分开保存。方法卡是可阅读的知识，不会因为被检索到就成为高优先级指令。要影响后续行为，需从方法中提出一个有作用域、有版本、可关闭的试用规则，经过宿主认可的设置字段启用。候选文字不能改变权限、追加工具、放宽预算或覆盖系统规则。

试验过程为：具体失败案例 → 原因假设 → 一个有限改动 → 固定样本对照 → 人工审核 → 指定范围试用 → 保留旧版与关闭入口。初期不建设无人值守的自我修改任务。

建议首次试验采用 8 个开发案例与 8 个未参与调节的保留案例，既有适用案例也有反例。冻结模型、材料版本、问题、可用工具和预算，对原规则与候选规则分别作答；32 份答案至少需要 32 次生成，若包含意图调用等会更多。运行前明确总预算，不能把这项评测偷偷塞进用户的一次反馈处理。

检查决定性证据命中、来源忠实、反例和条件保留、答案可用性，以及输入/输出用量和耗时。随机隐藏版本后由用户或独立审阅者比较；同一模型的自评分仅作辅助，不作为独立证据。新增严重事实错误或越权行为即拒绝候选；小样本通过只允许有限试用，不宣称普遍提升。

**成功标准：** 在未用于修改的案例上也有收益，且没有新增关键错误、额外空转或不可接受的成本。这里的改进是经过评测的记忆与行为配置改进，不是修改模型权重，也不等于获得了自主进化能力。

## 5. 对话与写入共用一套明确的责任

### 5.1 按本轮意图开放能力

普通回答继续轻量处理。有明确成果请求时，宿主在现有意图识别中增加成果类别，加载所需的短技能和有限工具；不把五份技能、全部旧工具和所有方法记忆放进每个请求。

原只读回答阶段的“没有工具、不能写卡”是正确能力描述。需要改变的是把它限定在只读阶段，并让成果请求有真实执行入口；不能全局删除限制后期待模型凭文字完成写入。

路由模型提出动作建议，宿主根据当前用户请求、选中对象和已有授权检查执行范围。材料、引用、旧回答以及方法卡中的命令都不产生授权。工具的存在也不代表可以发布草稿。

### 5.2 一个归属于对话的操作记录

建议扩展 `uno/state.js` 背后的 UNO 持久工作记录，将共同的归属、版本、预算和收据字段供新的对话成果种类使用。当前创建入口仅接受 compile/construct，不能直接接入；需要增加与编译分开的短成果执行分支，且不创建固定的编译角色会话。新操作不再写旧 pending 提案存储或 CognitiveRun；原生会话管消息和执行，工作记录管状态与授权，草稿管内容版本，Gateway 收据管提交事实，UI 只作投影。此扩展和 quick 互斥解除都属于待实施工作。

有副作用或需要恢复的成果操作至少绑定：

| 记录 | 用途 |
|---|---|
| 操作 ID、所属对话、请求消息 ID | 返回结果始终回到原对话，区分新请求与原操作恢复 |
| 读取库范围、唯一写入库、对象 ID 与原版本 | 切换页面或知识库不会改写既有操作的归属 |
| 请求的成果、允许的动作、累计预算 | 防止普通讨论、继续操作扩大权限或重置成本 |
| 已读来源版本、关键片段引用、当前草稿版本 | 保留支持、反证、未决问题；不靠模型重新回忆恢复 |
| 状态、提交幂等键、真实收据 | 处理刷新、超时、重复点击和服务重启 |

最小状态为准备中、待确认、提交中、已完成、已取消、需处理。用户继续聊别的问题时，待确认草稿仍归原操作；不能让它阻塞整个普通对话。研究等较长执行使用上述待扩展的工作生命周期，只由一处宿主调度，不再同时启动原生 Goal 和 Web 自动续跑。

草稿附着在生成它的消息处，准备结束显示“草稿已就绪，尚未保存”。用户换话题后折叠为可展开结果，不继续显示执行中，也不悬挂在输入框旁。确认、取消、冲突和重启恢复都更新同一条目，不制造新的重复状态卡。

相同请求的重复提交先查幂等键和收据。网络超时且提交状态不明时，显示“正在确认保存结果”，不能直接让模型重写。明确新草稿才产生新版本；旧草稿内容变化、来源变化或原卡变化都会使旧确认失效。

### 5.3 一次具体确认

“记下来”“修改这张卡”足以开始取证和准备草稿，不再问一次是否允许准备。新生成的知识正文需要完整展示后确认；内容已经完整展示且用户明确“就按这一版保存”，宿主应将授权绑定到这个明确版本，不再弹第二轮相同确认。

点击确认与自然语言确认进入同一验证入口；后者只有能无歧义定位待确认对象时才接受。改了草稿就展示新差异，不能把一句“好的”随意匹配到历史提案。多草稿可选择部分；存在跨卡依赖时说明哪些必须一起保存。

预览前先完成正文规范化、边界段补全和语义字段的默认处理，再对最终正文及语义元数据计算确认哈希。当前发布阶段会自动补入 boundary 段，需将这种改变前移。提交只允许补充明确列出的审计时间、收据等非语义字段，不再改变用户已确认的知识内容。

提交前取消撤销该提案的提交资格，保留对话中的草稿供参考。取消与发布按同一操作版本串行判定；已经进入提交时先核对事务结果，未知时保持“正在确认保存结果”。已经成功就显示保存成功，说明取消没有撤回成果，不能改标为已取消。迟到模型结果不能重新激活已取消操作。除非用户重新要求，不自动再次提出。提交成功返回实际卡片/报告链接；用户读回看到的版本应与收据一致。

## 6. 知识来源、上下文和方法记忆怎样组织

### 6.1 来源契约先于新能力上线

为 UNO-v3 增加明确的对话来源和归属表达，保留原文编译路径现有行为。建议新增信息包括贡献者类别、生成途径、证据状态、源消息/卡片及版本；字段名在 Schema 实施时统一，本文不把它们冒充成当前 API。

来源可能混合：用户提出假设、某卡提供数据、UNO作条件性综合。应在相关段落表达各自角色，不能用单一 origin 掩盖差异。修订旧卡默认保留原归属，新增部分另记贡献；已有来源继续保留，明确被撤回的主张。

生命周期表示对象是否仍使用，证据状态表示主张凭什么成立；两者不能混成一个 active 或质量分。可以检索到的假说仍是假说，人工点击保存也不会使它自动成为已证实事实。

| 持久内容 | 建议落点 | 边界 |
|---|---|---|
| 正式知识卡 | 01-Cards/ | 所有实质变更经 HarnessGateway |
| 报告、复盘文稿 | 04-OutBox/ | 受控产物写入，保存版本和证据引用；不等于知识卡 |
| 知识所需的对话来源 | 07-Conversations/ 中有稳定引用的 Markdown 摘录 | 仅保存获授权成果依赖的片段、必要上下文与归属；不是隐藏思考或整个聊天副本 |
| 已批准的领域方法、知识利用偏好 | 02-Profile/ 的明确作用域条目 | 要有用户授权；与方法卡相互引用，不复制成两份不同真相 |
| 待确认操作、预算、幂等键、评测执行状态 | .nexogenesis/ 的运行记录 | 运行状态不替代语义事实源；丢失时不得伪造授权或假装已完成 |

以上新增路径用途和 Gateway 写入种类均须实现；当前 validateSource 尚不接受对话摘录，也尚未形成报告/Profile 的新写入接口。

当前 stageKnowledge 在草稿阶段即要求来源文件存在，不能只放宽 validateSource 的路径正则。建议由宿主创建不可变的来源暂存对象，绑定原消息、库身份、内容哈希及必要上下文；草稿阶段仅能经该操作的受控解析器读取和校验此对象，模型不能把任意路径充当暂存来源。

预览列明将保存的来源片段。确认后 Gateway 在同一可恢复事务中发布这份内容未变的摘录和知识卡；提交前的校验需支持该事务的待写文件集合，保证正式引用和锚点有效，不能跳过存在性检查。取消后不生成正式来源。知识和来源必须一起成功或回滚。

删除聊天不能默默删除已经被知识引用的获授权摘录：界面说明被引用范围，并提供单独管理入口。跨库资料引用携带真实库身份和版本；早期无法可靠支持跨库来源时，应明确限制写入，而非复制成一个假的本库来源。

### 6.2 只向本轮模型提供用得上的内容

上下文按“当前请求和目标 → 必要历史 → 选定证据与反证 → 活动草稿/差异 → 当前技能”组织。稳定系统规则和工具定义尽量保持一致；不注入整本书、全部历史、全库目录和全部 Skill。

不能把持久化的已读记录等同于当前窗口已经有证据。每个引用同时区分“读过”“本轮提供了哪些片段”和“尚未提供的部分”。后续确需取回时按稳定引用读一次，不能为了省 Token 在丢失反例后只靠摘要作结论。

压缩优先保留当前目标、决定性依据、关键反例、待复核写入、下一项未解决问题；按结构省略整段次要材料，记录省略范围和可恢复引用，不再任意裁剪 JSON 中部。大报告保留章节引用与事实清单，修改哪节就带哪节和必要上下文，不每轮重发全文。

长期方法也按适用性检索。初期每轮最多选一个已启用方法，明确触发原因；不把用户每次反馈追加到系统提示。没有适用规则就使用默认路线。

## 7. 成本控制：预算服务交付，不服务机械流程

以下是首轮试验的建议上限，不是当前参数或质量保证。真实模型样本不足时不宣称省 Token 百分比。

| 场景 | 建议模型请求上限 | 继续条件 |
|---|---|---|
| 普通对话 | 保持当前直接回答 1 次、取证回答 2 次的成功路径 | 不因增加成果能力给每轮增加额外调度调用 |
| 小范围沉淀/修订 | 合计最多 4 次，含意图、作者、条件性审核与修正 | 只有具体证据缺口、语义风险或校验拒绝才追加；不强制用满 |
| 整理已有讨论为研报 | 合计最多 2 次，含自然语言路由 | 复用已提供材料，不重新开展研究 |
| 新专题研究 | 合计最多 8 次，证据收集最多 3 个集中批次 | 下一批必须对应尚未解决且可能改变结论的问题 |
| 判断复盘/提出方法候选 | 合计最多 4 次 | 方法评测是另一次明确请求，不夹带运行 |

调用次数不是唯一费用控制。每个操作还需冻结供应商、输入/输出额度或金额上限、墙钟时间；统计所有重试与辅助调用，分别记录输入、缓存和输出，输出内的推理用量不重复累加。无法确定价格时展示用量，不能编造人民币成本。单次请求上限和操作累计上限分别执行，预算不因刷新、继续或换模型重置。

初始草稿无需无条件独立审核。机械校验始终执行；只有新增关键因果主张、重要反证处理、实质性结论反转等具体风险时，才在同一预算内加入一次针对性语义审核。编译的作者/审核整条 Job 和默认 120 次请求预算不适合一次“记一下”。

当前 publishKnowledge 要求对应版本的 reviews，必须同步调整契约，不能填一个空 issues 来伪造已审核。对话成果区分三种凭据：机械校验结果、用户对最终版本的确认、按需产生的模型语义审核。宿主按操作种类和变化字段确定审核要求，并接纳实际发现的语义风险；作者不能单方面豁免。没有模型审核就如实记录，旧编译/建构仍执行其原有独立审核要求。

相同卡片、同版本、同片段已有当前有效证据时去重；读取成功却没有获得新证据或改变草稿，也计为无进展。连续无进展应停止并指出仍缺什么，不能只靠“连续三次相同失败”发现循环。预算不足时交付已完成的范围和剩余缺口，不谎报全部研究完成。

## 8. 一段完整的使用体验

以下是交互设计示例，不是真实研究结果，也不使用虚构卡片链接。

1. 用户问：“为什么有些政策出台后，市场反而向相反方向变化？”UNO 按原因路线分析，引用本轮实际提供的材料，说明预期与观察尚有哪些缺口。
2. 用户说：“把我们刚才区分政策动作和预期变化的这个方法记下来。”UNO 准备方法候选，说明适用场景与可能误用处，核对是否已有同对象卡片。用户看到完整内容后确认保存。
3. 用户打开一张旧卡：“这段说得太绝对，加入刚才讨论的限制条件。”UNO 以该卡为目标展示局部差异，确认后返回原卡的新版本。
4. 用户说：“把讨论整理为一份给投资委员会看的两页研报。”UNO 复用现有证据形成报告，指出未核验实时数据，保存到 OutBox；不重读全库，不自动拆卡。
5. 一段时间后用户提供新观察：“复盘一下，上次哪里判断错了？”UNO 对照原判断时点，区分新信息与原有遗漏；必要时提出修订候选。
6. 用户说：“以后这类问题能否优先检查预期变化？”UNO 先明确适用范围，提出有限方法试用；只有用户要求并批准评测预算后才运行样本对照。通过后可启用，遇到不适用的因果问题仍走默认路线。

全过程留在原对话。卡片、报告和操作收据有各自链接；不出现用户必须管理的五个特殊会话，也不重新引入“任务与待办”作为弥补归属混乱的入口。

## 9. 实施顺序与每步的验收边界

| 切片 | 实际改动 | 必须证明 | 代价与撤回 |
|---|---|---|---|
| 0 可靠来源与归属 | 修复 quick 历史事件兼容；统一操作归属、来源角色、草稿版本和确认绑定 | 发送→重启→读回→恢复草稿→确认→查收据；多库切换和并发目标不串写 | 需适配持久化与 Schema；保留旧日志，做向后兼容读取；失败则关闭新写入入口 |
| 1 沉淀与修订 | 扩展本轮意图；短技能和受限工具；完整候选/差异；Gateway 提交 | A/B 真实固定案例完成，保留反例、无重复写入；普通问答调用数不变 | 复用事务能力，不引入编译控制器；可关闭成果路由而保留已保存知识 |
| 2 报告与复盘 | 可恢复报告产物；整理与研究分路；必要的历史判断快照 | 整理不复读；研究到预算正确停止；报告真实保存且不隐式写卡 | 增加产物写入和版本管理；关闭新生成入口不删除已有报告 |
| 3 方法试用 | 明确偏好、方法候选、失败案例；固定样本对照；限范围启用和撤回 | 保留案例有效，成本可接受；撤回后恢复原行为 | 先手工试验和一个版本切换，不建立自动进化平台 |

建议先完成一个真实垂直样本：“从对话保存一项假说 → 重启 → 原卡加一项反例 → 再问相关问题时正确引用”。这个样本同时检验权限、语义来源、持久化、版本、检索和回答，不以接口返回 200 或前端显示成功代替验收。

角色归属、版本冲突、取消、冷启动、错误来源和预算用确定性测试检查；卡片是否值得保存、反例是否真正保留、报告是否解决问题用真实模型的固定材料案例检查。两类证据分别记录，不能相互替代。

## 10. 采用这些设计的依据

按具体任务选择轻量流程或有界 Agent 循环，是已有的 Agent 工程方法。Anthropic 的实践总结强调从简单组合开始，并用实际收益决定是否引入更复杂循环；这里用于指导 UNO 的能力组合，不构成 UNO 已经改善的证据。[Building effective agents](https://www.anthropic.com/engineering/building-effective-agents)

利用任务反馈形成可重用经验、影响后续尝试，可以参考 Reflexion 的语言反馈记忆思路。该论文的实验不能直接证明 UNO 的经济学判断或检索会提升，所以本设计增加保留案例、人工审核、作用域和撤回验证。[Reflexion 论文](https://arxiv.org/abs/2303.11366)

目前不需要因此安装新的 Agent 框架、增加一个“自我进化 Agent”或替换现有原生引擎。先把同一对话中的成果请求、可信来源和可靠提交做成可验证的完整能力，再决定哪些更强的研究与改进机制值得运行。
