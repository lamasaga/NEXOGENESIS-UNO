# UNO 知识卡与组织规则

UNO 把来源整理为可独立阅读、可回查、可继续修订的知识对象。分类只有两个维度：每张卡一个主类型 `type`，以及零到三个既有领域 `domains`。完整定义和审核示例见[知识卡分类契约](card-types.md)。

## 卡片

- `type` 说明卡片主要以什么结构承载知识，并决定正文骨架；只能取一个值。
- `domains` 说明卡片属于哪些长期知识问题空间；通常 1–2 个，最多 3 个。
- `tags/topics` 是旧数据字段。新编译、建构、筛选和界面不再写入或依赖它们。
- 标题、摘要和正文应围绕同一知识对象，保留作者归属、成立条件、反证和来源边界。
- 来源定位与关系说明不能替代正文；卡片须脱离原书目录仍可理解。

## 领域

领域定义保存在 `01-Cards/_meta/domains/*.md`。领域必须能够容纳多份来源与多张卡，并能说明核心问题和边界。一本书、一个章节、作者姓名和临时关键词都不是领域。

领域阅读展示核心问题、纳入与排除范围、代表卡和成员数量；领域之间可保存邻接、对照、桥接关系，注明使用条件和限制。完整示例与写入约束见[领域说明与领域关系](domains.md)。自动发现和创建关系留给后续建构。

卡片自身的 `domains` 是成员归属的唯一权威。领域文件中的 `representative_card_ids` 仅是代表性入口。检索选择父领域时可包含子领域成员，但磁盘上只保存最具体归属，不重复写父子领域。

## 关系

关系说明为什么值得继续阅读另一张卡。新编译使用 `specialization`、`supplement`、`contrast`、`challenge`、`analogy`、`example`、`application`，并在 `note` 中说明方向和具体理由。仅同属一个领域、出现相同词语或标题相近，不构成关系。详见[关系说明](relations.md)。

## 写入与使用

所有实质写入经过 HarnessGateway。程序检查字段、版本、来源、关系端点和事务边界；模型负责判断类型、领域是否适用、内容是否忠实以及关系是否成立。程序通过不等于语义质量已经证明。

编译制卡请求只能从既有领域中选择；没有合适领域时保存 `domains: []`，进入可重建未组织池。编译在 10 个有效单元、20 张新未组织卡或有足够材料的书末边界进入领域治理检查点：已有领域可批量挂靠，新领域形成边界完整的提案。任务默认逐项确认；用户开始编译时也可授权本次任务自动批准通过校验的提案。批准后都通过同一 Gateway 事务创建领域并挂靠首批成员。当前建构可以调整已有卡的领域归属，但不能拆分、合并、改父级或退役领域；这些高级能力尚未实现。

旧卡继续可读，不自动批量改写。任何存量迁移先生成预览并单独授权。
