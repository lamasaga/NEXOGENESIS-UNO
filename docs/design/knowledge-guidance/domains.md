# 领域说明与领域关系

领域是跨材料、长期成立的知识问题空间，保存在 `01-Cards/_meta/domains/*.md`。它不是普通知识卡类型，也不由一条概念定义或一本书的摘要代替。成员归属仍只读取知识卡的 `domains`，不保存第二份成员清单。

## 领域说明

| 字段 | 内容要求 |
| --- | --- |
| `summary` | 简述主要研究对象、问题与适用范围，不只重复领域名。 |
| `core_questions` | 可跨材料追问的长期问题，不能用主题词或章节标题凑数。 |
| `includes` | 纳入哪些对象、机制或问题，说明挂靠依据。 |
| `excludes` | 容易混入但不属于该问题空间的内容，明确排除理由或范围。 |
| `parents` | 可选上级领域 ID；属于层级导航，不是论证关系。 |
| `representative_card_ids` | 可选已发布卡 ID，作为少量阅读入口，不代表全部成员。 |
| Markdown 正文 | 可选的深入说明；已有人工正文原样保留，不要求模型复述上述字段。 |

新建领域和修订说明共用字段校验。程序能校验非空、引用和版本，不能证明问题空间划分合理。阅读界面展示摘要、核心问题、纳入范围、排除范围、上级领域、代表卡和直接成员数量；历史缺项如实显示待补充，不调用模型填充。几百张成员卡也不会整批进入阅读响应。

说明示例：

```json
{
  "id": "organizational-governance",
  "title": "组织治理与授权",
  "summary": "研究正式组织如何配置决策权、信息与责任，以及这些安排对执行的影响。",
  "core_questions": ["哪些信息条件适合集中或分散决策？", "授权后如何设置责任与反馈？"],
  "includes": ["组织层级中的授权、激励、监督与信息反馈机制"],
  "excludes": ["仅列出机构名称而不分析组织机制的材料", "不涉及正式组织安排的个人决策技巧"],
  "parents": [],
  "representative_card_ids": []
}
```

空代表卡列表是合法状态，不能为满足格式而编造 ID。

## 领域之间的关系

| `type` | 阅读用途 | 边界 |
| --- | --- | --- |
| `adjacent` 邻接 | 两个领域在明确的问题上相交，需要转向邻近问题空间。 | 同属经济学或共享关键词，不足以连边。 |
| `contrast` 对照 | 两个领域对同一问题提供不同观察尺度、对象范围或解释视角。 | 不表示一个领域否定另一个，也不代表内部观点一致。 |
| `bridge` 桥接 | 从本领域的具体问题进入另一领域的工具、机制或制度分析。 | 不直接宣称理论迁移、因果或效果等同已经成立。 |

每条新建或修改的关系必须有 `target/type/note/use_when/limits/basis`：

- `target`：当前库内有效领域 ID，不含 `domain:` 前缀。不能指向自身、未知或退役领域。
- `note`：两端的具体交界、比较维度或跨域路径。
- `use_when`：什么问题下值得沿此关系继续阅读。
- `limits`：什么不能由此推导、哪些条件不适用。
- `basis`：固定为 `navigation`。领域关系不充当来源证据。
- `anchor_card_ids`：可选 0–6 张不重复的已发布知识卡，必须属于至少一端领域。用于定位例子，不是自动证明。尚无合适卡时允许为空。

示例中的目标必须已经存在：

```json
{
  "target": "administrative-accountability",
  "type": "bridge",
  "note": "从组织授权中的决策权配置，转向行政责任领域的问责与申诉安排。",
  "use_when": "分析授权之后由谁承担决策责任、如何纠正错误时。",
  "limits": "组织效率与程序正当性是不同评价维度，不能直接互推结论。",
  "basis": "navigation",
  "anchor_card_ids": []
}
```

关系保存方向始终是源领域到目标领域。读取目标时显示“来自”的回看入口，不生成反向断言。A→B→C 可以逐级阅读，不据此产生 A→C 的传递关系。`parents` 独立保存，图上类型为 `domain-parent`，不混入这三类关系。不会自动生成领域到每张成员卡的边。

## 写入与能力边界

`HarnessGateway.writeDomain({ key, id, revision, ...fields })` 提供领域内容与关系写入基础。已有领域须使用最新 `revision`；未提供的字段保留，显式数组替换该字段，`relations: []` 表示清空本领域的出向关系。新领域需完整说明，且 `revision: null`。调用必须处于用户授权范围。

保存经过同一事务锁、版本校验、历史备份和幂等收据。只改关系不覆盖正文和边界，也不改任何成员卡。历史短关系允许读取与原样保留；修改该关系时需要补齐使用条件和边界。

当前编译检查点只生成领域说明与成员挂靠，不生成领域关系。建构的自动发现、提案、批准和批量连边尚未接入。本契约提供未来建构可用的写入与阅读基础；检索路由、自动跨域扩展和排序不因此改变。
