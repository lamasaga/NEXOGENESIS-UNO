## 2026-09-17：审查后先落卡，问题卡独立修复

本节记录当时的 `review-publish-repair-v1`，已由 2026-09-18 的 v2 分类修复替代；标记本身不作为行为验证。

1. 建卡：一次提供完整单元、有限参考卡、与 Gateway 相同的主类型正文规范及经过该规范验证的完整示例。模型只输出 JSON，不附修复说明。
2. 审查：程序一次收集逐卡规格问题，模型检查内容和关系。具体问题须写明改法及必要的短证据，避免修复阶段再读原文。可选扩展不作为阻塞理由。
3. 落卡：通过的卡立即经 Gateway 保存。指向尚未通过新卡的关系暂存在任务中，目标通过后补上；不保存幽灵链接。每笔提交保存幂等收据。
4. 修复：只提交问题卡及具体 issues，source_chars=0，无其他卡、整章原文、旧卡参考或历史。仅核对该卡与原问题，每卡最多两次模型修复；原响应重读不算新请求。
5. 恢复：已收到的响应先接收，已提交的收据先恢复，之后才判断是否需要模型请求。每次模型请求仍受累计预算限制。失败不撤销通过卡，不冒称全章完成，原书保留。

　　检查与复核响应采用 `compile-response-recovery-v1`：必需空字段等零歧义缺陷由程序修复；只有 JSON 或外层结构存在歧义时，才用一次不含原文和卡片上下文的局部恢复请求。恢复结果重新通过原检查器；同一响应按指纹熔断。预算、版本、语义和用户停止类失败不走该恢复模型。完整分类见 [编译失败恢复](UNO-编译失败恢复.md)。

验证包含保存发生在修复之前、失败保留成果、延期关系补写、旧响应接回、写后中断收据恢复，以及实际请求中没有原文或其他卡。程序回归与历史响应回放不是新模型质量验收；不得据此宣称新书真实编译已经成功。

# UNO 图书编译重建

核对日期：2026-09-18。现行入口为 `compile_profile=unit-cards-v3`，任务为 `workflow=uno-unit-compile-v3`，审核策略为 `review-publish-repair-v2`。判断方法、分类说明、正文骨架及正反例由宿主同批交给模型；宿主一次提交完整 Markdown 单元并直接调用模型服务，不再运行 `book_*` 原生工具循环。契约细则见 [单元编译实施](UNO-单元编译实施.md)，验收与运行状态见 [编译重构与验收](UNO-编译重构与验收.md)、[当前实现与验证](UNO-当前实现与验证.md)。

　　`book-reading-v1` / `uno-book-compile-v1` 及更早任务只读，不改签、不迁移、不自动重放。正式 3093 上次核验加载的是该 v1 路径，不能当作本版已上线证据。源码健康与准备接口的现行标识见 [当前实现与验证](UNO-当前实现与验证.md)。

## 要解决的问题

　　用户交付一本书或一篇长文，希望得到能独立解释问题、保留关键内容、相互连接且能回查来源的卡片。阅读一章不等于必须产生一张卡；同一对象可以跨单元出现，同一单元也可能包含多个不同对象。程序保全来源、按单元提交证据并执行可靠写入，把粒度、整合、关系及具体疑点留给模型判断，再用无工具检查约束忠实度。

　　这次从成品要求出发建立新路径，保留原生会话作为任务归属，不把模型补读、阅读组和独立二审当作前置条件。已有知识、历史任务和旧来源不自动迁移。

## 从原书到卡片

1. 用户选定 Inbox 原件、材料类型（自动／图书／文章）和本次要求。任务冻结原件版本与完整范围；Python 确定性提取目录、章节、正文定位和可用图片，提取失败或不完整如实保留。
2. 未完成时原件留在 Inbox，并按内容哈希保全到归档。提取结果另有版本。每个原文单元最多 60,000 Unicode 字符，同时受 240,000 UTF-8 字节上限约束；规范、要求、完整参考卡和检查材料等其余上下文合计最多 60,000 字符。两者独立计数，不以旧 128 KB 总字节阈值拦截合规中文正文。先找段落、句子边界，仍无法满足上限时硬切；用 `part/parts` 和 `continuation` 表明同章延续，不将分块当作独立知识对象。
3. 图书按真实章节切分，短文章保留整篇，长文章按内部章节与段落；用户可明确覆盖自动判断。宿主一次提交该单元完整 Markdown，附判断方法、正反例和本库确定性匹配的有限参考卡（最多 3 张完整卡与 5 张导航摘要，总计 22,000 字符）。已经引用当前原文单元的旧卡优先排序；冻结参考遗漏同源旧卡而模型再次返回同一 ID 时，宿主复用旧卡而不覆盖，并继续处理同批新卡。只有完整卡可以被修订或用于建立新关系；导航摘要仅用于避重与定位。没有模型补读工具、没有阅读组、没有历史正文叠加、没有子代理笔记。
4. 模型一次返回本单元全部卡片 JSON。程序经同一 Gateway 预检规格、唯一主类型、既有领域归属、来源、关系端点与版本；常规审核只提交候选卡和必要关系目标，不重复发送完整原文。明确的整体遗漏另以有限证据定点补全。检查材料超限时按卡片分组，不截卡、不累积历史。
5. 审核把问题分为卡片问题和关系问题。卡片修复只收到本卡和具体问题，不能新增目标；关系修复只收到本卡与问题明确引用的完整端点，只能修改 `relations`，端点版本变化后重新判断旧问题。每张卡每类最多两次，仍失败保留候选和具体问题。改旧卡或连接旧卡只能引用本次完整交付的版本。单元卡片及同批关系经 Gateway 原子提交。
6. 只有整本已处理、无延期、无提取缺失，并且归档原件哈希核验通过，Gateway 才将原书移出 Inbox。归档有真实收据和崩溃恢复，不因界面显示结束就直接移走未完成材料。

　　作者的判断方法来自 [book-compile-method.md](design/book-compile-method.md)，示例来自 [book-compile-examples.md](design/book-compile-examples.md)。程序不按关键词判断一张卡是否有思想，也不将生成的检查话术算成质量证据。参考卡匹配不是全库语义去重。

## 宿主请求，而不是五个工具

| 步骤 | 职责 |
|---|---|
| 生成 | 宿主提交完整原文与有限上下文，模型返回本单元全部卡片 JSON；无工具 Schema |
| 预检 | `HarnessGateway.checkBookCards` 核对规格、主类型、领域归属、来源、关系端点与版本 |
| 检查 | 另一次无工具请求，只报告具体问题，不重写未点名的卡 |
| 局部修复 | 仅问题卡，最多两次；复查仍走无工具请求 |
| 保存 | `HarnessGateway.saveBookCards` 原子提交本单元卡片及同批关系，留下真实收据 |
| 进度 | 程序结算已处理／延期单元并推进下一单元；`bookProgress` 只读任务状态 |

　　每次保存最多 100 张是事务范围，不是每章产卡额度。正常单元一次生成、一次检查；存在具体问题时增加局部修复及该卡复查。检查不是全库遍历，也不是多代理独立二审队列。

## 数据与写入边界

```text
00-Inbox/尚未完成处理的原书
03-Archive/books/<原件SHA256>/original.<扩展名>
05-Buffer/books/<原件SHA256>/<提取SHA256>/catalog.md
05-Buffer/books/<原件SHA256>/<提取SHA256>/units/c0001-p001.md
05-Buffer/books/<原件SHA256>/<提取SHA256>/assets/...
01-Cards/<稳定ID>.md
03-Archive/card-history/<稳定ID>/<旧版本SHA256>.md
```

　　相同原件的不同提取结果拥有不同目录。图片、原始实体页定位、章节信息和警告随提取版本保留；图片入口不表示模型已经核验图像，扫描件与复杂版式不保证完整转换。Python 只清除有结构证据的噪声，不能因为论证重复就删除正文。

　　卡片保留稳定 ID、标题、摘要、一个主类型、零到三个既有领域、自然正文、来源和关系，附本次任务及收据标识。模型来源只填本次原文 `ref`；程序在完整交付该单元后生成 `原文单元.md#char-起点-终点` 和 `source_spans`，保存确切范围、版本和定位。精确定位不表示整单元每一句都在支持该卡，语义对应仍需抽查。

　　来源界面可以点击打开真实归档文本，显示原书页码／章节定位，并提供归档原书链接。保全后的来源可查看不代表模型已经理解，也不代表图片已经经过视觉核验。

　　`basis=source` 表示来源支持的关系，`basis=navigation` 表示组织导航。程序校验端点和归属，无法独立证明关系在语义上成立。

## 恢复与完成

　　成功事务先保存卡片、历史、Journal 和真实收据。任务状态随后保存；两者之间即使进程退出，也可由 `reconcileBookReceipts` 核对当前／历史卡版本和收据，重建成果及来源汇总。恢复不能清空局部修复计数、重做已成功生成的整个单元或冒充完成。

　　延期、提取失败和内容检查未解决事项不计完成。主动结束保留成果和剩余范围，并禁止后续写入；结束决定不能被迟到返回撤销。整本完成后，Gateway 核对归档原件哈希并执行移出 Inbox 的事务。
