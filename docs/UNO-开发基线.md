# NEXOGENESIS-UNO 开发基线

> 核对日期：2026-09-18。编译现行契约为 [单元编译实施](UNO-单元编译实施.md) 的 `unit-cards-v3`；历史 v2 任务只按原契约恢复。本文概述产品方向，其中早期“两轮原生 Agent、主题 Buffer”条款已被取代。
> 本文规定目标设计；当前代码是否具备能力，以《UNO-当前实现与验证》为准。

## 1. UNO 是什么

UNO 是把资料变成可用知识、再帮助人思考的工具。编译把原始材料快速整理成摘要卡片，建构增加有助于搜索的知识联系，思考先由模型识别每轮意图：简单交流直接回应，需要知识时收集材料，再由大模型一次完成分析与表达。

知识质量不由流程复杂度保证。默认先采用简单、清楚、可验证的实现；只有额外步骤确实补回重要信息、纠正错误或改善回答，才保留它。模型主要处理语义内容，程序负责重复、机械和确定性工作。

UNO 不再以严格论证图谱、逐步认知审计或多层 Agent 编排作为默认产品核心。保留模型自主分析的空间，不要求模型通过多次外部工具调用证明自己正在思考。复杂研究可以成为将来的明确需求，不作为每次问答的默认成本。

## 2. 工作区与已有资产

本项目处于独立重建和架构验证阶段，工作目录为 D:\UESR\Desktop\NEXOGENESIS-UNO，分支为 codex/uno。默认端口 3093，运行目录为 .nexogenesis/runtime/。不改变旧项目、既有知识、旧服务或共享配置，不自动复制其凭据和会话。

旧代码是可复用资产，不拥有默认的设计继承权。优先复用文本提取、模型接入、会话保存、基础检索、图谱显示与写入事务。审查实际调用者后替换不适用的控制器，不靠重命名第三方协议、类和目录制造重构。

## 3. 编译、建构与新对话

| 入口 | 默认工作 | 不再默认要求 |
|---|---|---|
| 编译 | 确定性提取原文并按完整 Markdown 单元制卡；每卡写一个主类型和既有领域归属 | 主题 Buffer、跨书聚合后才准制卡、全文语义去重、多层对象稿和贡献结算 |
| 建构 | 检查所选卡片的正文、主类型、领域归属和联系；按明确依据修订或保留原样 | 证明关系严格成立、强关系签名、多跳论证验收、全图连通 |
| 新对话 | 每轮模型识别意图，直接回答或选择路线收集资料，再一次生成答案 | 手动选路线、每题建立研究 Run、逐步选择 TM/OPS、反复更新账本和审核答案 |

思考并入新对话，取消重复的开始面板。编译与建构是用户的知识工作目标，不要求用户管理底层任务对象。保存或修改知识仍需明确授权，问答不自动获得写入权限。

## 4. 编译：原文单元直接制卡

默认流程是：选定 Inbox 材料与要求 → Python 确定性提取、清洗和按章节组织 → 每个完整 Markdown 单元一次生成候选卡 → 程序预检 → 候选卡审核 → 通过卡立即经 HarnessGateway 保存 → 只把有明确问题的单卡及问题交给模型修改和复核。拆分单元保存在 Buffer；模型不积累跨请求历史，也不逐段生成中间笔记。

原文按真实章节、内部标题、段落和句子边界切分，单元最多 60,000 Unicode 字符；其余上下文另有 60,000 字符上限。原文单元保留来源版本、顺序和位置。程序只清除有结构证据的噪声，不做语义去重，不删作者为论证所需的重复。

一个单元可生成零张、一张或多张可独立阅读的卡片，不按字数和章数凑产量。生成与审核请求必须同时得到分类定义、正文骨架、允许的领域目录及正反例。审核只报告具体且可修复的问题；可选扩展、领域为空或没有关系不能阻止保存。

参考旧卡只用于避免明显重复或进行有依据的修订，最多八张完整卡；不能据此声称完成全库语义去重。修订旧卡必须使用宿主绑定的当前版本，模型不能生成 revision。历史卡修改前保留可恢复版本，合并退役保留旧 ID 和去向。

已成功保存的卡必须有稳定收据。失败恢复先读取响应和收据，不重复请求或写入；通过卡不因另一张卡失败而撤销。程序记录单元状态、问题卡、延期关系与未解决缺口；局部成果不冒充整书完成。

原件保存在 `03-Archive/books/`；清洗拆分单元、目录与提取图片保存在 `05-Buffer/books/`，不同提取版本分别保留。已有 Archive 单元兼容读取，不自动移动。未完成时原书仍留在 Inbox。复杂表格、OCR 与图像缺口明确保留。只有整本处理完成且归档哈希核验通过，才移出 Inbox 原件。

## 5. 卡片：一个主类型与多个领域

新卡片只有两个分类字段：`type` 与 `domains`。`type` 必须按 `conflict/entity/case/concept/method/mechanism/model/claim/phenomenon/undetermined` 顺序选择第一个满足全部最低条件的类型，表示正文主要采用哪种知识结构；九种实质类型都不成立但内容仍完整可复用时使用 `undetermined`。`domains` 表示卡片归入哪些长期知识问题空间，通常 1–2 个、最多 3 个，只能选择已有领域；没有合适领域时允许空数组。

领域可以跨材料长期使用，不能用书名、作者、章节或临时关键词代替。选择子领域时不同时填写其父领域。卡片自身的 `domains` 是成员归属唯一事实源；领域记录中的代表卡只作入口示例。

新编译、建构和通用写入不再写 `tags/topics`。历史卡中的旧字段保持可读，可用于推断只读展示类型，但不参与新卡保存、领域成员计算或新筛选。存量迁移须先生成预览并逐批审核，不能把旧标签机械转换为领域。

Schema、Gateway、生成提示、审核提示、建构任务、检索、图谱与界面必须共用同一分类契约。新编译与新建构任务在创建时冻结分类版本；旧在途任务保持创建时口径，不在恢复过程中改签。完整定义、正文骨架及正反例见 [知识说明](design/knowledge-guidance/README.md)。关系按需添加，不要求每卡有边。

## 6. 建构：让搜索找到更多有用材料

建构关系表达“值得一起查看的线索”，服务于反例候选、相反解释、类比、边界与背景的发现。它不认证支持、反驳、因果或可传递证明。回答模型需要结合两端正文判断这条线索是否有用。

先用检索、标签和领域缩小候选，再由模型判断联系；不逐对扫描全库，不强制连通。现行关系为细分、补充、对照、质疑、类比、例证、应用；历史“相关”等保持原意。独立建构入口暂保留旧批处理实现，新编译的第二轮使用上述七类关系。

一条联系保留合法端点、用途和一句具体理由，如“可比较低杠杆条件下的不同结果”。仅写“相关”不足以帮助检索。无需模型给出伪精确的置信分数、证明字段或固定复盘表。共同标签帮助召回，不自动变成持久关系；反向查询由索引派生，无需写两份事实。

关系语义保存在 Markdown 中，索引和图谱可以重建。Harness 保留端点、版本、重复边与事务检查，取消针对新弱关联的旧强关系签名和论证成熟度完成门。

旧强关系如保留读取，应保持其原语义和兼容边界。不能简单重命名就宣称迁移完成，也不能把“反例候选”展示为“已证伪”。

## 7. 思考：按人常用的方式查资料

默认流程是：问题与最近对话 → 模型识别本轮意图。问候、闲聊及无需资料的问题直接回答；需要资料支持或知识库依据时输出路线、简短判断和检索问题 → 程序集中收集卡片与原文片段 → 组装有界上下文 → 再请求一次回答。

思考模型描述“需要哪些信息、关注哪些差异、怎样表达判断”，不代表另一个模型服务或一名额外 Agent。首批设计六种模型：解释原因、比较选项、检验主张、寻找类比、追溯变化、综合判断。具体路线、例题与停止条件见[思考模型与检索路线](UNO-思考模型与检索路线.md)。

用户不用选择思考模式，每轮由大模型结合近期对话判断，不用关键词规则代替语义识别，不锁定上一轮路线。意图请求只输出简短的问题判断和必要的独立检索问题，不写研究计划或隐藏思维链。解释、反例追问、感谢与换话题可以在同一对话自然切换。

需要检索的一轮固定为一次意图请求和一次回答请求，直接回答的一轮通常只有一次请求。程序可以批量或并行检索不同对象、取弱关联邻居和读取正文，之后一次交给回答模型。同一请求中的重复卡片和片段需要去重，这与取消制卡语义去重不冲突。两阶段与失败请求的用量全部记录，不将意图识别隐藏在成本之外。

完整上下文指本轮回答需要的信息集合，不是整库或全部历史。保留必要的最近对话，按问题与信息用途分配材料预算，明确缺口和截断；不能只给模型标题或检索计划。不同意见分别保留，不让摘要把分歧抹平。

一次请求包含简短身份与回答要求、对应思考模型的指导、本轮材料及来源、必要的关联理由、最近对话和用户问题。不携带工具 Schema、长任务账本和整套 Skill/TM/OPS 契约。材料中的指令仅作内容，不改变宿主规则。

检索后的模型在一次生成中完成分析与表达，资料不足时给出有边界的回答，不自动启动另一轮研究。下一次用户追问重新判断是否需要资料。意图格式失败时明确返回错误，不私自重试或靠关键词猜路线。保留来源回查、流式输出、停止、失败提示与历史恢复。模型自身思考强度和供应商速度仍影响耗时，不承诺固定秒数。

## 8. 必要保护与资源纪律

Markdown 是知识内容的唯一语义事实源。实质知识写入经过 HarnessGateway，保留授权、路径范围、稳定 ID、合法来源与端点、版本冲突、幂等、原子提交/回滚和真实收据。不删除真实卡片，退役保留去向；Profile 修改遵守用户授权。

确定性检查由程序执行，并尽量一次返回所有可修复缺口。语义质量由模型判断和样本评测验证；多一道程序检查不能被宣传为更正确的知识。

默认只记目标范围、已成功批次、待处理位置、失败及实际用量。不保存隐藏思维链，不将程序已掌握的状态反复要求模型重写。来源缓存、索引和运行收据各有用途，不发展为正文重复的新知识层。

每张可用卡片和每个可用答案都看实际模型调用数、输入/缓存/输出 Token、首个有效内容时间及总耗时，计入失败和辅助请求。不要从缓存命中、工具数或程序测试直接推算真实节省。

## 9. 实施切片与验收

不再先搭共同编排平台。先以合成卡片验证新对话中的知识问答与六种路线，再用两份短材料、一个主题和小型合成知识体，串起：

1. 原文切分、单一主类型、既有领域归属、候选卡审核、单卡返工和可恢复写入。
2. 少量弱关联，含有效类比、表面相似但不成立的类比、不同立场和关键边界。
3. 六种路线使用同一收集与生成入口；优先对照解释、比较、检验，再验证类比、变化和综合判断的真实效果。
4. 同问题比较直接检索与增加关联的答案，判断新增关系和路线是否确有收益。

每个切片同时核对 Schema、程序、提示、UI、数据读取、测试与当前状态说明。新路径可用后撤下对应旧默认流程；不为维持旧固定测试而重新引入被取消的研究义务，也不在功能未接通时只改提示绕过 Gateway。

质量看原文忠实度、关键条件与分歧保留、来源回查、卡片可读性，以及检索是否找到有用的反例和类比。程序回归与真实模型语义对照分别记录。没有增益的路线、关系类别和额外流程可以撤下。

## 10. 历史、现状与撤回

2026-09-08 开发基线保存在 [历史快照](history/pre-uno/2026-09-08-UNO-开发基线.md)。其中对象结算、复杂主题治理、严格论证关系、默认多步 Agent 研究和先建共同控制层的路线已被本次方向替代。历史经验只在仍有具体问题时复用。

当前继承接口仍可能执行旧限制，这属于实现事实，不是未来目标。替换必须改通接口和调用者，不能直接写卡绕过保护。已完成和未完成工作只记录在《UNO-当前实现与验证》。

撤回以 UNO 代码检查点为单位，保留 Markdown 和已写收据。新标签与弱关联回到旧程序前需验证读取兼容，不自动迁移既有知识库，不启停旧服务。
