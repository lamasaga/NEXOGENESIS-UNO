## 三、第一轮：新手在加息转降息与衰退风险下如何投资

### 用户输入

> 我希望你对一个新手交易者提一些建议，比如在一个美元加息转向减息的周期，看起来也像一个衰退周期的时候，该怎么进行投资。

### 真实轨迹

```text
retrieve("加息转降息周期 衰退 资产配置 债券 股票")
  → 10 张候选：6 张直接命中，4 张一跳自动扩展

retrieve("货币政策 利率 流动性 金融市场 传导")
  → 10 张候选：含直接命中与一跳自动扩展

→ 直接输出约 1961 字投资建议
```

  本轮没有调用 `read_card`、`graph_walk`、`inspect_argument`、`compare_cards`、`select_thinking_model` 或 `finish_cognitive_run`。`retrieve` 自带的一跳扩展只提供候选，没有产生结构化论证遍历。

### 回答中做得较好的部分

- 将预防式降息与衰退救火式降息分开，避免把“降息”等同于单一利好。
- 强调新手控制杠杆、仓位和生存能力，没有承诺收益。
- 承认缺少实时数据，未声称已经判断当前处于哪一种情景。
- 最终表达清楚，包含风险、边界和后续可核对指标。

### 失败点

| 检查项 | 观察 | 判定 |
|---|---|---|
| 候选升级为证据 | 0 张卡被精读 | 失败 |
| 图关系利用 | 只有 retrieve 内置候选扩展，没有主动走图 | 失败 |
| TM 约束 | 未选择 TM | 对复杂投资问题不充分 |
| 证据归因 | 多个历史年份、指标和资产判断来自模型常识，却与库内摘要混合表达 | 失败 |
| 任务隔离 | 复用上一问题遗留的 implicit run，Workspace 目标仍是“思考方法” | 失败 |
| 任务闭合 | run 保持 `running`，没有正常结束 | 失败 |

  本轮最终文字有一定分析价值，但按项目契约只能判定为“模型基于候选摘要生成的谨慎回答”，不能证明知识图谱或思维体参与改善了判断。

## 四、第二轮：什么情况下才能判断处于衰退

### 用户输入

> 我需要你深度为我研究一下，什么样的情况才能判断当前处于衰退还是不处于衰退。

### 真实轨迹

```text
加载 nexo-report
→ start_cognitive_run(mode="report")
→ 4 次 retrieve，共返回 39 张候选
→ 精读 4 张核心卡
→ inspect_evidence_set
   - 8 个锚点中只有 5 个当时已读
   - 5 个核心结论仍为单点或同源支撑
   - 当时实际证据角色只有 support
→ 根据检查结果补读 3 张卡
→ verify_evidence_anchors
   - 因 reads 预算耗尽被拒绝
→ finish_cognitive_run 连续调用 3 次
   - 底层 run 被标记 completed
   - 会话表面均收到 lossless JSON 输出错误
→ 输出约 4616 字四层衰退判据报告
```

### 实质改善

- 正确进入 `nexo-report`，建立了独立目标、范围和受众明确的 report run。
- 精读了 7 张 Card，不再只依赖检索摘要。
- 使用 `inspect_evidence_set` 检查来源、证据角色和单点支撑。
- 审查发现未读锚点后补读 3 张卡，证明真实 Observation 至少一次改变了下一步。
- 最终报告明确区分【库内】与【通行方法】，并保留单一来源、外推边界和实时数据缺口。
- “结构脆弱—领先预警—同步确认—叙事校验”能够直接回答判定口径，最终文本结构和可读性较好。

## 五、为什么本轮没有多跳不是“图里没有关系”

  对相关焦点卡执行只读复查后，当前图谱能够返回有意义的 ready 两跳结构。例如：

```text
债务驱动泡沫与央行管理边界
  ├─ supports → 价格稳定并非金融稳定充分条件
  │                ├─ 12国实际资产价格周期规律
  │                └─ 2008年金融危机的政策应对约束
  └─ extends → 狂热困境恐慌形态学
                   ├─ 1929年崩盘的杠杆反馈与救市限度
                   ├─ 1931国际最后贷款人缺位五要素
                   └─ 对冲投机庞氏融资谱系
```

```text
1929年崩盘的杠杆反馈与救市限度
  ├─ extends → 1929年崩盘前的共识误判
  ├─ example-of → 市场与融资流动性螺旋
  └─ example-of → 狂热困境恐慌形态学
```

  因而本轮没有出现多跳流动，不是图谱稀疏或前端漏画，而是模型采用了“搜索—精读—写报告”的文档研究路径，没有进入沿关系核对机制、共同依据和历史实例的图推理路径。

## 六、跨两轮的共同诊断

### 已经成立

- 检索、精读、证据集合审查和 report run 基础工具可以正常调用。
- 模型能够生成有结构、保留风险边界的经济分析文本。
- 第二轮已经出现“审查发现缺口后补读”的最小 Agent Loop。
- 认知事件能够把候选、精读和证据审查投影到前端。

### 尚未成立

- Skill 文本要求的 TM 和图观察不会被 mode 完成门自动强制。
- 没有 TM 时，`finish_cognitive_run` 的模型义务检查自然为空，report 可以绕过应有的证据角色和锚点核验。
- 读取预算没有为最终确定性核验预留空间。
- 工具预算拒绝没有进入 Episode，事后只看运行文件会遗漏失败动作。
- Workspace 尚未把 retrieve、read、evidence inspection 投影成候选、已读证据、反证和开放缺口。
- 前端“节点发生变化”没有清楚区分直接召回、自动一跳候选、精读与真实多层遍历。
- 流畅、篇幅长、结构化的回答仍可能掩盖 TM 和图推理没有运行。

## 七、回归时必须保持的边界

- 不要求所有普通对话建立 CognitiveRun。

- 不把“必须三跳”写成全局规则；一跳足够时应停止，只有中介机制或共同依据需要时才进入二跳。

## 八、RC-001 通过标准

### 第一问：复杂普通对话

1. 当前问题不能复用带有旧目标的隐式 run；若建立 run，目标必须属于当前用户问题。
2. 不能仅凭 `retrieve` 候选支撑历史案例、指标阈值或资产机制等关键结论。
3. 至少精读能够支撑主要机制和边界的焦点卡；具体数量由证据需要决定，不设全局配额。
4. 若输出软着陆与衰退的条件比较，应选择适合的 TM，或明确降级为一般框架并说明证据限制。
5. fixture 中存在 ready 关系且回答使用跨卡机制链时，至少产生一次相应 `graph_walk`、`inspect_argument`、`graph_path` 或 `compare_cards` 观察。
6. 回答区分库内证据、系统综合和缺少实时数据的部分。
7. 本轮状态正常结束，不遗留污染下一问题的 `running` run。

### 第二问：专题报告

1. 只建立一个独立 report run，并选择一个适用 TM。
2. TM 选择后完成其真实 Observation、不同目标、证据角色和输出义务。
3. 至少一个关键论证通过 `inspect_argument` 或适当平面的关系观察核对。
4. 证据集合包含真实 support 与 counter/boundary；如果没有独立反证，必须把它记录为未闭合缺口，不能伪装成已完成。
5. `verify_evidence_anchors` 必须成功，失败或被预算拒绝时 `finish_cognitive_run(completed)` 必须拒绝。
6. 完成操作只产生一次有效回执；重复调用返回同一完成结果，不重复改变 Episode 或状态。
7. Workspace 能看到本轮已读证据、反证/边界、开放缺口和停止理由。
8. 前端只有真实 walk layers 才展示层级扩散；召回、自动扩展、精读和证据审查使用不同语义。

## 十、由本案例推导的近期优化设计

### 优先级一：先保证不能错误完成

1. 为 `report` 增加 mode 级完成义务：必须选择 TM、成功完成证据集合检查和锚点核验。该义务不能依赖“恰好选择了 TM”才生效。
2. `finish_cognitive_run` 从 Episode 检查本轮成功的 `verify_evidence_anchors`，不接受仅由参数声称“已经核验”的锚点。
3. 将 `verify_evidence_anchors` 视为使用既有读取结果的闭合审计，不让普通 read 预算把它挡在最后；最小实现可以从 read 预算中豁免该确定性检查，不新增预算体系。
4. 所有预算拒绝和工具拒绝都写入 Episode，保证界面与事后审计看到同一事实。
5. 修复 finish 返回的无损 JSON 问题，并使已完成 run 的重复 finish 返回原完成回执而不是追加新完成步骤。

### 优先级二：让 TM 与图关系真实进入复杂分析

1. `nexo-report` 在形成主要提纲后、使用核心结论前选择一个 TM；未选择时 report 完成门拒绝。
2. 对 `nexo-talk` 只强化 `evidence_need=required` 且明显包含多情景、多机制或现实金融决策的问题；不要让所有普通对话都建立 run。
3. 不新增“固定多跳工作流”。由 TM 声明语义观察义务：比较情景时需要条件对照，跨卡机制链需要论证/路径观察，历史演化需要 context 平面；模型根据一跳结果决定是否进入二跳。
4. 在 RC-001 fixture 中明确存在 ready 两跳路径，用单案例断言验证 GraphOps 被实际采用；这不是全局调用配额。

### 优先级三：让 Workspace 成为可恢复的已验证状态

1. `retrieve` 只投影为候选，不增加已验证证据。
2. `read_card` 将真实卡片及修订号投影到 `observed_nodes` 和证据候选。
3. `inspect_evidence_set` 将单点支撑、缺失反证和未读锚点投影到开放问题或待办。
4. `verify_evidence_anchors` 成功后才把锚点标为最终可用；拒绝时保留未闭合状态。
5. 只保存可观察状态增量，不保存模型隐藏推理文本。

### 优先级四：校准动效语义

1. 关键词直接命中显示为“候选召回”。
2. retrieve 自带的一跳补充显示为“关系候选”，不得表现成已验证传播。
3. `read_card` 表现为单节点精读。
4. `inspect_evidence_set` 表现为证据集合核对，不绘制虚构关系流。
5. 只有 `graph_walk` 或真实路径 Observation 才按 depth 展示扩散层，并显示实际到达深度、plane 与截断状态。

### 优先级五：把案例变成可执行回归

1. 建立最小冻结 fixture 和 manifest。
2. 保存两条用户输入、允许工具、预算和预期轨迹义务。
3. 确定性检查任务隔离、TM 选择、成功锚点核验、完成幂等性和事件层级。
4. 最终内容仍由人工评价分析价值、事实忠实度和不确定性，不用工具调用数生成综合智能分。

## 十一、停止条件与撤回方式

  近期实现到以下状态即停止扩张：RC-001 两问可以重复通过；普通闲聊仍可直接回答；简单事实问题不会被迫建立长任务；report 未完成核验时无法 completed；前端能区分节点点亮与关系扩散。

  若 TM 或关系观察强制导致简单任务成本明显上升，应只撤回 `nexo-talk` 的复杂问题门控，不撤回 report 的完成正确性、锚点核验和 finish 幂等性修复。若固定 fixture 证明某次图观察没有改善答案，可以调整该案例的 TM 义务，但不能用动画效果代替收益证据。
