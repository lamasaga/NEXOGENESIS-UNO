# 编译同名卡核对

新版单元编译生成的候选 ID 若命中未完整提供的既有卡片，在进入常规检查前执行一次局部知识对象核对。只有碰撞的候选与对应旧卡全文进入该请求；不携带原书、其他候选、参考包或会话历史，其余上下文仍受 60,000 字符上限约束。请求经过现有模型适配器、预算账本和提示词记录，阶段为“编译 · 同名卡核对”。

模型依据对象身份和信息增量选择：

- `reuse`：同一对象且旧卡已完整覆盖候选，保留旧文件，记录复用依据。
- `revise`：同一对象存在真实增量，生成保全旧内容、证据边界和领域的合并候选，继续常规检查及 Gateway 预检；旧来源、关系和历史版本由 Gateway 保全。
- `separate`：两个独立知识对象，宿主分配可重复计算且不冲突的新 ID，同步当前单元内指向该候选的关系，旧卡不改。

ID 相同本身不是覆盖或复用许可。局部请求交付的旧卡版本由宿主冻结，模型不接收或生成 revision。核对中发生并发改动仍拒绝；已完整提供的普通参考卡发生版本冲突也不进入同名恢复。退役卡不能自动复活。摘要参考只有在该局部请求实际交付完整旧卡后才能成为修订依据。

决策与旧卡快照保存在任务状态中。后续审核失败后沿用已完成核对；错误返回保留并按请求内容复用，不因点击继续而重复支付同一响应。知识写入仍只经过 HarnessGateway。历史 v2 任务不启用此分支。
