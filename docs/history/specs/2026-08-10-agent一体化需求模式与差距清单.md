# 一体化 Agent 化：需求模式与「智能感」差距清单

> 日期：2026-08-10
> 性质：愿景/需求模式文档（非单功能 spec），供本项目后续迭代与其它项目复用
> 关联 spec：`2026-08-10-web-agent-runtime-design.md`（本愿景的 P1/P2 落地设计）

---

## 一、需求模式（可复用陈述）

**一句话**：项目应自带完整的 agent loop 工程化实践——任何前端（Web / CLI / 未来的其它界面）都不复刻编排逻辑，统一调用项目内置的 agent runtime；skill、harness、知识体保持单源，一处修改、处处生效。

**五层检查表**（判断一个项目是否具备「agent 智能感」，也可作为迁移清单）：

| 层 | 含义 | 工程化标志 |
|---|---|---|
| 1. Loop | plan → act → observe 循环 | 工具调用循环、轮次上限、流式输出、可中断 |
| 2. Tools | harness 即工具 | 项目核心能力（检索/读/写/校验/索引）全部封装为模型可调用的工具，且是唯一入口 |
| 3. Context | 每轮上下文编排 | 动态组装 working set：system + 技能剧本 + 检索 + 记忆 + 档案，有限体积、高关联 |
| 4. Playbooks | 技能即声明式剧本 | SKILL.md 类文档热加载，改剧本即改行为，无需改代码 |
| 5. Discipline & Observability | 纪律与透明 | 高风险操作机械防呆（非提示词维持）、过程步骤可见、结果可查证、全程落盘可追溯 |

**边界声明**：不做通用 agent。智能感仅针对本项目领域完备——co-text（上下文编排）、loop、harness 三者围绕本领域知识体做深，不追求通用工具生态。

**验收标准（用户可感知的智能感）**：

1. 一次答不好会自己换角度再检索（多轮，而非单发）；
2. 回答引用的来源可点击查证（检索了什么、读了哪张卡，可见）；
3. 写入知识库前必先征得确认（结构化确认，非自觉）；
4. 记得本轮对话说过什么、引用过哪些卡（STM），跨会话有连贯感；
5. 该主动时主动（强信号轻问），不该打扰时安静（冷却）；
6. 过程透明：每一步在做什么（检索/读卡/写卡）实时可见，可中断、可纠偏。

## 三、差距清单（达到目标还需补充的工作）

按依赖顺序，A 为地基：

### A. Agent loop 落地（已出 spec，最高优先）

- 实施 `2026-08-10-web-agent-runtime-design.md`：function calling 循环、三技能路由、确认卡写卡。
- 完成后 Web 与 CLI 共用同一 skill/harness 单源，一体化成立。

### B. 上下文编排对齐（智能感的核心增量）

- Web agent loop 接入 `context_package` + `attention.yaml` 权重（与 CLI 同一套注意力组装），替换单发 rag_search。
- `02-Profile/`（领域理念、思维范式）注入 system 层，让回答自带领域气质。
- STM 会话卷接入 Web：每轮把 focus / tensions / cited_cards 摘要注入；`cited_cards` 驱动「enrich 优先于新建」的纪律在 Web 同样生效。

### C. 主动性强信号

- 触发器（用户陈述含新主张/与卡片冲突/提及 Inbox 材料）+ 冷却机制 + 轻问 UI（对话内温和一问，可拒绝）。
- 纪律照 thinking-body §2：捕获永远确认、分析默认留对话、提及 Inbox 只建议不自动跑。

### D. 摄入管线 agent 化（P3）

- compile/digest/construct 从「CLI 命令」变为「agent 可驱动的任务」：对话发起 → 任务面板呈现进度（事件流）→ 中途可追问/纠偏 → 产出回执入会话。
- 与对话态的区别：长任务、批处理、需要任务状态机（queued/running/done/failed）与断点。

### E. 可中断与可纠偏（steering）

- 生成中取消按钮（后端取消 loop，部分落盘纪律已有）；
- 中途插话纠偏：新消息打断当前 loop，带着修正指令重入。

### F. 过程透明的深化

- 步骤轨迹可展开（工具参数/结果摘要）；sources 芯片（spec 已有）；失败步骤可见。

### G. 自我校验循环

- 写后自动 `validate` 并把结果回填；检索不足时 playbook 编码「换词再检索」策略；judge 作为自我批评工具被 loop 复用。

### H. 评估闭环

- 建立检索/回答质量 eval 集（扩展 `tests/evaluation/`）：标准问句 → 期望命中卡/期望引用，随迭代回归，让智能感可度量、防退化。

## 四、迁移指引（别的项目如何套用）

1. 先立**单源纪律**：知识/技能/工具各只有一份，前端禁止复刻编排。
2. 用**五层检查表**（§一）盘点现状，找出断点层。
3. 先修 Loop + Tools（地基），再补 Context（智能感主要来源），然后 Playbooks 热加载，最后 Discipline & Observability 收口。
4. 每层都问一遍：这一步是「真机制」还是「看起来像那么回事」——凡装饰性机制（动画、标签、假进度）必须能追溯到真实的工具调用或数据。
