# 单体系架构决策：不追随上游「双执行平面」

> 日期：2026-08-19（用户定调）
> 状态：已确认的架构决策
> 关联：`docs/specs/2026-08-19-上游nexogenesis-org进展核对.md`、`docs/specs/2026-08-16-能力内核与双执行平面重构设计.md`（上游背景参考，非本仓目标）

---

## 1. 背景

原项目（nexogenesis-org）因历史原因存在 **Web、CLI、Code Agent 多个入口**，v2.1（2026-08-18）引入「能力内核 + 双执行平面」重构：**Web + DeepSeek 平面**（talk/emerge/assess/refine/report/construct）与 **Code Agent 平面**（仅 compile/digest，通过任务包/提交协议参与同一 Workflow）。该拆分是为协调多入口、约束外部 Code Agent 权限边界而设。

## 2. 决策（用户确认）

> **融合新仓是单体系：不采用双执行平面。**
> 融合仓 = 一个更符合用户需求的 DSH —— **Web 界面即唯一入口，界面下调用 DSH agent 完成任务**。
> talk / emerge / assess / refine / report / compile / digest / construct 全部由**同一个会话内 agent** 执行，不存在「Web 平面 vs Code Agent 平面」的分层。

理由：DSH agent 天然同时具备「对话/分析/语义判断」（上游 Web 平面的能力）与「工具执行/长任务」（上游 Code Agent 平面的能力），单入口系统不需要为协调多入口而拆分执行平面。双执行平面是上游的历史产物，对融合仓是多余复杂度。

## 3. 影响

| 项 | 立场 |
|---|---|
| `.agent/skills/`（9 个 nexo-* SKILL.md） | **保持统一 DSH 技能集，唯一事实源**；不迁移到上游 `schemes/default/web-skills/` 策略层 |
| `AGENTS.md`（v2.0 副本） | 保持 v2.0 语义；**不引入** v2.1 的「Code Agent 只能执行 compile/digest」纪律 |
| compile/digest/construct | 与 talk/emerge/assess/refine/report **同等**由会话 agent 执行（pipeline 会话 + 技能 + 知识域工具） |
| 上游 v2.1 功能级成果 | **仍可参考吸收**：digest v2.1 的 enrich 段落补丁语义、前端特性（digest_two_stage/历史/收藏）、yaml/ingest 健壮性修复——作为功能参考，不作为架构蓝本 |
| 文档中「双执行平面」表述 | 一律理解为**上游背景**，不是本仓目标架构 |

## 4. 验证含义

- 单体系下，「技能按需加载」= 会话内按意图选择 nexo-* 剧本；「入口」= Web UI 的 `/api/chat`（SSE 桥）唯一驱动 agent。
- M5 的 goal / subagent / plan / compaction 全部作用于**这一个** agent，无需按平面区分能力。
- 后续上游若继续演进双平面，本仓只吸收其功能/质量收益，不跟随其架构拆分。
