> 日期：2026-09-08

## 1. 设计判断与范围

### 1.1 当前问题不是简单的“思考太多”

真实记录同时存在两类问题：图谱确实帮助模型发现了重要边界，但模型有时把相关节点当成直接证据，把不同来源当成独立验证；另一方面，部分运行在已经形成有用答案后，长时间反复处理验收字段，最后以 blocked 收尾。

因此，本设计同时追求三件事：

1. 提高每次阅读和探索对具体判断的价值，减少来源、时期、样本和逻辑关系在综合时丢失。
2. 降低程序性验收对正常交流的阻碍，让不完整但诚实的分析可以交付并继续讨论。
3. 把主动关系推理作为核心能力：不止沿图找材料，还要利用关系识别依赖、接合机制、检验分歧、传播条件并推导新的有界判断。图谱动画呈现真实的探索与公开论证结果，不仅是检索装饰。

不能只放宽完成门，否则可能重新出现“候选摘要直接变成完整结论”；也不能只增加义务，否则会继续产生验收循环。

### 1.2 项目阶段与实施边界

项目已有实际知识实例、真实问答、知识写入与运行恢复机制，同时仍处于持续搭建和验证阶段。本次允许调整思维体的任务语义，但先通过一个覆盖后端、会话与界面的有效切片验证，不新建平行 Agent 平台。

本设计不包括：

- 更换 DSH 执行框架、模型供应商或知识存储。
- 新建图数据库、向量数据库、自动学习或多 Agent 裁判系统。
- 放松 compile、theme_compile、digest、construct 的来源、写入及完成约束。
- 自动修复本次发现的知识卡或关系；这些只能作为后续获授权的建构线索。
- 把报告默认保存进 OutBox，或把讨论记录自动转为知识。
- 修改 AGENTS.md。若实施确需改宪法条款，另行提交用户确认。

### 1.3 与现行文档的关系

当前分析契约仍规定 TM、观察义务与完成门；本设计建议调整的是普通分析的运行策略，不能直接作为模型跳过现行规则的授权。实施时须同步更新 Runtime、工具 Schema、Skill 引用、活契约和客户端，而非只改一段提示词。

已有统一入口方案中的思考面板、普通对话列表、暂停建构后讨论、原生 steer 插入可以继续沿用。本设计进一步调整其分析与交付逻辑。此前“未通过分析验收即 blocked”的处理不再作为目标设计，但“建构未验收不能假装完成”保持不变。

## 2. 真实问题与保留价值

以下来自前两轮对 2026-09-05 至 09-07 七个问答回合的重点核查。它们是诊断样本，不是随机抽样或正式性能基准。

| 样本 | 已观察到的有效行为 | 需要改进的行为 | 开发含义 |
|---|---|---|---|
| 通缩影响 | 检索后读取债务通缩、零利率反馈及生产率型通缩边界 | 答案覆盖面超出直接读取部分，材料与一般解释未充分分开 | 保留轻量解释，不强制图遍历；重要判断仍需清楚归因 |
| 日本通缩与资产负债表衰退 | 五张卡有完整阅读记录，形成可读的机制链 | 其他解释主要在结尾列举，未真正比较其解释范围 | 讲解一个框架与验证完整历史解释应区分 |
| 泡沫生成机制 | 读取 18 张不同卡，16 张有完整阅读记录；图谱补出了有效市场反方和日本案例 | 53 条运行操作记录，四次 completed 尝试后以 blocked 收束；后期反复对齐字段 | 改善收尾与缺口交付，不能把重复审计当研究进展 |
| 周期、货币与操盘应用 | 沿图找到权益泡沫与债务泡沫差异并补读，缩小了下行机制适用范围 | 同样记录 53 步并最终 blocked；部分跨作者支持被拔高为独立验证 | 保留图谱收益，改进证据关系和执行闭合 |
| 中国金融周期与康波 | 整理了历史研报、制度因素和周期框架 | 未做事后检验，却在总结中写“框架正确”；一般模型参数进入中国实证叙述 | 检查最终判断是否越过时期、地域与方法边界 |
| 流动性缓冲与火售 | 找到真实争议、历史案例和制度条件 | 把度量口径争议与代理边当作当前因果命题的直接反证 | 区分相关争议、替代解释与直接否证 |
| 制度短期稳定、长期脆弱 | 放弃弱类比，补读替代候选，保留断裂点 | “完全同型”等措辞超过实际类比力度 | 类比用来产生问题和假设，不承担因果证明 |

计数口径：Episode 中的操作记录不等于模型独立调用次数；合并审计会生成多条 Observation。耗时、调用次数、访问节点数均不是质量证明。旧记录缺少新版本的 reading 指纹时，不能按字段缺失推断当时完全没有精读。

还应保留一个重要经验：泡沫研究首次批量读取只返回边界片段，模型发现后补读全文。这种根据返回结果改变下一步的行为值得保留，不能为了提速一并删掉。

## 3. 目标体验

### 3.1 普通交流

用户可以直接提问、质疑、补充假设、要求简短解释或换话题。系统不因为这段对话曾经做过报告或建构，就永久锁定交付模板。

- 普通聊天不默认创建显式分析任务，不默认列出 TM 或审计面板。
- 有材料能改善答案时才检索；涉及用户指定的库内观点、历史来源或具体证据时必须实际查阅，不能用流畅回答替代。
- 用户反驳时先定位争议句：是在质疑事实、因果关系、适用范围，还是价值取舍；不自动重新运行整套研究。
- 用户明确设定的假设可以用于推演，但保持“在该假设下”的标记，不写成系统已证实的事实。

### 3.2 思考入口

沿用已有“深入理解、比较解释、检验判断、形成报告”目标和自动/标准/深入深度选项，不新增“必须使用某个 OPS”的用户配置。

面板只设定首轮目标与资源倾向，不决定固定语义步骤：比较解释可以用机制比较，也可能因材料不足先做来源核对；报告只是交付形式，不意味着每轮都要最大预算或特殊探索。

在执行过程中，用户可以：

- 继续排队输入。
- 立即插入修正方向或新增信息。
- 要求“先给目前结论”：不再开启无关新分支，在可用资源内完成必要说明并交付已有结果。
- 要求“继续核查某一点”：限定新增研究目标，而非把所有未决项重做一遍。
- 停止执行：及时结束，不强制为了生成完整答案而继续调用模型。

“先给目前结论”是协作指令；“停止”是取消执行。两者不能使用同一种后端处理冒充。

### 3.3 有缺口的交付

目标结果示例：

> 分析已交付，有待验证项。  
> 已解释泡沫的主要生成机制，并比较信用反馈与行为反馈。  
> 各机制在不同案例中的相对权重尚未验证，因此本轮不能判断哪一种是普遍主因。

用户可以继续讨论，不必先处理一个笼统的 blocked。未知项要具体到会影响判断的内容，不用“还需更多研究”填充。

### 3.4 建构后的讨论

保持已有暂停、只读讨论和恢复原建构的机制。共享普通对话容器不意味着共享写入权限、预算、目标或验收结果。

用户在讨论中表示赞同，既不等于批准旧提案，也不等于允许新写入。“记一下”仍按当前授权路径处理；暂停建构中的讨论不借新分析 Run 绕开原任务保护。

## 4. 职责与约束分层

本文中的“分析治理”指 Cognitive Runtime 的过程、预算和证据检查；HarnessGateway 继续专指知识写入权威。两者不能用一次全局“放松 Harness”开关一起调整。

| 责任 | 主责方 | 允许做什么 | 不承担什么 |
|---|---|---|---|
| 问题理解、下一步选择、判断修订 | LLM | 按新材料检索、比较、换向、缩小结论、结束 | 不自行增加权限、预算或伪造工具成功 |
| 任务目标和表达指导 | Skill、TM | 提醒观察角度、证据差异和停止条件 | 不把每次分析变成指定调用序列 |
| 候选、正文、路径、结构比较 | OPS | 返回可复核观察与真实覆盖 | 不把节点关联自动裁决成语义支持 |
| 范围、资源、运行、真实性检查 | Runtime、宿主 | 拒绝越权；验证版本和实际动作；记录交付与缺口 | 不宣称已自动证明因果或答案正确 |
| 知识提交 | HarnessGateway | 授权、预检、版本冲突、原子写入或回滚、收据 | 不因用户要快而跳过 |
| 阅读与控制 | UI | 展示真实结果、必要限制、插入和继续入口 | 不将动画或节点数量包装成智能水平 |

### 4.1 必须硬拒绝

- 未授权知识写入、冻结范围外修改、修改错误实例、绕过 Gateway。
- 旧确认投递到新 Run、重置预算续命、并发写入与讨论切换失配。
- 工具参数非法、知识路径不合法、伪造服务器所有字段。
- 请求把不存在、未读取或已过期的锚点登记成“已核验”。拒绝的是该登记，不是用户获得任何帮助的权利。

### 4.2 影响证据状态，不阻断整段交流

- 没有真实反例，或只找到了同源材料。
- 缺少关键数据、历史推演未做样本外验证。
- 只有竞争立场，没有能区分它们的观察。
- 类比不强、探索为空、路径不够用。
- 某个声明无法核验：撤回引用、改为假设或明确未知，仍可交付其他部分。

### 4.3 普通分析中改为提示或运行维护

- 没选 TM、不满足某个 TM 的工具配额。
- 未调用特殊探索 OPS，或没有两跳新节点。
- 复盘描述格式不足、次要工作记录未整理。
- 工作窗口太大：先由程序裁剪重复摘录与无关记录；仍不足时定点取用，不要求模型反复手动压缩整本账。

模型仍应使用适合问题的方法；只是“方法执行完整度”和“这份答案能否诚实交付”不再是同一个布尔条件。

## 5. 高质量思考的行为说明

以下是可分支、可回退的行为原则，不是后台顺序调度脚本。

### 5.1 先确定要回答的判断

多机制问题先形成少量可检验判断和真正的分歧，例如：

- 信用扩张是在解释泡沫生成，还是解释破裂后的损失传播？
- 日本信贷不振主要是供给受损还是借款需求变化？什么观察能区分？
- 社融领先关系来自哪个时期，是否经过后来数据检验？

保留用户原始问题与明确要求，避免通过删除难答部分让研究看起来完整。没有必要为每次聊天填写 hypotheses；深度分析仅在形成重要判断或改变方向时记录。

### 5.2 按问题选择证据动作

| 当前需要 | 优先考虑的已有工具 | 模型必须完成的语义工作 |
|---|---|---|
| 不知道材料在哪里 | retrieve、graph_search | 构造区分角度，避免重复换词检索同一簇 |
| 需要知道材料真正说了什么 | read_cards、read_card、read_card_unit | 区分全文、unit、片段；确认适用条件与来源立场 |
| 判断凭什么成立 | inspect_argument、trace_source | 阅读论据，不把边名当证明；区分原作者和转述者 |
| 多种解释如何不同 | compare_cards | 对齐解释对象、变量、方向、时期和预测差异；空矩阵不是无机制 |
| 怀疑漏掉边界或中间环节 | graph_walk、graph_path | 从焦点选择相关分支，补读需要用于回答的节点 |
| 核心前提可能不成立 | probe_assumption_inversion、trace_support_to_tension | 写清被挑战的命题及否定条件，检查候选是否真的针对它 |
| 需要迁移解释或产生新问题 | graph_analogize | 补读双方，说明对应与断裂；弱类比允许放弃 |
| 怀疑库内没有某材料 | inspect_knowledge_gap | 未命中只代表给定查询未定位；必要时换入口 |

“重要数字、强因果、独立验证、反方自我承认”是优先下钻来源的情形。不要求所有回答都 trace_source，也不能在明确需要原始依据时只停留在转述卡。

### 5.3 停止探索的依据

应停止或交付当前结果的典型情况：

- 已有证据可以在明确范围内回答问题，下一项探索不会改变关键判断。
- 多次探索只产生相同候选，已读材料也没有带来新的区分。
- 当前缺口依赖库外材料、现实测量或用户选择，继续库内遍历不能解决。
- 用户要求先交付，或资源上限将至。

不能仅凭“没有新节点”判定没有信息增益：重读旧节点可能发现新边界。反过来，新增很多节点也不代表认识增加。

## 6. 图谱利用：从节点增量转向判断增量

本节既是防止滥用关系的边界，也是需要主动增强的能力目标。减少 Harness 的流程负担，不应把思维体退化为“检索几张卡然后写一篇总结”。对关系密集且适合机制分析的问题，默认鼓励沿图工作；是否继续深入由判断价值决定，而非等待用户点名工具。

### 6.1 遍历前与遍历后分别回答什么

遍历前明确“希望解决哪个缺口”；遍历后区分四种结果：

1. 找到新材料，并改变或缩小了某项判断。
2. 找到相关材料，但没有改变判断。
3. 找到竞争解释，现有证据无法区分。
4. 没有找到合适材料，或结果不足以支持当前用途。

这些结果都可正常结束。不要求每次有洞见，不额外强制一条“无洞见证明”流程。

### 6.2 关系类型与路径用途

- argument 用于论证结构；context 用于时间、背景或关联；reference 用于归因和来源。
- 一个路径可以帮助找到材料，但不能把不同语义的边相乘成因果证明。
- `involves`、代理边或同领域归属不等于 `counter`。
- `argument_ready` 证明该边满足既有结构契约，不证明它对当前问题具有决定性论证力度。
- 多跳终点用于关键结论时必须读取相关正文；解释整条路径时，还应查验涉及的关系说明和必要的中间节点。只用终点的独立内容，不必为了配额把全图读完。
- 从桥接节点继续走图属于正常选择，累计路径可以超过单次跳数；不设全局最低深度。

### 6.3 来源依赖与代理边的处置

“外生冲击均衡倾向说”来自明斯基对对方的概括时，表达应是“明斯基将对方概括为……”，不能写“对方自己承认……”。若需要公平比较，对方的原始表述缺失就是具体缺口。

“中介资本比率与 AEM 杠杆因子符号之争”通过代理节点接到流动性螺旋时，可以提示度量与约束差异；若无法说明争议如何否定缓冲机制，应保留为相关争议，而不是强行补 counter 标签。

不自动修图来让本轮分析过关。发现知识结构问题可记录待办，后续在获授权的建构中复验。

### 6.4 什么才算“沿关系进行推理”

需要区分三个层次，不能只实现第一层却宣传第三层：

| 层次 | 实际行为 | 可合理声称的结果 |
|---|---|---|
| 关系引导的检索 | 从 A 找到相关 B、C，并读取内容 | 图帮助发现了材料 |
| 关系解释 | 说明 B 为什么支持、限定、依赖或反对 A，核对方向和适用条件 | 解释了这组知识之间的论证联系 |
| 基于关系的综合推理 | 查验多段关系的接合条件，得出单张卡没有直接给出的有界结论，或因边界改变原判断 | 基于已读材料形成了系统综合，仍需区分支持程度与待验证部分 |

目标是稳定提高第二、第三层的表现。不是所有问题都要到第三层，也不是每条路径都必须产生新命题。

社科知识中的 supports、based-on、influences 等关系通常不是形式逻辑的蕴含。A 支持 B、B 支持 C，不自动得到“A 充分证明 C”。图负责提供值得查验的连接，LLM 负责解释各段是否可以在当前问题中接合；程序检查真实端点、边、阅读与版本，不能自动认证整条语义推导。

### 6.5 主动性：从“有明显缺口才走图”提升为“有价值机会就主动探索”

在机制解释、因果比较、条件判断、制度传导及明确深度分析中，模型读到焦点材料后，应主动留意以下机会，不等用户要求“走图”：

- 当前结论依赖的前提藏在另一张卡，直接总结会遗漏成立条件。
- 焦点有支持、依赖、实例或冲突分支，可能区分两个看似相同的解释。
- 两个已读机制之间存在桥接节点，可能解释“为什么从这里传到那里”。
- 两条路径到达相近结论，但来源、时间尺度或机制不同，值得比较是否真的互相加强。
- 一处反例或制度条件可能沿依赖关系影响多个下游判断。
- 邻域出现与当前问题有关、但初始关键词没有点名的材料，可能改变解释对象或提供替代框架。

深度分析默认给这类机会留出探索空间；资源从减少重复审计和无效重读中腾出，不优先靠整体加大预算。窄概念解释仍可直接回答。没有有价值分支时可以结束，不额外提交“不走图证明”，更不以未执行图工具触发 blocked。

主动性首先通过 Skill/TM 指导、上下文中清晰的关系前沿和真实样本训练式迭代增强。宿主可提示可用分支及真实返回信息，但不自动替模型执行语义路线。低相关度的“意外发现”不能因为新奇就优先于用户问题。

### 6.6 优先增强的五类关系推理

这些是行为类型，不新增五套工作流、五个 TM 或五种关系。

| 推理行为 | 典型关系与已有工具 | 应产出的公开论证结果 |
|---|---|---|
| 追溯依赖 | 从判断沿出向 based-on 或入向 supports 查依据；inspect_argument、graph_walk | 哪个前提最关键，撤去它后判断是否还成立 |
| 接合机制 | 查 model 的组成、扩展与有条件影响；graph_walk、read_card_unit、compare_cards | 上一机制的结果能否成为下一机制的输入，在哪些条件下能够传递 |
| 比较竞争路径 | 查 conflicts-with、争议各方及各自证据；inspect_argument、graph_path、compare_cards | 两种解释对同一现象给出哪些不同预期，什么观察能区分 |
| 传播边界或反例 | 从受影响前提出发查下游依赖，读取必要端点 | 哪些下游结论需缩小、降级或保持；不是把整个连通簇全部推翻 |
| 跨簇组合与反馈分析 | 从相关桥接节点继续，必要时分平面查询；graph_walk、graph_path、graph_analogize | 新的组合解释、条件分叉或反馈回路，以及不能连接之处 |

“反向查依据”的遍历方向与知识关系的声明方向可能相反，必须同时保留。`involves` 先帮助找到争议各方，不能直接承担否证；`example-of` 可检查条件是否在案例出现，不因几个实例就推出普遍规律。

context 中的 influences、precedes 可以参与机制和时序分析，但必须显式标明用途并阅读其依据，不能一概排除，也不能混同成 argument 证明。precedes 只证明时序，不单独证明因果；reference 可以帮助确认作者和同源性，不增加因果链强度。

### 6.7 接合条件：每个关键跨越都要讲清“为什么能接上”

针对最终要采用的路径，模型应检查以下事项；不要求为所有候选逐项填表：

1. **对象与变量一致性**：两张卡中的“信用”“资本”“流动性”是否指同一对象与口径；名词相同不等于变量相同。
2. **方向与功能**：这条边提供支持、依赖、扩展、时序还是情境影响；沿反方向找到材料不等于反向因果成立。
3. **范围相容性**：时期、国家、部门、制度与时间尺度是否能衔接；不相容时明确迁移假设。
4. **条件相容性**：上一段输出是否满足下一段前提；条件集合是否冲突；不能把互不同时成立的机制串成必然链。
5. **证据独立性与循环**：回到同一来源、同一案例或起点不是新增独立支撑。真实反馈机制需说明作用方向和时序，不从图上有环直接推导自我强化。
6. **结论力度**：输出是可能机制、有条件推论、解释竞争，还是已被具体样本支持的判断；条件不够时保留断点。

已读且版本未变的必要节点可以复用。把阅读相关机制单元作为优先选项，不为了“路径每节点全文”浪费预算；若声称完整理解整张卡，则仍遵从完整阅读覆盖规则。

### 6.8 一条具体路径应怎样产生增益

以已有“财富效应先于货币政策驱动衰退螺旋 → 债务驱动泡沫与央行管理边界 → 权益泡沫与债务泡沫的损失传播结构不同”的发现路径为例：这里的箭头只表示实际访问顺序，不声明三条因果关系。

模型先有判断：“资产价格下跌可能经财富与信用渠道放大衰退。”沿关系读取到权益/债务泡沫的差别后，应判断新卡限制了哪一个环节：损失是否会通过杠杆、抵押品和中介资产负债表外溢，而不只是“又找到一条泡沫知识”。

可交付的综合应类似：

> 不能只根据资产跌幅推断系统性衰退。需要区分损失由风险资本吸收，还是会触发偿付、保证金及银行资本约束。原来的财富效应解释因此要按融资结构分情形讨论。

这是期望行为示例，不是新增已验证经济结论。进一步探索时可以主动追问“哪些制度会改变损失传递”，从相关桥接节点寻找边界；若现有材料不能回答，就保留未知。不得把访问了三张卡本身写成三跳因果证明。

### 6.9 保存的是可复核论证结果，不是额外思维账本

首版复用 hypotheses、证据 explanation 和少量 insight_reviews。对实际进入答案的重要关系推理，保留：受影响的判断、实际路径引用、必要正文锚点、接合或断裂的理由、适用条件、结论改变及未验证项。发现后未采用的普通分支只保留工具观察，不要求模型逐个复盘。

节点、边、方向、原工具步骤和版本尽可能由宿主从 Observation 关联，LLM 只补充公开的论证理由。若现有字段难以表达路径引用，可以增加一个小型可选字段；不得让这个字段成为新的必填完成门，也不引入独立“推理链数据库”。

以“相关证据支持某项条件式判断”呈现，不声称复现模型全部内部思考过程。模型口头说“我沿图推理了”不是路径证据；宿主有路径和阅读记录，也不意味着语义接合已被自动证明。

### 6.10 候选供给与自主选择的改进顺序

当前 graph_walk 已返回分层节点、完整路径、边方向与说明、readiness、focus_query 和被截断前沿；已有词面相关性排序和有限分支多样性处理。retrieve 本身也已包含关系候选扩展。不能把“传递路径信息”或“增加一个新分支位”当成尚未实现的能力。

先观察模型是否利用了这些信息：是否明确焦点、选择了相关方向和关系、读到桥接点后继续、发现相同词语不同含义后退回、识别同源循环。若没有，优先改善工具返回的可读性、Skill 的选择指导和工作窗口，不先另造检索算法。

若真实样本显示高连接节点仍吞掉有价值路径，再定点改善前沿排序与路径多样性：优先保留能区分解释的分支、同一终点的不同依据路径和可读的关系理由。现行节点去重不保证保留全部替代路径，也不应为了找环取消去重；反馈问题可通过定向路径查询或有限边记录补查。改动需保持返回上限、来源归属和延迟预算。

任何新排序分数都只是候选选择信号，不命名为“推理正确率”；语义上的有用程度仍由真实回归确认。

## 7. 证据与表达契约

### 7.1 分开“读过”“核验过地址”“判断受到支持”

建议沿用现有 hypotheses、evidence_anchors、reading 和来源字段，仅在需要时补充少量元数据。不要新建平行证据数据库，也不要为每句话生成一张表。

| 维度 | 谁产生 | 能证明什么 |
|---|---|---|
| 阅读覆盖与内容版本 | 工具、Runtime | 返回过哪些正文/unit，是否仍匹配当前版本 |
| 锚点有效性 | 确定性核验 | 地址存在、覆盖有效、归属正确 |
| 材料怎样作用于命题 | LLM 的 explanation | 可供审阅的支持、反驳、限定或综合理由，不是程序证明 |
| 来源独立性 | 来源线索加语义判断 | 是否同书、转述、共用数据；未知时保持未知 |
| 实证检验是否执行 | 真实工具记录或已读检验材料 | 做过何种检验，针对什么样本；不能只靠模型自报 |

现有 `supported` 仅表示“本轮所读材料提供支持”，不是事实认证。禁止新 UI 把它显示成“已证实”。

### 7.2 核心判断的最小记录

复用 `hypotheses` 的 id、statement、status、scope、uncertainty、anchors。对关键证据关系保留 explanation；需要时明确：

- 原作者立场、对手转述、历史预测、样本内发现、模型推演或本次系统综合。
- 直接反证、竞争解释、边界条件或背景线索。首版可写在 explanation，不急于修改知识卡的类型或关系枚举。
- 是否进行了用户要求的实际验证；没有执行就记未完成。

建议的解释示例：

> 这份材料说明 2012—2015 年样本中社融与产出缺口的领先关系；没有检验之后时期。因此支持“该报告据此作出周期推演”，不支持“社融始终优于 M2”。

### 7.3 输出约束

- 先回答问题，随后给最能区分解释的依据和限制。
- 不把“常见机制”写成“必要条件”，除非材料与范围足以支撑。
- 不能一边说历史预测未核验，一边总结“已经正确”。
- 不能把一般模型的模拟参数写成特定国家的实证估计。
- 不能仅凭多位作者或多张卡宣称独立验证。
- 关键库内依据保留可点击引用；来源检验、样本外验证与实时数据没有做就明确说明。
- 假设与类比可以自由讨论，但不得通过用户表示认同自动升级为事实。

程序能确定的无效引用应由宿主标记为未核验，不提供“已验证”标识。程序无法全面判断自然语言是否过度断言；这部分必须靠提示、真实样本审阅和针对性评测验证，不能声称新增一个字段就已解决。

## 8. 收尾检查的重新设计

### 8.1 基本决策

复用 `finish_cognitive_run`，不新增一个与它并行的完成工具。为新普通分析增加明确的交付意图，例如 `intent: "deliver"`；具体 Schema 在实施时统一修改。现有 pipeline 与固定评测继续使用原完成契约。

新的调用含义是“整理本轮交付依据并结束探索”，不是“请求证明所有研究条件已经满足”。

建议一次返回四类信息：

| 字段（拟议） | 用途 |
|---|---|
| `invalid_claims` | 哪些锚点、覆盖或已验证声明不能接受，绑定 claim_id 与原因 |
| `limitations` | 哪些结论缺少反方、独立来源、样本或实际验证 |
| `process_notes` | 哪些方法观察或复盘记录没有完成，不自动阻断交付 |
| `next_actions` | 少量直接可行的选择：补读、修正角色、撤回引用、降低结论或带缺口交付 |

不能再只返回“还差五项”。应说明每个缺口影响的是哪句判断、哪种声明，而不是要求模型猜测字段之间的依赖。

### 8.2 无效声明不等于整轮失败

交付检查对无效锚点返回“不接受为已核验”，其余证据保留。模型可以补读，也可以不用该锚点并承认无法判断；不允许把无效项静默删除后仍把相应结论显示为已验证。

如果用户请求必须依靠某项验证才能回答，例如“检验康波预测是否兑现”，只有理论梳理时结果必须是“部分回答/验证未完成”，不能利用可交付机制把原始请求改写成“介绍康波理论”。

### 8.3 减少重复审计

合并审计本身已有实现，不把“合并调用”重复当成新功能。新增重点是结果分层、增量失效与重复请求识别。

检查指纹至少覆盖：实例与 Run、原始请求和范围版本、判断的语义字段、证据地址及角色、实际阅读记录和相关内容指纹、分析策略版本、影响本次结果的观察。不能直接用会被审计自身改变的总 step_count 或纯展示字段作键。

- 输入与相关内容未变：返回已有结果，不再次展开同样的三项审计。
- 新增或更换证据：重查受影响的条目与依赖判断。
- 仅修改复盘文案：不重新读取全部卡片。
- 内容版本变化：相关证据失效，不能沿用旧核验。
- 用户改变核心问题：不是旧审计的缓存命中，应按新目标处理。

审计缓存是运行派生物，不改变 Markdown 事实源地位。重复网络请求可以保留简短请求回执，但不重复扣取语义操作额度、伪造研究进展或触发模型自动续跑。

### 8.4 不再围绕步骤编号过关

真实的 graph_walk 加补读，只要对判断产生可解释影响，就可以贡献探索结果；不必须转调用三个特殊 OPS 之一。

operation_step 等关联应尽可能由实际调用回执和宿主建立。LLM 只负责“发现是什么、影响哪项判断、为什么”；旧字段可保留兼容读取，但不再因为模型填错复盘步骤号让整段交流无法结束。

缺失语义检验不能自动填成已完成；应显示为“尚未核查此推断”，而不是“缺少字段，请继续直到过关”。

## 9. 运行、交付与证据状态

### 9.1 必须分离的三个事实

1. **执行状态**：模型是否运行、等待用户、暂停、正常结束、失败或受外部阻碍。
2. **交付状态**：面向用户的答案是否真实写入会话历史。
3. **请求覆盖与证据限制**：回答了哪些要求，哪些仍未完成；核验过什么，不知道什么。

不要把所有情况压成一个“完成/blocked”。也不要只是把原 blocked 改成绿色“完成”而不保存缺口。

### 9.2 推荐的数据方向

建议为新版普通分析新增一个终态 `closed`，仅表示“本轮执行正常结束”，不表示研究证明或知识任务验收通过。保留已有 completed 的旧语义，用于旧运行和原来的知识任务；不要全局重定义 completed。

在现有运行存储中增加宿主管理的交付记录，不直接放进 LLM 可任意 patch 的 extension.result：

```json
{
  "analysis_policy_version": "conversation-v2",
  "delivery": {
    "state": "delivered",
    "turn_id": "宿主确认的回合标识",
    "message_ref": "已持久化的用户可见消息标识",
    "coverage": "partial",
    "stop_reason": "budget_exhausted",
    "review_ref": "本次证据检查快照标识",
    "limitations": [
      {"claim_id": "C2", "code": "empirical_test_not_performed", "detail": "未检验该历史预测的兑现情况"}
    ]
  }
}
```

这是拟议数据示例，不是当前接口。state 建议区分 none、prepared、delivered、interrupted；coverage 建议区分 answered、partial、unanswered、unknown，不增设含混的“全局可靠度百分比”。coverage 是带依据的请求覆盖判断，不是程序自动确认语义完美。

analysis_policy_version 由宿主创建并冻结。客户端、历史提示和模型不能通过切换策略豁免旧任务、评测或写入规则。

### 9.3 谁能确认交付

- `finish_cognitive_run` 返回时，只能确认准备记录与证据检查，不得立即写 delivered。
- 准备交付后 Run 仍等待本回合实际结束，不提前写 closed；正常终止时由宿主结算 closed，故障或取消仍记录各自执行状态。准备期间默认不再自主扩展研究；若用户插入或确需修正判断，撤销旧 prepared 快照并保留修订记录，不重置累计预算。
- 宿主观察到用户可见的完整回答已进入持久会话历史后，才写 delivered 并绑定真实消息与回合。
- “证据已经充分，马上回答”之类过程消息不算最终交付。
- 只有 finish 成功但模型随后失败：保持 prepared/未交付。
- 只生成了片段后被取消：记录 interrupted，保留片段，不宣称完整交付。
- 浏览器断开而后台完成：以后台真实记录为准；重连可恢复。
- 消息已落盘、交付状态尚未写入时进程崩溃：恢复时按稳定消息标识幂等对账，不能重新生成一份答案。

宿主若无法确定哪条消息承担交付，delivery.state 保持 none/prepared，coverage 保持 unknown，不靠非空字符串或 turn/end 猜测研究已经完成。若 SDK 无法直接区分，实施时需约定交付准备之后的完整最终消息并覆盖取消、插入等边界。

模型未调用 finish 就直接回答时，宿主仍可正常结束执行并保存真实消息；不得补造审计成功。能确认是最终回答时登记交付事实，证据检查标为未执行或沿用确实适用的已有快照，覆盖不明时保留 unknown。模型最终措辞超出 prepared 中的判断，程序不一定能自动发现，因此不能把 prepared 检查结果展示为对整篇自然语言答案的认证。

### 9.4 状态映射与行为

| 情形 | 执行状态建议 | 交付/覆盖 | 用户看到什么 |
|---|---|---|---|
| 正常回答且没有重要未完成要求 | closed | delivered / answered | 已回答 |
| 主体可答，但关键验证未做 | closed | delivered / partial | 已回答部分，标出未验证项 |
| 预算耗尽但能交付局部结果 | closed | delivered / partial | 本轮已结束，可继续核查指定问题 |
| 用户必须选择范围或提供材料 | waiting_user | 可有局部交付 | 需要你的选择或材料 |
| 外部依赖不可用，无法继续关键任务 | blocked | 可有 partial/unanswered 说明 | 具体阻碍和已有成果分开显示 |
| 模型或系统失败 | failed | none、interrupted 或既有 delivered | 执行失败，已保存内容不丢失 |
| 用户取消 | cancelled | 保留此前真实交付或片段 | 已停止 |

外部阻碍允许 blocked，但不因为缺少复盘字段或没有特殊探索就使用它。`closed` 与 delivered 不互相推导；系统也不得因缺少 delivered 自动恢复已结束的执行。

### 9.5 旧状态不能直接批量改写

旧 blocked 原因可能是预算、证据、工具故障、用户决定或写入治理；必须保留。旧 completed 也不等于新策略所有维度均已核验。

旧记录没有交付元数据时默认未知。可以按已有持久消息只读重建“存在回答”的事实，但不得重新认定语义验收或把历史研究标成已验证。

新增 closed 会影响终态枚举、冻结判断、续跑、侧栏、工作中心、按钮和旧客户端，必须整体盘点。不能只改 finish 或 UI 一个文件。若无法完成兼容闭环，先实现内部证据检查分层，不上线新状态。

## 10. 资源与收尾空间

首版不把调大默认预算作为主要措施，保留当前分析预算作为对照基线。

- 检索和探索预算仍是硬上限；取消和超时保持有效。
- 在预算接近边界时，优先读取已经发现且最能影响结论的材料，不再扩张分支。
- 预留有界的交付空间，用于确定性状态落盘、必要的证据说明，以及供应商额度允许时的一次最终回答；不是为继续研究提供隐形无限预算。
- 明确区分认知工具预算与供应商上下文/输出/token/额度限制。没有模型调用能力时只能保存已有成果和缺口，不能保证仍可生成完整回答。
- 用户说“先给结论”时冻结额外探索意图，不提升证据等级；正在执行的工具在支持的边界收束，不承诺即时回滚。
- 用户点击停止时不强制执行最终生成；取消优先于体验上的完整性。

重复审计计费需要区分实际模型调用、工具执行和派生 Observation；不能通过少记 Episode 来伪造节省。

## 11. 后续讨论、插入与继续研究

### 11.1 同一回合中的插入

沿用现有请求标识和 expected_run_id 校验，使用原生 steer，在最近支持的步骤边界接收；这不是撤销已执行工具。

- 澄清、缩小范围或纠正事实：写入本题公开约束，作废受影响的准备交付快照。
- 实质换题：旧研究保留已有成果与缺口，建立新问题状态，不能直接覆盖 goal 洗掉历史。
- 要求新增写入：不能作为普通 steer 自动授权，与现有写入路径分开。
- 迟到的工具结果、结束消息和重连事件必须绑定原 turn/Run，不修改新问题的状态。
- 指令重复或响应丢失：以请求回执对账，不能盲目重发。

### 11.2 已回答后的追问

简单解释、反驳或改写优先在普通对话中继续，不重启上次研究。新的实质分析建立新的只读 Run；可以继承显式结论和证据线索，但不继承旧通过状态或写入授权。

证据复用必须区分“知道旧材料在哪里”和“当前证据仍有效”。同题未变内容可在记录来源运行和检查指纹后复用；跨题要重新判断相关性。若首版尚未实现安全复用，明确补读，不能静默把历史链接当成本轮已核验。

### 11.3 继续核查未完成项

推荐首版创建关联原 Run 的新只读研究，以用户选择的缺口为目标；旧运行不改写、不清空预算。用户明确启动继续核查才获得新一轮受控预算，不允许模型自动新建 Run 绕过额度。

“恢复原建构”是另一条路径：必须回到原 Run、原范围、原累计用量及原待办。不得把这两种继续混用。

### 11.4 建构讨论与旧队列

保持安全边界后再切换只读讨论。任务切换后的旧队列停止自动发送，由用户确认目标；旧确认、原生提问及恢复指针不能被分析交付覆盖。

用户关闭讨论、返回建构，不要求先把讨论的所有证据缺口消灭；只需保存真实讨论结果并确认当前执行已停止。原建构的待确认事项仍需原有授权。

## 12. 界面呈现

### 12.1 默认呈现内容

优先显示答案与关键引用，过程只显示有意义的变化，例如：

> 找到一项重要边界：债务泡沫与权益泡沫的损失传播不同，原来的下行判断需要缩小范围。

避免反复显示“最终审计”“还差三项”“即将收束”。确有影响用户等待或判断的故障必须说明，不能把问题藏进折叠区。

结果卡只在有重要未完成项、需用户决定或执行失败时突出显示。普通顺利回答不必增加一整块“全部通过”仪表盘。

### 12.2 可展开的依据与过程

可以查看：关键判断、实际阅读范围、相关路径、来源限制、哪些探索改变了判断、实际工具拒绝和结束原因。不展示隐藏思维链，不把公开工作记录称为完整内部推理。

图谱呈现区分：候选发现、正文读取、关系观察与实际写入。点亮节点不等于读过，更不等于证实。首版复用现有事件能力，不为本设计额外增加表演性动效。

动画是帮助用户理解探索与论证的正式产品能力，不因反对表演性动效而被弱化。其吸引力应来自“看见模型在哪里发现了依赖、遇到反方、改变了判断”，而不是固定播放一次全图扩散。

| 已发生的事实 | 适合呈现的语义 | 不允许暗示 |
|---|---|---|
| retrieve 返回直接命中及图扩展候选 | 候选发现，明确不是已读 | 每个命中都已被理解 |
| graph_walk / graph_path 返回实际路径 | 沿真实边展开，可区分访问方向、关系方向和关系类型 | 浏览方向就是因果方向，或最短路径就是最强解释 |
| 关键节点正文/unit 返回 | 该节点的实际内容已读，可显示覆盖 | 部分内容已读等于整张卡已核验 |
| 模型基于已读路径给出公开论证说明 | 聚焦采用的路径及条件，标为本轮综合 | 宿主已证明整条推理正确 |
| 真正发现反证、边界或无法接合处 | 对应判断的分叉、断点或限定 | 所有 conflicts-with 邻居都推翻原命题 |
| 模型放弃分支或结束探索 | 分支保留为未采用/未核查，结果自然收束 | 没有采用就是错误证据，或空探索等于失败 |

候选路径、已读路径与采用的论证路径应可辨认，不要求增加复杂图例才能聊天。点击采用的路径可查看少量正文锚点、关系说明和条件；不能只给用户一个无法解释的闪光轨迹。

所有视觉事件绑定真实 instance、Run、turn 和 Observation；允许合并、节流或回放，但回放必须可辨识，不伪装成实时推理。取消或切题后不继续向新题播放旧轨迹；动画不得拖延答案、扩大模型预算或诱导补调用。保留减少动态效果选项，静态路径和文字能表达相同信息。本轮只定义语义映射，具体动画参数另在实现与视觉验收时确定。

### 12.3 前端必须通过的交互

- 思考面板取消不生成任务、不丢草稿；开始失败可恢复输入。
- 四种目标共用普通聊天，后续要求一句话回答不被报告模板锁住。
- 立即插入、排队输入与停止的含义可区分；中文输入法不误发。
- 部分交付后仍可正常聊天；工作中心不持续要求处理一个并不存在的用户待办。
- 刷新、重连和换会话后，结果、缺口与执行状态一致。
- 390px 窄屏、桌面、键盘焦点、读屏标签和长中文缺口文本可用。

## 14. 验收：流畅度与分析质量必须一起看

### 14.1 确定性与安全用例

| 用例 | 必须满足 |
|---|---|
| 普通分析没选 TM 或没用特殊 OPS，但有可交付内容 | 可结束并表达范围，不因工具缺额阻断 |
| 用户要求实证但只取得理论材料 | 可以交付理论部分；coverage 为 partial，不标验证完成 |
| 锚点不存在、仅候选摘要、正文版本变化 | 不授予已核验标记；可撤回或降低声明后交付 |
| 多张卡同源 | 不自动增加独立验证数量，不凭 card 数清除限制 |
| 重复 finish、网络重试和重复回合结束事件 | 一份审计结果、一份交付记录，无重复预算消耗或自动续跑 |
| 修改判断、角色或相关正文后再次 finish | 受影响的审计正确失效，不能复用过期结果 |
| 预算耗尽、探索为空、复盘缺字段 | 有界停止；保存具体缺口；不无限重试 |
| finish 已返回、最终消息尚未生成便失败 | 不显示已交付 |
| 最终消息已持久化后宿主崩溃 | 恢复可幂等对账，不重复生成 |
| 插入改变问题，旧工具和结束事件迟到 | 只影响原 Run/turn；旧交付快照失效，不串题 |
| 停止与先给结论 | 停止不强制生成；先给结论不伪造验证、不越预算 |
| 旧 pipeline、固定测试与知识写入 | 原完成门、权限、事务、回滚及范围保护不退步 |
| 暂停建构后讨论再恢复 | 原任务、预算、提案、待答和收据均保留 |
| 旧客户端、旧记录、混合版本 | 不把未知状态当成功或可续写；显式能力提示 |

优先扩展已有 `general-analysis-closure`、`general-analysis-budget`、`analysis-coordination`、`working-memory`、`evidence-inspection`、`chat-general-lifecycle`、`work-lifecycle`、`deep-thinking-closure`、`conversation-control` 测试；不能通过删除旧安全断言获得绿色结果。

### 14.2 真实问答回归集

| 原题/追加挑战 | 重点观察 |
|---|---|
| 通缩如何影响经济 | 是否保持轻量、能区分机制与边界，不强行特殊探索 |
| 日本通缩与资产负债表衰退；追问“这是唯一解释吗” | 是否从讲解框架转向比较，承认未做的鉴别 |
| 泡沫如何产生 | 保留图谱提供的反方和日本案例；不反复四次申请 completed |
| 周期、货币与操盘应用 | 不把机制框架当回测策略，不把多作者直接写成独立验证 |
| 中国金融周期与康波；要求验证预测是否兑现 | 历史判断与实际结果分开；不得将一般参数冒充中国实证 |
| 流动性缓冲能否阻止火售 | 正确识别代理边与度量争议，不冒充直接反证 |
| 制度短期稳定长期脆弱；指定类比 | 允许放弃弱候选，不用“完全同型”拔高对应 |
| 材料不足且用户要求先回答 | 局部成果可交付，缺口不消失，后续讨论自然 |

先冻结同一知识快照、问题、模型及配置，保存旧策略结果与新策略结果；不得拿不同知识版本的改进全归功于新 Harness。

第一批最小实验采用“通缩、泡沫、周期应用、中国专题”四题，各条件至少三次独立新会话。旧策略与新版比较质量和成本；再用相同新版策略对照“普通检索阅读”与“允许自适应图谱探索”，单独观察图谱增益。资源不足时缩小题数并标为试跑，不宣称得到稳定统计结论。

该对照必须进一步注明：现行 retrieve 本身包含图扩展，因此“没有显式 graph_walk”不是“没有图谱”。首版比较的是“现有检索阅读”与“在同样入口上增加主动关系推理”；若要测纯文本检索与图谱的差异，需要在隔离评测中显式关闭检索内的图扩展，不能只删一个工具名就宣称完成消融实验。

### 14.3 评价维度

- **证据忠实度**：原句与引用关系是否成立；是否保留立场、时期、地域、样本和条件。
- **问题完成度**：用户的核心要求是否回答，未完成项是否被隐藏或偷换。
- **分析价值**：是否提供有区分度的机制、真正挑战或可检验预测，而非概念并列。
- **图谱净收益**：哪些判断因图中发现而变化；其中哪些普通检索也已提供，哪些实际经过补读。
- **交流体验**：首次有用反馈、最终交付时长、插入响应、追问是否自然。
- **运行成本**：实际模型调用、工具执行、派生审计记录、返回字符量和可取得的 token 用量分别统计。
- **失败恢复**：丢失、重复、旧状态污染、错误交付标记和越权事件。

人工审阅优先盲读答案，再看轨迹；案例作者数不能代替来源独立性审查。自动检查只负责可确定事项，不把另一个模型的评分当作事实验证。

上线最低门槛：安全用例全部通过；无已知无效证据被标成已核验；无把未做实证写成验证完成的严重错误；重复无变化审计可稳定复现地被消除；四题真实样本未观察到质量退步且呈现更顺畅的收尾。具体延迟改善以实测报告，不预先承诺百分比。

### 14.4 主动关系推理的专项验收

不能仅靠七题中的工具计数验收这一核心能力。补充少量人工审阅的冻结案例，先区分“路径确实有用”和“不应组合”：

| 案例结构 | 期望行为 |
|---|---|
| 初始关键词不命中关键限制，但焦点邻域存在相关桥接卡 | 用户未要求走图时仍能发现机会、读取桥接材料并缩小判断 |
| 必须接合两个机制才能回答，任一单卡都不充分 | 说明中间变量与接合条件，形成有界综合，不只并列摘要 |
| 存在两条竞争路径，结论依赖不同制度条件 | 同时审视相关路径，给出可区分观察而非按最短路径选真相 |
| 一项前提被反例削弱，只有部分下游判断依赖它 | 有针对性地修改受影响判断，不把整簇全部推翻 |
| 同源支持环、代理争议边、时间先后链 | 识别循环支持、代理与因果跳跃，不声称多跳验证成立 |
| 表面同名变量属于不同国家、部门或度量口径 | 识别不能直接接合，保留迁移假设或断点 |
| 有真实反馈机制，但遍历因去重未返回闭环 | 不仅凭“没看到环”否定反馈；必要时定向检查，不全图漫游 |
| 简单概念或图中无相关路径 | 轻量回答或诚实退出，不为了主动性强行图推理 |

人工评价至少分开：机会识别、方向正确、关键节点阅读、条件相容、竞争解释、综合增益和停止合理性。自动统计“有机会时发起了多少次相关探索”和“其中多少被读取、采用”用于诊断；不设线上每轮必须探索的 KPI，不把采用率越高越好作为目标。

选择其中一个接合案例做隔离对照：保留卡片内容不变，仅隐藏一条关键桥接边，观察模型是否改用明确检索或承认路径不可得；再恢复原边。还可以在固定材料下提供或不提供真实关系说明，观察解释质量是否变化。没有边仍能从正文推得结论不算失败，但不得捏造已观察的路径。所有消融仅在评测副本操作，不修改真实知识体。

上线报告应能展示数个“关系如何改变回答”的具体案例，同时展示主动放弃错误组合的案例。只有动画更热闹、调用更多或答案更长，不算能力达标。对“主动关系推理比现有检索阅读更好”的判断，必须由盲评与同预算对照支持；未观察到增益时继续调整，不扩大默认探索范围。

## 15. 实施顺序与撤回

### 15.1 第一批：验证收尾与交付的有效切片

依次完成证据检查分层、宿主交付记录、新普通分析的 closed 生命周期、UI 状态和旧策略兼容。这些是同一切片的依赖，不能只上线“把 blocked 换个名字”。同时加入必要的证据表达指导，以及第 6.5—6.8 节的主动关系推理基线，利用已有工具验证，不把关系推理推迟成遥远的可选增强。

第一批至少包含一个真实桥接限制案例和一个不应接合的反例，展示实际路径与公开论证结果。动画先正确投影已有事件；更复杂的视觉打磨不阻塞核心能力回归。

先运行隔离测试，再以四题真实回归验证。未通过真实模型与交互验证前，新策略只用于明确选择的试用会话，不自动接管所有新题。

### 15.2 第二批：依据结果优化探索与讨论

在第一批有效后，针对实际低收益动作改进候选选择、来源下钻、证据复用和指定缺口续查；补齐完整七题及插入、取消、重连、建构讨论样本。不以新增 TM/OPS 数量作为交付内容。

### 15.3 兼容与部署

- 策略版本在 Run 创建时冻结，旧 Run 继续按原策略解释。
- 新 closed 状态启用前，统一盘点所有终态判断、续跑与权限入口；新增能力标记并要求前后端匹配。
- 既有 strict 执行测试继续保留固定契约，只评价执行完整度，不作为日常聊天默认标准。
- 不修改旧知识内容或重写历史状态；评测数据与运行实例不进入通用分发包。
- 运行中任务不强制热切换。上线记录代码、构建、后台重启和真实验收状态，不能互相代替。

### 15.4 撤回

关闭新策略的新建入口，保留兼容读取与交付元数据；在用任务先安全结束或暂停，不把新状态直接交给不了解它的旧执行器。

如果发现质量退步，可恢复旧分析策略，但保留能理解新字段和 closed 的宿主兼容层。需要回退整个二进制时先验证旧版本如何读取新记录，必要时采用只读兼容导出或前滚修复；不批量把 closed 改为 completed，不删除运行记录来消除报错。

知识写入路径在本次不改，所有既有卡片、来源、提案、Journal 和确认结果保持原样。

## 16. 设计决策与开发前确认点

### 建议作为实现基线

1. 主动关系推理是核心能力：提高关系解释、机制接合与条件传播的质量；取消以动作数量证明深度的普通分析完成门，不削弱有价值的图谱探索。
2. 安全硬约束、证据有效性和过程建议分开处理。
3. 不完整分析可以交付；“已交付”不意味着“已证明”。
4. 保留普通聊天、思考、报告和建构讨论共用对话容器，运行与权限隔离。
5. 优先复用已有 Runtime、OPS、会话事件与工作区，不新建并行治理系统。

### 开发前必须核查的具体兼容问题

- DSH 当前事件与历史 API 能否稳定标识最终完整消息；无法证明时交付状态如何保持未知。
- closed 枚举的全部消费者及旧客户端兼容方式；没有完成盘点不得启用。
- token/输出预留能力哪些可由宿主真正控制；供应商额度耗尽时只能承诺保存已有成果。
- 当前 analysis 与 judge/deep-inquiry 的识别是否足以冻结策略，防止模型自行降级测试。
- 同题、跨题证据复用的指纹和关联记录能否复用既有实现；不能安全支持的部分先补读。

这些是实施前的核查项，不是当前已经具备的能力。若需要改变用户已确认的权限边界或 AGENTS 条款，应暂停该部分并讨论；其余可独立验证的切片继续推进。

## 附录 B：交付前自检

- 是否把减少过程阻碍误写成降低证据真实性要求？
- 是否仍然需要模型为了字段而反复调用结束工具？
- 是否有图谱发现真正改变了判断，而非只增加了节点和篇幅？
- 是否能区分观点转述、直接证据、系统综合和待验证假设？
- 是否把未完成的用户核心要求保存下来，而不是从结论里删掉？
- 是否把执行终态、实际交付和知识写入验收混成一件事？
- 是否仅通过改名制造“完成”，没有解决后台循环？
- 是否为当前问题增加了用不到的平台、类型或长期维护负担？
- 是否完成了同版本知识与模型下的真实回归，而非只看测试通过？

本设计的成功标准是：用户更早得到有用且诚实的回答，能随时改变讨论方向；模型更少为流程过关而工作，同时在来源、范围、反证和不确定性上比原来更严格。
