# 无 Buffer 聚合编译实验记录

## 当前范围与假设

本次处理金融底座 Inbox 冻结的 13 份图书/论文。由当前 Codex 和获用户授权的三个子助手完成语义阅读与复核，主助手统一裁决知识落点，通过 HarnessGateway 写入。不调用项目 DeepSeek API，不调整 Profile，不把这次实验当成 Web 统一入口已实现。

用户明确要求不用 Buffer，并允许为未来统一编译入口灵活实验；同时明确废除“优先丰富已有卡”。本轮以知识对象身份、解释完整性、独立复用价值与承载负担选择新建或修订，必要时拆分、合并或保留可追溯来源。新卡数、旧卡吸收率与连边率都不是优化目标。

关键假设：先保存按问题组织、包含多个来源对象的聚合档案，再决定各对象的卡片去向，可以减少“先找母卡再塞内容”和“一书一批孤立卡”。这是待实际结果检验的假设，不是已经证明胜过旧流程。

## 本次实际实施

- `03-Archive/aggregates/<topic>/<dossier>.md` 保存可独立阅读的聚合档案。主题是组织入口，不是论证节点；不新增卡片类型。档案可跨书，也可保留单书独有贡献，不强求每项都是多书共同结论。
- 档案中的稳定来源对象只声明一次；不同主题和卡片引用同一对象，不复制出多份语义真相。对象保留作者问题、机制/证据、条件、不同意见、真实页码或 EPUB 位置，以及当前知识去向。中间对象与 Card 不要求一一对应。
- 新增 `HarnessGateway.commitAggregationDocument`，只写上述目录中的档案或覆盖账，检查实际来源指纹、对象声明与修订版本，保留 Journal 和失败回滚。它不判定模型已经充分理解来源，也不按字数或卡数证明质量。
- Card 继续通过现有单层写入与关系裁决能力落盘；采用局部建构任务承载已读来源的知识接入和复验。这些局部任务完成不代表整批图书编译完成，整批另由来源、对象、卡片去向总账验收。不开空的旧主题编译任务，也不伪造旧 Buffer 覆盖记录。
- 复用已有 Gateway 归档事务，它本就接受 Archive Markdown 来源；实验总账通过后才调用。兼容参数名 `chapter_sources` 在此传聚合来源档案，不宣称生成了旧章节来源格式。原书及聚合档案来源引用一并迁移，卡片引用稳定的聚合对象锚点。
- 修正 Archive 来源锚点精读：精确读取对象章节及其子节，并明确返回锚点是否找到。此前正则可能只返回标题，或找不到锚点却不揭示回退；本次增加针对性回归。

Markdown 是事实源。`.nexogenesis/unified-compile-20260908/` 只放提取缓存、候选草稿、读取记录、快照和可重建验收数据，不把仅存 JSON 的独有知识当作完成沉淀。

## 原书阅读与验收

先核实每书版本、作者及真实章节结构，再读正文并识别自然知识对象。提取全文不等于阅读；目录、绪论或结论不能代替未读章节。图片、表格和数学式在影响结论时回看原页。第二次查漏从不同原书入口开始，保留实际新增对象与误读修正，不把同一模型的自检叫作独立实验。

整批收束需要同时核对：13 份原件版本；各实质章节的阅读和处置；所有已识别重要对象的实际 Card 去向或有理由的依附保留；独立对象是否被大卡吞没；新增卡是否经比较后建立真实关系或有理由独立；来源锚点能否从卡片回查；Buffer 与 Profile 是否保持不变。未解决的重要阅读缺口不能以“非核心”排除并宣称完整完成。

## 已观察到的摩擦

1. Metrick–Yasuda 原件 575 物理页，按全文换页符拆分却得到 593 段。已改为逐物理页提取并保留错误缓存用于追溯，不用错位页号引用原书。
2. `lucas76.pdf` 为 14 页、每页两页书页的旋转扫描件。已全文视觉复读 *Econometric Policy Evaluation: A Critique* 并反向核对脚注；末页夹带另一论文的导言，不包含其完整实证结果。OCR 空白不等于材料没有价值。
3. 首轮聚合样本把网络效应、采用均衡、识别方法和兼容政策分开；把房地产四象限均衡与信用反馈分开；把 VC 董事参与配置与投资绩效因果效应分开。样本显示对象边界值得比较，不构成整批质量结论。
4. 部分书内 OCR、公式符号及历史统计口径本身存在问题。已要求逐项保留证据边界，禁止用作者叙述补猜丢失的数值或系数。
5. `lucas76.pdf` 与旧主题来源正文记载的原扫描指纹一致，已经有三张直接承接卡。本次应复验已有知识而非默认重编；原页复读发现消费与投资机制尚未充分展开，旧菲利普斯模型还把信息提取混写为工资价格调整。仅文件名和 Inbox 状态不足以决定“新材料”。
6. 首个四象限模型实验已完成：五个来源对象先存一份聚合档案，其中三个形成一张新模型卡，另两个保留明确待办；新卡的一条关系只支持旧卡的收益资本化环节，不背书其全部信用反馈。原生局部任务已完成，但整批仍进行中。
7. `knowledge-organization` 运行时会要求新卡也先建立局部计划，与 Skill“不是新建卡要求”的文字存在不一致。实验保留保护并建立计划；计划内未改动的结果卡也必须写后完整复读。第一次验收据此未通过，恢复只补复验，没有重放成功写入。后续应在计划回执提前明示复读集合，而不是到结束才暴露要求。
8. 卢卡斯局部编译已完成：复用六个旧来源对象，新增消费信息结构与投资抵免转售机制两张模型，修正规则评价和菲利普斯信号提取两张旧卡，保留预期总括卡；新增三条真实关系并移除一条只以共有限制解释的弱扩展边。原扫描已通过事务移至 Archive，指纹保持不变。这是第一份完整材料的局部闭合，不代表其他十二份完成。
9. 局部计划已经包含问题、替代方案和操作对象，写入前仍要求另在 `candidate_actions` 声明意图。工具总 schema 又允许某些仅其他模式支持的 workspace 扩展字段，construct 实际拒绝。应让已保存计划可作为意图证据，并输出当前模式专用 schema；不是删除计划或授权检查。
10. 多条关系分别模拟后，实际写入只接受最新一次模拟，不按关系案件保存可提交裁决。本轮恢复时逐条重新模拟后立即提交。近期可选择明确披露“单一当前裁决”，或保存带端点/卡片修订指纹的案件级裁决；不能仅凭过去曾模拟就越过版本检查。
11. 实际卡片追溯发现旧 `05-Buffer/...md#obj-...` 将片段名误当作文件名，错误报告来源不可用。已修正为文件与对象锚点分开解析，复用子节精读并返回 `anchor_found`。这是确实影响旧库可用性的缺陷，不是图谱知识本身丢失；原 Buffer 文件未改动。
12. 同一篇论文的来源卡仍被统一规则要求同时出现作者原意、跨书综合、系统推论三个声明。当前补入真实说明，没有伪称跨书研究。未来应根据实际来源与推论角色检验归属，避免把固定词语出现当作语义分离的充分证据。
13. 家庭配置第一组已形成两张独立新模型并修订一张同对象旧卡，新增三条前提/机制细化关系、移除一条泛家庭主题扩展。它说明“新建还是修订”应按对象职责裁决，而不是优先选某一种；同一主题可以同时需要两种操作。
14. 独立助手的有界抽核确实发现根助手遗漏的数学前提：重复投资的风险容忍凸性比较使用零净无风险利率；同一章节的消费分摊CRRA结论却允许一般确定毛收益。已按原页回读同时补正卡片和聚合对象，没有把修正错误扩散到正确公式。交叉复核应针对关键假设和可复算式，而不只检查格式、字数或引用数量；关键推导组应等待这种复核再关闭局部任务，本轮过早关闭使补正另开了一次明确范围的修订，属于可避免的流程成本。
15. 参数 schema 查询脚本会初始化局部运行并冻结卡片范围。因此应先完成对象发现和候选范围再开始可写任务，纯工具 schema 探查不宜有运行初始化副作用。本轮发现的背景风险旧卡留到下一明确小组修订，没有修改被冻结范围外的旧卡，也没有重新命名任务绕过失败或预算。

16. 家庭参与与测量组已新增固定入市费用模型、家庭组合统计方法，修订背景风险和参与边际两张旧卡；初始两条有依据的 `based-on` 与新卡一起通过原生写入，另增加背景风险对人力资本的机制扩展并删除泛主题边。新建允许携带已审查关系，不必先造孤立卡再逐条补边。该组四个对象闭合，整书其余内容未完成。
17. 根助手把计划中的“必须保留原句”选成准备纠正的过宽断言，导致首次修订被保留检查拒绝。应选择真实需要保留、且仍成立的知识片段；精确文本保护不是语义等价判断。本次没有删除保护或重置运行，而是保留旧句并明确其线性套保/候选原因语境。未来计划应允许明确声明需纠正的旧命题及证据，与保留项分开。
18. 第二次拒绝来自来源角色的固定措辞：`跨章综合`不被识别，改为准确的`跨来源综合：在本书不同作者章节之间`后通过。通用提交脚本现先展开内容补丁做只读预检，减少进入正式提案才发现格式门槛的反复。该改动不证明语义已正确，也没有放宽质量规则；后续应以真实归属和推断范围替代仅匹配词串。
19. 已读国家章节出现同名资产桶、家庭均值与财富加权份额不一致；方法卡明确区分参与率、条件家庭份额、参与者财富权重，并处理零参与与负净财富。背景风险卡同时保存意大利符合观察及荷兰未确认结果，不只吸收支持模型的章节。荷兰ESSP表中收入系数与正文符号冲突经原页视觉确认，未修成模型偏好的结论。

20. 后续三张生命周期方法使用“候选有界交叉复核—只读预检—含真实初始关系的创建”，写入没有拒绝。年金公式补充折现、给付和存活的联合状态条件；回测工资从“末年放大”纠正为整条工资轨迹统一放大。独立复核定位关键前提，而非每页机械重读，能产生实际质量增益。
21. 来源追溯参数`limit`即使传30也被当前实现封顶8。已改为逐条显式查询每张卡声明的聚合来源；此轮24张已变更卡共93个聚合锚点均能找到。默认预览是注意力窗口，不是覆盖验收，界面和工具应分别呈现“预览几条”和“尚有几条未验收”。
22. 计划阶段又出现两个可在提交前发现的确定性错误：漏列保持不变的参照卡去向、保留原句少于8字。都在原运行内修正，未绕过保护。临时准备脚本现先检查每张源卡是否有真实8–500字保留片段与计划内结果，避免将这种机械问题反复交给可写模型纠错。此检查只是本次脚本，不宣称已升级Web运行时。
23. Household Portfolios第二入口复读章注发现两个需要保留的方法对象：异质主体均衡的财富分布近似，以及逐变量唯一解不保证联合迭代收敛。不能将首遍对象清单冻结成终局，再把第二遍发现当超范围。当前该书134对象是阅读结果，不是Card配额或已编译完成数。
24. 同一理论中的三个问题不能共用一个模糊条件：跨期限重复投资的零净利率前提、固定总财富下CRRA消费分摊的一般确定利率、同期限信息比较的独立机会结构。后一项由第二次有界复核指出，已同时收紧预测卡及来源对象；不机械将第一次纠错条件复制到所有相似公式。
25. Lifecycle Investing已成为第二份完整闭合材料：20对象验收后归档原件，指纹不变，带来6张新卡和2张同对象旧卡修订，另参与跨书理论区分。按材料计算的贡献有交集，不能将各书统计相加冒充全批唯一卡数。截至此检查点全批18张新卡、6张旧卡修订；其余11份未闭合材料继续处理。
26. Household Portfolios税收章的11对象没有生成11张卡，而以6张模型/方法承载状态风险分担、账户位置、实现时点、因果识别、税收客群和中介服务。历史税率表、未核细系数与错误原句保留可回查来源，不做过时税务百科；英国和荷兰对象又补资格、锁定与产品替代边界。此组是根助手审查，不冒称独立模型评测。

27. 根助手在三书聚合发布时误给The Venture Capital Cycle添加“第二版2004”标签；随后直接复读原件物理1–3确认本批实际为1999、ISBN 0-262-07194-0，已通过Gateway逐档修正，未改原文页码与对象内容。Metrick原件版权2011而CIP含2010，已区分。版本标签必须来自原件版权页并随来源指纹冻结，不能靠记忆补入，这是本轮真实失误而非原书错误。

28. 天使治理与筛选组出现两次准备阶段的确定性错误：只有一张旧参照卡却调用最少两张的比较工具；三张新卡加四张参照卡超过局部计划六个结果对象上限。没有卡片被写坏，均在原运行恢复。临时准备脚本已增加数量预检、单卡跳过比较。后者通过缩小为三张具体关系参照解决：样本选择方法仍作已读比较，不增加仅有抽象方法意义的跳边。未来不能把检索过的所有近邻都自动算作待验收结果，也不能为了固定上限删掉真实必要的关系；必要时应拆开独立写入组。

29. 候选格式适配脚本曾给已带语义单元标记的章节重复插入标记，造成只读预检报告空单元。这里是根助手脚本制造的错误，不是知识内容缺乏，也不是Harness过紧。已改为只有原章节没有标记才补入，并在原运行重新预检通过；成功步骤不重放。后续确定性执行应在前一步成功后才继续验收，避免无意义的“缺收据”次级报错。
30. 根助手给私募绩效卡补入候选遗漏的来源时，手填了存在但不包含该对象的聚合文件名。当前写入检查接受文件，最终逐锚点验收准确拦住；已在同一运行经来源事务修正，没有修改正文或重复新建。准备脚本现在提交前就核对精确对象标题，候选适配器支持按已冻结对象映射追加来源，避免手写所属档案。文件存在、引用数量多和默认追溯预览均不足以证明来源闭合。
31. 实际审查也发现候选层会遗漏可用知识：反稀释候选只有机制概括而未载入已核验转换价算法，融资权利和私募绩效正文使用了未列元数据的对象，DPI文字还容易被理解为全是现金。根助手分别补计算变量与条件、真实锚点及实物分配口径。未来验收需检查对象内的机制、算法、证据和边界是否真正被承载，不能仅凭“每个对象映到一个候选文件”判定充分。

## 验证、成本与撤回

`tests/aggregation-experiment.test.mjs` 已通过来源指纹、重复对象、修订冲突、精确追溯、失败回滚、无 Buffer 归档兼容及取消 enrich 默认偏好的测试。连同既有主题编译与摄入闭合的最新定向运行共 13 项通过。上述是确定性验证，不是 Web 模型质量测试，也不是知识召回率测量。

新增维护范围仅一个 Gateway 方法、Archive 与旧主题 Buffer 的锚点精读修正及相应测试；未新增 Web 页面、独立写入器或自动学习系统。若实验效果不佳，可以停用该方法，保留可读 Markdown 和原书，现有追溯仍可访问归档来源。删除代码不损失知识；已写卡不能随代码回滚自动删除，应按收据和快照另做受控修订。
