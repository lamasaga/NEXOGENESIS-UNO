# 2026-08-31 版本管理与多知识实例切换设计

> 状态：下一阶段设计与实施边界，尚未实现  
> 核对日期：2026-08-31  
> 目标：把通用程序与领域知识实例可靠分离，并在此基础上逐步支持一个 Web 使用多个知识实例。

## 一、为什么现在需要整理

  当前 `NEXOGENESIS-DSH` 同时承担两种职责：一方面保存 Web、Agent、GraphOps、Harness、Skill 和通用模板；另一方面，运行时默认从同一个根目录读取 `00-Inbox/`、`01-Cards/`、`05-Buffer/` 等知识内容。Git 已经通过忽略规则阻止实际知识目录进入核心提交，但“代码在哪里”和“知识实例在哪里”在运行配置中仍是同一个 `projectRoot`。

  这不会立即造成数据错误，却会带来三个已经可见的限制：纯净版本依赖额外排除规则；领域材料和通用代码容易在提交时混淆；Web 只能绑定一个固定知识根目录，无法安全切换其他知识图谱。

  本设计不要求立刻重写运行时。下一阶段先建立清晰边界和单实例外置能力，经过隔离验证后，再增加 Web 切换入口。

## 二、统一术语

| 名称 | 含义 | 是否独立 Git 管理 |
|---|---|---|
| 项目仓库 | NEXOGENESIS-DSH 的通用代码、规则、模板、测试和通用文档 | 是，可公开 |
| 知识实例 | 一个具体领域的 Cards、Profile、Buffer、Archive、Journal 等内容 | 是，通常私有 |
| 实例根目录 | 运行时读取某个知识实例的文件系统根路径 | 属于知识实例仓库 |
| 本地运行状态 | 会话映射、任务断点、缓存、索引、临时文件和密钥 | 否，不进入 Git |
| 纯净发行版 | 只包含通用程序，不包含任何领域知识、真实回归案例或领域评测材料的发布物 | 从项目仓库生成 |

  “项目仓库”和“知识实例仓库”是两个真正独立的 Git 仓库，不是同一仓库的两个分支。分支共享对象历史，不能充当发布或隐私边界。

## 三、当前事实

### 3.1 Git 状态

  当前版本基线位于 `D:/UESR/Desktop/NEXOGENESIS-DSH`，核心标签为 `dsh-core-baseline-20260831`。实际知识目录和 `.nexogenesis/`、`tmp/` 已被核心 Git 忽略，提交前边界测试会阻止这些目录被误跟踪。

  金融经济评测资料和真实回归案例与真实知识图谱同属领域知识资产，不属于纯净发行版。当前标签归档已经通过 `export-ignore` 排除它们；在公开项目仓库之前，应把它们迁移到私有知识或评测实例仓库，而不是长期依赖公开仓历史中的排除属性。

  原有 `Nexogenesis-org` 与 `NexogenesisV1.6org 金融2` 是仍然存在的独立旧仓库，本设计不删除、不合并也不改变它们的远端配置。

### 3.2 运行时耦合

  当前 Web Host 配置只有一个 `projectRoot`。图谱、Cards、Inbox、任务状态和 Harness 写入都从该路径读取；新建 DSH 会话时也把它作为 `cwd`。`patch/cordis.patch.yml` 与 `presets/nexogenesis/agent.cordis.yml` 还直接写入了当前机器上的绝对路径。

  因此，当前版本只能可靠地运行一个固定实例。更改根路径并重启服务可以形成手工切换，但尚没有实例登记、兼容性检查、切换事务和前端状态清理机制。

## 五、版本管理方案

### 5.1 项目仓库

- `main` 或现有稳定分支保存可运行的通用程序。
- 功能分支只处理代码、通用契约和通用测试。
- 确认版本使用带说明标签，例如 `dsh-core-baseline-20260831`；以后决定采用语义版本时再统一命名，不在本阶段强行改名。
- 纯净发布必须从已确认标签生成，并运行仓库边界测试。
- 项目仓库不得用其他分支保存真实知识实例，因为其他分支和历史对象仍可能被克隆或误推送。

### 5.2 知识实例仓库

- 每个需要独立授权、备份或演进的领域使用独立私有仓库。
- 稳定分支保存当前可用知识状态；实验分支可用于关系迁移、领域重构或评测前快照。
- 重大消化、建构或迁移前打实例标签，便于比较和恢复。
- 实例清单记录最近验证过的项目标签与知识格式版本，但不自动宣称兼容所有新项目版本。
- 项目升级若需要知识迁移，应先在实例分支执行并验证，不直接修改稳定分支。

### 5.3 知识实例中哪些内容进入 Git

| 内容 | 建议 | 原因 |
|---|---|---|
| `01-Cards/`、`02-Profile/` | 跟踪 | 核心语义事实 |
| `05-Buffer/`、`06-Journal/` | 跟踪 | 当前体系中的来源、贡献和操作追溯 |
| `03-Archive/` | 跟踪或使用 Git LFS/外部存储 | 需要来源追溯，但二进制材料可能很大 |
| `00-Inbox/` | 按实例政策决定 | 未处理原料可能很大或受版权、隐私约束 |
| `04-OutBox/` | 只跟踪需长期保留的正式产物 | 临时导出可重建 |
| `07-Conversations/` | 默认私有，可按需跟踪 | 可能含个人信息和过时上下文 |
| `.nexogenesis/`、`tmp/`、索引与缓存 | 不跟踪 | 本地运行状态或可重建产物 |
| API Key、DSH 凭据 | 永不跟踪 | 机器级秘密 |

  当前 `.nexogenesis/` 中若存在必须长期保存的贡献结算或治理事实，不能简单依赖缓存目录。实施拆分前要逐项确认：真正属于知识事实的记录迁入受控 Journal 或其他现有持久目录；纯运行状态继续忽略。本阶段不为此预建新的账本体系。

### 5.4 最小实例清单

  每个实例拟增加一个可跟踪的 `nexogenesis.instance.yml`，只保存稳定身份和兼容信息，不保存本机绝对路径、密钥或运行状态。

```yaml
schema_version: 1
id: finance
name: 金融经济知识实例
knowledge_schema: 1
tested_core: dsh-core-baseline-20260831
```

  本机路径由用户级登记表保存，例如 `%USERPROFILE%/.dsh/nexogenesis-instances.json`。实例仓库中的清单回答“我是谁”，本机登记表回答“我在这台机器的哪里”。

## 六、运行时边界设计

### 6.1 拆分两个根路径

  当前单一 `projectRoot` 应拆成两个职责明确的配置值：

| 配置 | 职责 |
|---|---|
| `appRoot` | Web dist、preset、Skill、通用模板和工具代码所在位置 |
| `instanceRoot` | Cards、Buffer、Archive、Journal、任务状态和实例会话工作目录 |

  GraphOps、Harness、Inbox、Pipeline 和认知运行只接收 `instanceRoot`；静态页面和通用 Agent 能力只从 `appRoot` 加载。DSH 会话可以以 `instanceRoot` 为工作目录，但 Skill 目录必须继续显式来自 `appRoot`，不能要求知识仓复制一套程序文件。

### 6.2 第一版只支持单一活动实例

  第一版 Web 切换采用“一个服务进程、一个当前活动实例”。它不是多租户系统，也不允许两个实例的任务同时运行。这个范围足以解决个人使用中的知识图谱切换，同时避免引入账户、权限组或跨实例调度。

### 6.3 本机实例登记

  后端只接受已经登记并通过校验的实例根目录。登记时至少检查：

- 路径解析后的真实位置稳定存在。
- 存在合法的 `nexogenesis.instance.yml`。
- 实例 id 在本机登记表中唯一。
- 必需目录可创建或已存在。
- 路径不是项目代码目录、系统根目录或另一个实例的子目录。
- Web 请求只能提交实例 id，不能直接提交任意文件系统路径。

## 七、Web 切换流程

### 7.1 页面表现

  顶部或侧栏显示当前实例名称，并提供一个克制的实例选择器。选择器展示实例名称、基本状态和最近打开时间，不暴露完整本机路径。空白实例应显示正常的空状态和初始化入口，而不是错误页面或伪造种子知识。

### 7.2 原子切换步骤

1. 用户选择目标实例。
2. 后端确认当前没有运行中的编译、消化、建构、写入确认或未完成交互。
3. 若仍有活动任务，返回明确冲突状态，要求用户先停止或完成；不得静默取消。
4. 校验目标实例清单、目录和兼容版本。
5. 将当前活动实例一次性切换为目标 `instanceRoot`，并增加实例世代号。
6. 前端丢弃旧实例的图谱、Cards、Pipeline、提案和认知投影缓存。
7. 重新读取目标实例的概况、图谱、固定任务线程和当前状态。
8. 页面明确显示新实例名称，后续写入只允许落入该实例。

  每个请求在开始时捕获实例 id 与世代号；切换后返回的旧请求结果必须被丢弃，不能覆盖新实例页面。这一约束用于解决异步加载造成的跨实例视觉污染。

### 7.3 必须隔离的状态

| 状态 | 隔离方式 |
|---|---|
| Cards、图谱、Buffer、Archive | 位于各自 `instanceRoot` |
| 图布局、索引、任务断点、贡献记录 | 位于实例自己的 `.nexogenesis/` |
| 固定编译/消化/建构线程映射 | 按实例 id 分开保存 |
| 普通对话与认知运行 | 创建时绑定实例 id，之后不得跨实例继续 |
| 待确认写入和交互 | 绑定实例 id 与内容版本 |
| 模型供应商和 API 凭据 | 机器级共享，但不携带知识状态 |
| Web 组件临时状态 | 切换时清空并重新加载 |

## 八、近期实施顺序

### 阶段 A：外置单实例

1. 删除 preset 与 patch 中对当前机器项目路径的硬编码，改由启动器生成或注入 `appRoot` 与 `instanceRoot`。
2. 让现有 Web Host、tools、GraphOps 和 Harness 全部从 `instanceRoot` 取知识数据。
3. 提供空白实例初始化命令或脚本，只创建目录和实例清单，不写入示例卡片。
4. 分别用金融实例和空白实例启动服务，验证 Git 状态与写入路径。

### 阶段 B：登记与后端切换

1. 增加本机实例登记表及最小读写接口。
2. 增加获取当前实例、列出实例和切换实例的本机 API。
3. 切换前检查活动任务、待确认写入和实例兼容性。
4. 所有运行、会话映射和待确认对象补充实例归属校验。

### 阶段 C：Web 选择器

1. 显示当前实例并提供选择器。
2. 实现切换中的加载、阻塞原因和失败恢复状态。
3. 使用实例世代号阻止旧请求回写新页面。
4. 为两个实例往返切换增加前后端回归测试。

### 本轮暂不做

- 不支持多个实例同时运行任务。
- 不在 Web 中创建或管理 Git 分支、提交和远端。
- 不把知识实例做成 Git Submodule。
- 不增加账号、多用户权限、云同步或实例市场。
- 不自动迁移旧仓库，也不删除现有 `Nexogenesis-org` 和金融实践仓。

## 九、验收标准

### 9.1 版本边界

- 纯净项目归档不包含任何 Cards、Buffer、Archive、Conversations、真实回归案例或金融评测资料。
- 在金融实例中执行消化或建构后，只有金融实例仓库出现知识变更，项目仓库保持干净。
- 修改 Web 或 Harness 后，只有项目仓库出现代码变更，实例仓库不复制程序文件。
- 项目和实例可以分别提交、打标签、回退和配置远端。

### 9.2 单实例外置

- 同一份项目代码可以分别以金融实例和空白实例启动。
- 空白实例显示零卡片的正常状态，且编译入口可用。
- 所有写入、断点、索引和日志都落入当前实例，不回写项目仓库。
- 删除项目仓中的本地知识目录后，外置实例仍可完整运行。

### 9.3 Web 切换

- 从金融实例切到空白实例后，页面不残留金融节点、卡片、候选、对话或任务状态。
- 切回金融实例后恢复其自己的状态，不复用空白实例会话。
- 活动任务、待确认写入或未完成交互存在时，切换稳定返回可理解的阻塞原因。
- 非登记路径、重复 id、无清单目录和不兼容实例均被拒绝。
- 快速连续切换时，旧请求不能覆盖最后选择的实例。

## 十、迁移原则与撤回方式

  迁移先复制验证，再改变默认路径；不直接移动或删除旧仓库。金融知识实例完成独立启动、读写和 Git 状态验收前，当前目录保持可运行。任何自动迁移都必须先形成可恢复标签或备份，并对文件数量、内容指纹和关键目录做前后核对。

  阶段 A 若验证失败，只需恢复单一 `projectRoot` 配置，不改变知识 Markdown。阶段 B、C 的登记表和选择器属于外层接线，撤回时仍可通过启动参数指定一个实例，不应要求回滚或重写知识内容。

  这项工作的完成标志不是“出现一个切换下拉框”，而是项目 Git、知识 Git、运行状态和 Web 当前上下文四者拥有可验证且不会串写的边界。
