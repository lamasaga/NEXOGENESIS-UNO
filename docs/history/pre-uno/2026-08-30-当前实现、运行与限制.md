#### 行为与约束

| 环节 | 已实现行为 | 不代表什么 |
|---|---|---|
| 进入分析 | 宿主记录本次用户请求、admission 与真实 DSH turn；Run 冻结 `analysis_policy_version` | 模型或客户端不能用 Workspace 参数自行开启豁免 |
| 方法选择 | v2 不把 TM 配额、特殊 OPS、最少阅读数、固定跳数或复盘字段作为完成门 | 不削弱实际阅读、证据版本、预算和知识写入保护 |
| 关系推理 | 提示主动检查隐藏前提、竞争解释、边界、桥接和机制接合，复用现有 OPS | 不是新增图推理算法，也不保证每题均能产生洞见 |
| 准备回答 | `finish_cognitive_run` 一次检查引用与证据结构；保留缺口并返回 `prepared` | 工具成功不等于答案已交付，不认证最终全文 |
| 重复收尾 | 相同输入及证据快照复用结果、不重复记录步骤；耗尽普通预算后最多容许三次不同准备检查，已发生次数计入上限 | 不承诺供应商额度耗尽后仍可生成完整答案 |
| 新证据或插入 | 判断、引用角色、用户要求、冲突、延期、pending 等实质变化使准备快照失效；正文版本参与核对 | 不重置原预算，不用新 Run 偷换本题目标 |
| 回合结束 | 正常结束记 `closed`；另按持久化最终正文确认 `delivered` | `closed` 不是知识验证成功或研究完成 |
| 恢复对账 | 在线先等待原生 `sessions.flush`，再用 `sessionPersistence.readFrom` 读取物理事件；冷会话同样只读核对 | 内存 history、流片段、隐藏推理、工具 finish 声明不充当持久答案 |
| 自由追问 | 新消息按新 admission 接收；即使直接回答、不创建 Run，也能正常结束流 | 不复用旧题预算，不把旧题完成度当新题完成度 |
| 待答与暂停 | 保留实际待答；回答前验证原 Run 并恢复合法状态，先保存要求再消费答案；投递失败保留恢复记录 | 不用“先交付”绕过用户决定，也不重放知识事务 |

  没有 finish 而实际交付了正文，覆盖度仍为 `unknown`。正常结束但无法确认持久化正文时，只显示本轮结束/交付待确认。取消或失败片段不能显示为完整交付。没有正常结束记录、但下一问题已经开始时，旧运行隔离为失败而不是猜测完成。旧 blocked 普通分析不再仅凭状态声称“已形成回答”。

  阅读和路径核验只认证可确定的来源事实。无效锚点不会授予已核验标记；与原请求相关的未完成项不能因为降低方法要求就消失。声明 `answered` 但存在核验限制时下调为 `partial`。源码保留作者立场、时间/地区/样本边界、同源与代理关系提示；是否真正遵守仍须审阅模型正文。

#### 关系如何进入答案

  `relation_findings` 是可选公开结果，不是隐藏思维链或新的每轮表格作业。每项含 `claim_id`、实际访问的 `path`、正文 `anchors`、`finding`、`conditions` 和 `outcome`。结果可以是接合、缩小结论、竞争解释、未改变、拒绝接合或仍不确定；放弃不相容的组合也是有效发现。

  当前核验匹配本轮真实 `graph_walk` / `graph_path` 的有向关系记录，检查现行卡片上的关系类型与说明，并要求路径各节点具有同一判断下的有效正文或 unit 阅读锚点。未匹配、缺读或关系已变化时标为 `unverified`，不显示成已采用的可回查路径。方向是关系的声明方向，不自动转换成因果方向；路径真实也一律保留 `model_synthesis_not_certified`。

  前端在答案下展开“关系如何影响判断”，显示关键路径、条件、采用或拒绝理由，核验通过的卡片可以打开。原有图动画继续来自实际工具事件，本轮没有增加动画强度、伪造推导事件或重写图遍历器。其他 OPS 的探索仍保留在 Episode，不伪装成已经支持上述路径核验。

### 2026-09-07 思考入口、建构讨论与消息插入

  侧栏新增“思考”准备面板，提供深入理解、比较解释、检验判断、形成报告四种目标及按问题决定/标准/深入三个深度选项；正式开始才创建普通对话。新对话仍直接自由交流。思考与建构记录进入普通聊天列表，建构保留原任务标记用于兼容，不把它作为永久的聊天模式。准备取消不丢原草稿，不同会话的草稿在当前页面内分别保留。

  建构对话支持“暂停并讨论 / 讨论结果”和“返回并继续建构”。暂停复用 DSH 的 session.cancel，等待宿主确认会话不再执行后才切换；不把取消请求返回当作已安全切换。已提交事务保留，中断工具的结果不能凭空视为成功或直接重试。原建构 Run、冻结范围、累计用量和待办保存在原处，宿主独占的 `.nexogenesis/cognition/session-discussions.json` 记录讨论对应的建构运行。讨论使用同一 DSH 对话中的独立 general/assess/report Run，并由 Runtime 强制禁止知识写入或提案；模型不能通过改 Workspace 或新开 construct Run 取消这一保护。恢复明确回到原 Run，有旧确认/问题时先恢复待办而不是自动执行。已验收的建构允许直接追问，但不能作为未完成任务再次续跑。

  暂停中的原确认、原生问题和续跑不能投递到讨论 Run；停止讨论也不撤销原建构提案。讨论期间要求保存知识，需先回到原建构或新建明确授权的对话，当前不在暂停讨论内开放捕获写入。不同会话仍隔离，当前只将建构纳入这种讨论切换，编译/主题编译/消化的终态与恢复规则保持原状。

### 2026-09-07 图谱作用力调节

  图谱左上角提供低对比的调节图标，默认收起；展开仅显示集中引力、节点斥力、连线吸引力三个滑块名称和数值，不加说明文字。统一使用0～4.0、步长0.1，0关闭对应力、1.0为默认。集中引力按数值的1.5次方增强；斥力和连线吸引力按2的数值次方减1增强，连线吸引力调高时同步缩短平衡长度，使三个滑块都有可见影响。恢复默认将三项还原为1.0，并从当前坐标重新调整；实体碰撞约束始终保留。

  前后端共用力计算与邻域碰撞校正；浏览器使用更快的移动参数和220轮计算，每6轮返回预览，继续调节会取消旧计算并从当前画面接续。参数、节点坐标和缩放平移视角按实例保存于当前浏览器；完成后的布局在图谱结构未变时直接恢复，不重复移动。中途关闭会保存进度并在重开时从保存位置继续；节点或关系变化才重新校正，标题或后台坐标刷新不清空用户布局。计算状态仅提供给读屏工具，失败时提供重试图标，不修改卡片、关系或后台坐标缓存。清除浏览器存储后偏好与布局需要重新建立；此前版本未保存的调整坐标无法补回。刷新前端即可加载新版；验证与回退见[图谱布局与拖动优化](../../2026-09-06-图谱布局与拖动优化.md)。

### 安全与数据完整性基线

- 所有改变状态的本机 API 都要求精确同源、本进程短期令牌和预期 `Content-Type`；不同端口不视为同源。
- Nexo API 只能访问项目 metadata 已登记的 DSH 会话；认知运行 id 只接受 UUID，并在存储层再次检查路径范围。
- Card 和 Buffer frontmatter 由 `yaml` 库生成与解析；写入前拒绝控制字符，Card 在替换前执行“对象 → Markdown → 对象”深比较。
- Inbox multipart 按字节解析，上传内容不经过文本往返；同名、大小写或文件名清洗碰撞返回冲突，不覆盖原材料。
- EPUB 设有条目数、单条目大小、解压总量和压缩倍率上限；Poppler 子进程设有超时、输出上限和超时终止。
- 来源正文和 Buffer 在工具返回与 compile/digest 提示中明确标为不可信分析材料；这能约束指令边界，但不能承诺识别所有语义提示注入。

## 三、编译

  当前编译可列出 Inbox，为纯文本、Markdown、常见 EPUB 和有文本层 PDF 建立有限索引，再由 Agent 按需读取片段、写入 Buffer 并检查覆盖。EPUB 按 spine 顺序提取 XHTML；PDF 按页保留来源位置。用户在 Web 选择一份材料后，该次任务只处理这个冻结版本。

  2026-09-05 的摄入闭合调整：来源索引支持分页，短定义和反例不再因不足 80 字符而消失；实际阅读按来源及指纹合并区间。编译与主题编译共用 retained/excluded/deferred 去向审计，核对完整索引、已返回正文与本轮实际产物，而非接受覆盖 ID 声明。重要内容延后会阻止完整完成和归档；原件变化要求新任务核对，产物变化要求重审去向。主题整体审计绑定原件、章节、总账、矩阵和 Card 版本，不能在更新后继续使用旧通过结果。

  上述检查能够发现未读取位置、无去向材料和过期验收，但不能证明模型已经理解或准确保留全部思想。一般来源篇幅不足、知识点占比偏低改为可见提醒；明显空薄、缺语义角色、宽范围薄摘要和重复模板仍阻断，不能为通过字数检查扩写。来源到 Card 的实际语义贡献仍需原文抽查。

  主题编译的语义执行器由入口决定：Web 端使用设置中当前选择的模型服务；Codex 端由当前 Codex 直接完成文本处理，不应另行调用项目配置的模型 API。两条入口共享 HarnessGateway、`05-Buffer/themes/` 来源层和相同验收规则。当前章节来源写入已要求真实章节覆盖、自然命名关键知识点及其命题/机制或证据/边界/定位；最终验收还会阻断宽范围薄摘要、长页段低信息覆盖和主题内重复模板段落。卡片默认受限追溯会把通过 `theme-source-v2` 的章节来源排在历史来源之前，以免前三项读取窗口被旧薄摘要占满；显式指定来源时不改变用户选择。

  跨书矩阵现在必须包含 Markdown 形式的“知识对象覆盖审视”。它提醒模型同时检查共同主干、单书或少数来源的独立贡献、理论/方法/证据差异，以及重要对象被丰富、新建、并入证据、合并、延后或排除的理由；不使用 JSON，也不按来源知识点数量分配卡片。启发式审计会把代表性知识点触及偏少、单书对象讨论不足和计划—落卡未对齐作为 caution 回送模型，但允许模型在有充分理由时保留现状。完全缺少覆盖审视、没有任何处置判断，或明显只找共同点且几乎未触及来源知识对象时才阻断。

  主题 warning 的运行语义已经统一：Harness 预检产生的 warning 会随写入结果返回模型，最终验收只阻断 `error`，不再把全部 `caution` 伪装成硬失败。无阻断但仍有提醒时状态为 `ready_with_cautions`，可以完成任务，但验收报告应披露提醒与保留理由。

  编译完成必须同时满足：存在有效 Buffer、覆盖审计通过、来源锚点可迁移、任务以 `completed` 收尾。满足条件后，Harness 将源文件从 `00-Inbox/` 移入 `03-Archive/`，并把新 Buffer 的来源更新为归档路径。归档处存在同名异内容文件时追加内容指纹，不覆盖旧材料。

  失败、阻塞、暂停、无有效 Buffer 或来源迁移失败时，源文件继续留在 Inbox，任务不能误报为完整完成。

### 已有保护

- 材料指纹用于区分版本和查找同一版本断点。
- 用户明确选择继续后，可以恢复已读位置、覆盖清单和已写 Buffer 记录。
- PDF 图片候选经支持图像的主模型或已配置的独立视觉服务复核后，由 Harness 保存 PNG、语义侧车、来源指纹和页码锚点。
- 加密、ZIP64 或损坏 EPUB 会停止，不生成伪 Buffer。
- 超限 EPUB 会在解压前或达到输出上限时停止；PDF 文本和图像子进程超时后会被终止。

### 当前限制

- 前端已经提供“新建任务 / 继续此任务”。没有新版 Run 的旧记录不能凭聊天摘要自动恢复，需要新建任务后核对已有产物。
- 一次任务只可靠归档一份冻结材料，多份材料应拆成独立任务。
- EPUB 的复杂样式、脚注、非 UTF-8 内容和二进制图片尚未形成充分回归。
- PDF 依赖 Poppler；扫描版需先 OCR，复杂编码和整本扫描材料不能承诺可靠。
- HTML 尚无可靠正文清洗和章节还原；DOCX 尚未支持。
- Poppler 调用仍是同步工具边界：用户取消会阻止后续工作，但当前正在执行的单次转换最迟由超时终止，尚不是即时可中断的异步 Worker。
- 旧式知识对象覆盖依赖自然标题和代表性提及；新来源可用显式 ID 与实际 Card 引用对账。两者都不能发现未识别对象或证明领域穷尽；真实长材料仍需独立查漏、原文抽样和模型响应 caution 的评测。

## 四、消化

  消化先列出未结算 Buffer 的标题、来源和有限摘要，再按需精读质料、检索候选卡。一次 Card 修改可以综合 1～6 份相关 Buffer，正文与对应来源一起提交；确认后逐份记录实际影响的目标 Card，已结算或明确跳过的 Buffer 默认不再进入待处理清单。

  首次 list_buffer 冻结本轮路径与版本，默认 pending 包含 partial，后到材料不自动加入。新语义补丁通过 buffer_outcomes 显式区分完整与部分处理；部分贡献保留 remaining，后续去向累计而不覆盖历史记录。提案后的 Buffer 版本变化会拒绝写入，旧式无理由 skip 也被拒绝。完成门同时核对冻结范围与新卡接入；有具体 reason/next_action 的 deferred 可阶段结束，但回执明确尚未全部吸收，材料继续保留在待办队列。

  2026-09-08 经用户确认，沉淀规则、Skill、默认消化提示和 candidate-assimilation 已取消“优先丰富旧卡”的操作偏好，改为按对象身份、真实增量、解释完整性、独立复用价值和承载负担选择新建、修订或必要的拆分与合并。共享判断留在 ingest-pipeline.md，主题产物格式留在 theme-compile.md；这是提示与判断契约调整，不代表自动拆分能力或真实模型质量已经验证。摄入模式返回独立的有界工作窗口，包含来源进度、Buffer 阅读、当前知识对象与未解决贡献，不再套用普通问答的探索配额提示。tests/ingestion-closure.test.mjs 验证漏读漏处置、版本变化、部分贡献、范围隔离及带缺口收束；尚未进行新一轮真实长书的模型质量对照。

  启用时重启 DSH 并使用新任务；旧 compile 断点可在用户选择后复用产物，但没有新版读取与处置记录时须补读重审。旧待确认消化提案建议重新生成，避免沿用没有部分贡献声明的旧语义。撤回可分别处理 Skill 提示与完成门；如回退 partial 功能，须先核对仍在队列中的部分贡献，不能把它们自动视为 settled。

  Harness 会拒绝同一批次中的重复目标，避免多个从旧版本展开的补丁互相覆盖。新建 Card 必须给出接入决定：立即形成可推理关系、有证据缺口而延后，或经比较后有理由保持独立。

### 当前限制

- 候选被拒绝后能否稳定换方向，主要仍取决于模型依据 Observation 继续决策，真实案例不足。
- 多 Buffer 的结构契约已具备，但共同结论、增量证据、差异和边界能否稳定综合仍需人工评测。
- 一次只修改一个层面；正文、关系、领域和来源不能伪装成一个大补丁。
- 尚无充分证据证明长期运行能稳定避免重复卡、错型卡和错误领域归属。

## 五、建构

  建构可以从关系债务、结构问题、领域成员、孤立卡、冲突或用户指定范围开始。结构问题现按 P0 确定性错误、P1 关系语义债、P2 接入与类型候选、P3 结构探索排序，重复问题合并为稳定指纹。未接入扫描继续使用游标、入出边摘要和 Card 指纹；候选信号分为 E1 召回、E2 比较和 E3 写入候选，共同领域与普通词面重合不再提高关系成立资格。

  `inspect_relation_case` 会为两个端点组装核心语义槽、来源、现有方向、互指、1～3 跳路径、邻域、镜像、可用关系类型和移除影响。`simulate_relation_patch` 使用 `keep | change | remove | defer` 统一裁决结构，检查自指、重复、镜像、等价路径、conflict 角色、结构断裂、枢纽、跨领域和 readiness；证据、反证、方向与边界均具备时才达到 E4。高风险调整必须完成第二次反对性复核，完全信任模式也不跳过。

  `isolated-card-integration` 已要求枚举队列、生成候选、精读双方、比较知识功能、检查论证方向并记录最终处置。孤立卡无写入时也必须形成近重复、待重分类、待调整领域、暂时独立或具体证据缺口之一；写入后必须用原检测范围精确复核同一张卡，读取无关对象不能满足完成门。

  Harness 拒绝候选后，拒绝原因返回原 Loop。Agent 应补证据、缩小范围、换动作或说明停止原因，而不是因为一次失败结束整个任务。一次提交只处理一个层面、最多三个紧密相关原子操作。完成门维护运行态问题账本，区分已修复、已排除、已延期、开放、重新打开和写后新增错误；发生过复核但问题未闭合不能完成。

### 当前限制

- 工具存在不代表模型一定会选对局部或产生有价值修改。
- 分页、指纹失效、候选信号、同题复验和无写入处置已有合成回归；183 张真实存量卡尚未完成持续运行验证，不能据此声称结构债已经下降。
- 领域拆分、跨领域关系、冲突建立和历史关系迁移尚未在足够多真实知识库上验证。
- 关系 readiness 能约束路径和写入，但不能替代对内容真伪、重要性和解释力的人工评价。
- 存量关系不批量自动重写，迁移仍需按局部证据循环推进。
- 历史专项审查已整理出 787 个中高置信候选裁决，并生成 100 项非黄金候选清单；其中延期样本仅 1 项。端点历史版本、反证锚点和人工复核尚未补齐前，不能把该清单当作正式评测集。

## 六、对话、研判、报告与沉淀

  普通对话先在模型上下文内判断意图与证据需求，再选择三条路径。`direct` 面向身份、方法、协作、界面和轻量开放讨论，不调用知识工具；`grounded_quick` 面向需要本地依据但范围窄的概念、单一机制或单对象解释，最多一次 `retrieve` 和一次 `read_cards`，不建立 CognitiveRun、不选择 TM、不走图；`analytical` 才处理明确深入研究、多机制多阶段、批判性争议、多对象比较以及高影响投资或政策判断。快速路径发现冲突或三张卡不足以诚实回答时，可以复用既有候选升级一次，不重复同一检索。

  需要知识时，首轮统一使用 `retrieve`：复杂问题由当前对话模型在同一轮形成 `focus`、`mechanisms`、`context`、`contrasts`、`exclusions` 各最多三个具体短语的临时检索意图，原始问题仍会以低权尾部补召回保留；`intent_effects` 与 `raw_tail_candidate_total` 明示两者是否实际进入候选，不以字段存在冒充生效。直接召回与最多两跳的 ready 图候选先填满阅读计划；随后才从直接命中卡的严格中文内容锚点发现没有 ready 图路径的未证实候选关联。英文模板、Markdown 结构、高频泛词和通用标题不参与该发现；候选至少共享三个彼此独立的低频锚点，嵌套短语不重复计数，只占剩余的一个探索位，小于六张的预算不返回候选。候选关联只提示“值得比较”，既不是正式关系也不是证据，不能进入图遍历前沿；必须精读并用 `compare_cards` 比较双方后才可继续判断或进入关系案件。计划中的图路径仍须 `graph_walk` 核验；`graph_search` 只保留高级元数据筛选入口。分析路径建立只绑定当前问题的 general CognitiveRun，在知识观察前选择一个 TM，完成精读与必要的两跳结构观察，再用 `inspect_evidence_set`、`verify_evidence_anchors` 和 `inspect_cognitive_sufficiency` 验收。Run 按 `light`、`standard`、`deep` 分配确定性预算，范围依次为 8–16 步/4–8 次读取、20–32/12–20、40–60/20–32；模型只能在档位范围内调整，普通问答写入预算恒为零。证据集合检查、锚点核验和充分性检查不占知识读取额度，并在分析步数外共享最多三步尾部审计额度。深度档至少精读四个不同对象，具备支持、边界，以及真实反证或有记录的定向挑战未果。新增观察会使旧充分性结论失效；`finish_cognitive_run` 只在 TM、证据与停止条件闭合后接受完成。只读工作区检查不会隐式创建任务；重复结束同一状态会返回原回执，不能把既有终态改写成另一状态。宿主会在回答边界关闭或隔离遗留 Run，下一问题不复用上一问题状态。当前路由仍由 persona、Skill 与工具契约共同驱动，没有新增独立分类模型；真实模型在边界问题上的稳定性仍需继续回归。分析默认留在对话中，不会因为回答完整就自动写入 Card 或 OutBox。

  显式的 `nexo-deep-think` 与日常基准循环分开：只有用户明确要求「测试 TM/OPS」、固定执行压力测试或 `/deep-think` 才触发；普通「深入思考」走自适应分析。它固定使用 deep 档和 `deep-inquiry` TM，并由完成门检查两个检索角度、分析前的两跳观察与三张精读、论证检查、语义比较、一次受控认知偏移、跨域类比及候选精读、类比后的冲突检查与反例补读，以及最终证据集合、锚点和充分性验收。受控偏移在 `trace_support_to_tension` 与 `probe_assumption_inversion` 中择一：前者只沿 ready `supports` 回溯并在第一处真实冲突收束，后者要求模型显式写出原假设与反转假设，只返回待精读候选。整轮至少精读六个不同对象；特殊 OPS、类比或冲突没有返回也可以作为真实空结果，但模型必须说明停止原因或改换后续否证性检索，不能循环调用来凑出“灵光”。两种特殊事件已经具有独立画布语义：支持链按层传播，遇到张力时用珊瑚洋红碰撞信号；假设反转用紫青双环翻面，且只在观察包含真实关系时沿边传播。减弱动态模式保留颜色和目标，不播放旋转或碰撞手势。该 Skill 的目的，是用固定流程检验模型是否服从 TM 与 OPS 契约，不代表所有困难问题都应承担这套成本。完成后的重复 `finish_cognitive_run` 现在幂等返回原 Run，不再生成幽灵隐式任务。确定性门、事件投影与动画状态已由合成测试覆盖，真实模型能否在当前活动知识实例上稳定选对特殊 OPS 并产生有效偏移，仍需新会话人工回归。

### 深度分析的工作记忆与证据覆盖

  2026-09-05 的两轮真实对话审计发现：批量“精读”实际删除了部分章节，完成检查却按工具名计数；比较矩阵空缺未被追问；同书切片被当成独立来源；普通 deep 档没有触发特殊探索；最终结论的确定性超过历史材料。此次修改针对这些实际问题，不增加新的 GraphOps 或跨会话记忆系统。

  `read_cards` 默认保留所有章节，只受共享预算限制；read_card / read_cards 的 reading 记录完整、片段、已完整交付的 unit 和有限定位摘录。卡片级锚点要求完整覆盖，局部证据须使用已经交付的 unit。TM 的精读义务依据真实覆盖，不再依据能力标签。`compare_cards` 在章节标题无匹配时返回正文关键词候选，明确标注待语义复核；仍为空的维度保留缺口。来源通过有限来源链归并，source_family_count 是出处组数，independent_source_count 为 null，不再把路径数冒充独立佐证。

  普通分析、研判和报告的 deep 档除已有 TM 和证据义务外，还检查少量显式 hypotheses 的判断、范围、未知项和最终锚点，以及一次有理由的特殊探索机会。模型根据问题选择支持链寻张力、关键前提反转或跨域类比；确实不适用可附完整读取的焦点和原因收束，不固定普通分析的 OPS 顺序。候选须补读；声称改变判断须指向探索后真实的挑战观察；类比附结构对应和断裂点，空结果正常收束。专用 deep-think 保留其更严格的执行测试义务。

  工作区检查、更新、充分性与结束工具返回 working_memory，默认上限 14000 字符：当前判断、已读材料片段、最新证据角色、来源组、探索结局、比较缺口和未知项。它由本轮 Episode 与 Workspace 派生，优先保留核心证据，超限明确省略，不写入知识体。角色核验使用最新快照，不混用旧角色；已补齐的证据缺口会从自动待办中移除。最终输出仍由模型负责，程序不能自动证明语义正确或保证自然语言绝不越界。

  `tests/working-memory.test.mjs` 已覆盖批量全文与截断、未读 unit 拒绝、同书归并、正文维度定位、普通 deep 工具闭环、空探索、类比补读与挑战、跨任务隔离和工作窗口预算。后端测试共 68 项通过；这是合成与工具集成验证，不是新的真实模型认知效果评测。修改后需重启 DSH 并创建新会话；旧运行没有 reading 覆盖元数据，不会被自动认定为完整精读。撤回可只移除工作记忆的 deep 完成条件及对应提示；读取覆盖和来源诚实计数应独立保留。

### 缺口驱动的探索与多跳资源

  2026-09-05 后续调整：graph_walk 新增 focus_query，deep 缺省取工作区未决问题或目标；候选先满足关系就绪，再按缺口词片相关度和新颖度排序，并在有余位时保留不同父分支。排序只是有界文本启发式，不代表语义关联已成立。每层省略的 ready 分支通过 deferred_frontier 返回；这些分支不混入实际访问节点，不播放已访问动画。

  工作记忆的 exploration_budget 汇总剩余读取和步骤、明确缺口、最近发现增量、已读/未读桥接前沿和近三次多跳中未展开的分支。信息不足时，可先精读桥接卡，再从它继续有限多跳，累计路径可以超过三跳；单次仍最多三跳/24 节点，整轮预算不变，不自动扩大调用权限。连续两次发现没有新候选时提示阅读或换向，精读已知候选不被误判为无信息收益。

  deep 按未读候选预留 2–4 次读取和 4–6 步用于精读、验证、整理与收尾；发现类工具不能耗尽这部分资源，仍保留既有三步尾部审计额度。对 analytical general、assess、report 的 deep 档启用，不改变轻量问答与知识处理任务预算。特殊探索的四条只是工作窗口显示上限，优先保留影响当前判断的有效变化，再按新近程度选择，完成检查核对全部实际记录，不再以显示上限拒绝更多有理由的探索。

  新增 tests/exploration-budget.test.mjs，验证缺口排序发现原固定顺序遗漏的深层节点、保留未展开分支、桥接后继续、资源预留、重复发现换向以及显示与运行限制分离。后端 72 项、前端 122 项测试通过；真实模型能否更好地使用这些资源仍须新会话复测。撤回时可独立移除探索预留门或 focus_query 排序，原读取覆盖、证据验收和写入边界不受影响。

### 图谱动作播放与精读标题（现有实现）

  2026-09-05 调整：图谱事件按实际动作窗口依次播放，同节点的语义动作保留先后关系；后台页面恢复时不在单帧追赶所有事件。一般手势采用展开、结果停留和淡出三个阶段，支持链按上一层传播窗口推进，真实反对边采用对向汇聚与停止标记。队列积压时旁白标注操作回放，动画不代表模型此刻仍在执行该工具。

  比较采用同步括号，类比采用源对象括号与候选虚线菱形，不将候选冒充已经成立的对应关系。关系模拟使用独立临时虚线及方向箭头，正式写入只响应成功回执；临时线不进入知识图谱数据。充分性展示证据集合的闭合或开放轮廓，减少动态效果时保留静态符号。

  自动卡片标题仅在精读期间出现，最多同时一个、两行、省略超长部分，使用半透明渐隐底色并避让视口边缘；主动悬停仍可查看标题。当前已用合成节点的实际 GraphCanvas 组件验证桌面、窄屏与连续事件交接，尚未据此证明真实长调研中所有批量规模和认知行为都具有足够可读性。

### 特殊 OPS 人工验收问题

  下列问题分别检验支持链寻张力、假设反转和自适应选择。验收时同时观察最终回答、执行收据与图谱动画；专用动画出现只能证明相应 OPS 已真实返回，不能单独证明洞见成立。

1. `/deep-think 从知识库已有材料出发，深入思考：流动性缓冲是否一定能阻止被迫出售的自我强化？请追溯核心判断的支持链，直到找到最早出现的反对关系或边界。`
2. `/deep-think 深入思考：高连接度是否必然提高系统韧性？请识别该结论依赖的关键假设并反转它，判断结论是被推翻、被缩窄还是保持。`
3. `/deep-think 深入思考：一个制度为何会在短期稳定系统、长期却积累脆弱性？请完成机制比较，执行一次最适合当前图结构的受控认知偏移，并给出跨领域类比及其断裂点。`

  专题报告目前可以在对话中完整生成，但 OutBox 还没有统一 Harness 提案工具，因此不能把“生成了报告”写成“已经保存报告”。

## 七、任务、交互与并发

  CognitiveRun、Workspace 和 Episode 分别保存任务状态、当前已验证工作区与工具轨迹。复杂问答的已观察节点、证据、反证、未知项与充分性检查会由真实 Observation 自动投影到 Workspace；它们不是新的知识库，也不保存模型隐藏思维链。

- 编译、消化和建构使用独立会话与任务状态，普通对话可以在后台任务运行时继续。
- 普通输入在任务运行时可作为补充方向排入当前任务。
- 只有下一步确实依赖用户范围、取舍或价值判断时，才使用有状态交互。
- 一次任务只允许一个待答问题。
- 回答已保存但模型未成功接续时，会留下待投递 continuation，并可通过恢复接口重投递。
- blocked 或 cancelled 任务不会自动混入新任务，需要显式开始或恢复。

### 当前限制

- 前端没有完整任务管理与恢复页面，也没有专门的 continuation 恢复按钮。
- 回答交互先完成会话归属与答案校验，再持久化决定并入队；入队失败会进入可恢复暂停状态并保留 continuation。
- 当前隔离粒度是“是否登记为本 Nexo 项目会话”，不是账号、组织或多租户权限系统。
