# 2026-08-30 项目定位、愿景与总体架构

> 状态：现行项目说明  
> 核对日期：2026-08-30  
> 适用范围：NEXOGENESIS-DSH 当前实现与长期方向  
> 事实边界：当前能力以代码、测试、`AGENTS.md` 和 `.agent/reference/` 为准。

## 一、一句话说明

  Nexogenesis DSH 是一个以 Markdown 知识体为长期事实源、由 Agent Loop 主动调用认知工具、并通过 Harness 控制知识写入的知识操作系统原型。它的目标不是让模型保存更多笔记，而是让知识结构和思维方法都成为可检查、可组合、可评价、可修订的长期对象。

## 二、项目解决什么问题

  普通资料库擅长保存文件，普通 RAG 擅长从文本中召回片段，通用聊天模型擅长临时生成答案，但它们通常不会长期维护一个思想主体已经形成的主张、模型、冲突、适用边界和来源承诺，也不会把“采用什么思考方法”保存为可评价的对象。

  本项目关注三个连续问题：

1. 如何把书籍、报告、讨论和观察沉淀为可追溯、可修订的知识结构，而不是章节摘要堆积。
2. 如何让 Agent 在真实工具反馈中自主选择下一步，而不是由按钮背后的固定管线替模型决定语义动作。
3. 如何把 Thinking Model 与 GraphOps 的组合变成可以版本化、比较和逐步演化的认知能力。

  因此，项目不是通用办公 Agent，也不是自动切书器、个人日记或无约束的自主写库程序。它是一套面向长期知识建构与分析的专用认知环境。

## 三、最上层结构：知识体、思维体与 Agent

```text
┌────────────────────────────────────────────────────┐
│ Agent：承载任务、循环、工具、权限、状态与人机协作     │
│                                                    │
│   ┌──────────────────┐   ┌──────────────────────┐  │
│   │ 知识体            │   │ 思维体                │  │
│   │ Card / Buffer     │   │ TM × GraphOps        │  │
│   │ 关系 / 来源 / 边界 │   │ 评价 / 版本 / 组合      │  │
│   └──────────────────┘   └──────────────────────┘  │
│             ▲                      ▲               │
│             └──── Harness 与 Observation ─────────┘│
└────────────────────────────────────────────────────┘
```

  知识体和思维体是项目希望长期积累的两类资产，Agent 是承载、调用和约束二者的运行环境。三者不是把所有东西都归入“记忆”：Card 与关系是可推理知识，Thinking Model 是认知策略对象，Workspace 与最近对话才属于任务期工作状态。

### 3.1 知识体

  知识体保存系统愿意长期承担的认识，包括领域、主张、现象、模型、方法、实体和冲突，以及它们的来源、关系、适用范围和成熟状态。

| 组成 | 当前载体 | 作用 |
|---|---|---|
| 正式知识 | `01-Cards/` | 可长期引用、修订和建立关系的 Card |
| 待沉淀质料 | `05-Buffer/` | 保留来源与结构，但尚未成为正式知识承诺 |
| 原始材料 | `00-Inbox/`、`03-Archive/` | 摄入前材料与处理后归档 |
| 思想主体档案 | `02-Profile/` | 领域级关注、立场与协作约束 |
| 输出与记录 | `04-OutBox/`、`06-Journal/` | 分析产物与可审计写入记录 |

  Markdown 是知识语义的事实源。图索引、搜索索引、缓存和运行数据库都必须能够由 Markdown 重建，不能反过来成为隐藏的第二份知识真相。

### 3.2 思维体

  思维体不是一段人格提示词，也不是“模型的所有记忆”。它是系统可以长期保存、选择、组合和评价的认知能力集合。

| 对象 | 职责 | 当前状态 |
|---|---|---|
| Thinking Model（TM） | 描述一种审视问题、组织证据和决定停止的策略 | 已是一等配置对象，已有多种模型与能力闭合检查 |
| GraphOps / OPS | 执行搜索、精读、走边、比较、溯源、结构检查等原子认知行动 | 已有统一工具注册与结构化 Observation |
| 评价 | 判断结果、证据、轨迹、成本和稳定性是否改善 | 只有确定性测试与设计稿，完整测评闭环尚未实现 |
| 版本与演化 | 比较 TM、OPS 或提示候选，保留谱系并受控晋升 | 属于未来目标，不允许生产任务自由改写自身 |

  项目最重要的长期假设是：`Thinking Model × GraphOps` 可以组合出丰富的思维策略，TM 与 OPS 又可以分别演化。这个假设必须通过固定任务、真实轨迹和人工评价逐步验证，不能因为目录或配置已经存在就宣称完成。

### 3.3 Agent

  Agent 把一次用户意图变成持续的观察—行动循环，并负责在知识体、思维体和用户之间传递真实结果。

| 运行部件 | 作用 | 不承担的职责 |
|---|---|---|
| Agent Loop | 根据新 Observation 决定下一步工具、继续、换路、询问或停止 | 不预先固定全部语义步骤 |
| Skill | 规定任务目标、允许能力、预算、停止条件和表达方式 | 不复制 TM，不实现工具，不写死调用顺序 |
| HarnessGateway | 校验权限、结构、关系、修订和原子提交 | 不代替模型判断知识是否重要或正确 |
| CognitiveRun | 保存目标、范围、预算、状态、发现和待办 | 不是长期知识卡 |
| Workspace | 保存本次任务已验证事实、假设、证据缺口与下一步 | 不是隐藏思维链，也不自动进入知识体 |
| Episode | 保存可审计工具轨迹和结果，供排错与未来评测 | 当前不会自动修改 TM 或 OPS |
| 有状态交互 | 在确需用户范围或价值判断时暂停，并回到同一任务继续 | 不替代普通对话或写入确认 |

## 四、Skill 在体系中的位置

  Skill 是面向任务的轻量契约和外部扩展接口。它回答“用户现在要完成什么、可使用哪些能力、什么情况下应该停”，而不是回答“思维体永远怎样思考”。

  当前 `nexo-talk`、`nexo-assess`、`nexo-report`、`nexo-emerge`、`nexo-refine`、`nexo-compile`、`nexo-digest` 和 `nexo-construct` 分别提供对话、研判、报告、捕获、精修、编译、消化和建构入口。它们可以选择 Thinking Model 并调用 OPS，但不拥有知识写入权。

  未来仍可允许用户或插件增加 Skill，用来接入新的任务场景、外部数据源和交互方式；真正希望积累和演化的认知策略应进入 Thinking Model，而不是把越来越复杂的思维程序都塞进 Skill 文本。

## 五、两条主要工作路径

### 5.1 知识摄入与建构

```text
原始材料
  ↓ compile：建立材料索引、按需阅读、形成可追溯 Buffer
质料 Buffer
  ↓ digest：检索既有 Card、综合证据、优先丰富、形成候选
正式 Card
  ↓ construct：观察局部结构、关系、领域与冲突，提出小范围调整
可继续推理的知识图谱
```

  三个环节都由 Agent Loop 驱动。确定性工具负责读取、索引、模拟和写入检查；模型根据 Observation 决定下一步；Harness 只接受一次一个层面的少量原子操作。按钮只是启动对应任务，不是隐藏的语义工作流。

### 5.2 对话、分析与沉淀

```text
用户问题
  ↓ talk / assess / report
选择 TM → 调用 GraphOps → 形成有来源的分析
  ↓ 用户要求“记一下”或“精修”
emerge / refine → 候选 → 用户授权 → HarnessGateway
  ↓
知识体更新，再由后续任务使用
```

  分析默认保留在对话中。只有用户明确要求沉淀，或在已经授权的编译、消化、建构任务范围内，系统才可以提出知识写入候选；候选仍须经过统一写入闸门。

## 八、典型使用场景

### 场景一：处理一本书

  用户从 Inbox 选择一本书并启动编译。Agent 先建立材料目录，再按需读取章节和图表，写出少量可独立理解的 Buffer；覆盖检查通过后归档源文件。随后消化任务把相关 Buffer 综合进已有 Card 或少量新 Card，而不是为每章机械建卡。

### 场景二：分析一个问题

  用户直接提问或启动研判。Agent 选择合适的 Thinking Model，搜索相关 Card、沿论证关系扩展、读取证据和反例，再给出区分事实、知识体主张与自身推断的回答。分析不会自动写回知识体。

### 场景三：整理知识图谱

  用户启动建构或指定一个局部范围。Agent 从结构问题、关系债务、领域成员或冲突入口开始观察，选择一项值得验证的小改动；Harness 拒绝后，反馈回原 Loop，由 Agent 缩小范围、补证据、换动作或说明停止原因。

### 场景四：改进思维方法

  未来评测系统在固定案例中比较不同 TM、OPS 和检索组合，保存结果与轨迹，经过人工审核后再晋升更有效的候选。生产任务本身不能因为一次自我反思就永久修改认知策略。

## 九、不可退让的边界

- Markdown 知识体是唯一语义事实源。
- LLM 负责开放语义判断，Harness 负责确定性边界与原子写入。
- GraphOps 返回 Observation，不替模型宣称知识真伪。
- Skill 不得退化为固定管线，Loop 也不能以“自由发挥”为由绕过工具和检查。
- 一次写入只处理一个层面、最多三个紧密相关操作。
- 任何“已实现”都必须能对应代码与测试；真实语义效果仍需案例评测。
- 自动学习、策略晋升和大规模存量改写必须晚于可靠评价与回滚能力。
