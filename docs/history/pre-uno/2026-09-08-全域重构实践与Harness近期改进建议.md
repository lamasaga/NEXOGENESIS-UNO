# 全域重构实践与 Harness 近期改进建议

本文件记录金融底座领域重构对近期流程的启示。实例迁移结果以 `04-OutBox/2026-09-08-金融底座全域重构与归属验收.md` 为准；以下建议没有自动成为运行规则，也不表示 Web/DeepSeek 已经稳定具备此次 Codex 人工主审的能力。

## 已验证的做法

本次沿用现有 Markdown、domain 类型与 HarnessGateway，没有另建分类事实库。先冻结知识快照和全局边界，再按互斥卡片清单并行只读审查，由主助手统一裁决和写入。成员迁移只修改领域归属；正文、来源、起源、成熟度与论证关系分别受保护。

普通 `propose_write` 的 membership 层可以表达完整多重归属，不需要把每个调整拆成多轮移除、再添加。每次事务仍最多三个相关操作。小批次回读、版本校验、来源与文本锚点保留，以及全库不变量比较可以共同工作。

领域新建取决于现有对象是否形成清晰问题，而非预先锁定领域数。来源批次可以同时贡献多个问题域；少数内容暂不设领域也是有证据的合法结论。领域组织变化没有制造普通卡之间的论证捷径。

## 真正的摩擦与该保留的保护

一次参数名错误和一次前批尚未完成时尝试启动下一计划，被工具或本地防护及时拦住，均没有知识写入。这是执行调度问题，不应归咎于语义规则太严。

领域综合的来源边界曾未充分显式区分作者论述、跨来源组织与系统判断，写前被拒绝。修正后沿用原未提交计划，不重做已提交内容。归因要求应保留；更好的改进是提供精确的缺失位置、新旧差异和可继续的修复路径，而不是降低证据标准。

收尾还发生一次计划类型错误：把多源内容分流到两个已有领域标为 `merge`，在计划阶段即被拒绝。当前 `merge` 只接受一个结果，`split` 限定单一源且要求已有目标列入源阅读范围；因此分流到多个已有对象应使用完整比较的 `synthesis`。本次按现有合法能力表达同一语义任务，来源承接与退役检查仍执行。近期应补充这个真实参数示例，不能让使用者或模型靠反复拒绝猜出契约。

真正影响大任务效率的是运行日志重复：在二十余项领域调整后，主运行 episode 已约 27 MB，每一步都重复完整的 2,539 个范围 ID。本次以至多 36 张的冻结成员批次分段执行，保留总账、原授权和全部收据，没有修改运行时代码。分段是实例执行适配，不是已经实现的通用调度能力。

语义回读还能找到格式校验未发现的问题：旧邻域名称残留、对某学派不够中立的措辞、编者说明混在引文，以及遗漏的稳定段落地址。它们说明必须保留独立内容复核，不能把质量分数或写入成功当成验收终点。

## 建议优先完成的有限改进

### 0. 先修复退役对象的读取一致性

最终实测：`cards.js` 的 `readCard` 能按原 ID 读取已替代领域，但模型工具 `read_cards` 通过活跃 GraphOps 表读取，返回 `card_not_found`；`read_card` 当前也走该活跃路径。退役不应被说成对象不存在。应允许显式 ID 的历史读取并明确显示生命周期、承接入口和非活跃身份，同时继续禁止它进入默认活跃检索或论证路径。需要分别测试底层函数、模型工具和 Web 的实际行为，而不是只验证一个函数后宣传完整能力。本次未改运行时代码；全部原文件与来源仍在，活跃知识已承接。

### 1. 缩小事件日志，而不缩小事实与权限

冻结范围保存一次，每个事件保存范围引用、摘要与实际变化，避免逐步重复全量 ID。恢复时验证范围指纹，仍能重建原授权和实际用量。先用此次同规模实例回放测试日志增长、续跑正确性与读写耗时；不需要先建通用 Agent 平台。

### 2. 支持精确的归属调整预览与恢复

Web 展示“卡片当前归属 → 建议归属 → 内容依据”，允许用户看懂为什么移动。基于已有 membership 写入能力封装预览，而非另建写入通道。中断恢复以卡片版本、已提交收据和待验收计划为依据，不因界面重试重复写入。

预览还应识别语义空操作。本轮一个标题校准提案与现有显示标题已经相同，虽不损害知识，却形成一次多余事务。应在提交前比较实际字段，明确报告保持，不把重新序列化当成知识改善。

全库任务如果提供分批执行，需一个总目标和累计预算、覆盖账本；批次结束不是全库完成。运行时应正式验证批次无重叠、范围未扩大和累计预算，而不能依赖调用者无限另开任务。

### 3. 将组织验收与内容验收分开

组织调整验收应检查全部目标是否有效、退役领域是否仍有成员、未归属是否有明确理由、原正文与真实关系是否保持。内容拆并才需要独立核查知识是否充分承接，不能把题名命中当成语义质量证明。

成员数只作为检查线索；不设置统一下限、上限或“每卡必须至少一个领域”的伪质量规则。新领域必须有真实对象和清晰纳排。对用户设定的理论问题保留主权，不根据规模自动重写。

统计口径也应明确：当前 `inspect_domain_members` 的总数可包含其他领域卡，`type_counts` 则只计算返回的有限样本。本次危机领域原生总数是 407，而普通成员是 406。Web 和工具应区分普通成员总数、领域组织引用与样本类型分布，不把样本分布包装成全域分布。

内容完整性、版本冲突和非法关系应继续硬拦截；表达偏好则应区分情境。本次最终结果仅因出现用户已明确熟悉的“运行时 Harness 规则未修改”，被 `INTERNAL_USER_COPY` 术语正则拒绝，改成自然语言后再收束。建议把孤立术语词表降为可修正文案提示，而不是任务完成硬门；仍拦截无法理解的关系代码堆叠，但不把技术读者的正常术语使用视为知识不合格。该建议尚未实施。

### 4. 用有限真实样本检验 DeepSeek 的独立能力

把本次的六类难例做成冻结输入与人工裁决样本：书批次混装、理论断言型领域、证券效率与福利效率同词异义、实物期权与家庭配置、文学经验与行为证据、暂无适切领域。

模型应给出逐项处置与证据，不只命中预设标签；评测检查必要多归属、错误泛化、来源保真、恢复不重复和用户介入次数。分类不同不自动判错，要能说明可接受边界。先验证小样本真实 Web 流程，再决定是否扩大自动执行范围。

## 与统一入口方案的关系

本次支持“编译负责把材料融入知识体，建构负责调整已有知识体，思考默认只读”的分工。统一编译可以合并用户入口，却不能删除来源保存、知识落点追踪与旧卡丰富判断。长期主题和领域如要整合，应保留同一个稳定身份及定义；文件夹改名不能自动改变论证关系。

本轮没有实现主题页、领域投影、编译消化合并或自动学习。近期需要的是可理解的预览、有限的失败修复、可恢复账本和真实模型评测；不让系统依据一次成功自行修改 Harness 或晋升未经验证的策略。

## 验证与撤回

程序改动先在副本验证：同一初始快照、同一输入、同一模型设置；检查知识不变量和恢复，再比较耗时与用户干预。日志或界面实验可撤回，但旧收据、范围和知识 Markdown 应继续可读。改变硬规则仍须独立确认，不以此次用户给予实例重构的灵活性替代项目治理。
