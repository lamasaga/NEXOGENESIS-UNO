# NEXOGENESIS-UNO 开发基线

> 核对日期：2026-09-08。状态：下一阶段开发依据，不是完成声明。
> UNO 表示统一。适用对象是新的、空白初始化的产品版本，不是金融底座的迁移方案。

## 1. 产品目标与边界

  用户可以把书籍、论文、报告、研究手稿与个人见解，处理为可独立阅读、可追溯、可复用、可参与推理的知识结构，再用它改善分析与回答。默认使用者不需要理解 Skill、Thinking Model、OPS、知识对象、索引或事务。

  只有三个知识工作入口：编译、建构、思考。普通聊天仍可以直接开始，不增加第四种工作入口，也不要求每次交流先选任务。三个入口不是永久的会话类型；同一个对话可以先分析、再明确授权整理知识，任务与权限在切换时显式交接。

| 入口 | 用户的目标 | 明确边界 |
|---|---|---|
| 编译 | 把选定材料中的有价值知识落实为卡片 | 整合原编译、主题编译、消化；不是只交中间文件 |
| 建构 | 改善已有知识的内容和结构 | 可精修、调整粒度、拆合、修正关系和主题归属；不是只调整画布布局 |
| 思考 | 利用知识体帮助理解、比较、检验与产出 | 默认只读；候选召回、真实证据与模型综合分开 |

  不以卡片数量、连通率、调用次数或审计数量代理质量。不预设丰富旧卡优先，也不预设新建优先；按知识对象身份、真实增量、解释完整性与承载负担决定。用户偏好可以影响选择，但不能迫使模型重复造卡或把不同问题塞入杂糅大卡。

## 2. 开发与既有知识隔离

  新分支为 `codex/uno`，新工作区为 `NEXOGENESIS-UNO`。旧项目目录、分支上的工作文件、金融知识库、模型凭据和运行服务不因开发而改变。只带入已核对的程序、规则、测试和研究记录；不复制真实 Inbox、Card、Buffer、Archive、Journal、会话或实例登记。

  UNO 拥有自己的配置、会话、实例登记、进程和端口。不得通过共享运行目录、开发代理、测试绝对路径或预览脚本间接访问旧金融服务。工作区隔离不等于运行隔离；Git 工作区共享历史，不是隐私或发布边界。

  项目身份、界面文案、发行包名称和新开发文档使用 UNO。当前仍使用的上游运行时包名、协议字段和插件服务 ID 保留准确名称，不用全局替换破坏依赖，不把保留上游适配接口解释成仍是旧产品。HarnessGateway 的事务保护与模型供应商名称也不属于要删除的品牌残留。

## 3. 知识组织：主题取代新建领域容器卡

  新统一路径不再创建独立 `domain` 卡。主题负责组织、范围和导航；普通卡负责知识命题、模型、方法、现象、冲突及对象描述。主题不是论证节点，不因共享主题而产生推理边。

  保留 `05-Buffer/`，其中的 `themes/<主题目录>/` 存放主题定义及知识对象。这里不再是旧普通 Buffer 的待消化片段队列，也不再另建一套正文相同的 Archive 聚合层、候选层和矩阵层。原始材料最终进入 `03-Archive/`；来源摘录、对象正文和正式卡片各有不同职责，避免重复抄写。

  每个主题至少有稳定 ID、名称、问题范围、纳入与排除边界、少量代表性对象及别名。名称服务于下一轮路由，不要求均衡分配成员数量。两张卡的主题可能合理，百张卡的主题也可能合理，判断依据是范围清晰与使用价值。

  目录名允许变化，但主题身份、对象 ID 和来源锚点不依赖可变名字。重命名必须一次更新引用并留下可解析的历史别名；移动中断不能造成对象失联。对象具有一个主存放位置，可以关联多个主题；跨主题不得复制出多份语义事实。

  卡片的主题归属最终引用稳定主题 ID，不再要求 ID 对应 domain 卡。Schema、Gateway、检索、过滤、界面与样例必须在同一切片调整，不能只撤掉 `list_domains` 的提示而让写入器继续要求领域卡存在。旧 domain 读取可以保留兼容，但不要求为此迁移金融底座，也不让兼容类型重回默认创建入口。

  主题级联系由真实成员关系和对象交集派生，供导航、查找候选入口和下钻。真正推理须回到具体卡片及真实关系。若跨主题联系本身构成明确理论命题，保存为普通知识卡，而不是直接赋予两个容器 `supports` 等论证边。主题投影索引可重建，不新增另一套知识真相。

## 4. 编译：围绕完整问题滚动落实

  以下是必要责任和依赖，不是强制所有任务执行相同调用顺序，也不要求全批材料完成上一阶段之后才能进入下一阶段。

1. **辨认材料。** 冻结本次选择、实际版本与指纹，核对章节和可读性。目录或 OCR 缓存不等于已经读过正文；影响解释的图、表、公式需实际读取，不凭标题猜测。
2. **决定组织。** 看轻量主题目录，检索少量候选主题定义，再决定加入既有主题或创建新主题。混合材料允许跨多个主题，不能按一本书或一卷自动建领域。
3. **形成知识对象。** 围绕可独立理解的问题聚合定义、机制、证据、条件、方法及反例。既保留跨书共同结构，也保留单一来源的独特贡献、不同立场和不可直接合并的口径。
4. **落实可用成果。** 一小组对象可完成来源核对、卡片新建或修订、真实关系判断与写后检查后，即作为局部成果交付，再选择下一组。不先积累数百个候选让后续多次转写成为瓶颈。
5. **结算贡献。** 每个对象记录实际影响的卡片和具体贡献；部分处理保留剩余。不能以“对象映到一个文件”代替检查其机制、公式、证据和边界是否真正保留。
6. **检查改变的主题。** 本轮尾部审查新增或受影响主题的名称与范围。只读取这些主题和可能重名、重叠的少数邻居，不全库重读；轻量全局目录仍用于发现碰撞。
7. **如实结束。** 逐材料报告已落实、待处理、不可读和有理由排除。完整编译需闭合授权范围；定向提取完成不等于整书编译完，不能把重要延期改标排除后归档。

  新型材料优先试一个有代表性的完整问题单元，验证其落卡质量再扩大；已验证的简短材料不强制重复做试验。没有语义增量的重复材料可以只保留出处和已有落点，不为了“所有对象必须新建卡”产生废卡。

### 对象的状态与重新打开

| 状态 | 默认队列 | 要求 |
|---|---|---|
| 待处理 | 进入 | 有来源及当前理解，不伪装成完整知识 |
| 部分落实 | 进入 | 已保存贡献与未落实内容分开 |
| 已落实 | 不进入 | 能回查实际卡片、贡献及结算版本 |
| 延后 | 明确显示待办 | 说明阻碍及下次处理条件，不当作全部完成 |
| 无新增贡献或排除 | 不进入 | 有具体理由和可追溯去向，不靠标签遮盖漏读 |

  已落实不是不可检索、不可纠错。新证据、原件版本改变、明确错误或用户请求可以重新打开受影响部分，保留历史结算，不整批重跑。重命名主题本身不使全部对象失效；来源正文改变与组织名称改变应具有不同的失效范围。

## 5. 面板与知识行为设置

  本次面板表达“我现在要做什么”；长期设置表达“我通常希望怎样做”。模型参数与 API Key 留在模型连接设置，不混入知识行为。默认设置必须让新用户无需写提示词也能开始。

| 本次面板 | 可选目标示例 | 本次必须看得见的内容 |
|---|---|---|
| 编译 | 自由编译、围绕问题提取、继续未完成内容、重点审查主题组织 | 材料/对象范围、目标、权限与投入摘要 |
| 建构 | 自由建构、精修内容、调整粒度、修正关系、整理主题 | 焦点卡或范围、允许改动、仅建议或执行 |
| 思考 | 自由思考、深入理解、比较解释、检验判断、形成报告 | 问题、可用资料、结果需求 |

  选项是可检验的初版，不固化为技术模式。必要时可合并相近选项；“更偏向新建还是修订”“核对投入”“通常是否自动执行”更适合长期设置，并允许本次覆盖。主题整理是本次明确目标时放面板，是否默认在编译尾部轻量审查则属于策略默认值。

  知识行为设置建议提供：质量投入（高效/均衡/严格）、落点偏好（按对象判断/更偏向新建/更偏向修订）、写入确认方式、外部来源使用、表达风格和是否采用已验证经验。不要把这些压成一个“准确率”滑块，也不承诺严格模式零误差。

  高效减少重复阅读全文与例行审计；均衡按风险抽查；严格扩大独立检查和来源复核，但仍避免无信息收益的反复。质量投入、资源上限和写入权限是三个不同维度，不能选高效就默认扩大权限，也不能选严格就反复确认已授权的机械步骤。

  打开面板、切选项、查看范围只做本地只读检查；启动后才调用收费模型。取消不创建空任务、不丢草稿。任何设置必须真实改变服务端策略，不能只有提示词变化或界面开关。

  点击选择与斜杠加自然语言都形成同一份受验证的任务请求：入口、目标、范围、本次覆盖、授权和资源上限。自然语言保留原文，不让斜杠文本自行授予信任模式、任意路径或预算豁免。普通聊天不必包含斜杠。

## 6. Agent Loop 与工具组合

| 部分 | 应负责 | 不应负责 |
|---|---|---|
| Skill | 任务目标、表达、可用能力、边界与停止判断 | 固定每一步调用顺序，重复整套本体说明 |
| Thinking Model | 需要什么证据、比较维度、可能盲点与有效停止条件 | 自动决定结论、给每次任务强制同一审计配额 |
| OPS | 有界检索、批读、图路径、比较和确定性检查 | 把候选当证据，暗中作语义裁决 |
| 模型 | 选择问题和方法，解释证据，判断缺口与下一步 | 代替事务、权限检查或自己认证来源真实 |
| Runtime / Harness | 生命周期、预算、授权、版本、原子写入、诊断反馈 | 用模板词频、固定字段数量代替意义判断 |

  默认在一个循环内工作：模型提出信息需求，执行器完成一组边界明确的检索/读取/路径操作，回送实际证据、出处、覆盖和缺口，模型再决定补证、换方法、落实知识或回答。中间可自动处理分页、去重、锚点解析、版本核对和格式装配，不把每个机械动作变成新的模型往返。

  组合操作可以中断、受同一预算约束，保留子操作失败与部分结果；不把整组重复运行当作默认恢复。引入组合操作前测量真实高频组合与返回体积，先复用已有批读、图检索与合并审计，不为了架构完整新造大量 OPS。

  Workspace 保存目标、明确判断、引用、缺口、成果、待办、版本与预算，不保存隐藏思维链。模型只能看到被放入上下文的内容；工作区文件不是模型天然可见的记忆。返回有界工作窗口、原文摘录及回查地址，同时保留真实观察记录。不能声称一个窗口替换了整段对话上下文，也不额外强制一次“重写最终 Prompt”的模型调用。

  语义讨论在 Skill/TM 按需读取；完整工具 Schema 不反复附带到每条回执。来源摘录可以复用，但变化使对应证据失效。方法改变不必重读所有材料，方法专属缺口须真实补足。

## 7. Harness：硬保护、诊断与语义复核分开

  始终硬保护：写入授权、目标范围、合法路径、稳定 ID、可解析来源和关系端点、版本冲突、幂等、原子提交或回滚、真实收据、知识与运行数据分离。无效锚点不能标为已验证，推理不能借主题容器制造捷径。

  默认诊断：主题过宽/过窄、疑似重复、低收益搜索、潜在孤立、来源覆盖偏弱、对象承载过重。回送具体位置、影响和可用修复方式，由模型判断；有理由独立的卡片可以保持独立，不能为了绿色通过机械补边。

  语义复核：是否正确理解作者，公式前提是否成立，反例有无遗漏，对象是否完整，关系是否有意义。按风险和用户投入决定强度，关键公式、因果判断、来源冲突及不可读片段重点检查。检查结果不是自动真理认证。

  确定性错误在提交前一次集中报告，给出当前模式适用的 Schema 和可修复位置；不要一个字段拒绝一次。相同快照复用已通过检查；变更只使真正受影响的检查失效。多条关系裁决需要绑定各自端点版本，不因“仅保留最后一次模拟”迫使前面的关系反复模拟。

  事务按一致性边界与实际影响组织，不把旧“每批最多三项”机械继承为产品原则。一次跨层任务可以包含多个可恢复事务，但不能冒充全部原子回滚。何时扩大单批规模必须有故障注入和恢复测试；在新策略落地前，旧 Gateway 的实际限制仍不能绕过。

## 8. 对话和任务生命周期

  对话容纳多轮协作，任务保存一个具体目标及其执行状态。新问题不重用旧问题完成度；补充要求不重置预算和权限。前端显示用户的工作，不要求管理底层 Run ID。

| 情况 | 应有行为 |
|---|---|
| 运行时补充 | 可加入队列，或在安全步骤边界立即插入；显示是否已被接收 |
| 暂停并讨论 | 等待停止当前执行后进入只读讨论，保留原任务与已提交成果 |
| 继续任务 | 恢复原目标、范围、预算和待办；不重复成功事务 |
| 刷新/断网/重启 | 未发送草稿、队列、待答与已接收消息分别持久化并对账 |
| 结果不确定 | 先查收据及服务端事件；不得盲重发写入或支付模型请求 |
| 用户改变目标 | 区分修改当前任务与新任务，明确冻结旧状态或交接 |
| 取消 | 阻止后续执行，已提交成果保留，正在提交的事务以真实收据为准 |
| 回答或任务结束 | 执行结束、正文交付、覆盖完整度分别记录；部分成果不冒充全量完成 |
| 后续追问 | 留在正常对话，不重新弹首轮面板或复制旧授权 |

  对话或任务之间不得共享隐式进度、待答项和权限。当前已有建构讨论与消息插入机制，优先验证和扩展，而不是另起一套聊天引擎。取消、工具执行和恢复的真实边界必须经过测试，不以按钮状态替代后台事实。

## 9. 有约束的经验改进

  保存有用的操作经验而非无边界“自动学习”：材料类型与解析异常、实际高收益方法、已知失败原因、用户纠正、耗时和结果质量。经验按实例、版本、适用条件和有效期管理，可关闭、查看及撤回。

  运行时可以采用已批准的偏好和有据可查的提示，不能自行改代码、提升权限、放宽硬保护，不能因为某策略便宜就自动晋升。候选策略先在隔离样本对照，合格后由开发者或用户明确接受；高效/严格两档都受同一硬边界约束。

  收集调用数、去重后返回字符量、模型用量、首次可用成果时间、总耗时、拒绝原因与纠正成本，不保存不必要的密钥、隐藏推理或全文日志。没有真实模型数据时，不把工具条数换算成 Token 或时间收益。

## 10. 开发切片与验收

| 切片 | 实施内容 | 验收依据 |
|---|---|---|
| S0：独立开发起点 | 工作区、运行隔离、品牌/路径清理、文档收束、可重复测试 | 干净安装可启动；旧库指纹不变；测试不引用旧绝对路径 |
| S1：共同任务入口 | 同一请求契约、三个面板/斜杠、设置与服务端真实策略、任务交接 | 两种入口权限等价；取消无任务；暂停/插队/刷新不串任务 |
| S2：统一编译闭环 | Buffer 主题定义、对象状态、来源贡献、Gateway、主题索引与无领域卡新路径 | 两份异质短材料→完整问题→可用卡片→真实结算；中断继续不重写 |
| S3：建构与思考整合 | 主题归属/投影下钻、局部结构改进、可组合证据获取 | 不造伪边；检索比较减少零碎往返；答案和卡片质量不退步 |
| S4：经验与投入验证 | 有界经验提示、风险审计差异、策略对照 | 同模型同材料比较质量与成本；低收益策略可撤回 |

  这是目标路线，不要求把全部阶段在一次开发中完成。每个切片同时包含代码、提示、Schema、测试和当前状态说明；只有新路径端到端通过，才撤下对应旧入口与规则，避免仅修改文档造成工具无法执行。

  首个编译验证选择短材料、两种互有联系又有独特贡献的来源，以及已有相近卡的合成实例；加入重复原件、扫描/不可读位置、公式条件、关系无依据、同名主题、部分写入和版本变化。第二轮再用较长且结构不同的材料，避免重复整批十三本的高在制量实验。

  质量由原文忠实度、对象内贡献覆盖、边界与异议保留、卡片独立可读性、关系可解释性和后续检索任务共同判断。程序测试只证明工程边界；真实模型的语义评测必须单独记录，不能把 HTTP 200、界面动画或 fixture 通过写成“知识质量已经提高”。
