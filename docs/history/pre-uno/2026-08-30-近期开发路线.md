## 二、P0：修复思维体分析完成闭环

### 工作内容

1. 为 `report` 增加不依赖 TM 是否已选择的 mode 级完成义务：必须选择适用 TM、完成证据集合检查并成功核验最终锚点。
2. `finish_cognitive_run` 从本轮 Episode 检查成功核验事实；不能仅凭提交参数接受“已核验”声明。
3. 复杂普通问答按 `light`、`standard`、`deep` 分配受控预算；预算是上限，闭合审计和充分性完成门决定提前停止或带缺口受阻。
4. 将预算拒绝和工具拒绝写入 Episode；Workspace 分别承接候选、已精读节点、证据角色、单点支撑和未闭合缺口。
5. 修复 `finish_cognitive_run` 的无损 JSON 输出，并使重复 finish 幂等返回既有回执，不重复追加完成步骤。
6. 复杂 `nexo-talk` 只在现实金融、多情景或跨机制且证据需求为 required 时建立受控 run；普通闲聊和简单事实问题保持轻量。
7. 在 RC-001 的最小 ready 子图中验证适当的 `inspect_argument`、`graph_walk`、`graph_path` 或 `compare_cards` 确实发生；不制定全局固定跳数。
8. 认知动效区分直接召回、retrieve 一跳候选、精读、证据审查和真实 walk layers。

### 通过门槛

- RC-001 第一问不能在零精读、零关系观察的情况下把候选摘要包装为库内结论。
- RC-001 第二问必须选择 TM；支持、反证/边界和最终锚点义务未闭合时不能 completed。
- `verify_evidence_anchors` 被拒绝、失败或未调用时，report 完成门稳定拒绝并留下可恢复缺口。
- 同一 run 只产生一次完成状态和一次完成回执；重复 finish 不增加 Episode 步骤。
- Workspace 能解释本轮已读什么、缺什么以及为何停止，不保存隐藏思维链。
- 前端只有真实图遍历才显示层级扩散，节点点亮不再被误读为多跳推理。
- “你是谁”和简单概念解释仍可直接回答，修复不把所有对话升级成长任务。

### 本轮不做

- 不强制所有问题走两跳或三跳。
- 不以调用次数、耗时、字数或动画规模作为智能指标。
- 不新增 `nexo-research`、向量库、新 Agent 框架或自动学习机制。
- 不在完成门正确性尚未修复时扩张新的 TM 与 OPS 名称。

### 本批优化后的真实对话复测

  2026-09-05 的工作记忆、真实读取覆盖和普通 deep 探索机会已通过合成与工具集成测试，当前只需复测实际收益，不继续增加 OPS 名称。新会话复用“周期与货币的机制梳理”“中国金融周期实证与康波表现程度”两个原问题，并增加一个适合跨域结构类比的问题。

- 不添加 `/deep-think`，观察普通 deep 是否依据焦点材料选择特殊探索或提出合理的不适用理由。
- 比较原答案与新答案的证据忠实度、时期/地域/样本边界、最强反例，以及探索是否真正改变某项判断；空结果不扣成失败，未检验却宣称洞见才是失败。
- 检查 finish 返回的 working_memory 是否保留最终需要的关键证据、未知项和探索结局；不把窗口生成或程序通过当作认知收益证明。
- 记录为得到上述收益新增的工具调用与字符成本；如果新约束导致机械补字段或大量空探索，调整触发条件，不以增加次数作为优化目标。

### 全流程耗时复测

  共享索引、模型结果去重、分层工作记忆、合并启动与分析验收已完成代码回归，详情见《当前实现、运行与限制》。2026-09-05 的新服务真实复测受 Kimi 7 天额度耗尽阻断；额度恢复或用户明确选择其它供应商后，使用新会话继续验证，不将失败短耗时计作提速。

- 同模型、同知识版本分别复测窄概念、机制比较、深度研究和局部建构，至少重复三次，分别记录首个有用反馈、总时长、模型步骤、工具耗时、结果字符量与用量。
- 建构、编译、消化的写入样本先用隔离副本；精读覆盖、来源完整性、反例/边界、特殊探索质量和写后复核不因提速退步。
- 确认分析实际采用合并审计且没有重复工作区账本；若总时长仍主要耗在模型响应，依据逐轮遥测再决定模型配置或上下文管理调整，不先降低探索能力。

## 三、P1：验证编译闭环

  原书查漏补强后的下一步采用少量真实章节做人工对照：保留初次对象集，从原书不同入口查漏，检查新增重要对象和同类遗漏；分别记录结构处置、对象查漏、忠实度、实际去向及成本。先完成这一验证，不因目标写着 90% 就增加卡片配额、强制全文双读或建设多 Agent 平台。独立上下文与重要性加权评测尚未由程序实现。

  2026-09-05 已补齐来源读取/去向对账、主题验收版本绑定，以及消化范围对账和部分贡献结算。三个 Skill 的对象判断统一，条件性探索不设调用配额。下一步验证真实材料的忠实度、完整对象保留、有效增量与成本，不继续增加工具类别。

- 普通编译样本同时包含短定义、关键反例和图表：漏读或图像延后应保留 Inbox；不要为覆盖配额拆质料。
- 主题样本采用两份存在同词异义、独有机制或尺度差异的材料：检查作者重建是否独立、对象划分是否合理，审计后改变矩阵须重新验收。
- 消化样本让一份 Buffer 同时需要 enrich、新建和延后：部分成功仍在队列，跨批贡献累计，最终说明真实剩余内容。比较人工原文判断，不把测试通过当作认知收益。

### 工作内容

1. 用至少三本结构不同的真实 EPUB 验证目录顺序、长章节、脚注、表格和异常文件。
2. 用有文本层 PDF、扫描 PDF 和包含统计图的 PDF 分别验证正文、失败说明和视觉候选。
3. 在前端提供明确的“继续旧任务 / 重新开始”选择，不要求用户理解 run id。
4. 验证成功归档、同名异内容归档、来源锚点迁移和中途失败保留 Inbox。
5. 记录每次模型阅读范围、Buffer 数量、覆盖缺口与人工质量判断。

### 通过门槛

- 中断并重启后能显示已有进度，继续时不重复写成功 Buffer。
- 文件内容变化后不会误用旧断点，用户可以放弃旧状态。
- 编译成功后源文件只归档一次，Buffer 来源可回查实际 Archive 文件。
- 损坏、加密、超限或超时材料不会生成伪结果，也不会拖死服务。

## 四、P1：验证消化闭环

### 工作内容

1. 选择 2～4 份讨论同一问题的真实 Buffer，重复进行多 Buffer 综合。
2. 检查模型是否先检索和精读已有 Card，再决定 enrich、新建或跳过。
3. 主动制造一次 Harness 拒绝，观察 Loop 是否根据原因改选，而不是结束或原样重试。
4. 检查新 Card 的 `link_now`、`deferred_with_evidence_gap` 或 `intentionally_standalone` 决定是否有证据。
5. 核对每份 Buffer 的实际去向、原有来源保留和重复目标保护。

### 通过门槛

- 综合结果体现共同结论、增量证据、差异和适用边界，不是正文拼接。
- 候选失败后能够补证据、换目标或有理由停止。
- 已结算 Buffer 不再进入默认清单，且能追溯到实际影响的 Card。
- 没有为了满足关系配额制造空泛边。

## 五、P1：验证建构与关系治理

  运行契约见[《2026-08-30 TM、Skill、OPS 与知识流程统一实施 SPEC》](2026-08-30-TM-Skill-OPS与知识流程统一实施SPEC.md)。存量关系不做机械批量迁移。

  P0–P3 问题队列、稳定问题指纹、E1–E4 候选与写入证据分层、关系案件、写前影响模拟、结构化裁决和问题闭合门已经落入代码与合成测试。下一步不再扩张 OPS，而是用真实存量卡验证排序、裁决与结构债变化。

### 工作内容

1. 从冲突缺边、近重复、错型实体、明确可连接和合理独立五类存量样本中各选择少量卡，验证队列优先级与候选信号。
2. 写入前精读端点，区分论证边、情境边、待核验旧边和非法边。
3. 一次只修改一个层面，最多三个紧密相关操作。
4. 写入后以原范围和焦点卡重复同一检测器，确认 readiness、路径或结构问题确实改善；无写入样本也要形成带指纹处置。
5. 保存“本次改变、未改变、待办”和用户对价值的判断，并记录未解释孤立、已确认独立、近重复与错型候选数量。
6. 从 `tmp/construct-eval-candidates.jsonl` 的 100 项候选清单人工确认裁决，补齐裁决时端点版本、支持/反证/边界锚点和风险标签；不得直接把模型历史输出当黄金答案。

### 通过门槛

- 至少完成三个不同局部簇，每次都能说明证据、改动和复核结果。
- Harness 拒绝后返回原 Loop，并产生不同的合法下一步。
- 二跳、三跳论证路径不经过 `legacy_candidate`，argument 与 context 不混走。
- 建构无写入时也能给出具体发现和下一项可验证任务，而不是只报告上下文字数。
- 焦点问题必须进入修复、排除、延期或保持独立之一；Card 变化后问题重新出现时能够重新打开。
- 正式关系评测集覆盖保留、改向/改型、移除、延期和 conflict 角色，且每项均经过人工复核。

## 六、P2：建立认知能力评价基线

  四套固定案例、冻结 fixture、执行 profile、checksum 校验、隔离 materialization 和运行计划已经具备。下一步把计划接入 DSH 模型会话并取得首批可比较 Episode。

1. 将 `run-plan.json` 的每个 checkpoint 接入独立 DSH 会话；同一重复内显式传入上一轮冻结答案，不同重复使用新会话。
2. 先运行 A/B/C/D，再运行 `D_skill_only`、`D_tm_only` 与 `E_thinking_body_v1`，避免把 Skill 与 TM 的贡献混在一起。
3. 分开评价证据忠实度、分析价值、轨迹合理性、成本和稳定性；匿名版先于具名版。
4. `cross-sectional-vulnerability` 与 `multi-timescale-shock-decomposition` 只在对应案例的 overlay 中启用，固定集和后续隐藏集均通过后再决定是否晋升。
5. 首批结果必须保留原始答案、解析答案、Episode、确定性评分和盲评材料；工具存在或计划生成不算能力证明。

## 七、暂不开发

- 生产任务自由修改自身 Skill、Thinking Model、OPS 或代码。
- 新的 Agent 编排框架、图数据库、向量数据库或多 Agent 平台。
- 没有真实案例支持的新 Card 类型、关系类型和 GraphOps。
- 大规模自动补边、自动合并领域或自动删除 Card。
- 核心任务尚不稳定时的大规模界面重写。

  这些方向不是被永久否定，而是必须等当前问题反复证明现有结构不足，并且具备清晰评价与撤回方式后再进入实施。
