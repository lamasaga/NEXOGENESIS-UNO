## 本轮实际实现：思考

- 新建“思考”只需填写问题，不提供路线选择。普通“新对话”也默认创建使用新流程的会话。每轮先由模型结合本轮问题和有限近期对话识别意图；问候、感谢、闲聊、非经济领域问题，以及不需要新增材料的对话整理，直接回应且不扫描知识库。
- 需要经济、金融或商业知识时，模型输出简短问题判断、独立检索问题，以及解释原因、比较选项、检验主张、寻找类比、追溯变化、综合判断之一。程序不再用关键词规则分类，客户端旧路线参数不会锁定后续路线。检索回答附有可展开的“本轮问题判断”，直接聊天不展示这些流程信息。
- 路线同时影响资料优先级和回答指导。比较对明确对象分别检索；检验优先对照和边界；类比优先类比联系；变化优先时间与背景联系。没有词面相关材料时返回空上下文。
- 程序只读取一次缓存的 Markdown 快照，在其中做有限词面与 TAG 匹配、一跳关系收集和去重。最多 9 张卡，每张正文最多 1,800 字符，卡片资料包约束为 22,000 字符；保留有限来源与关系理由，标明正文及来源截断。
- 最近最多 4 组完整问答、约 8,000 字符进入历史上下文。旧轮次的检索资料包不再次发送，不额外调用模型做摘要。
- 直接分支在意图识别的同一次请求中流式回答，共一次模型调用、零次知识收集。检索分支在识别之后收集一次资料，再请求一次最终回答，共两次模型调用；两个阶段的用量分别记录并汇总。每轮重新分流，不沿用上一轮分类。两阶段均无工具调用权限，不执行知识写入、不做模型重排、自动补检或失败重试。
- 意图协议为一行有上限的 JSON 控制信息，直接回应正文随其后流式传送；控制信息不进入答案正文。格式无效、截断或在检索前夹带答案会明确失败，不猜测路线或暗中增加模型请求。
- 保留流式输出、停止、来源回查、对话记录、部分回答状态和实际用量。资料已提交后禁止立即插入；补充可排入下一轮。执行期间阻止删除对话和切换实例。
- 前端在创建新思考或普通新对话前检查后台能力标记 uno_intent_routing=1，避免新版界面静默使用旧后端。健康标记只说明代码路径，不证明回答质量。

核心实现：[意图协议](../packages/nexogenesis-web-host/lib/thinking-intent.js)、[资料路线](../packages/nexogenesis-web-host/lib/thinking-routes.js)、[分流与会话](../packages/nexogenesis-web-host/lib/quick-thinking.js)、[思考界面](../web/src/components/ThinkingSetup.tsx)。

单次生成部分参考此前 DSH 的快速思考实现，只迁入需要的会话和生成机制，再接入 UNO 路线；没有整体复制 DSH 后续控制器或旧知识。保留 quick 等兼容标识不表示新界面仍要求选择两套模式。

## 本轮实际实现：编译与建构

- 编译直接选择多份材料和主题，原文切片进入共享主题 Buffer，一批一次请求摘要成多标签卡片。每批最多两份原文单元、六张卡片；没有中间笔记、对象贡献账或全库语义去重。
- 仅按标题高度相似度提示少量候选。用户可以确认保留独立卡片或跳过重复候选；没有模型去重调用。逐批确认和完全信任设置继续有效，信任模式遇到高近重标题仍需确认。
- 原文版本、定位、单元处理状态与实际卡片去向保留在 Markdown。相同原文跨主题引用，不复制正文。完成或明确跳过的文本归档；提取失败、PDF 图表与 OCR 未核验材料保留在 Inbox 并标记部分完成。
- 建构按当前知识体或一个标签固定范围，以词语、标签和已有正文缩小候选，每批最多十二张卡的一次模型请求，生成相关、对照、类比、边界、背景五类检索联系。无合适联系可以结束，不强制连通或证明。
- 新卡使用 uno-card-v1 和 tags，不写唯一 type；旧图标分类只在读取时派生。标签已接入卡片正文阅读、浏览筛选、图谱与思考检索。
- 所有知识写入通过 HarnessGateway 新方法，保留授权、路径、来源、两端版本、重复边和批次幂等检查；事务失败回滚，中断恢复先核对收据。旧正文、标签和关系含义不因补充弱联系而改写。
- 新面板支持完整候选预览、原文回查、暂停、继续、重新生成和历史任务重开；后台任务保留每次调用的模型、Token 用量、耗时和状态。保存成功但任务状态尚未更新时，不再请求模型或重写卡片。
- 编译、建构按钮直接进入新面板，主应用撤下旧的编译 / 主题编译 / 消化和两步建构准备分支。历史任务仍可恢复，不重新创建旧流程的新任务。

完整流程、数据位置与限制见[编译与建构](UNO-编译与建构.md)。核心实现：[任务执行](../packages/nexogenesis-web-host/lib/uno-jobs.js)、[Gateway 事务实现](../packages/nexogenesis-tools/lib/harness/uno-storage.js)、[卡片与标签契约](../packages/nexogenesis-tools/lib/uno-contract.js)、[工作面板](../web/src/components/UnoKnowledgePanel.tsx)。

## 当前限制与兼容边界

模型连接设置已参考 DSH 完善：直接选择常用型号与原生套餐 ID，供应商间分别暂存草稿和密钥，新增只读目录测试与错误提示。实际接口、测试含义与原生能力边界见[模型连接](UNO-模型连接.md)；目录可访问不代表实际生成已经验证。

新默认编译与建构已经使用新路径；旧聚合、消化、单值类型、领域容器与强关系校验仍留在历史任务和工具中，不作为新流程的要求。新 Schema 的写入由新 Gateway 方法负责，不通过旧完整卡片覆盖接口降级为单值类型。

新弱联系已验证从生成、写入到检索的程序路径，不等于真实反例或类比成立。卡片正文、来源与关系候选是否忠实、有用仍需模型样本评测。当前没有自动合并、自动精修或跨域语义搜索，用户确认跳过的重复候选也不会覆盖旧卡。

当前检索使用本地词面、元数据和已存关系；模型在意图阶段结合历史补全检索问题，没有额外的查询改写模型、向量库或联网研究。跨域类比是否有用取决于卡片和关系质量。意图判断和路线排序仍须真实样本验证；不承诺分类始终正确或任意比较对象都能准确拆分。用户可以通过自然语言补充或纠正问题，下一轮重新判断。

旧研究请求、旧原生会话和编译建构任务保留原协议，仍可能进入旧 Agent Loop，不自动转换历史任务。已经使用 quick 流程的会话在加载新后端后改为每轮意图识别，新建普通对话也默认使用该流程。完整移动工作台尚未完成适配；已验收思考以及新编译、建构面板的窄屏布局。

第三方 @deepseek-ai 包、DSH_HOME/DSH_WEB_URL 协议、preset、Cordis 服务及 HarnessGateway 仍用于兼容，不机械改名。新知识写入继续遵守 Markdown 主权、授权、合法路径与来源、版本冲突、幂等、原子提交和真实收据。
