# 知识沉淀闭环与图谱质量设计

> 状态：已进入实现
> 日期：2026-08-28
> 范围：Compile、Digest、Construct、HarnessGateway、知识质量 Observation

## 一、目标

  知识沉淀的目标不是产生更多 Markdown 文件，而是形成思维体可以稳定检索、组合、质疑和追溯的知识底座。每张卡至少应让思维体回答五个问题：它在主张什么或描述什么、依据是什么、在什么条件下成立、来源在哪里、与哪些既有知识存在何种可解释联系。

  因此，本次优化把“分析可用性”作为验收标准。结构合法只是最低条件；只有正文、来源、贡献去向和图谱位置都能被后续推理利用，才算完成沉淀。

## 二、当前事实与缺口

  2026-08-28 对 996 张活跃卡的确定性审计结果如下：676 张未发现规则级缺口，241 张需要复核，79 张存在会影响使用的确定性缺口。主要问题包括 94 处必需语义槽缺失、9 处必需槽只有占位内容、172 张非领域卡尚未完成关系复核、51 张卡仍在正文使用 Wiki 链接，以及 5 张卡的 `origin` 不符合当前枚举。

  当前还有 4083 份 Buffer。数量本身不代表待办严重程度，但如果消化只是逐片建卡、跳过没有理由、贡献结算回退到整批操作，这个规模会迅速放大重复卡、错型卡和浅关系。

  已确认的具体漏洞：

- Buffer 写入过去只检查角色、标题和 80 字长度，没有强制来源锚点，也不阻止占位正文与标题回声。
- 新 Card 过去只检查 id、标题、类型字段是否存在，不检查七型语义槽、来源、领域归属和占位内容。
- 正文契约一边禁止用“原文未提及”凑格式，一边又要求缺槽时写该占位语，实际鼓励了形式合格但无法推理的卡。
- Digest 的旧提示仍描述批量 YAML 和 `write --batch`，与 DSH 的语义补丁、贡献账本和 HarnessGateway 不一致。
- Buffer 的贡献账本在映射缺失时会把整批操作当作该 Buffer 的去向，导致审计记录不精确。
- Construct 能观察结构，但缺少统一的内容质量观察，难以把错型、缺槽和占位卡纳入修复选题。

## 三、完成定义

  一份来源完成知识沉淀，需要经过以下闭环：

```text
来源地图与覆盖范围
→ 有来源锚点的语义质料
→ 明确的 enrich / create / skip / defer 判断
→ 通过类型与来源门槛的 Card
→ 精确记录每份 Buffer 的实际贡献
→ 写后复核内容质量与局部图谱位置
→ 将仍需证据的结构问题交给 Construct，而不是强行连边
```

  “写入成功”不再单独等于“沉淀完成”。写入回执还应包含受影响卡片的质量观察；Digest 与 Construct 根据这个 Observation 决定继续补内容、检查关系、记录待办或结束。

## 四、分层门槛

### 4.1 硬门槛

  硬门槛只处理可以确定判断、且放行会直接污染知识体的问题：

- Buffer 必须有来源锚点，正文不能明显过薄、不能只有占位内容、不能预写 Wiki 关系。
- 新 Card 的 `type`、`maturity`、`lifecycle`、`origin` 必须属于活契约枚举。
- 新 Card 必须满足对应类型的必需语义槽；必需槽不能以“原文未提及”“暂无”“待补充”等占位语交差。
- 文档与外部来源 Card 必须声明可追溯来源；非领域 Card 必须进入至少一个真实领域。
- 内容 enrich 不要求一次修完所有历史缺口，但不得新增缺槽、占位槽或其它确定性质量倒退。
- 每份已结算 Buffer 必须明确指向它真实影响的 Card；不再允许用整批操作兜底。

### 4.2 质量告警

  下列事项需要语义判断，不能机械阻断：

- 一张卡是否确有必要新建，还是更适合 enrich。
- 卡片与现有卡是否近义重复。
- 一条关系是否有足够证据，以及关系类型是否表达了真实论证。
- 没有关系的卡是否真的孤立。无关系只触发复核，不强制连边。
- 用户或系统综合卡尚未声明对话或知识依据。
- domain、phenomenon、conflict 是否写了易读的“诠释”。

  告警进入 Observation 与写入回执，供 Digest 写后复核和 Construct 选题；它们不能被悄悄吞掉，也不能自动转成无依据的结构修改。

### 4.3 存量兼容

  旧卡允许继续被读取和渐进修复。Creation 使用完整硬门槛；Content 与 Digest-content 使用“不可新增质量缺口”的非回退规则。这样不会因为历史卡缺槽而阻断所有 enrich，也不会让一次修订把新的空槽或错型结构写回知识体。

## 五、三个知识流程的职责

### 5.1 Compile：保留可再加工的真实质料

  Agent 先建立来源地图和覆盖清单，再按论证、证据、条件和表图边界读取有限窗口。每个 Buffer 必须说明它保存的判断或材料、关键依据、适用边界和来源位置。字数只用于拦截明显空心内容，不能替代语义质量判断。

  高质量图书、论文和金融报告继续采用两段式语义审稿；碎片材料不强制两段式，但仍不能省略来源和足以复用的事实或机制。Harness 拒绝后返回修复或延后两种合法动作，Agent 应修订当前质料或改读证据，不得把一次拒绝当作整个编译结束。

### 5.2 Digest：结算知识贡献，而不是结算文件

  Digest 先按共同问题与可能承接对象组合 1–6 份 Buffer，再比较其共同结论、增量证据、差异、冲突和边界。每个语义补丁必须写 `contribution_summary`，说明这组质料实际给目标卡增加了什么。

  `skip` 只用于已经确认没有新增贡献的质料，并必须记录原因；无法判断时使用 `defer`。新建卡必须通过七型槽、来源和领域门槛。写入后读取质量回执并检查受影响卡片，必要时把关系或结构问题交给 Construct，而不是在正文补丁中夹带结构修改。

### 5.3 Construct：持续改善可推理结构

  Construct 的对象不只是孤立节点和领域归属，还包括错型、缺槽、占位、来源异常与尚未复核关系的卡片。`inspect_knowledge_quality` 提供确定性候选，GraphOps 提供局部邻域与论证结构；模型负责判断哪些问题值得修复以及是否存在有证据的潜在联系。

  建构不能以“每张卡至少一条边”为目标。它应区分没有被检查、证据不足和确实独立三种状态。每次写后重新观察受影响卡的质量与邻域；达到轮次上限、局部结构稳定或剩余问题需要新证据时结束。

## 六、与思维体的接口

  沉淀质量最终通过思维体的使用效果验证，而不是只看校验通过率。Card 应向检索与推理提供：对象类型、核心语义槽、条件边界、来源摘要、领域归属、论证关系以及关系说明。Thinking Model 可以据此选择证据三角验证、机制对照、情景条件等策略，而无需重新扫描长材料。

  后续评测至少覆盖：检索命中是否包含真正相关卡、回答能否区分事实与推断、关键结论能否追溯来源、冲突和边界是否被主动使用、Graph 相比纯文本基线是否提高解释完整性而非只增加引用数量。

## 七、本次实现范围

- 新增确定性 Card / Buffer 质量审计模块。
- Buffer 写入门槛改为结构化 Harness 拒绝回执。
- Creation 严格校验，Content / Digest-content 使用非回退校验。
- 写入回执返回受影响 Card 的质量结果。
- 新增 `inspect_knowledge_quality` 只读 OPS，供 Digest 与 Construct 使用。
- Digest 补丁强制说明贡献；Skip 新接口要求理由；贡献账本取消整批兜底。
- 统一正文契约、共享提示、Digest 提示与三个 Skill 的真实行为。
- 增加质量门槛、贡献结算和存量兼容测试。

## 八、验收标准

- 无来源、明显空心或含 Wiki 关系的 Buffer 无法落盘，并得到可修复回执。
- 错型、缺必需槽、占位必需槽或文档来源为空的新卡无法通过预检。
- 存量缺陷卡仍可 enrich，但修订不能新增确定性质量缺口。
- 每份 settled Buffer 在 Contribution Ledger 中都有精确目标与贡献说明；skip 有理由。
- Construct 可以直接取得质量问题候选，并在关系证据不足时保留为复核项而非强制连边。
- 完整 Node 测试、Web 测试与前端构建通过。

## 九、明确不做

  本次不自动批量重写 79 张存量缺口卡，不新增卡片类型，不引入向量数据库或新的工作流框架，也不把质量分数包装成知识真伪评分。质量审计只负责发现确定性结构缺口；知识是否真实、重要和有解释力，仍由模型结合来源证据与后续评测判断。
