# 思维体核心技能与图谱行为统一设计

> 状态：实施规格
> 日期：2026-08-28
> 范围：DSH Web 思维体的 talk / assess / report / emerge / refine，及其共用 Thinking Model、OPS、CognitiveRun、Harness 和图谱动效接线

## 一、目标

  本次更新不是再增加一套固定流程，而是让现有思维体形成可验证的闭环：理解任务，选择审视方式，调用真实 OPS，以 Observation 更新工作区，在证据足够时输出分析，在用户授权时沉淀知识，并让中央图谱忠实呈现已发生的操作。

  完成后，用户应能明确区分：模型正在采用什么审视方式，刚刚真实查询或读取了什么，哪些内容成为了依据，哪些只是候选或猜想，任务是已完成、等待确认还是因证据不足停止。

## 二、当前问题

1. Skill 已覆盖对话、研判、报告、涌现和精修，但输出状态、证据分级和停止条件不统一。
2. 研判和报告仍主要依赖 Skill 文本要求，没有通过 Thinking Model 对必需观察能力形成运行时约束。
3. Thinking Model 的完成校验只看 Operator 是否调用过，被拒绝、失败或取消的观察也会被误算为能力证据。
4. 普通对话使用持久 general run，跨多轮累计的步数和读取预算可能阻断后续正常问答。
5. trusted 模式的语义补丁和领域操作虽已写入，回执结构嵌套在 `data.receipt`，事件层容易误投影为“已提案”而不是“已写入”。
6. `tm.selected`、来源追溯和部分结构操作没有对应的前端语义；领域成员的动效文案又被误写为“知识领域”。
7. 旧 `/judge` 兼容入口仍在活契约和 Skill 目录中，与已统一为 assess 的产品语义冲突。

## 三、核心边界

### 3.1 Skill

  Skill 只定义用户意图、权限、必需产物、知识沉淀路径和停止标准，不复制 OPS 实现，不把模型硬锁成唯一工具顺序。

### 3.2 Thinking Model

  Thinking Model 是可选的审视约束，不是隐藏思维链模板。它必须声明用途、必需能力、偏差校正和停止条件；必需能力只能由成功或有效的部分 Observation 满足。

### 3.3 OPS 与 Observation

  OPS 是唯一的图谱行为入口。前端动效、思维工作区和完成校验都消费同一份结构化 Observation，不从回答文本或工具名猜测模型做了什么。

### 3.4 Harness

  Harness 仍是知识与报告写入的唯一通道。talk、assess 只读；report 只在用户要求保存时提案；emerge、refine 始终需要用户确认。知识摄入流程的主权模式由另一套已有设置决定，不改变思维体写入权限。

## 四、核心 Skill 契约

| Skill | 主要产物 | 必需图谱行为 | 写入边界 | 正常停止 |
|---|---|---|---|---|
| talk | 直接结论、依据、边界与未知 | 检索；重要依据精读；复杂问题按需比较、冲突检查或溯源 | 不写入，最多询问一次是否捕获 | 已回答问题，或明确说明知识缺口 |
| assess | 条件式研判，含 2–4 个有区分度的观察角度 | 每个角度都要留下真实 Observation；争议问题必查反证或冲突 | 只读 | 给出定位、适用条件、不确定性和需用户承担的选择 |
| report | 可独立阅读的结构化报告 | 提纲所有核心结论均有读卡或溯源依据，反证不能只是形式段落 | 默认留在对话，明确要求保存才提案 | 回答核心问题，证据、边界和待验证项可追溯 |
| emerge | enrich / create / skip 三类候选决定 | 近义检索、关键卡精读、必要时检查冲突与来源 | 最多三项，用户确认后由 Harness 写入 | 候选被接受、拒绝或明确不应沉淀 |
| refine | 一张现有卡的可审阅差异 | 读取完整现状；语义改变时追加来源或相关证据 | 单卡、单结构层、用户确认 | 用户理解改了什么及为什么，写入回执明确 |

  所有输出都使用共通的用户状态：“已完成”、“等待你确认”、“需要补充信息”、“受阻”。不得在没有可操作确认卡时要求用户“点击确认”。

## 五、新增的 Thinking Model

1. `evidence-triangulation`：检查结论是否有多条独立依据、来源质量和反证，适用于可靠性问题与报告核心判断。
2. `mechanism-contrast`：比较多种解释机制的因果环节、覆盖范围和失效条件，适用于“为什么”和理论争议。
3. `scenario-conditions`：用已有证据组织基准、上行和下行条件，不把情景写成无条件预测。

  这三种模型只复用现有 retrieve、read_card、compare_nodes、inspect_conflicts 和 trace_source 能力，不新造尚未实现的 OPS。

## 六、真实事件与动效

| 真实事件 | 可视化 | 不得表达的含义 |
|---|---|---|
| `tm.selected` | 底部工作信息区更新“审视方式”，使用克制的淡入 | 不把 TM 画成知识节点 |
| 检索 Observation | 只点亮真实命中节点 | 检索请求发出不等于已命中 |
| 读卡 Observation | 橙黄色节点光晕 | 失败或被拒绝不显示成功读取 |
| 关系 Observation | 沿真实 edge id 传播，保留关系原色 | 不为类比或文本共现伪造知识边 |
| 来源追溯 | 突出真实卡片并显示“追溯来源” | 来源不是图节点时不画连线 |
| trusted 写入回执 | 新建和丰富节点进入写入完成动效 | 不显示“等待确认” |
| 手动提案 | 只显示待确认状态 | 不提前把预览当成已落盘知识 |

  动效引擎保持小型稳定词汇，新 Skill 通过现有事件自然获得动效，不按 Skill 名称复制视觉逻辑。减少动态模式下仍保留文本状态、节点颜色和事件顺序。

## 七、本次实施范围

1. 新增共用思维输出契约，重写 talk、assess、report、emerge、refine 的产物、证据与停止要求。
2. 新增三个复用现有 OPS 的 Thinking Model，并纳入契约闭合测试。
3. 修复 Thinking Model 的有效观察判定和 general 对话跨轮预算误阻断。
4. 把 trusted 写入回执规范化为统一结构，确保事件投影为 `write.applied`。
5. 补齐常用 OPS 的人类可读名称、TM 切换和来源追溯的前端语义，修正领域成员文案。
6. 删除已废弃的 nexo-judge 活入口，多角度分析只保留 nexo-assess。

## 八、验收标准

1. 失败或被拒绝的 Operator 不能满足 Thinking Model 必需能力。
2. 普通对话不会因过去多轮读卡而永久阻断；compile、digest、construct 的原有治理约束不受影响。
3. trusted 语义补丁和领域操作写入后，事件必须含有真实 created/enriched，前端播放写入完成而非待确认。
4. `tm.selected`、trace_source、graph_members 均有准确且不夸大的界面状态。
5. 所有 Thinking Model 的 required capabilities 在真实 OperatorRegistry 中可闭合。
6. 前端单元测试、Node 运行时测试和 Web 生产构建通过。

## 九、为未来保留的接口

  未来增加新的研究型 Skill 时，只需声明产物、读写权限、停止条件和可用 Thinking Model。新 Thinking Model 只声明现有 capability；只有现有 OPS 确实无法产生所需 Observation 时，才增加新 Operator。新 Operator 只要返回标准 Observation，就能被 Episode、Workspace、TM 校验和 CognitiveEvent 统一消费。

  本次不引入新工作流编排器、不把运行事件升级为事件溯源数据库，也不展示模型隐藏思维链。这些都不是当前闭环所必需。
