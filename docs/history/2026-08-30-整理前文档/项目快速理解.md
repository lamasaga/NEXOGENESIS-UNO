# Nexogenesis 项目快速理解

> 写给第一次接触本项目的人。不堆术语，只讲「它是什么、怎么转、有什么特点」。  
> 更细的契约与命令见 `[AGENTS.md](../AGENTS.md)`；开发欠账与结构真图见 [`架构真图与后续路径.md`](架构真图与后续路径.md)。

---

## 一句话

　　**Nexogenesis（智构涌现）是面向一位思想者、或一个学派的知识架构体系**：用大模型把材料**聚合涌现**为可修订的立场、模型、冲突与证据结构——再经讨论与建构校准。它不是把书自动切成碎片的批处理器；切得碎、槽位齐，不等于有知识结构。

---

## 它解决什么问题

　　笔记与资料库往往停在「收集」：材料很多，却缺少**可演进的知识架构**——说不清核心问题域、主张与对立、解释世界的框架，也难在后续讨论里被系统性地挑战与改写。

　　Nexogenesis 要做的是另一件事：

- 为思想者或学派搭一套**可外化的知识骨架**（领域、主张、模型、冲突、关系与来源）；
- 把阅读与对话当作**进料与考验**：新材料、新反馈进入后，用来丰富、修正或拆开旧结构，而不是只多一篇摘要；
- 在讨论、分析、建构的循环里，让架构自己「长出」新观点、新认识，以及更能说清世界的诠释——**涌现是结果，架构是载体**。

## 常见疑问：公版知识入库，对大模型还有用吗？

　　例如用本系统处理一系列经济学教材。这些内容基座模型多半已经学过。那搭出来的知识库，回答这类问题时会不会有**实质性**提升？

　　**结论先说：** 如果只是把教材再抄进库、再让模型复述公版内容，对「会不会背教材」的提升通常不大，甚至接近零。基座模型在这类材料上往往已经够用。Nexogenesis 的价值不在「让模型第一次学会供求曲线」，而在**你搭的那套架构如何约束、校准、复用回答**。

### 什么题有增益，什么题几乎没有


| 问题类型 | 基座模型本来怎样 | 知识库通常多出来什么 |
|----------|------------------|----------------------|
| 「什么是机会成本？」式事实 / 定义 | 往往已经答得不错 | 增益有限；最多是措辞更贴你选的教材版本 |
| 「用我们课的框架解释通胀」 | 会混多种教材口径 | **有**：强制走你消化后的模型卡、领域边界、术语偏好 |
| 「A 派与 B 派在这里怎么对立」 | 容易和稀泥或漏一边 | **有**：冲突卡、各自证据、失效边界被显式召回 |
| 「这和上周我们定的主张是否打架」 | 没有你的会话承诺 | **有**：长期结构 + 短期记忆，回答可对照「已承诺」观点 |
| 「引用第几章、别把教科书说成我的立场」 | 归因常糊 | **有**：来源与文档观点 / 用户立场分开 |

　　所以：对**公版回忆题**，别指望「建库 = 模型变聪明」；对**带架构的解释题、比较题、学派题、教学一致性题**，才可能有实质性差别。

### 「实质性」在这里指什么

　　不是参数变多了，而是回答的**约束条件**变了：

1. **召回的是你的结构，不是全网平均通识**——检索拉的是卡片关系网与你入库的摘录；模型仍会用预训练知识补洞，但主骨架可以变成「这套材料消化后的领域 / 模型 / 冲突」。
2. **可修订的承诺，而不是一次性发挥**——你改一张主张卡、补一个冲突，下次对话会跟着变。这是架构在演进，不是又摘要了一遍。
3. **对抗与边界被摆上台面**——公版教材内部也有张力（流派、假设、适用条件）。若消化与建构认真做了冲突与失效边界，回答更像「定位」，而不是标准答案腔。
4. **教学 / 学派场景的一致性**——同一套卡给不同人、不同轮次用，口径可对齐。这是产品价值，不一定是「准确率榜上多几分」。

　　若库只是「章节摘要堆叠、无关系、无冲突、无你的取舍」，那和「把 PDF 丢进普通检索」差不多，对已学过教材的模型，提升往往很薄。

### 什么时候值得啃公版教材

**值得：**

- 你要的是一门课 / 一个学派的**外化架构**（问题域、核心模型、争议点、例题与反例怎么挂）；
- 后续有大量讨论、作业、比较解释、改写框架，需要同一骨架反复被考验；
- 你关心归因（教材原意 vs 你的诠释）和版本（用哪一派、哪一版）。

**不太值得（仅为此）：**

- 只想偶尔问「GDP 是什么」——直接问大模型更省；
- 入库质量低：无结构涌现、只有复述——等于给模型喂它已会的文本，还多一层维护成本。

　　预训练解决的是**统计上的通识**；你的库解决的是**某一个思想主体的架构与承诺**。教材再公版，「我们采用哪条主线、拒绝哪条调和、哪里标失效」并不是基座里的稳定对象——那才是本系统该长出来的东西，也才是回答质量可能实质变化的地方。

　　一句话：**公版知识进库，买的不是「模型没学过」，买的是「可演进的学派 / 课程架构 + 受约束的再诠释」；没有架构，就几乎买不到提升。**

## 三层分工

```text
你 + AI（思维）     →  聊天、判断、提议要不要记下什么
Harness（程序）     →  检查格式、统一写入、建索引、防写坏
Markdown 文件（底座）→  真正的知识内容，删了程序也能读
```


| 谁      | 干什么                     | 不干什么     |
| ------ | ----------------------- | -------- |
| **你**  | 决定记什么、改什么立场、批不批准写入      | —        |
| **AI** | 理解材料、找关联、写候选、组织回答       | 不经你同意改卡片 |
| **程序** | 校验、原子写入、生成目录视图、图/RAG 索引 | 判断内容好坏   |


　　**底座纪律**：约定文件夹里的 **Markdown 是内容的唯一权威**；图索引、搜索索引都可以删掉后从 Markdown 重建。Git 用来留历史、回滚，**不是**思想本身。

## 文件夹在干什么（地图）

```text
00-Inbox/          刚放进来的原文（书、论文、网页导出…）
05-Buffer/         编译后的「质料」——还没承诺成正式知识
01-Cards/          正式知识卡片（扁平存放，靠关系而不是文件夹分类）
02-Profile/        你的问题清单等档案
03-Archive/        已处理完的原文
04-OutBox/         某次分析、讨论纪要（可检索，默认不算「已定结论」）
06-Journal/        系统操作大事记
07-Conversations/  Web 对话原文（不是卡片）
```

　　可以记成两条线：

1. **对话线**：聊 → 偶尔「记一下」→ 你确认 → 进卡片或问题清单
2. **阅读线**：Inbox → 编译成 Buffer → 消化进卡片 → 必要时再整理整体结构

## 两种「东西」：质料 vs 卡片

　　这是本项目最容易搞混、也最重要的区分。


|          | 质料（Buffer）         | 卡片（Card）             |
| -------- | ------------------ | -------------------- |
| **像什么**  | 厨房里的食材、剪报          | 菜谱上的一道道「认定」          |
| **从哪来**  | 编译文档、对话草稿          | 你确认后的写入              |
| **特点**   | 有摘录、有来源，**还不承诺结构** | 有类型、有关系、可长期复用        |
| **七种卡片** | —                  | 领域、主张、现象、模型、方法、实体、冲突 |


　　**问题清单**单独放在 Profile，不算卡片类型；**阶段性长文回答**可以放 OutBox，需要时再拆成卡片。

## 日常怎么用（对话为主）

　

1. **正常聊**：问问题、要分析、要反驳——模型可按需在图上搜索、走边、读卡；**不保证**每一轮都先检索再答。
2. **偶尔被轻问一句**：设计上，出现很值得留下的判断时系统可以问「要不要记下？」——目前这条门铃主要在 CLI，Web 还没接上。
3. **你说「记一下」**：给出少量候选（自然语言），你改完再批准。
4. **批准后**：程序一次性写入，并更新索引。
  **分析默认留在对话里**，不会自动变成报告文件；**写入永远要你确认**，对话捕获不会自动入库。



### 思维体在后台补的三样东西


| 名字       | 大白话                           |
| -------- | ----------------------------- |
| **长期记忆** | 已有卡片和它们之间的关系                  |
| **工具书**  | 归档原文、讨论稿、Buffer 片段——用来查细节、引证据 |
| **短期记忆** | 最近对话的焦点、张力、引用过哪些卡             |


　　在 Web 里，nexo 每轮会带上你最近的焦点、张力和协作约定；要不要上图翻卡片，由模型按剧本选用 GraphOps，而不是系统先打好一整包检索结果再开口。CLI 另有 `retrieve`，给消化选种和命令行打包用。

## 读文章时怎么用（摄入线）

　　当你往 `00-Inbox/` 放了材料，典型顺序是：

```text
compile   快节奏意义切片：少标注，把杂乱原文切成消化时舒服的 Buffer
   ↓
digest    对着领域骨架滋养（v3.1）：enrich 优先，偶发新建
   ↓
construct 在卡片网上发现、合并、升枢纽与张力
```

　　每一步都是：**程序生成任务说明 → AI 产出结果 → 你或** `--auto` **自检后 → 统一写入**。图书会先在 `.nexogenesis/tmp/compile/materials/` 里按章切一份可重建缓存，不要把章节稿再拆进 Inbox。

　　说「开始消化 / 开始建构」或加 `--auto`，表示你授权这一轮自动自检落盘；**不是**让 AI 随便改库。

## 检索：对话走图，质料另有一本账

　　Web 问问题时，模型在**结构图**上搜索、走边、读卡（GraphOps）。原文摘录、Buffer、讨论稿走**质料搜索**（RAG/FTS），主要给消化/建构选种和 CLI `retrieve` 打包；对话里默认不把质料包当「唯一世界」。

| 方向       | 找什么        | 谁在用       |
| -------- | ---------- | -------- |
| **结构图**  | 相关卡片、关系、冲突 | Web 对话主路径；消化也会用 |
| **质料搜索** | 原文摘录、讨论、归档 | CLI / 摄入选种；讨论稿标成「研讨草稿」，**不能**当成已认定主张 |

　　命令行若要一次性打结构+质料包：`python -m nexogenesis retrieve --query "…" --mode talk`。这不是 Web 问答的统一入口。

## 七个特点（为什么不是普通笔记软件）

1. **文件即真相**：不绑死某个数据库；换电脑、删索引，Markdown 还在。
2. **写入有闸门**：改卡片必须走 `write --batch`，先校验再落盘，失败不留半成品。
3. **质料与结论分层**：没想清楚的内容不会假装成正式知识。
4. **冲突要露面**：鼓励用「冲突卡」记录对立，而不是只留赢家。
5. **领域是骨架**：用「领域卡」组织空间，而不是深层文件夹。
6. **架构可演进**：讨论、反馈、分析与建构用来考验并改写骨架，而不是只往里堆材料。
7. **复杂度要证明**：新机制必须能说清解决什么摩擦、怎么撤回——避免系统越养越重。

## 五分钟上手

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows
pip install -e ".[dev]"

python -m nexogenesis init      # 建目录、装 hook
python -m nexogenesis doctor    # 自检
```

**只想聊天、用已有库：** 启动 Web（见 `AGENTS.md` §八），不要把 CLI `retrieve` 当成聊天入口。

```bash
.venv\Scripts\python.exe -m nexogenesis serve --root . --port 8787
```

**刚丢了一篇 PDF/文章进 Inbox：**

```bash
python -m nexogenesis compile --plan    # 先看怎么分批
python -m nexogenesis compile         # 生成编译任务
# AI 写完 response 后：
python -m nexogenesis compile --check-responses
python -m nexogenesis compile --apply
```

**命令全集**：见 [`.agent/reference/harness-cli.md`](../.agent/reference/harness-cli.md)。

## 和 AI 协作时，它读什么、守什么

**每次重要操作前，AI 应读：**

- `AGENTS.md`（规矩）
- `01-Cards/_meta/ontology.md`（卡片类型）
- 与问题相关的卡片或自动生成的领域/冲突视图

**AI 必须遵守：**

- 不绕过写入入口直接改卡片  
- 区分「你的话 / 文档的话 / 系统推测」  
- 优先丰富已有卡，少造空卡；图表挂进依据，少独立图注卡  
- 可核验的最新事实/统计序列默认外查，不靠堆卡膨胀  
- 捕获须你批准

**你不必遵守：** 背诵全部 CLI；用自然语言说意图即可。
