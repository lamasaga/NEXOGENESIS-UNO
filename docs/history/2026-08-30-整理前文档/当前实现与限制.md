# 当前实现与限制

> 核对日期：2026-08-29。本文描述当前代码，不描述长期愿景。

## 运行方式

  DSH 负责模型会话和工具调用循环。`nexogenesis-tools` 注册知识工具，`nexogenesis-web-host` 把 DSH 会话接到现有 Web 界面。页面上的编译、消化和建构按钮只创建对应任务会话。

## 编译

  当前编译工具能列出 Inbox、给纯文本、Markdown 和常见 EPUB 建立段落、章节、表格和图片引用索引，按位置读取有限片段、写入 Buffer，并检查哪些索引项已覆盖。EPUB 在工具内解包，模型只接收正文与 `EPUB spine` 来源位置。Web 点击“编译”时先由用户选择一份 Inbox 材料，随后 DSH Agent Loop 只在该材料范围内自主阅读和生成 Buffer；选择器不规定阅读步骤。

  覆盖审计完成并以 `completed` 结束后，Harness 会把本轮源文件从 `00-Inbox` 移到 `03-Archive`，同时把本轮生成 Buffer 的来源锚点改为实际归档路径。若归档目录已有同名但内容不同的文件，会保留两者并给新版本追加内容指纹；不会覆盖旧材料。任务失败、阻塞、暂停、没有有效 Buffer 或来源锚点无法迁移时，源文件继续留在 Inbox，任务也不能被误报为完整完成。

  当前限制：

- EPUB 目前覆盖普通 ZIP、stored/deflate 压缩和 XHTML spine；加密、ZIP64、损坏文件会明确停止。真实长书、复杂样式、脚注和非 UTF-8 EPUB 仍需继续验证。
- DOCX 等其他压缩容器仍只会被识别并停止，尚不能提取正文。
- PDF 依赖 Poppler 的文本提取和页图工具；有文本层的常见 PDF 可以按页读取，扫描版、损坏文件、复杂编码和 OCR 仍不能承诺可靠处理。
- HTML 没有正文清洗和章节还原。
- 同一材料版本可检索旧断点，并在用户明确选择继续后恢复已读位置、覆盖清单和已写 Buffer 记录；前端尚未提供专门的“继续/重来”窗口，模型需要在对话中询问用户。
- 当前一次完成收尾只支持归档一份冻结材料；Web 选择器本身也以单份材料为一次编译范围。多份材料需拆成独立任务，避免共用一份覆盖与归档状态。
- PDF 已接入编译专用视觉模型与关键图片归档，但必须在设置中另行配置支持 `image_url` 的 OpenAI-compatible 模型。未配置或识别失败时只登记候选并延后，不由 DeepSeek 文字模型猜测。该能力已由第一组计量经济学样本验证，尚未在大量版式、整本扫描材料和复杂统计图上形成稳定性结论。
- EPUB 图片目前仍只保留正文引用和来源位置，尚未复制其二进制图片或接入同一视觉复核通道。

## 消化

  当前工具先列出未结算 Buffer 的标题、来源和有限摘要，再按需读取质料、检索并精读候选卡。一次 Card 修改可以综合 1～6 份相关 Buffer，并把它们编译成一个最终 Card 版本；正文与对应 Buffer 来源一起提交，确认后逐份记录实际影响的目标 Card。已经结算或跳过的 Buffer 默认不再出现在待消化清单中。

  Harness 会拒绝同一批次中的重复目标 Card，避免多个从旧版本展开的补丁互相覆盖。已有回归测试覆盖多 Buffer 单补丁、既有来源保留、精确贡献结算和重复目标保护。

  当前限制：

- 失败后改选候选主要依赖模型根据工具结果继续判断，真实稳定性尚未形成回归案例。
- 一次只允许正文补充或新建一个层面；消化正文会自动追加本次 Buffer 来源，其他领域、关系或来源调整仍需另提操作。
- 多 Buffer 的工程契约已经具备，但“共同结论、增量证据、差异和边界”能否被模型稳定综合，仍需真实材料验证；结构安全不能替代内容质量评价。
- 还没有足够证据证明它能长期避免重复卡和错误归属。

## 建构

  当前工具可以搜索局部图、查看领域成员、模拟领域拆分，并从全库元数据区分完全孤立、缺关系和缺领域的卡。对确认合适的无领域卡，可提出少量归入既有领域的成员操作；这不会自动建立关系或凭标题批量归类。

  当前限制：

- 工具存在不代表模型一定会选对范围或产生有价值修改。
- 领域拆分、关系梳理和冲突建立尚未在足够多真实知识库上验证。
- 所选 Thinking Model 现在会校验能力闭合，并在完成前检查实际调用痕迹；它仍不能证明模型的语义判断正确，内容质量需要评测。

## 任务记录

  每次长任务可以保存一个运行文件、一份当前状态和一份工具操作记录。代码中的名称分别是 `CognitiveRun`、`Workspace` 和 `Episode`；它们本质上是任务记录，不是新的知识库，也不会让模型自动变聪明。

  当前限制：

- 状态恢复主要针对同一 DSH 会话中的运行中或等待用户任务。
- 被标记为 blocked 或 cancelled 的任务不会自动重启或混入新任务；需要显式开始新任务，并可从记录中带走必要的已验证事实。
- 前端尚无完整的任务状态管理页面。
- 操作记录只供排错和回看，尚无可靠的自动评价或方法改进功能。
- 专题报告可在对话中完整产出，但 OutBox 尚无 Harness 提案工具；当前不能把“生成了报告”声称为“已保存报告”。

## 有状态交互

  当 Agent 已经完成一段观察、但下一步取决于用户的范围、取舍或价值判断时，它可以调用 `request_user_choice`。这不是普通回复末尾的一句追问：系统会把问题、选项、所属任务和状态保存为一份待答记录；前端显示选项与“其他想法”，刷新页面后仍会恢复；用户回答后，答案会写入任务指令并唤回同一 DSH 会话继续。

  这套机制只用于确实需要人作决定的节点，不替代普通对话，也不替代写入确认。普通输入在任务运行时会作为补充方向排入当前任务；涉及领域处理方向等明确抉择时，才使用有状态交互请求。

  当前限制：一次任务只允许一个待答问题。网络中断发生在答案已保存、但模型尚未接续时，系统会持久化待投递 continuation，并提供 `POST /api/cognition/runs/:id/resume` 重投递；前端还没有专门的恢复按钮。

## 尚未实现

- DOCX 和 PDF 的可靠正文、章节、表格与图片提取。
- EPUB 二进制图片提取、复杂版式与大量真实书籍的回归验证。
- 面向前端的一键“继续/重来”断点交互，以及在复杂并发情况下的完整材料级恢复。
- 向量检索；当前候选检索是本地关键词加一跳关系扩展，另有受控 1～3 跳 GraphOps 供模型进行结构观察。
- 文档所称 STM、自动注意力组装和强信号捕获；现有 `attention.yaml` 只是保留模板。
- 根据历史任务自动改进分析方法。
- 成熟的桌面安装包和服务器部署方案。
