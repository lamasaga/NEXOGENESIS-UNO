# 下一阶段评测方案

> 适用版本：DSH agentic baseline 之后的 Card 保真、Observation OPS、Thinking Model 约束与 Loop 治理实现。

## 目标

  这轮评测不把“模型说得流畅”当作成功。需要分别确认：知识卡不会在往返写入中失真，模型能取得足够且可解释的观察，所选 Thinking Model 真正影响运行，长任务能在停止、限额和投递失败时留下可恢复结果。

## 第一层：确定性回归

| 编号 | 场景 | 通过标准 |
|---|---|---|
| R1 | 读取一张含 `school`、`applicable_scope`、`theory_status`、未知扩展字段和关系 `note` 的卡，再经 enrich 与领域调整写回 | 所有字段和值保持；关系说明不丢失 |
| R2 | 用元数据筛选，再对照两张卡 | 返回筛选结果、共同领域、显式边及边说明；不虚构正文结论 |
| R3 | 追溯一张卡来源 | 只读取该卡声明的 Buffer 来源；任意未声明路径必须被拒绝 |
| R4 | 选择每一种 Thinking Model | 所有所需能力都能映射到实际 Operator；缺能力时拒绝启用 |
| R5 | 读取、提案和总步骤分别到达预算 | 对应操作不能继续；步骤耗尽时任务为 `blocked` 并保留停止原因 |
| R6 | 用户停止、或确认后 DSH 投递失败 | 任务状态与会话一致；待投递 continuation 可在重试接口中恢复 |

  R1–R6 应成为每次修改 Harness、Card 或工具注册后的必跑回归。当前仓库已经为 R1、R2、R4、R5 写了自动测试；R3 与 R6 的接口行为需要在真实 Web 会话中补测。

## 第二层：固定任务集

  建立一个小而稳定的评测集，而不是直接用整库随机问题。建议先做 12 个任务：金融报告 4 个、论文或书籍章节 3 个、碎片材料 2 个、已有卡修订 2 个、跨领域结构诊断 1 个。每项保留输入材料、允许范围、预期证据锚点和人工评分记录，但不要预先规定模型必须得出哪一句结论。

| 任务类型 | 观察重点 | 人工评分问题 |
|---|---|---|
| 编译金融报告 | 是否保留数字口径、时间、条件、图表或页码锚点 | Buffer 是否可独立理解，是否漏掉反例和条件？ |
| 消化多份 Buffer | 是否优先丰富旧卡、正确结算贡献、避免重复卡 | 最终卡是否比输入更凝聚，且来源链可回查？ |
| 对话研判 | 是否先召回再精读，能否沿关系与冲突扩展 | 回答中的关键判断是否能对应已读证据和边界？ |
| 建构诊断 | 是否从结构信号进入、限定小范围、提出可审查变化 | 建议是否改善结构，而非按标题机械连边？ |
| 来源核验 | 是否使用 `trace_source` 与卡片的来源字段 | 是否清楚区分“卡片主张”“来源证据”“自己的推断”？ |

  每项任务分别在相同材料、相同模型设置下运行两次。若两次产生不同写入，比较的是“是否都可追溯、可解释且符合边界”，而不是要求文字完全一致。

## 第三层：评分量表

| 维度 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| 证据忠实度 | 无来源或明显错引 | 有来源但条件、口径或反例不完整 | 来源、条件和不确定性完整可追溯 |
| 知识结构 | 重复建卡、错连或无意义扩张 | 基本可用但关系理由薄弱 | 优先丰富，关系与领域归属有明确理由 |
| 推理过程 | 直接给答案或机械扫卡 | 有检索但缺少改选或反证 | 根据 Observation 改变下一步，能说明停止原因 |
| 运行治理 | 无法停止或结果丢失 | 有记录但状态不清 | 预算、停止、等待用户与恢复状态一致 |
| 用户可读性 | 只有工具日志 | 有摘要但无法判断影响 | 清楚说明本轮做了什么、未做什么、为什么 |

  第一轮建议只把平均分低于 1.5 的维度列为工程问题。若证据忠实度低，先修模型提示、来源工具或 Card 契约；若运行治理低，先修 Loop 和 Web 状态；不要用 UI 润色掩盖其中任一种问题。

## 第四层：执行顺序

1. 先运行 R1–R6，修复确定性失败后再调用真实模型。
2. 用 12 项固定任务集完成第一轮，保存完整 Episode、Workspace、提案和最终卡差异。
3. 人工按量表独立评分；对低分项标出发生在“检索、读卡、模型判断、Harness 拒绝、投递恢复”的哪一步。
4. 每次只选一个重复出现的失分模式修复，然后重跑对应任务子集与 R1–R6。
5. 连续两轮稳定后，才扩大到更长的金融报告和更大的卡片库。

## 当前不应宣称已经验证的内容

  本次实现证明了契约和治理路径已经有代码与自动回归，并不证明 DeepSeek 在真实金融材料上的语义质量已经稳定。特别是：多 Buffer 综合、跨领域建构、来源与正文的一致性，以及长时运行下的模型主动改选，仍需按本方案用真实任务验证。
