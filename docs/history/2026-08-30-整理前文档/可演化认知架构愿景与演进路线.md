## 0. 如何阅读这份文档

  这份文档整理的是一条从 Nexogenesis 出发的长期演化方向。它不要求现在立即重构，也不把讨论中的每个概念都变成模块。文中出现的 ECA（Evolvable Cognitive Architecture，可演化认知架构）是理论框架候选名，ExoCortex（外置认知皮层）是项目或产品候选名；二者都不构成对 Nexogenesis 的正式改名决定。

  阅读时应始终区分三层：**已经成立的底座**、**值得验证的发展假设**、**只有在前序证据成立后才进入的远期研究**。任何假设进入开发，都仍须回答真实摩擦、最小改动、判断标准和撤回方式。

## 1. 北极星问题

  未来系统要解决的核心问题，不再只是「怎样让模型检索到更多知识」，而是：

> 如何把知识、认知状态、思考操作、思考策略和经验学习外置为显式、可组合、可评价、可修订、可继承的计算对象，并让不同大模型在这套结构中持续工作？

  可以用一个暂定抽象表示：

```text
可演化认知架构
  = Memory
  + Representation
  + Workspace
  + Operators
  + Policy
  + Evaluation
  + Learning
```

  它追求的不是一个更大的知识库，而是一套独立于模型权重、可以长期积累和迁移的认知结构。基础模型可以更换，已经形成的知识承诺、分析框架、思考程序、案例经验与评价历史仍应尽可能保留。

  由此，系统的长期价值不在于替代基础模型，而在于形成两种智能的协作：

| 层 | 擅长什么 |
|---|---|
| 参数智能（LLM） | 语言、模式识别、通用常识、直觉式生成与模糊联想 |
| 外置认知层 | 显式结构、来源与版本、受控操作、认知轨迹、评价与持续修订 |

  最终要验证的研究命题是：**在不依赖持续修改基础模型权重的前提下，一个可观察、可编辑、可学习的外部认知层，能否稳定提升复杂分析、解释与判断的质量。**

## 2. 为什么从 Nexogenesis 演化，而不是另起炉灶

  Nexogenesis 已经完成了未来架构最难替代的第一层工作：把思想材料变成有来源、有类型、有关系、可修订的长期语义结构，并用 Harness 和用户确认保护这套结构不被模型随意污染。未来演化应建立在这些不变量之上，而不是用一套时髦 Agent 框架把它们覆盖掉。

| Nexogenesis 已有基础 | 对未来架构的意义 |
|---|---|
| Markdown 是唯一语义事实之源 | 认知结构可读、可迁移，不被数据库或模型供应商锁定 |
| Buffer 与 Card 分层 | 区分待加工质料与已经承诺的长期认知结构 |
| 七型卡片、关系与来源 | 已有一套面向社科思想结构的语义记忆原型 |
| `write --batch` 统一闸门 | 为未来信念修订、策略更新和结构演化提供主权边界 |
| 知识体 + 思维体 | 已经开始区分「知道什么」与「怎样使用这些知识思考」 |
| GraphOps 对话循环 | 已有原子认知操作与按步取用结构的雏形 |
| STM 与协作记忆 | 已开始区分长期承诺、当前焦点与协作约定 |
| 来源归因、冲突显化、可重建索引 | 为可观察、可审计的认知演化提供基础 |

  无论未来架构如何扩展，以下不变量应继续保留：

1. 人对长期认知结构拥有最终主权；模型不能静默改写承诺。
2. Markdown 继续承载不可丢失的语义；图数据库、向量索引和运行缓存仍是可重建层。
3. 公共知识、个人立场、过程经验不能因技术便利而混成一层。
4. 来源、归因、版本和变更理由必须先于自动优化。
5. 新复杂度必须由真实使用摩擦和可观测收益证明。
6. 开发仓与知识实践仓继续遵守单向镜像纪律。

## 3. 核心转变：从知识架构到认知架构

  当前 Nexogenesis 的中心仍是可演进的知识骨架，思维体围绕这套骨架进行 talk、assess、emerge、refine 与 report。未来的关键转变不是放弃图，而是让图从「系统中心」变成「长期结构化记忆的一种核心表示」，并在它上方增加显式的工作空间、程序性记忆、策略、轨迹和学习回路。

```text
问题 / 任务
    ↓
问题识别与目标形成
    ↓
┌──────────────────────────────┐
│ Cognitive Workspace          │
│ 当前目标 · 假设 · 证据 · 冲突 │
│ 未知项 · 不确定性 · 预算       │
└──────────────┬───────────────┘
               ↓
认知规划器 / Thinking Policy
               ↓
GraphOps + 受控工具
               ↓
┌──────────────┼───────────────┐
↓              ↓               ↓
语义记忆       个人认知结构      案例与经验记忆
               ↓
可观察的 Reasoning Trajectory
               ↓
答案 / 判断 / 结构提案
               ↓
评价与反馈
               ↓
经验更新 → 策略更新 → 必要时结构更新
   快              中               慢
```

  这里真正成为运行中心的是 **Workspace + Policy + Memory System**。Graph 继续负责明确关系与长期承诺；Embedding 或搜索负责模糊联想和质料召回；LLM 负责理解、生成和综合。三者不是替代关系。

## 4. 未来认知系统的对象分层

### 4.1 语义记忆：世界与领域结构

  语义记忆回答「系统已经知道并承诺了什么」。Nexogenesis 的 `01-Cards/`、关系网、来源与领域结构已经是它的主体。未来可逐步强化 Claim、Evidence、Mechanism、Assumption、Context、Counterclaim 等论证要素，但不应急于把它们全部扩张成新卡片类型。

### 4.2 个人认知结构：一个思想主体怎样理解世界

  个人认知结构回答「这个人或学派通常从什么问题、框架、偏好和启发式出发」。它可以包含领域理念、分析范式、偏好、信念强度和方法习惯，但必须与文档事实和公共知识保持归因隔离。Nexogenesis 的 `02-Profile/` 是这一层的早期落点，不意味着未来所有个人认知对象都应塞入同一个文件夹。

### 4.3 情节记忆：以前怎样思考，结果怎样

  情节记忆记录一次具体问题的目标、上下文、调用过的操作、读取过的材料、产生的中间假设、最终回答、反馈和评价。它不是知识卡片，也不是简单聊天历史，而是可复盘的认知案例：

```text
Question → State → Ops Trajectory → Answer → Feedback → Evaluation
```

  `07-Conversations/`、运行事件和现有任务日志提供了原始材料，但未来是否形成独立 Episode 表示，需要先用真实案例验证其复盘价值。

### 4.4 程序性记忆：系统知道怎样思考

  程序性记忆回答「面对某类问题，通常应怎样组织认知动作」。现有 Web skills 是其软性原型；未来的 Thinking Mode 可能逐步从自然语言剧本演化为可版本控制、可组合、可测试的认知程序或条件策略。

### 4.5 工作记忆：此刻正在想什么

  工作记忆不等于最近十条聊天记录，而是有限容量的 Cognitive Workspace。它至少可能包含当前目标、候选假设、证据与反证、未决冲突、已知缺口、下一步子目标和剩余预算。现有 STM 是基础，但未来 Workspace 更接近一次推理过程中不断变化的显式认知状态。

  这些记忆不必全部使用 Graph 表示。未来应坚持「先按认知职责分层，再选择表示」，避免把所有对象都强行做成节点与边。

## 5. 图的未来：从知识关系走向可推理结构

  社科知识不能只表示实体之间的事实关系。真正有分析价值的结构通常包括主张、证据、论证担保、机制、假设、适用情境、反例、反驳和不同理论框架下的解释。未来的图因此更接近 Knowledge Graph、Argument Graph、Causal Graph 与 Reasoning Graph 的协作，而不是一张包办一切的超级图。

  发展时应同时守住两条原则：

- **增强论证能力**：让系统能追问证据支持什么、隐含假设是什么、什么会推翻当前解释、因果链在哪一环断裂。
- **抵抗 schema 爆炸**：保持少量稳定对象与关系，优先用组合表达复杂性；只有大量案例反复证明现有语义不足，才升级 ontology。

  Provenance 应成为一等公民。未来任何长期对象和重要推理结论，都应能回答：来自哪里、由谁生成、何时生成、依赖哪些材料、经过哪种 Thinking Mode、置信与适用边界是什么、后来为什么被修改。

  图与向量也不应二选一：**Graph 负责明确结构，Embedding 负责模糊联想，原文与 Buffer 搜索负责质料核验。** 任何派生索引仍不得升格为语义事实之源。

## 6. 把“思考”变成可观察、可组合的过程

### 6.1 GraphOps 是原子认知动作

  GraphOps 不只是数据库查询封装，而应逐渐被理解为可观察的原子认知操作，例如定位主张、寻找证据、寻找反证、展开机制、识别假设、比较解释、寻找类比、检查边界和更新置信。操作集宜小而稳定，复杂性主要来自组合，而不是不断增加近义工具。

### 6.2 Thinking Mode 是操作的组织方式

  Thinking Mode 可以经历三种形态，而不必一步跳到最终形态：

| 形态 | 表达 | 作用 |
|---|---|---|
| 软剧本 | 自然语言 playbook | 低成本表达某类问题的思考纪律 |
| 认知程序 | 可组合、可版本化的步骤与分支 | 可以重放、比较、局部修改和测试 |
| 认知策略 | `π(action | cognitive_state)` | 根据当前状态动态选择下一步操作 |

  早期最重要的是让轨迹可见，而不是马上学习最优策略。只有看得见「在哪个状态选了什么、观察到了什么、为什么停止」，后续评价和优化才有对象。

### 6.3 受控工具循环是运行基础

  未来更完整的思维体需要把单次补全扩展为受控循环：模型判断是否缺少上下文，调用白名单工具，系统返回 observation，模型更新 Workspace，再选择下一步，直到完成或触及预算。现有 Web GraphOps 循环已经提供了这一方向的雏形；后续若扩展到参考契约、项目状态、质料与案例读取，必须同时具备：

- 路径与能力白名单；
- 敏感文件过滤；
- 工具调用次数、字符与 token 预算；
- 完整审计轨迹；
- 按任务打包的项目上下文；
- 失败、无进展和提前退出机制。

  工具越多不等于认知能力越强。是否开放一种工具，应由它能否解决反复出现的认知缺口决定。

## 7. 演化发生在哪里

  讨论中的「学习」更准确地说，早期应是 **case-driven cognitive policy optimization**，而不是立即宣称采用强化学习。系统可以先冻结基础模型，只观察和优化外部结构，这样才能判断收益究竟来自认知架构，还是来自模型本身的变化。

### 7.1 三种时间尺度

| 时间尺度 | 学什么 | 典型结果 |
|---|---|---|
| 快：单次或少量案例 | 记录轨迹、反馈与失败模式 | Episode 增长，形成可复盘经验 |
| 中：一批同类案例 | 调整路由、步骤、分支与 Thinking Mode | 策略版本迭代，保留或拒绝候选变体 |
| 慢：大量跨任务证据 | 修订 ontology、GraphOps 与记忆结构 | 受闸门控制的 schema 演化 |

  慢速层不能由单次低分触发。Schema 更新应比策略更新更难，策略更新应比记录 Episode 更难；这一速度差是防止系统越学越乱的关键。

### 7.2 评价先于优化

  真正困难的不是生成更多 Thinking Mode，而是定义「什么叫想得更好」。复杂社科分析不能只用正确／错误评分，至少要考虑事实性、证据质量、因果解释、反论证、连贯性、新颖性、校准、边界意识和任务成本。

  评价应是多维的，并允许存在 Pareto 权衡：某种策略可能更严谨但更保守，另一种更有洞察但风险更高。个人思维风格可以部分表现为目标权重，但不能把偏好伪装成客观真理。

  在引入自动优化之前，至少需要：稳定案例表示、可重放轨迹、明确 rubric、人工或多评审者对照、训练／验证／隐藏测试隔离，以及对随机性的统计判断。否则所谓「演化」很可能只是对案例库过拟合。

### 7.3 搜索优先于强化学习

  Thinking Mode 多半首先是离散程序搜索问题。早期更适合用人工变体、消融、Beam Search、进化搜索或黑箱优化来比较候选程序；只有状态、动作、奖励和长期回报被稳定定义后，MDP 与强化学习才可能成为合适工具。

  更远期可以形成一个循环：**外部显式探索 → 案例积累 → 成熟策略稳定 → 必要时蒸馏为模型直觉 → 外部系统继续探索。** 这只是长期假设，不是当前路线的前提。

## 8. 理论与技术研究地图

  这不是要求按教材顺序学完的课程表。每个领域只有在它能回答当前架构问题时才进入。

| 研究簇 | 对本系统真正要回答的问题 | 进入时机 |
|---|---|---|
| 图论、KRR、Ontology | 怎样表示稳定关系，又不落入 schema 爆炸 | 近程、持续 |
| 论证理论、因果推断 | 什么构成证据、反驳、机制与有效解释 | 近程、优先 |
| 认知架构、记忆研究 | 长期、程序性、情节与工作记忆怎样协作 | 近程、优先 |
| MDP、Planning、HTN | 状态、操作、目标与分层计划怎样表达 | 中程 |
| 信息论 | 下一步操作怎样减少不确定性 | 中程，有可靠置信表示后 |
| 统计学与评测科学 | 系统是否真的变好，还是随机波动和过拟合 | 中程、优化前置 |
| Program Synthesis、DSL | 怎样生成、修复和组合 Thinking Program | 中远程 |
| 进化计算、黑箱优化 | 怎样搜索离散的认知程序空间 | 中远程 |
| Belief Revision | 新证据与旧承诺冲突时怎样理性修订 | 中远程 |
| Continual / Meta-learning | 长期运行后怎样更聪明而不是更混乱 | 远程 |
| 强化学习、多智能体、复杂系统 | 策略学习、协作与涌现是否带来净收益 | 远程，必须有前序证据 |

  ACT-R、SOAR、Global Workspace、Toulmin、AGM、DSPy、Graphiti、Cognee、LangGraph、OpenCog、Hyperon、PyWhy 等都可作为思想或工程参照，但目前不构成依赖选择。项目需要吸收的是问题框架，而不是照搬任何一套现成架构。

## 9. 分阶段演进路线

  以下阶段是能力依赖关系，不是版本号、工期或并行开发清单。后一个阶段只有在前一阶段产生可观察收益后才值得启动。

### Horizon 0：守住并补强 Nexogenesis 底座

  目标是让当前知识体、思维体、GraphOps、STM、协作记忆、来源与写入闸门稳定形成闭环。此阶段继续以 [`架构真图与后续路径.md`](架构真图与后续路径.md) 的 P0/P1 为实际开发依据，不因本愿景另开一套实施线。

  通过条件：真实使用中能稳定完成摄入、对话、结构提案、用户确认和建构；运行事实与文档一致；关键失败可追溯。

### Horizon 1：建立可观察的认知回路

  目标是把一次复杂思考表达成可复盘的 State—Action—Observation 轨迹，并形成最小 Cognitive Workspace 与 Episode 记录。评价先以人工 rubric 和失败分类为主，不做自动策略改写。

  通过条件：面对差回答，能够定位主要问题来自知识缺口、工具观察、操作选择、停止条件还是综合阶段；Episode 确实减少重复诊断成本。

### Horizon 2：形成可编程的 Thinking Mode

  目标是把少量高频问题类型的软剧本转成可版本化、可组合、可重放的认知程序。先做最小 DSL 或结构化表示，不追求通用编程语言；先有稳定原语，再谈自动生成。

  通过条件：同一模式在案例集上可重复运行；局部步骤可以替换和消融；版本差异能解释性能变化；操作集没有快速膨胀。

### Horizon 3：启动案例驱动的策略优化

  目标是建立案例库、轨迹比较、多维评价、候选变体生成与保留／拒绝机制。优先采用人工设计变体与离散搜索，并冻结基础模型进行对照实验。

  通过条件：改进能在隐藏案例上复现；收益不是 token 或工具调用次数无上限增长换来的；失败模式和回滚路径清晰。

### Horizon 4：进入受控的认知演化

  目标是在足够案例证据下探索动态 Policy、信念修订、多目标偏好、信息增益选步和慢速 schema 演化。所有长期结构更新仍经过更严格的审查与版本控制。

  通过条件：系统能够处理冲突证据而非简单覆盖旧信念；策略变化可以解释；长期运行没有明显的知识污染、奖励投机和灾难性遗忘。

### Horizon 5：成为模型无关的长期认知基础设施

  目标是让认知结构、程序与经验可以跨模型、跨时期迁移，并研究成熟外部策略是否值得蒸馏、多 Agent 是否带来净收益、不同领域是否可以共享认知原语。

  通过条件：更换模型后仍能继承主要认知资产；跨领域复用不破坏领域边界；新增复杂性在质量、成本或可维护性上有明确净收益。

## 10. 每一阶段都必须守住的闸门

  未来路线最容易失败的方式，不是技术做不出来，而是过早把愿景名词变成大量 schema、工具、Agent 和自动化。每一个新机制进入实现前都应回答：

1. 它解决了哪一种反复出现的真实认知摩擦？
2. 为什么现有卡片、关系、GraphOps 或 playbook 无法以更小改动解决？
3. 它的状态和输出是否可观察、可审计？
4. 怎样判断它提升了分析，而不是只增加 token、延迟和复杂度？
5. 失败时如何关闭、回滚或降级？
6. 它产生的是长期语义，还是可删除的运行痕迹？
7. 它是否会混淆公共知识、个人信念和案例经验？
8. 它是否仍服从用户确认与统一写入闸门？

  以下信号应被视为暂缓扩展的理由：没有可复盘的失败案例却先设计奖励函数；没有稳定 GraphOps 却先发明 Cognitive DSL；没有隐藏测试却声称策略进化；没有个人／公共边界却引入自动信念更新；单 Agent 的认知循环尚不可解释却先增加多 Agent。

## 11. 尚未拍板的战略问题

  下列问题应保留为研究议程，而不是在本文中伪装成决定：

- ECA、ExoCortex 与 Nexogenesis 最终是理论名、产品名、子系统名，还是不采用新命名？
- Public / Personal / Episode 是逻辑分层还是物理分库，哪些内容必须进入 Markdown 事实源？
- Cognitive Workspace 的最小稳定字段是什么，哪些只是任务特定临时状态？
- 哪些 GraphOps 足够原子且跨领域，哪些应留在领域 Thinking Mode 中？
- Episode 保存完整轨迹、压缩轨迹还是失败摘要，长期成本如何控制？
- 谁定义 Cognitive Fitness Function，怎样表达用户偏好而不污染事实判断？
- Web 思维体需要开放哪些质料、参考契约和项目状态工具，权限边界如何证明安全？
- Thinking Mode 何时值得从自然语言剧本升级为 DSL，升级后的收益如何验证？
- 何种证据足以触发 relation、ontology 或 memory schema 的慢速演化？
- 外部策略何时成熟到值得蒸馏进模型，蒸馏后如何保持可解释与可撤回？

## 12. 这条路线最终想保留下来的东西

  Nexogenesis 当前保存的是一套思想者或学派可以持续修订的知识架构。未来若这条路线成立，系统还应逐渐保存：它如何界定问题、如何组织证据、如何发现冲突、如何选择下一步认知动作、哪些方法在什么情境下有效、哪些失败曾经发生，以及这些方法为何被修改。

  因而，真正持续演化的对象不是某一个 LLM，也不只是某一张知识图，而是独立于模型权重存在的**认知结构本身**。Nexogenesis 的任务不是跳过今天的可靠底座去追逐这个终点，而是让每一次有证据的小步演进，都为这个终点增加一种真实、可解释、可继承的能力。
