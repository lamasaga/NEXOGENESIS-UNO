# 后续开发

> 本页只保留近期工作。完成一项并经过真实测试后，再决定是否增加下一项。

## 1. 用真实 EPUB 验证直接编译

  EPUB 已能读取书目文件，按章节顺序提取 XHTML 正文，并保留标题、表格、图片引用和来源位置。下一步不是继续扩展解析器，而是用真实书籍确认它在常见格式、长章节和异常文件上的表现。

  验收条件：

- 使用真实 EPUB 建立正常章节索引，不出现压缩乱码。
- 章节顺序与目录一致。
- 正文、表格和图片引用具有可回查位置。
- 损坏或加密 EPUB 给出明确错误，不生成 Buffer。

  暂不同时设计通用文档解析平台。EPUB 经真实使用验证后，再按实际需求决定 DOCX、PDF 或图片二进制提取。

## 2. 验证编译断点恢复体验

  当前已经用材料指纹识别同一版本，并可在用户明确选择继续后恢复已读位置、覆盖清单和已写 Buffer 记录。下一步要验证真实中断后的行为，并把“继续/重来”做成前端可见的选择，而不是要求用户理解 run id。

  验收条件：

- 编译中途停止并重启后，能够显示已有进度。
- 继续时不重复写入已经成功的 Buffer。
- 文件内容变化后不错误沿用旧断点。
- 用户可以明确放弃旧断点。

## 3. 用真实案例验证消化和建构

  目前两类任务已有工具，但实际效果还没有充分证明。下一步不增加新工具，先各选一组真实材料重复测试，记录模型选择、工具拒绝、最终修改和用户判断。

  验收条件：

- 消化失败一个候选后能改选，而不是直接结束或反复重试。
- 选择 2～4 份讨论同一问题的真实 Buffer，确认它们能形成一个综合 Card 修改，而不是重复补丁或正文拼接。
- 消化后每份 Buffer 都能回查到实际影响的 Card，既有来源不丢失，已结算质料不会再次进入默认清单。
- 建构至少能产生一个有证据的小修改，或给出具体且有用的暂不修改理由。
- 同类失败重复出现后，优先修正工具说明、输入或检查规则。
- 没有真实收益的工具应合并或移除。

## 暂不开发

- 自动改写分析方法或所谓自我学习。
- 新的记忆分类、评价平台和多阶段策略晋升。
- 为当前没有案例的问题增加更多 GraphOps。
- 在核心任务尚不稳定前进行大规模界面重构。

  这些方向可以继续讨论，但不进入代码，除非现有真实案例表明它们是解决问题的最小办法。
