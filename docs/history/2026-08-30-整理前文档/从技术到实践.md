## 0. 怎么用这份文档讲

　　按听众时间选一条路径，不要从头念到尾。

| 时长 | 讲什么 | 跳过什么 |
|---|---|---|
| 30 分钟 | §1 它是什么、§2 质料与卡片、§5 三条线怎么跑 | 包结构、前缀缓存、双仓细节 |
| 90 分钟 | 加上 §3 技术分层、§4 双执行平面、§6 消化两阶段 | 源码路径级走读 |
| 动手半日 | §7 实践仓一天、§8 常见翻车、当场 compile 或 digest 一波 | 设计史 |

　　讲的时候反复钉三句话，听众就不会把系统听成「又一个笔记软件」：

1. Markdown 是知识，程序是闸门，模型是语义工人。
2. 先有质料，再有承诺；承诺要进卡片，分析可以留在对话里。
3. Code Agent 只管把材料变成结构；思考、建构、日常对话走 Web。

## 1. 它是什么

　　Nexogenesis（智构涌现）是给**一位思想者或一个学派**用的知识架构体系。它要外化的不是「我读过哪些文件」，而是一套可修订的骨架：这个领域在问什么、主张是什么、和谁打架、用什么机制解释、证据从哪来。

　　它明确不做三件事：

- 不做把书自动切成碎片的批处理器。切得碎、槽位齐，不等于有知识结构。
- 不做个人日记系统。日记没有领域骨架，也没有冲突卡。
- 不把基座模型没背过的公版定义当成主要卖点。教材进库，买的是**你这套架构如何约束以后的解释**，不是让模型第一次学会供求曲线。

　　系统里同时住着两具身体：

| 名称 | 落在哪 | 干什么 |
|---|---|---|
| **知识体** | `01-Cards/`、`05-Buffer/`、`02-Profile/` | 可校验、可演进的结构与质料 |
| **思维体** | Web 对话：talk / assess / emerge / refine / report | 带着结构去推理、分析、提议改结构 |

　　知识体是长期承诺。思维体是每轮注意力。思维体可以建议改卡片，但不能绕过你（或你授权的工作流）直接改库。

## 2. 知识对象：从质料到卡片

### 2.1 为什么要分层

　　读一本书时，模型很容易直接「写成一张卡」。那会把还没想清楚的切片，伪装成已经认定的结构。所以摄入必须停一站：

```text
原文（Inbox / Archive）
    → 质料 Buffer（有摘录、有来源，还不承诺类型与关系）
    → 卡片 Card（有类型、有关系、可被以后的对话当骨架用）
```

　　Buffer 像厨房里的食材。Card 像你承认可以对外端出去的菜。问题清单放在 `02-Profile/`，不算七型卡片。某次长分析可以进 `04-OutBox/`，默认不是已定结论。

### 2.2 七型卡片

　　卡片扁平放在 `01-Cards/`，不靠文件夹分类。空间靠 `domains` 字段和关系边。

| 类型 | 它在骨架里的职责 | 一句话例子 |
|---|---|---|
| `domain` | 划领域、核心问题、边界 | 短期波动与 AD-AS |
| `claim` | 可争辩的主张或立场 | 存货周期是内生阻尼振荡 |
| `phenomenon` | 可观察的重复模式 | 日美政策利率相位差 |
| `model` | 解释机制与组件 | 缺货规避如何生成振荡 |
| `method` | 怎么估计、怎么识别 | VAR 特征根与相位计算 |
| `entity` | 人物、制度、学派、组织 | 某委员会、某法案 |
| `conflict` | 两造对立，钉 1～2 个分歧点 | 振荡定义 vs 转折点定义 |

　　关系常用：`applies-to`（挂到领域）、`based-on`、`supports`、`conflicts-with`、`involves`（只给 conflict 卡指向两造）、`example-of`、`extends`、`influences`。

　　消化时的硬纪律：优先 enrich 已有卡；真正新、重要、可独立复用才新建；冲突要露面，不要和稀泥只留赢家。

### 2.3 一张卡长什么样

　　文件名即中文 `id`。开头是 YAML frontmatter（类型、领域、来源、关系、成熟度），后面是按类型规定的正文槽。主张卡必须有「一句话主张 / 依据 / 已知限制 / 原文摘录」；方法卡是「输入 / 步骤 / 输出 / 适用边界」。缺证据就写「原文未提及：……」，禁止用套话凑槽。

　　`origin` 区分声音：`document` 是材料里的话，`user` 是你的立场，`system` 是系统推断。`origin: system` 未经你批准，不能标成 `mature`。

## 3. 技术分层（给能讲系统的人）

### 3.1 四层，从上到下

```text
入口          Web 按钮 / Cursor Code Agent / CLI
应用工作流     CompileWorkflow / DigestWorkflow / ConstructWorkflow
能力内核      检索、校验、写入、Run 状态、事件
底座          Markdown 文件（唯一长期语义事实）
```

　　入口不拥有业务流程。Web 点「消化」和 Cursor 里说「开始消化」，应走进**同一个** DigestWorkflow，只是请谁来填语义不同：Web 请 DeepSeek，Cursor 请 Code Agent。

　　删掉代码、图索引、RAG 库，只要 Markdown 还在，知识内容零损失。图和搜索都可以重建。Git 管历史和回滚，不是思想本体。

### 3.2 Harness 与模型怎么分工

　　Harness（`nexogenesis/` 这套 Python）强制过程：卡片 schema、幽灵链接、原子写入、索引、Buffer 状态、波次选择。它不判断「这主张写得好不好」。

　　大模型负责语义：这段材料在讲什么、该并进哪张卡、有没有冲突、正文是否可读。

　　两者的接缝是**写入事务**。任何对卡片、Profile、问题清单的实质改动，必须走：

```bash
python -m nexogenesis write --batch <file>
```

　　执行顺序是：读 batch → 校验 → 写到临时目录 → 全库校验 → 成功才原子替换并刷新索引。失败则丢掉临时文件，不留半成品。这就是「写入有闸门」。

### 3.3 检索：两套入口，不要合成一套世界

　　系统里有两条检索能力，服务不同入口：

| 入口 | 怎么找 | 给谁用 |
|---|---|---|
| **GraphOps** | 模型按步 `search` / `walk` / `members` / `read_card` | Web 对话主路径。不强制首轮检索。 |
| **Context Package** | 结构子图 + RAG 质料打成一包 | CLI `retrieve`；digest / construct 选种 |

　　质料轨（原文、Buffer、讨论稿）不得直接写成卡片关系。讨论稿标成研讨草稿。Web 要不要把质料工具加回对话，见开发主文档，尚未拍板。

　　思维体还叠一层**记忆**：长期结构是卡片图，短期是本会话焦点，协作约定在独立 markdown 库。每轮只带一小包，而不是把全库塞进 prompt。

### 3.4 代码地图（需要指目录时）

| 路径 | 职责 |
|---|---|
| `nexogenesis/application/workflows/` | 编译 / 消化 / 建构工作流 |
| `nexogenesis/ingest/` | 切窗、选波、prompt 渲染、digest 服务 |
| `nexogenesis/runtime/` | Web API、DeepSeek 调用、任务面板 |
| `nexogenesis/adapters/` | 外部 Agent 任务包、事件、检查点、写入网关 |
| `schemes/default/prompts/` | 真正喂给模型的语义模板 |
| `schemes/default/web-skills/` | 仅 Web 的思维体策略 |
| `.agent/skills/` | 仅 Code Agent 的 compile / digest 技能 |
| `.nexogenesis/runs/` | 某次 Run 的任务、结果、状态（可恢复，不是知识体） |

　　开发欠账、文档与代码偏离、后续补丁顺序见 [`架构真图与后续路径.md`](架构真图与后续路径.md)。日常操作不必翻历史设计稿。

## 4. 双执行平面（v2.1 的关键）

　　同一套消化工作流，两种请工人的方式。不要混。

```text
                    DigestWorkflow（唯一）
                           │
           ┌───────────────┴───────────────┐
           ▼                               ▼
   Web + DeepSeek                    Cursor Code Agent
   一次 HTTP 无记忆补全               多轮对话 + 读文件 + 提交 JSON
   规则必须写在这一次请求里            规则必须写在这一份任务文件里
   固定前缀可缓存                      对话会被摘要，不能只靠「刚才读过技能」
```

### 4.1 Web / DeepSeek

　　每一波路由、每一波落卡，都是一次独立 API 调用。DeepSeek 看不见 Cursor 的技能，也看不见上一波聊天。所以 prompt 开头放**可缓存常量段**：路由用判断契约，落卡再用判断契约 + JSON 写卡契约 + 七型正例。开头逐字不变，连续消化时从第二波起可以走前缀缓存。

　　产品行为：每波 9 片质料，**不设波次上限**，直到 scratch 清空、本波没进展被熔断，或你在界面暂停。

### 4.2 Cursor Code Agent

　　这是带工具的 Agent 循环，不是把任务文件 POST 给 DeepSeek。但连续消化时对话会被系统摘要，上一波读过的 `SKILL.md` 可能掉出窗口。

　　因此 v2.1 规定：每一份任务文件**开头自带判断契约**（决策树、七型槽位、质料密度、enrich 补丁协议）。不带七型正例全文，以免把本波质料挤掉。需要对照写法时，再打开 `.agent/reference/card-contracts/card-exemplars/` 里本波用到的类型各一篇。

　　Code Agent 只提交 SemanticResult（JSON 文件）。Workflow 校验、写入、改 Buffer 状态。禁止直接改 `01-Cards/`。

　　人按波提交。用户只说「消化一波」时，不要接着填系统已经准备好的下一波路由。

### 4.3 谁干什么

| 动作 | Code Agent | Web |
|---|---|---|
| compile（Inbox → Buffer） | 可以 | 可以 |
| digest（Buffer → Card） | 可以 | 可以 |
| construct（通盘整理结构） | 不可以 | 可以 |
| talk / emerge / assess / refine / report | 不可以 | 可以 |

## 5. 三条工作线

### 5.1 阅读线：材料变成骨架

```text
00-Inbox 原文
    → compile   切成带摘录的 Buffer（scratch）
    → digest    并进或新建卡片（enrich 优先）
    → construct 合并、升枢纽、显化张力（仅 Web）
    → 03-Archive 原文归档
```

　　**编译**不管「这是不是一张好卡」。图书先按目录切成 `.nexogenesis/tmp/compile/materials/<书名>-<哈希前12位>/chapters/` 里的章节稿（丢掉封面、版权、目录等附属页），再在单章内开窗；窗内产出 1～6 块有名字、有机制、有原文的 Buffer。图书 PDF 禁止用固定页数假造章节。

　　**消化**是骨架滋养。两阶段：

1. **路由**：只看每片约 220 字核心表达 + 候选卡标题，判定 enrich / new / skip，输出路由表。
2. **落卡**：只装载路由点名的卡全文和 Buffer 全文，写成写入事务。已有卡用 `"mode": "enrich"`，只交要改的节（`replace_sections` 等），Harness 合并后再校验。

　　单次最多 6 条 writes。同簇质料必须落到同一张卡，禁止一片一卡。

　　**建构**不是第二次消化。原则上不新建，只把已有对象收干净。Code Agent 不要代做。

### 5.2 对话线：带着骨架想问题

　　Web 里正常问、分析、反驳。模型可按需在图上定位和读卡，**不是**系统先检索再开口。分析默认留在对话里。出现值得留下的判断时，可以走 emerge：先提少量候选，你确认后才写入。

　　对话路径写卡必须 `approved_by: user`。不存在「聊着聊着 agent 自己落盘」。

### 5.3 维护线：索引与健康

```bash
python -m nexogenesis validate   # 卡片契约
python -m nexogenesis index      # 领域 / 冲突 / 理论视图
python -m nexogenesis doctor     # 目录、钩子、索引是否陈旧
```

　　pre-commit 会跑 validate。实践仓要用 `.venv\Scripts\python.exe`，Git Bash 里裸 `python` 可能落到微软商店占位符。

## 6. 消化在技术上实际发生了什么

　　便于讲解「一波」这两个字。

```text
选 9 片 scratch Buffer（副本折叠成同一席位）
    → 为每片召回约 5 张候选卡（字符 bigram + IDF，分数只排序不判阈值）
    → 阶段 A 路由 JSON
    → 按 load_cards 装载全文
    → 阶段 B 落卡 JSON（新建完整 body / enrich 只交补丁）
    → Harness 展开补丁 → 校验 → 原子写入
    → Buffer 标 digested，副本一并清账
    → 若还有 scratch：Web 自动下一波；Code Agent 生成下一波任务并等待提交
```

　　Run 状态在 `.nexogenesis/runs/<run-id>/`。任务文件在 `tasks/`，你提交的结果在 `results/`。这些是过程证据，不是知识体。知识只在 Markdown 卡片里。

　　无进展熔断：若本波消化后待消化数量没有下降，停止，避免空转。

## 7. 实践仓一天（金融知识体）

　　开发仓是干净的程序发行版。实践仓才装金融卡片、Buffer、Inbox。补丁只允许：

```text
开发仓提交  →  实践仓 git fetch dev ; git merge dev/main
实践仓知识  →  永不 push 回 origin（远端 push 已 DISABLED）
```

　　停用词等实践侧配置也不回注开发仓。

### 7.1 启动 Web 思维体

　　根目录运行 `启动Web.bat`，或：

```bash
.venv\Scripts\python.exe -m nexogenesis serve --root . --port 8787
```

　　浏览器打开 `http://127.0.0.1:8787/`。DeepSeek key 在设置面板填写，落到 `.nexogenesis/web-settings.json`，不入库。

　　在 Web 里：编译、消化、建构、对话、涌现。消化开着两阶段开关时走路由+落卡；关掉则一轮到底。

### 7.2 用 Cursor 消化一波

```bash
.venv\Scripts\python.exe -m nexogenesis digest --agent --root .
```

　　按打印出的 Task Prompt 路径打开任务文件。先读开头「本波纪律」，再根据数据写 JSON，保存后：

```bash
.venv\Scripts\python.exe -m nexogenesis digest --resume <RUN_ID> --submit <RESULT_FILE> --root .
```

　　成功后系统可能立刻准备下一波路由。没有被要求连续做时，停。

### 7.3 编译新材料

　　把 PDF / Markdown 放进 `00-Inbox/`，然后：

```bash
.venv\Scripts\python.exe -m nexogenesis compile --plan --root .
.venv\Scripts\python.exe -m nexogenesis compile --agent --root .
```

　　同样用 `--resume` / `--submit` 交语义结果。Workflow 负责审稿、返修、写成 Buffer、归档来源。

### 7.4 你怎么判断「这波消化算做好了」

- 事务一次通过，Buffer 变成 `digested`。
- 优先看到 enrich，而不是九片九张新卡。
- 新卡能独立读懂，有机制或数字，有原文摘录。
- 对立被标成 `conflicts-with` 或 conflict 卡，而不是写进同一段和稀泥。
- 会议程序、参与者名单一类没有结构价值的片，skip 并清账。

## 8. 讲解时预留的误解

| 听众容易以为 | 实际 |
|---|---|
| 这是 RAG 问答机器人 | RAG 只是质料轨；主产品是可演进的卡片骨架 |
| 一片 Buffer 必须变一张卡 | 同簇必须并到同一张；多数情况是 enrich |
| 模型会记住上一波的规则 | Web 每波失忆；Code Agent 对话会被摘要。规则在当次 prompt / 任务文件里 |
| 在编辑器里改卡片更快 | 绕过 `write --batch` 会破坏校验与索引，也违反宪法 |
| 开发仓带一套示范经济学库更方便 | 开发仓必须可分发给任意学科；知识只住实践仓 |
| 建构就是再消化一遍 | 建构通盘整理已有结构，原则上不新建 |
| 空心「原文未提及」凑满槽位也算完成 | 那是反模式；没有质料就 skip 或写明缺什么 |

## 10. 收束

　　若整场讲解只留一段话：

　　Nexogenesis 用 Markdown 把学派的问题、主张、模型和冲突做成可修订的骨架；用程序保证写入不翻车、索引可重建；用大模型做聚合而不是切片。Web 负责带着骨架思考和整理结构，Code Agent 负责把新材料编译并消化进骨架。v2.1 把这两条请工人的路分开：DeepSeek 靠请求里的稳定前缀，Cursor 靠每一波任务文件自带的纪律。没有架构的入库，只是给已经会背公版的模型再喂一遍文本。
