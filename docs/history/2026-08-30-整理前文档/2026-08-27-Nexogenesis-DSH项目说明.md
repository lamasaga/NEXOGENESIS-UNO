## 一、一句话说明这个项目

  Nexogenesis DSH 是一个面向长期知识工作的 Agent 系统：它把材料沉淀为可追溯、可连接、可推理的知识体，把有效的思考方式沉淀为可组合、可评价、可演化的思维体，再由运行在 DeepSeek Harness 上的 Agent 在持续循环中使用和改变二者。

  它最终要建设的不是一个自动摘要工具、一个知识库聊天框，也不是一组固定工作流，而是一套能够长期操作知识、积累认知能力并与用户共同迭代的基础设施。

## 二、项目为什么存在

  一般知识工具容易停在两个阶段：要么保存原文和笔记，要么让模型临时读取材料后给出一次回答。前者缺乏结构化推理能力，后者的认识和思考方式会随着会话结束而消失。

  Nexogenesis DSH 试图同时解决三个问题：

1. 材料越来越多后，怎样形成一套能够长期维护的领域知识结构，而不是不断堆积文档。
2. 任务不断发生后，怎样让有效的思考方法留下来，并能在新问题中重新组合和改进。
3. 怎样让 Agent 拥有足够的自主判断能力，同时保证知识写入仍然可检查、可确认、可回滚，并服从用户主权。

  因此，这个项目的价值不只来自某一次回答是否聪明，更来自知识结构和认知能力能否在多次任务中持续改善。

## 三、最上层架构：两类长期资产与一个运行时

```text
Nexogenesis DSH
│
├─ 知识体 Knowledge Body
│  └─ 系统知道什么
│
├─ 思维体 Thinking Body
│  └─ 系统怎样思考
│
└─ Agent Runtime
   └─ 系统此刻怎样行动
```

  知识体和思维体是可以跨任务保存、积累和演化的两类长期资产。Agent Runtime 是它们在当前任务中发生作用的场所。

  Agent 不应被理解成“包含”或“拥有”两体。一次 Agent 任务可以结束，一个运行状态可以被清理，但知识体和思维体仍然存在，并可以被后续任务或多个 Agent 会话继续使用。

  最容易理解的表达是：

> 知识体保存认识，思维体保存认知能力，Agent Runtime 把二者转化为当前行动。

## 四、知识体：系统愿意长期承诺的认识

  知识体不是资料仓库，也不是把模型记忆换成文件。它负责把原始材料中的论点、机制、边界、事实和证据，组织成可以独立阅读、相互连接、持续修订的知识结构。

```text
原始材料
  ↓ 编译：保留语义结构与证据位置
Buffer 语义质料
  ↓ 消化：聚合、比较并丰富已有认识
Card 知识卡片
  ↓ 建构：改善领域、关系、冲突和枢纽
可检索、可追溯、可推理的知识图谱
```

### 4.1 主要组成

| 组成 | 当前载体 | 作用 |
|---|---|---|
| 原始材料 | `00-Inbox/`、`03-Archive/` | 保存进入系统的书籍、论文、报告、访谈等来源 |
| 语义质料 | `05-Buffer/` | 保存尚未成为正式知识、但具有完整意义和证据位置的材料单元 |
| 知识卡片 | `01-Cards/` | 表达领域、主张、现象、实体、方法、模型和冲突 |
| 领域特质 | `02-Profile/` | 保存有来源的领域级认识特征与思考倾向 |
| 关系结构 | Card frontmatter 与可重建图索引 | 表达支持、挑战、依赖、组成、适用和冲突等关系 |
| 分析产物 | `04-OutBox/` | 保存报告、研判和其他面向使用的输出 |

### 4.2 三条底线

  第一，Markdown 是唯一语义事实之源。索引、缓存、Workspace 和可视化都可以重建，不能反过来成为比 Markdown 更高的知识权威。

  第二，知识必须保留证据和来源。系统长期承诺的认识，应当能够返回材料中的章节、页码、片段或其他可核查位置。

  第三，知识写入服从用户主权。模型可以发现问题并提出候选，但正式改变必须进入统一写入边界，经授权、校验、事务提交和审计后才能成立。

  知识体保存的是系统愿意长期承诺的认识，而不是模型在某一次生成中的临时猜测。

## 五、思维体：系统能够长期积累的认知能力

  思维体不是一个总提示词，也不只是 Agent 的“程序性记忆”。它是项目未来最重要的长期资产之一，负责保存可复用、可组合、可评价和可演化的思考能力。

```text
思维体
├─ Skill
│  └─ 定义任务目标、范围、授权和完成条件
├─ Thinking Model
│  └─ 定义怎样观察、假设、验证、切换和停止
├─ GraphOps / DomainOps
│  └─ 定义能够执行哪些原子认知动作
├─ Evaluation
│  └─ 判断一次思考和行动在哪些维度有效
└─ Evolution
   └─ 根据案例和评价推动认知能力受控迭代
```

### 5.1 Skill：轻量的任务契约

  Skill 回答“这次要完成什么”，而不是规定模型必须按什么顺序思考。

  一个 Skill 应主要保存：

- 用户意图和触发方式；
- 任务目标、输入和默认范围；
- 可以使用的能力与写入权限；
- 应交付的结果；
- 任务完成、停止和请求用户判断的条件。

  `/compile`、`/digest`、`/construct` 是稳定的能力入口，但它们不能变成“第一步做什么、第二步做什么”的隐藏程序。按钮也只负责创建或聚焦对应任务，不能在 Agent 外部拥有固定语义流程。

### 5.2 Thinking Model：一等认知对象

  Thinking Model 回答“面对这一类问题，应该怎样思考”。它不从属于某个 Skill，也不能只是一段嵌在 Skill 中的提示语。

  项目的目标是让每个 Thinking Model 拥有：

- 独立身份、用途和适用条件；
- 独立存储、来源和版本历史；
- 观察、假设、证据、反证和停止原则；
- 可用能力和偏好的 GraphOps；
- 与其他 Thinking Model 的组合、切换和继承关系；
- 可回放的任务案例和多维评价结果；
- 有依据的候选变体、晋升和回滚机制。

  从认知科学角度，Thinking Model 与程序性记忆存在相似性；但在本项目的主架构中，它应被直接称为思维体的一等认知资产，而不是被降级为“记忆的一种”。

### 5.3 GraphOps：原子认知行动

  GraphOps 回答“系统可以对知识状态采取什么动作”。它们包括检索、精读、比较邻域、检查领域成员、寻找冲突、模拟拆分、提出关系和提交小范围改变等操作。

  GraphOps 不是完整的思考方法。相同的 GraphOp 可以被不同 Thinking Model 以不同目的调用；相同的 Thinking Model 也可以根据知识状态选择不同 GraphOps。

### 5.4 Thinking Model × GraphOps

```text
Skill
“要完成什么”
       ×
Thinking Model
“怎样观察、解释、验证和收敛”
       ×
GraphOps
“能够读取、比较、模拟和改变什么”
       ↓
当前任务中的思维策略
```

  这个组合是思维体产生丰富策略的核心。具体策略不是预先写死的工作流，而是 Agent 根据当前任务、知识状态和最新反馈动态形成的运行时实例。

  例如，在建构任务中，“冲突辨析”Thinking Model 可以调用冲突邻域检查、证据比较、领域拆分模拟和关系提案；“跨领域桥接”Thinking Model 也可能使用证据比较和关系提案，但它关注的是结构相似性、迁移条件和类比失效边界。

  不需要把每次组合都保存成新的永久对象。只有当一种组合在多次案例中稳定有效，并形成明确适用条件时，才值得沉淀为新版本、组合模型或 Thinking Model 变体。

### 5.5 两条独立演化路径

  Thinking Model 的演化主要改善观察角度、假设形成、证据标准、模型切换和停止条件。

  GraphOps 的演化主要改善行动能力、输入输出契约、前置条件、结构化 Observation、可模拟性和可回滚性。

  两者能够协同演化，但不能混为一谈。Thinking Model 的升级不能偷偷扩大写入权限；GraphOp 的升级也不能替 Agent 决定语义方向。

## 六、Agent Runtime：让知识与思维在此刻发生作用

  DSH 提供模型能够持续调用工具的 Agent Loop。Nexogenesis 在这套 Loop 上装配知识工具、任务状态、Skill、Thinking Model、GraphOps、Harness 和 Web 交互。

```text
Agent Runtime
├─ LLM / Controller
│  └─ 理解语义并形成当前判断
├─ Agent Loop
│  └─ 观察 → 判断 → 行动 → 接收反馈 → 继续判断
├─ Workspace
│  └─ 保存当前任务的显式状态
├─ Skill / Thinking Model 激活
│  └─ 建立任务边界并选择认知策略
├─ Tool / GraphOps Executor
│  └─ 执行读取、检索、模拟和提案
├─ Runtime Memory
│  ├─ 工作记忆
│  └─ 协作记忆
└─ Harness 治理边界
   └─ 权限、契约、revision、事务、回滚和审计
```

### 6.1 Loop 与 Harness

  Loop 和 Harness 位于相近的运行层面，但承担不同职责。

- Loop 决定下一步做什么，保证任务具有认知连续性。
- Harness 判断一个具体行动能否合法发生，保证写入安全和事实边界。
- Harness 拒绝必须作为新的 Observation 返回原 Loop。
- Agent 可以修复参数、改用专用操作、缩小范围、继续只读或有依据地停止。
- Harness 不替代模型判断内容意义，模型也不能绕过 Harness 直接修改知识体。

```text
观察知识状态
  → 选择或切换 Thinking Model
  → 调用 GraphOps
  → Harness 检查行动
      ├─ 通过：原子提交并返回收据
      └─ 拒绝：返回原因与合法替代方向
  → Observation 回到原 Loop
  → Agent 继续判断
```

  这也是 Agent Loop 与固定管线的根本差别：管线预先决定步骤，Agent Loop 根据新状态和反馈决定下一步。

### 6.2 Workspace 与记忆

  为避免“所有东西都是记忆”造成概念失真，本项目在主要架构中收窄记忆的含义。

| 对象 | 准确定位 |
|---|---|
| 工作记忆 | 当前目标、假设、证据、反证、待办、预算和操作结果 |
| 协作记忆 | 用户决定、偏好、授权和跨轮协作状态 |
| Workspace | 当前任务的结构化显式状态，不保存隐藏思维链 |
| Episode | 一次任务的行动与观察记录，用于排错、回放和未来评价 |
| 知识体 | 长期可推理认识，不称作普通 Agent 记忆 |
| Thinking Model | 长期认知资产，不在主架构中降为程序性记忆 |

  Episode 只有在经过评价、比较和提炼后，才可能为 Thinking Model 或运行策略的改进提供依据；原始日志本身不等于系统已经学习。

## 七、Skill、Plugin 与自由交互

  Skill 是用户意图与 Agent 能力之间的任务接口。Plugin 则是工程上的安装、分发和外部连接容器，两者不属于同一认知层级。

```text
Plugin
├─ Skills
├─ Thinking Models
├─ GraphOps 或工具适配器
├─ Web 交互组件
├─ 外部服务连接器
└─ 配置、权限和版本信息
```

  一个科研分析插件可以同时提供文献综述 Skill、证据等级 Thinking Model、论文搜索 GraphOp 和外部学术服务连接器。Plugin 负责把这些能力带入系统，但不负责代替 Agent 思考。

  用户也不需要每次显式输入命令：

1. 普通讨论可以直接进入对话 Loop，按需使用 Thinking Model，不必强行建立长任务。
2. 明确的编译、消化、建构、研判或报告任务可以激活对应 Skill。
3. 新颖但尚未稳定的任务可以先形成仅在本轮有效的临时任务契约。
4. 只有反复出现且边界稳定的任务，才值得沉淀为新 Skill。

  因此，自由对话和 Skill 并不冲突。Skill 提供目标和权限边界，但不垄断 Thinking Model，也不把 Agent 退化为菜单驱动的软件。

## 八、项目的知识工作流程

```text
材料进入
  ↓
编译：理解材料并形成可追溯语义质料
  ↓
消化：把质料同化到最合适的知识对象
  ↓
建构：改善领域、关系、冲突、实体、方法与模型结构
  ↓
对话 / 研判 / 报告：使用知识体形成可追溯分析
  ↓
Episode / Evaluation：记录和比较任务表现
  ↓
受控演化：提出 TM、GraphOps 或策略候选，经验证与批准后晋升
```

  这张图描述业务上的前后关系，不意味着每一环都是固定管线。编译、消化和建构分别拥有独立 DSH session 与 CognitiveRun；它们共享同一套 Agent 底座、知识体、思维体和 Harness 契约，但不会共享隐式任务进度。

  用户可以在长任务运行期间继续普通对话。只有多个任务试图修改同一对象时，才需要由 revision 和写入边界进行局部协调。

## 九、面向使用者的体验原则

  页面按钮可以保留，但它们只表达“我要开始编译、消化或建构”，不能拥有隐藏工作流。

  长任务界面应持续用自然语言回答四件事：

1. 正在检查什么；
2. 刚刚发现了什么；
3. 下一步准备验证或调整什么；
4. 是否需要用户决定。

  只有范围、价值取舍或高影响改变确实需要人作判断时，系统才弹出选择或输入界面。用户回答必须返回原任务会话，Agent 从当前状态继续，而不是重新开始。

  任务结束应明确呈现：

- 本次改变；
- 本次未改变及原因；
- 留下的待办或待验证问题；
- 是否存在值得继续的任务；
- 用户可以怎样评价结果。

  Token 数、上下文字数、波次、文件路径和工具代码不能作为主要进度。界面展示的是可审计的关注点、观察和行动理由，而不是模型隐藏思维链。

  DSH 是唯一模型—工具循环。本仓不会恢复 ORG 的 Python Agent Runtime，也不会让 Web handler 或外层 workflow 决定模型的语义下一步。ORG 的成熟能力只迁移其确定性契约、算法和测试，不迁移其固定控制流。

  根目录 `nexogenesis/` 是历史 Python 占位，不是当前 DSH 写入权威。所有知识体实质写入必须进入 `HarnessGateway`。

- 人工批准、版本晋升、退化检测和可靠回滚；
- 在不扩大失控风险的前提下形成可解释的学习闭环。

  当前已经存在 Thinking Model 文件、Registry 和选择工具，这说明目标方向已经进入代码；但这不等于思维体已经能够自动学习或可靠演化。

## 十二、不可退让的架构原则

1. Markdown 是知识体的语义事实之源。
2. DSH Agent Loop 是唯一语义决策循环，不建立平行 Agent Runtime。
3. Skill 定义任务边界，不规定固定工具顺序。
4. Thinking Model 是一等认知对象，不是 Skill 内的一段提示词。
5. GraphOps 是可验证的原子行动，不是假装自主性的隐藏工作流。
6. Workspace、Episode 和索引不是知识事实，也不保存隐藏思维链。
7. 所有实质写入只经过 HarnessGateway。
8. Harness 拒绝必须回到原 Loop，不能把拒绝当作任务自然结束。
9. 一次写入只处理一个语义层面；多次微变更可以连续组成一个任务。
10. 用户拥有授权、确认、改变方向和停止任务的最终权力。
11. 自动学习必须晚于真实任务、回放评价和人工批准，不能在运行中静默自改。
12. 任何“已实现”都必须能够指向代码、测试和真实行为证据。

## 十三、项目不是什么

- 不是把长文档机械切块的批处理器；
- 不是把所有材料都新建成卡片的笔记软件；
- 不是依赖一次超长上下文生成知识图谱；
- 不是按钮触发的固定工作流集合；
- 不是把知识、Thinking Model、日志和索引全部称作“记忆”的 Agent；
- 不是通过增加工具数量来假装更聪明；
- 不是允许模型绕过用户确认自动改写知识库；
- 不是已经完成自动学习与自我演化的成熟系统。

## 十四、判断项目是否真正成功

  项目的成功不能只看代码中是否存在 Loop、Skill、Thinking Model 或 GraphOps 文件，而要看真实任务中的行为。

  至少需要证明：

- 知识体随着材料增加变得更有结构、更可解释，而不是更臃肿；
- Agent 能根据新观察改变下一步，而不是执行预制步骤；
- Harness 拒绝后 Agent 会修正、换向或缩小范围；
- 中断恢复不会重复已经成功的写入；
- Thinking Model 的不同版本和组合能够在案例上产生可复现差异；
- GraphOps 的增加或修改对应真实认知需要，而不是概念膨胀；
- 用户能够理解系统正在做什么，并对重要改变保持控制；
- 思维体的演化来自评价证据，而不是模型对自身输出的主观认可。

## 十五、最终定位

  Nexogenesis DSH 的最终目标，是成为一个知识操作与认知迭代系统。

  知识体让系统能够长期积累对领域的认识；思维体让系统能够长期积累怎样形成认识、检验认识和改变知识结构的能力；Agent Runtime 则在每一次真实任务中激活两者，在 Harness 的治理下持续观察、判断、行动和修正。

  它要探索的核心不是“怎样给 Agent 再加一个工作流”，而是：

> 当 Thinking Model 与 GraphOps 都成为可独立演化的一等对象时，Agent 能否在真实知识图谱和真实任务反馈中形成越来越丰富、越来越可靠、同时仍然可理解和可控制的思维策略。

  这是项目最重要的未来愿景，也是当前所有架构选择最终需要服务的目标。
