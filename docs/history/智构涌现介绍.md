# 智构涌现（Nexogenesis）介绍

> 版本：2026-07-27  
> 对应项目：`NexogenesisV0.1/`  
> 运行契约：`AGENTS.md`；正文结构：`01-Cards/_meta/body-structure.md`

---

## 一、简介

**智构涌现（Nexogenesis）** 是面向一位思想者、或一个学派的**知识架构体系**。目标不是传统笔记管理，而是外化并维护一套可修订的知识骨架；再通过讨论、反馈、分析与建构持续优化，使新的观点、认识和对于世界的诠释从结构演进中涌现。

核心组成：

- 以 **Markdown** 为唯一语义事实源的本地知识底座（git 为推荐版本层）；
- 由代码强制过程拓扑、由大模型负责语义判断的 **Harness**；
- 对话与文档摄入进料，结构整理与捕获回流，形成「架构—考验—改写」的工作流。

---

## 二、设计取向

系统在「只有堆积没有结构」与「模板过重难以坚持」之间取务实路线：

- **领域是骨架**：用 domain 卡与 `domains` 字段组织思想空间，而不是目录树；
- **质料与对象分层**：Buffer 整理原材料，Card 承诺知识对象；
- **复杂度必须有证据**：新增机制须说明真实摩擦、最小改动、有效判断与撤回方式。

---

## 三、核心原则

### 3.1 底座主权不变量

　　约定目录下的 **markdown 是唯一语义事实之源**。删掉代码与可重建索引后，只要保留 markdown，知识内容零损失。图谱、向量库、关系数据库都是可重建索引。**git 是强烈推荐的版本层**（历史与回滚），不是思想本体；未启用 git 时不得声称操作已可逆。

### 3.2 Harness 负责过程，LLM 负责语义

- **Harness**：统一写入、schema 校验、权限、索引视图；
- **LLM**：内容判断、冲突识别、卡片撰写、论证组织。

### 3.3 写入统一入口

实质写入须经 `nexogenesis write --batch`。禁止绕过入口直接改卡片。

### 3.4 写路径优先

优先降低高质量内容进入底座的摩擦。

### 3.5 复杂度必须有证据

新增机制须回答：解决什么摩擦、最小改动、如何判断有效、如何撤回。

---

## 四、系统架构

```text
思维体：对话 / 判断 / 理论 / 反思（LLM 语义）
Harness：写入入口、触发、校验、权限、视图
Scheme：可替换的沉淀策略与 prompt
索引层：可重建（领域/冲突/理论视图等）
底座：markdown（语义）· git（推荐版本层）
```

## 六、两层：Buffer 与 Card

### 6.1 Buffer（质料层）

compile 把原文整理为可等待消化的质料。用 `role` 标注用途（`meaning-unit`、`artifact-table`、`artifact-figure`、`tension`、`link-hypothesis` 等），**不定** Card 的 `type`，不写 `id` / `relations`。按意义单元成片，细节内嵌；重要表图单独成质料。

### 6.2 Card（本体对象层）

七种类型：

| 类型 | 回答的问题 |
|---|---|
| `domain` | 这是哪个思想领域？ |
| `claim` | 主张/立场是什么？ |
| `phenomenon` | 发生了什么模式？ |
| `model` | 怎么理解这个复杂事物？ |
| `method` | 怎么做？ |
| `entity` | 这个对象是什么？ |
| `conflict` | 根本矛盾在哪？ |

问题在 `02-Profile/问题清单.md`；阶段性综合可在 `04-OutBox/`。

### 6.3 结构涌现

| 机制 | 落点 |
|---|---|
| 聚类 | `domain` + `domains` |
| 区分 | `conflict` + `conflicts-with` / `involves` |
| 衔接 | `relations` + 可复用时的 `model` / `method` |

### 6.4 关系类型

`extends`、`supports`、`conflicts-with`、`involves`、`example-of`、`applies-to`、`based-on`、`influences`。

正文槽位与校验见 `body-structure.md`；写法正例见 `01-Cards/_meta/card-exemplars/`。

## 七、工作流

### 7.1 对话-捕获-回答

```text
提问 → /talk
     → /capture（≤3 候选，用户确认）
     → write --batch → Journal → 索引
     → /answer 复用
```

### 7.2 文档摄入

```text
00-Inbox
  → compile → 05-Buffer/<role>/
  → digest  → 01-Cards + 问题清单（跨源对照，涌现候选）
  → construct → 结构方案（聚类/区分/衔接齐扫）后写入
```

Harness 生成 prompt/batch；Agent 调用 LLM 回写；`--apply` 落地。

## 八、Harness CLI

```bash
python -m nexogenesis init
python -m nexogenesis validate
python -m nexogenesis index
python -m nexogenesis write --batch <file>
python -m nexogenesis doctor
python -m nexogenesis migrate --to <scheme> --dry-run
python -m nexogenesis compile [--apply]
python -m nexogenesis digest [--apply]
python -m nexogenesis construct [--apply]
```

## 九、Scheme

`schemes/default/` 含方案说明、ontology 模板、prompt 模板与迁移规则。可按语料与建模对象替换。

## 十、延后机制（进入条件）

| 机制 | 进入条件 |
|---|---|
| 更多摄入自动化 | 手动 Agent 模式成为主要瓶颈 |
| 图检索/向量库 | 文本检索在真实规模下明显失效 |
| Web 界面 | 文件与 code agent 成为主要障碍 |
| 多 Agent | 出现可测的并发/隔离/专业化需求 |
| 联邦交换 | 至少两个真实用户需要交换结构化思想 |
