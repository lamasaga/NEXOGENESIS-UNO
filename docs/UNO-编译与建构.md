# UNO 编译与建构

> 2026-09-18：新建编译采用 [单元编译实施](UNO-单元编译实施.md) 的 `unit-cards-v3`；已保存 v2 任务只按原契约恢复。本文早期固定摘要批次、主题 Buffer、标签分类和 v1 卡片描述均为历史，以下编译节已按现行契约改写。

> 2026-09-12：本文件描述新默认路径的实际接口。旧任务通过保存的协议恢复，不将旧聚合、消化或严格论证流程套到新任务。

## 编译

用户选择 Inbox 材料、材料类型和本次要求。Python 确定性提取并按真实章节、内部标题、段落和句子边界形成 Markdown 单元；一个单元最多 60,000 Unicode 字符，其余上下文另有 60,000 字符上限。提取失败保留原件和错误，不提交模型、不计作完成。

原件保存在 `03-Archive/books/<原件哈希>/original.<扩展名>`；清洗拆分后的 Markdown 单元、目录与提取图片保存在 `05-Buffer/books/<原件哈希>/<提取哈希>/`，按版本保留供卡片溯源。已有 Archive 单元继续按原路径读取，不自动迁移。新编译不让模型生成逐段中间笔记，也不拼接历史对话；一个单元一次生成候选卡，不按单元强制产卡，不维护另一套对象贡献账。

每张新卡必须有稳定 ID、标题、摘要、一个主类型 `type`、零到三个既有领域 `domains`、正文、来源和必要关系。`type` 严格按 `conflict/entity/case/concept/method/mechanism/model/claim/phenomenon/undetermined` 顺序选择第一个满足全部最低条件的类型；`phenomenon` 需要观察对象与依据，其他九类都不成立但内容仍完整可复用时使用 `undetermined`。生成提示词同时提供类型与领域说明、正文骨架、允许的领域目录及正反例。没有合适领域时 `domains: []`，编译不得发明领域；新卡不得输出 `tags/topics`。

无领域卡按批进入领域治理检查点。新领域默认由用户逐项确认；开始编译时勾选“允许编译自行决定领域”，会把 `domain_approval_mode: automatic` 冻结到本次任务，合规提案随后自动批准。自动模式仍执行相同的成员唯一性、领域边界、父级、卡片与领域版本、幂等和原子写入校验；它不授权合并、拆分、改父级、退役或修改卡片正文。

程序先预检，再只携带候选卡和必要关系目标进行常规审核。通过卡立即经 HarnessGateway 保存。审核把问题分成卡片问题和关系问题：卡片修改只含本卡与具体要求，关系修改只增加明确且完整核对过的端点并只能改 `relations`。两类各自复核，关系端点改变后不复用旧判断。已保存响应和收据在恢复时优先接回，避免重复调用。

只有全部单元已处理、无延期或提取缺口且归档原件哈希核验通过，才移动 Inbox 原件。图像、复杂表格与 OCR 完整性没有得到验证时保留明确缺口，不能静默算作完成。

## 建构

用户选择当前知识体、主类型或领域，并可补充希望发现的联系。开始时固定范围内的卡片 ID，并冻结当前 `card_classification`；作者、独立审核与写入工具使用同一分类版本。缺少版本字段的旧在途任务保持旧分类口径。每批以少量卡为起点，用标题、正文、主类型和领域缩小候选；不枚举全库卡片对，不按连通率补边。

模型可以不返回联系。正文与分类只用于候选召回，不能自动证明两张卡值得连边。

| 存储用途 | 界面名称 | 检索作用 |
|---|---|---|
| related | 相关 | 值得一起查看的相关信息 |
| contrast | 对照 | 不同结果、观点或反例候选 |
| analogy | 类比 | 可以比较的机制或过程 |
| boundary | 边界 | 可能限制某种解释的条件或案例 |
| background | 背景 | 理解问题所需的历史、制度或情境 |

每条联系有不同且存在的两端、用途和一句具体理由。来源端必须在本批范围，另一端可以是实际提供的范围外候选。两端都记录读取版本，提交前校验；同用途的反向边也视为重复，索引反向查找无需再存一条。

新联系保存在来源卡的 relations 中，标明 system 生成来源。正文、主类型、领域、原有来源和旧关系语义保持；不增加证明、置信分数或论证成熟度字段。回答模型仍须阅读正文判断反例或类比是否成立。没有合适联系的批次可以结束，结束只代表候选比较完成。

## 写入与恢复

新默认入口使用 /api/uno，复用现有模型服务、设置和原生会话身份。实质知识写入统一调用 HarnessGateway 的 prepareUnoSource、commitUnoSummaries、commitUnoLinks、archiveUnoSource；Web 不直接写知识卡。

原文切片与卡片、关系、归档分别有各自的事务批次。写入前检查范围、版本、合法路径、来源、端点与重复标识；不经过符号链接写入。事务日志保存恢复所需的前后版本，完成后清除临时日志，只留下收据。失败回滚，遇到中断时下一次 Gateway 写入先恢复未完成事务；遇到外部修改会停止，不能直接覆盖恢复。此机制不提供任意外部编辑器之间的协同写锁。

任务文件只保留范围、批次位置、尚待批准的一批结果、收据和用量，不保存隐藏思维链。结果已写入而任务状态未更新时，恢复先查收据，避免再次调用模型或重复制卡。待确认批次会保留；失败不自动重试，只有用户明确继续或重新生成才发起新请求。

一次执行最多十二次模型请求，达到上限或十分钟后保留进度并暂停。暂停阻止后续模型调用与提交，已经完成的事务保留；模型供应商的实际停止响应仍影响停下的时间。编译、建构运行时阻止删除对应会话或切换知识实例。每次模型调用记录供应商、模型、输入/输出用量、耗时与状态，失败调用也计入，未报告的用量不按零消耗解释。

## 界面与兼容

默认知识入口为编译、建构、思考。新编译不再要求用户先选“普通编译 / 主题编译 / 消化”，新建构不再要求选旧目标、工作量和严格论证流程；对应的旧准备面板已经从主应用装配中撤下。新任务面板提供预览、原文回查、暂停、继续和历史任务恢复。旧任务记录保留，新对话不会自动得到知识写入权限。

已保存的旧编译与旧建构任务所需分类校验保留在明确的兼容分支；新建任务不能调用该分支。更早工具和历史任务只读。旧接口兼容不代表新模式沿用旧规则，也不能把旧 `tags/topics` 写入 v3 卡片。

## 验证与限制

隔离测试应覆盖材料到卡片、一个主类型、多个既有领域、空领域警告、非法领域拒绝、父子领域去重、来源归档、筛选、关系、取消、版本冲突、写入中断、收据恢复和提取失败。还要单独证明已保存 v2 任务能按旧契约恢复。测试替身不会证明真实模型质量。

程序行为通过不等于摘要忠实度、关系价值或速度已经由真实模型证明。下一步用实际选定模型与短材料，对照原文条件保留、合理反例与类比增量，以及每张可用卡片和每次回答的总成本。长文规模、PDF 图表、OCR 与跨领域类比收益需要单独实测。

撤回以 UNO 代码检查点为单位，先暂停确认属于 UNO 的任务。已经保存的 Markdown、来源与收据保留；旧程序不能完整编辑新 Schema 时保持只读，不自动降级或改写知识。
