# UNO 领域说明与检索优化方案

范围：领域说明的结构化阅读、共享内容校验、领域关系的 Gateway 保存与图谱／阅读接口属于当前最小实现，契约见[领域说明与领域关系](design/knowledge-guidance/domains.md)。本文的领域辅助召回、自动连边、大目录外发优化和检索效果实验仍为待实施设计；不代表检索行为已经改变。领域创建、批准和成员事务以 [领域治理方案](UNO-领域治理方案.md) 为准。

## 1. 目标和范围

领域的首要价值是帮助用户和 UNO 找到适合当前问题的知识、发现相关边界与遗漏。知识图谱的视觉表现是次要收益。领域数量、正文长度、成员覆盖率和连边率均不作为成功指标。

本方案只有三个实施事项：

1. **领域说明**：让已有的范围、核心问题、边界和代表入口成为可读、可检索的信息。
2. **领域辅助检索**：在现有卡片检索上增加有界的领域召回和领域内检索，解决大领域、小领域和未归属卡共存的问题。
3. **领域间检索关系**：仅为具体检索缺口建立跨领域线索，经过对照验证再用于默认检索。

原先所称“领域导航层”主要指点选领域、展开成员或聚类的图谱交互。本方案不把它作为独立工程，不建设全屏领域地图或全量成员连线。基本的领域阅读页、成员筛选和检索结果解释归入前两项。

保留 `type + domains`：不恢复 `tags/topics`，也不增加每张卡必须填写的新分类字段。领域仍为独立 Markdown 记录，成员仍以卡片 `domains` 为唯一事实源。自动批准是本次编译的授权选择，不意味着领域已通过语义效果验收。

## 2. 已核对的当前实现

| 当前事实 | 实际作用与缺口 | 主要位置 |
| --- | --- | --- |

本次只读统计：中国政治经济库有 202 张知识卡、6 个正式领域；六个领域正文均为空，摘要为 37–55 个字符，各有 3–4 个核心问题、3–5 张代表卡，成员数为 4、14、11、4、16、3。这说明主要缺口是信息消费和检索接线，不是先让模型多写几百字。统计属于该时点，不代表后续任务状态。

## 3. 领域说明应该说明什么

### 3.1 内容契约

一个领域说明应能回答以下问题，而不要求固定篇幅：

| 用户需要理解的内容 | 数据来源 | 写法要求 |
| --- | --- | --- |
| 这个领域处理什么问题 | `title`、`summary` | 用一段简短说明界定对象、问题和尺度；避免只复述名称 |
| 什么问题适合从这里检索 | `core_questions` | 通常 3–5 个可区分的问题；写出条件或比较维度，不把待检验观点预设成结论 |
| 什么内容可以放进来 | `includes` | 按知识问题定义；概念、机制、案例和反例只要服务该问题均可纳入 |
| 哪些问题应该另找材料 | `excludes` | 明确相邻范围、粒度或情境，不把“缺少材料”写成“不存在这种现象” |
| 从哪几张卡开始 | `representative_card_ids` | 通常 3–5 个有效成员入口，覆盖不同核心问题；入口不穷尽全部成员 |
| 当前已有多少材料、覆盖怎样 | 从有效成员派生 | 成员数、主类型／来源分布、待核验入口；统计可重建、不手工维护 |
| 与哪些领域存在可用检索联系 | `parents`、经过验证的 `relations` | 按第 6 节显示使用条件和边界；没有可用关系时不凑数 |

简短说明约 300–800 字可以作为阅读上的参考，不作最低字数校验，也不另开模型请求填满篇幅。页面直接把现有结构化定义组织为连贯的阅读内容；模型已有的字段不再复制为第二份必须同步的长正文。

历史领域若已有正文，应保留并展示。只有用户或建构任务确有跨卡综合需要时，才补充带引用的综合说明；其中的主张不能因为位于领域页就被当成全领域共识。领域记录用于说明组织边界，具体事实和论证仍引用知识卡及其来源。

### 3.2 示例：双碳目标与能源转型

以下是写法示例，不是对现有领域文件的修改，也不声称示例问题已被现有成员完整回答。

**范围说明**：围绕减排约束下的能源供给、工业用能与制度安排，组织能源替代、系统可靠性、脱碳路径和碳市场设计的知识。使用时同时区分技术可行性、经济成本、运行条件和政策目标。

**适合检索的问题**：

- 清洁能源替代需要哪些电网、储能与备用条件？
- 不同行业的减排路径为什么不同，成本和约束分别是什么？
- 碳市场、补贴与行政要求通过哪些机制影响减排选择？
- 减排、安全供应和短期成本之间在什么条件下产生冲突？

**纳入边界**：能够说明上述问题的机制、模型、政策比较、具体项目、失败案例与反例。

**排除边界**：纯粹的设备操作教程，或与能源、减排及制度安排无关的金融交易信息。一个项目规模小、只来自一家公司，并不是排除理由。

**阅读入口**：展示现有有效代表卡的标题、主类型和摘要，例如能源结构、工业脱碳和碳交易三类入口；用户点开后读取原卡。阅读入口不代替全领域的检索结果。

必须改进的语义尺度：避免用“数字经济为什么必然提高生产率”作为领域核心问题，应写“数字经济在什么条件下影响生产率，可能受哪些约束”。否则领域说明本身会给后续回答预设立场。

### 3.3 更新方式

新增成员后，数量、来源分布和成员页自动更新，零模型请求。代表卡退役或被替代时标记失效，并在合法 `superseded_by` 能明确解析时更新派生入口；不悄悄改写正式语义说明。

核心问题和边界不随每张新卡重写。只有用户提出修订、检索持续暴露错配，或新材料形成原定义无法承载的稳定问题时，才进入有界治理。模型读现定义、相关新增卡摘要及少量代表证据，不重读全部成员。

## 4. 领域如何辅助已经存在的检索

### 4.1 查询流程

保留普通对话现有的意图判断与回答路径。领域处理在宿主的一次资料收集内部完成，不增加逐域模型选择、逐卡阅读或审核循环。

```text
当前问题和已有检索路线
  ├─ 全库卡片直接检索：保留未归属卡、具体实体和精确命中
  ├─ 领域定义匹配 → 少量候选领域 → 在成员集合内按当前问题检索
  └─ 原有卡片关系扩展；启用验证过的领域关系时，再加有限跨域候选
             ↓
  按卡片身份去重、合并排名、保留问题所需的证据与反例
             ↓
  形成有界资料包：实际选中卡片 + 真正相关的领域说明片段
             ↓
  模型回答，并引用实际提供的卡片或来源
```

全库检索始终保留。自动判断领域属于软性召回，不会把用户的问题锁死在某一个目录；用户明确指定“只看某领域”时才应用硬范围，且不得借跨领域关系越界。

### 4.2 复用与补齐

复用现有稀疏检索、领域过滤、卡片关系邻域、问题路线和上下文组包。新增一个共享的领域读取与检索模块，供对话、编译和治理使用；调用方可以选择不同预算，但不能各自解释字段。

领域索引内容采用字段区分：标题、规范同义名称（后续确有同义召回缺口再增加）、摘要、核心问题、纳入边界是正向线索；排除边界用于解释歧义和检查候选，不能作为正向加分文本。

普通的“排除条款里出现一个词”也不能成为确定性禁止检索的理由。程序不凭关键词理解复杂否定：遇到歧义保留全库候选，在资料包中提供该范围说明，交由回答结合实际卡片判断。

先检索领域定义，再检索成员卡。不要把同一份领域长说明复制到数百张成员卡的检索正文中，否则全体成员会因同一句话一起命中、稀释具体内容。

初版的预期收益是：问题命中领域名称或核心问题后，在较合适的成员集合内重新排序，找回被全库高频结果压住的具体卡。这仍是词面／稀疏检索；如果问题与成员卡完全没有可用词面对应，领域本身不会自动补出语义理解。弱命中时不把全部代表卡当成答案证据。固定题若显示主要缺口是同义表达，再单独比较有限查询改写或向量召回；不把这类能力写成首轮保证。

将不同召回渠道的排名合并，避免直接把领域相似度、稀疏分数和关系优先级相加。初版可评测 RRF（按排名融合）与现有排序；它适合合并不同指标的候选列表，但在 UNO 上是否更好必须由固定题验证。[RRF 官方说明](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/reciprocal-rank-fusion)

同一张卡即使属于三个领域，也只算一个领域渠道候选；父子重叠和双向关系同样去重。精确 ID／标题命中和比较问题的双方对象单独保留，不能被“大领域票数”挤掉。领域渠道仍需成员卡与当前问题的相关性证据；不会把所有成员自动加分。

### 4.3 初版实验预算

以下是实施时的起始配置，用固定题调整，不是知识质量阈值，也不是已经上线的参数。

| 范围 | 起始约束 | 意图 |
| --- | --- | --- |
| 领域候选 | 默认至多 2 个，跨主题比较最多 3 个；可一个都不选 | 限制错误路由和目录膨胀 |
| 本地卡片候选 | 全库直接约 24 条，领域内合计约 24 条，关系扩展合计约 12 条；去重后至多 60 条 | 多找候选仅发生在本地，不等于外发模型 |
| 回答资料包 | 初版沿用现有至多 9 张卡及总资料约 22,000 字符的口径 | 不因领域变大而增加每轮模型输入 |
| 领域说明 | 最多 2 份紧凑定义，合计参考上限 1,200 字符，计入同一资料预算 | 通常发送范围和与本题有关的问题、边界；无必要则省略 |
| 跨领域扩展 | 最多一跳、2 个目标领域，与卡片关系共享上述候选预算 | 禁止领域递归扇出 |
| 模型请求 | 相对现有对话路径不增加领域选择／排序请求 | 保持可测量的调用成本 |

22,000 是资料组包预算，不含全部系统提示和用户消息，也不是 Token 数。实施应记录真正序列化后的字符和供应商 Token 用量。多个关联库最终共享总预算，域 ID 使用“库 ID + 域 ID”区分。

领域说明有价值才进入资料包；不能为了满足固定字数而挤出关键证据。跨域比较须给双方保留候选机会，反例和边界优先于重复说明。摘要或节选必须标注交付范围，不能写成完整阅读。

此前“3 张完整卡 + 5 张摘要卡”是当前编译参考的交付规则；本方案不把它冒称为普通对话的现行实现。编译继续遵守自己的上限，普通对话先保持现有基线以隔离领域优化的效果。

## 5. 一个领域有几百张卡时

### 5.1 集合索引代替整域上下文

程序维护可重建的 `domain_id → active_card_ids` 倒排表，搜索时在该成员集合中评分。500 张卡是本地候选集合，模型仍只接收本题选中的少量证据。

例如，“双碳”领域有 500 张卡，用户询问“碳价为什么未能改变某行业的投资决策”。程序结合当前问题在全库和本领域查找成本传导、预期、配额及投资约束等相关卡，不把储能、电网、氢能等全部材料搬进提示词。这里的机制词是示意，不预设当前库已经有这些证据。

领域、成员映射、卡片与 Buffer 使用可独立刷新的索引部分，避免卡片检索因 Buffer 的规模或更新被迫扫描和重算。复用现有分词与检索能力，不以这次优化为由引入新的数据库。冷启动允许本地重建；日常读取使用快照和文件变更指纹，不能每次问题都重新读取全部正文。

### 5.2 数量增长与语义拆分分开

几百张卡并不自动说明领域需要拆分。研究问题一致、检索能定位证据时，一个大领域可以继续使用。

只有以下证据持续出现，才考虑子领域或边界修订：同一领域内多个稳定问题群经常彼此干扰；用户问题难以召回相关卡；既有边界无法解释大量成员；跨群资料被反复错误组合。先查排序和归属问题，再决定是否需要新领域。

拆分属于已有高影响治理边界，需要影响预览和授权。检索内部可以使用临时分组去重和提高覆盖，它们不回写卡片，也不生成一套隐藏的永久 Tag。

### 5.3 代表卡和综述请求

代表卡用于初次了解一个领域，不是检索白名单，更不是每次固定送给模型的前几张卡。普通具体问题按问题选卡，代表卡仅在相关时竞争排序。

用户问“这个领域都有什么”时，提供现有核心问题、各问题的动态成员分布和有限代表卡，标明当前覆盖。用户要求全面研报时，属于显式扩大范围的任务，应按问题分组、保留处理范围和预算，不能拿普通回答的九张卡宣称已经综述几百张卡。

成员浏览采用现有卡片列表的领域过滤和分页，默认每页 30 条；不需要额外的图谱操作。统计区分直接成员和包含子领域的成员，两者按 ID 去重，不能把父级计数简单累加。

### 5.4 领域数量也会增长

领域数量少且定义总量较小时可提交全部短定义；数量或内容变大时，编译与治理都只外发相关候选及必要的父级／近邻定义。

- 对话：问题召回少量领域。
- 制卡：用当前单元标题、摘要线索及原文的本地特征召回有界目录，生成与本单元审核共用同一允许目录快照。
- 治理：用本批卡的候选并集形成请求，只传候选完整定义和必要上下级；并集超预算时分成互不重叠的卡组，不截断边界假装完整。
- 写入：Gateway 仍检查完整实时目录、版本和祖先关系。全目录参与程序校验，不等于全目录进入提示词。
- 增域去重：新提案进入正式提交前，程序再检查全目录的同 ID／规范同名和相近领域；语义近似结果保留为待核对，不冒充确定重复，也不丢弃已生成知识卡。

现有 10 单元／20 张未组织卡等检查点先保留，不把领域说明优化变成新的逐卡模型流程。

## 6. 领域之间的关系如何增加检索效果

### 6.1 从漏检问题出发

创建领域关系前必须说明：哪类问题仅查当前领域会漏掉什么，目标领域能补充什么，在哪些条件下不适用。仅仅“都是宏观经济”不足以建边；一条具体卡片关系就能解决的问题，优先使用该卡片关系。

先沿用现有领域关系 `adjacent / contrast / bridge` 及独立的 `parents`，不扩张普通知识卡的七类关系：

| 关系 | 检索用途 | 使用限制 |
| --- | --- | --- |
| `parents` | 用户按较大范围检索时覆盖子领域成员 | 只表示范围包含，不能从相近主题推导父子关系 |
| `adjacent` | 查找互补范围，如能源技术转型涉及的融资约束 | 问题实际触及共同边界时才扩展 |
| `contrast` | 查找可比的问题处理方式、竞争解释或制度条件 | 不把整个领域认定为彼此反驳 |
| `bridge` | 为跨领域机制比较或类比召回候选 | 必须指出对应结构与不可迁移的条件；类比仍需核对端点正文 |

领域关系只是找材料的线索。它不能直接支持事实、因果、反驳或类比结论。

### 6.2 最小关系记录

在现有 `type / target / note` 基础上，为新关系增加：

- `use_when`：什么问题或条件需要访问对端；
- `limits`：哪些情况下不应使用这条线索；
- `anchor_card_ids`：可选 0–6 张任一端领域内的实际卡片，用于定位联系；没有合适卡时允许为空，不以格式要求强迫建立证据。后续检索实验可要求更强的两端覆盖。

保存 `basis: navigation`，锚点用稳定 ID；版本与审核快照放事务／审计信息，运行时重新解析有效成员。旧关系缺少这些信息时仍可显示，但默认不参与自动跨域扩展。不给所有旧领域自动补边。

例：从“制造业与产业链现代化”访问“数字经济与数据要素治理”，使用条件可以是问题涉及生产数据共享如何影响产业链协同；不适用于仅比较生产基地的交通距离。将此关系用于自动检索扩展的实验前，需要从两侧卡片核对支撑这一导航理由的锚点；当前基础读写允许不附锚点，示例不能直接当作现有证据。

领域关系按声明方向扩展。需要反向查找时必须核对反向的使用条件，不能把单向依赖或问题条件自动翻转。

### 6.3 创建、调用和维护

先选择 2–3 个有明确漏检案例的领域对做实验。模型在一次有限请求中查看两端定义及少量锚点提出关系，随后按同问题对照检索结果；初版不作为每轮编译的强制附加调用。

查询时无需模型逐条审核关系。程序用当前路线、问题词、`use_when` 和实际锚点召回限定候选，再对目标领域的卡片重新按原问题评分；`use_when` 的词面匹配只表示候选，不是语义证明。不匹配、没有有效锚点或检索不到相关目标卡时，边存在也不扩展。

关系不存在、锚点失效、领域退役或目标库不在本轮授权范围时，退回普通检索。自动批准“新建领域并挂靠”不被默认为允许补写任意跨领域关系；该能力的写入授权和预览需在实施关系治理时单独定义。

## 7. 制作、审核与回答提示词

复用同一领域定义序列化函数，避免制作提示词、审核提示词和阅读页各自维护一份格式。

领域制作指导应包含以下原则与正反例：

> 领域描述可长期检索的问题空间。范围说明不预设争议命题正确；核心问题指出对象、条件或比较维度；纳入边界允许与这些问题有关的概念、机制、案例、失败和反例。排除边界用来区分范围，不能以来源少或卡片类型为由排除有用证据。选择少量现有有效成员作为入口，不复制全部成员，不输出修复说明。
>
> 正例：“制度安排如何影响投资激励，在哪些条件下出现相反结果？”
>
> 反例：“制度安排必然提高效率”；“不收单个企业案例”；为了显得完整列出库中尚无证据的成熟理论体系。

审核区分两类问题：字段／ID／父子循环／版本由程序拒绝非法写入；边界含混、预设结论、代表卡单一和语义重叠属于语义检查。程序不能宣称自己已证明领域边界合理，也不为每张成员卡增加独立审核调用。

回答提示词增加简短说明：领域定义是组织与检索说明，领域范围不保证本轮材料覆盖全部问题；领域关系只解释为什么找到某卡，实际判断须依据已提供的卡片正文与来源；未召回不等于不存在。

说明字段缺失的旧领域应展示已有信息和具体缺口，允许继续普通检索，不为了格式完整阻塞对话、编译或已通过卡片的保存。

## 8. 界面只做必要的阅读与检查

领域页显示范围、核心问题、边界、代表入口、成员数量，并提供“查看成员”进入现有卡片列表。用户能够读懂领域即可，不要求学习新的图谱操作。

检索记录可展开查看：哪些领域被选中，为什么选中，哪些卡由哪个渠道找到，哪些候选因重复、弱相关或预算未进入资料包。正常回答不播报这套过程。

图谱本轮仅修正领域标题、打开详情和必要的已有关系显示。是否高亮成员或显示一跳联系可在检索效果验证后决定；不为消除孤立节点而创建论证边，不把成员归属线计入论证连边率或作为知识质量提升的证据。

真实知识迁移先产生差异预览；必要的语义写入经 Gateway。新说明的派生展示不需要重写全部领域文件或成员卡。旧 `type: domain` 卡的迁移是独立问题，本方案不自动改变它们。

## 10. 如何证明提升了检索

先冻结只读知识快照、问题、相关卡和必要反例。初版建议 32 个问题：12 个领域内具体问题、6 个边界／近义混淆问题、6 个跨域比较问题、4 个未归属或空目录问题、4 个大领域检索问题。不得用“新建了多少领域”代替评测。

设置四个可归因条件：

- A：现有检索。
- B：A 加可用的领域说明，候选卡集合固定，用于检查说明对回答是否有帮助。
- C：A 加领域辅助召回与领域说明，不启用领域关系。
- D：C 加经过人工核对的少量领域关系。

D 另做关闭／打乱关系目标的诊断，判断收益是否来自有意义的关系，而非只是多搜了一遍。各条件保持相同最终资料预算、模型、问题与生成参数，答案匿名比较；参数调优题与验收题分开。

先做零模型的召回评测，再做获授权的小规模回答评测。历史编译请求额度不作为新实验预算。

重点观察：

| 指标 | 为什么看它 |
| --- | --- |
| 前 9 条的相关卡命中与排序 | 更好的领域入口最终有没有把需要的卡送到模型 |
| 必要反例、限制条件和比较另一方的命中 | 防止只召回同域的同一立场 |
| 精确 ID／标题问题的保留 | 防止领域机制干扰本来可靠的直接查询 |
| 未归属卡、弱归属卡和跨库边界 | 防止分类不完整变成检索盲区或越权扩展 |
| 回答引用支持、条件保留与错误断言 | 区分“找到了卡”和“正确使用了卡” |
| 输入 Token、实际调用数、冷热检索耗时 | 验证成本不会随成员量转化为外发上下文膨胀 |
| 每种新增渠道的独有相关卡与噪声 | 判断哪个机制值得保留 |

程序规模测试覆盖单领域 50／500／2,000 张卡及目录 20／200／1,000 个领域；其中重复模板的合成数据只验证性能、预算和隔离，不证明语义召回提升。已有真实小库的关系实验也不外推为千卡效果。

验收门槛：权限、事实边界、精确目标和预算必须全部通过；领域辅助召回在事先标注的漏检问题中带来可复核的新证据，且无不可接受的直接查询退化；领域关系必须相对于 C 独立改善跨域题，而非只增加内容。如果 D 没有稳定收益，保留 A–C 的成果，领域关系不进入默认检索。

新增日志只记录查询、候选、字段命中、路径、排除原因、交付范围和用量，置于可重建运行数据中；不记录隐藏思维，也不把这些日志塞回下一轮提示词。

## 11. 可执行的优先级

先完成 A；同时将 C 中“只发送候选目录”的局部约束列为优先项，可以复用已有领域候选逻辑并先修正排除边界正向加分的问题。随后以 B 为主要效果工作，建好共享召回后完成 C 的统一接线。D 以真实漏检案例为条件，E 后置。

领域规模增长时，知识内容可以增加，单次问题所需的领域定义、候选证据和模型往返仍保持有界。方案的取舍由相关证据的命中和回答质量决定，不由图上是否热闹决定。
