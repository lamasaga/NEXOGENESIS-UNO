# 2026-09-02 便携知识体发行包

> 注意：这是既有知识实例的迁移包，不是纯净核心 Agent 发行包。纯净初始化分发应使用 `tools/export-clean-agent.ps1`。

  便携发行由两份相互绑定的 ZIP 构成：核心知识体包交付 Agent 源码与派生知识，原始资料包只交付尚未处理和已经归档的来源文件。两者都不携带本机运行记录、会话、缓存、索引、已安装依赖和前端构建结果。它们是可恢复运行的源码与知识快照，不是免安装的桌面程序。

## 一、发行边界

| 类别 | 处理方式 |
|---|---|
| Agent 主体 | 保留 `.agent/`、运行时代码、Thinking Model、OPS、Harness、Web 源码、配置模板和锁文件 |
| 核心知识体包 | 保留 Agent、`01-Cards/`、`02-Profile/`、`04-OutBox/`、`05-Buffer/`；创建空的 Inbox 与 Archive 目录 |
| 原始资料包 | 只保留 `00-Inbox/` 与 `03-Archive/`，不重复打包 Agent、Card 和 Buffer |
| 运行状态 | 排除 `.nexogenesis/`、`tmp/`、`06-Journal/`、`07-Conversations/` |
| 本地依赖 | 排除所有 `node_modules/`、`.venv/` 与 Python 缓存 |
| 构建结果 | 排除 `dist/`；接收方按锁文件重新安装和构建 |
| 密钥 | 排除 `.env`；DSH 用户目录中的供应商密钥本来就不在项目内 |

  `06-Journal/` 虽然记录了写入历史，但不属于 Markdown 语义事实源，因此默认不分发。如果某次交付需要审计历史，应把它作为单独、受控的审计附件，而不是重新混入知识体快照。

## 二、生成压缩包

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\export-portable-snapshot.ps1
```

  默认输出到仓库同级的 `NEXOGENESIS-DSH-distributions/`，避免压缩包或暂存目录反过来进入自身。脚本只从源仓库复制文件，不会删除、移动或清理当前知识库。

  默认会生成三项结果：文件名以 `-core.zip` 结尾的核心知识体包、以 `-materials.zip` 结尾的原始资料包，以及以 `-release.json` 结尾的绑定清单。两份 ZIP 各自包含内容清单和逐文件 SHA-256；外部发布清单记录两个压缩包的名称、大小和 SHA-256，防止混用不同批次的核心与资料。

  如果程序工作区还有未提交改动，默认文件名会带 `working`，清单中的 `source_worktree_dirty` 也会是 `true`。用于正式长期分发时，应先提交并验证程序改动，再重新导出不带 `working` 的版本；知识目录本身不进入核心 Git，但仍会逐项进入知识统计和哈希清单。

  ZIP 内部固定使用较短的 `NEXOGENESIS-DSH/` 根目录，以免版本名继续放大归档材料中的长文件名。Windows 接收方仍建议解压到较短路径，例如 `D:\NEXOGENESIS-DSH`，并使用支持长路径的解压工具。

## 三、接收方恢复运行

  将两份 ZIP 解压到同一个父目录。它们内部都以 `NEXOGENESIS-DSH/` 为根，资料包会把 Inbox 和 Archive 覆盖合并到核心包创建的空目录，不会覆盖 Agent 或派生知识。随后在项目根执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\prepare-nexogenesis.ps1
```

  准备脚本按三个 `package-lock.json` 执行 `npm ci`，构建 `web/dist/`，然后把实际解压路径写入用户级 DSH preset 与 profile。它不会把依赖或密钥写回发行包。

  准备完成后运行：

```cmd
start-nexogenesis.cmd
```

  接收环境仍需预先安装兼容的 Node.js、npm 与 DSH。PDF 编译能力另外依赖 Poppler；没有 Poppler 不影响已存在 Card、Buffer 和归档材料的保存，只影响新的 PDF 解析。

## 四、为什么不直接压缩整个工作目录

  排除列表式清理容易漏掉以后新出现的缓存、遥测或会话目录，也存在误删源仓库的风险。当前方案采用“允许进入发行包的内容白名单 + 暂存区 + 写后核验”，与知识主权边界一致：知识内容原样保留，程序依赖可以重建，运行状态不冒充知识。

  当前双包结构已经把高频变化、体积较小的 Agent 与派生知识，同低频变化、体积较大的原始资料分开。更长期的工程方式仍是把 Agent 核心与私有知识实例分别版本化，再由发行器组合指定的核心 Tag 和知识快照；本次不额外引入第二套知识写入系统。
