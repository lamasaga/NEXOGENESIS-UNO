# UNO 知识处理优化设计方案

日期：2026-09-13。版本：proposal-v2。状态：**总体设计已获用户认可；本轮同步 B、D、N、O 的反馈，尚未实施到编译、检索或知识库中**。

依据：本轮 18 点反馈与新增的自由提示词要求；UNO、DSH 的现行契约、实现和 UNO 本轮公众号编译记录。本文不将旧批处理结果当作新 Web 流程的验证结果。数字均区分现有限制与试验默认值；建议参数需要样本验证，不是已证明的最优值。

配套：[可编辑流程对齐页](design/uno-knowledge-optimization/alignment.html) · [知识处理设置与编译弹窗原型](design/uno-knowledge-optimization/interaction.html)。页面意见不会自动发送给助手，也不会改变业务行为。

## 1. 推荐的整体取舍

采用“小批完整闭环”：**确定范围与要求 → 清洗和分类 → 带来源定位的 Buffer → 阅读、聚合和制卡 → 新上下文复核与修订 → 结算本批 → 按选择继续下一批**。一本长书可跨批处理，各批共享简短的全书背景与同一份增量聚合档案。

质量由三个不同机制共同负责：直接注入的内容规范指导写作；程序挡住确定的结构和写入错误；新上下文审核检查来源忠实度、遗漏和实际可用性。它们不能互相替代，也不需要各建一套大台账。

| 关键问题 | 推荐决定 | 收益与代价 |
|---|---|---|
| 第一次阻挡还是第二次检查 | 写入时做有限硬检查；每小批做一次实质复核 | 避免低级错误进入正式知识，同时保留一次额外语义审查的成本 |
| 一张卡不合格会怎样 | 保留草稿和问题，只暂停该对象及真实依赖它的修改 | 需要对象级状态；不能用一个全局错误标志锁住整批 |
| 阅读证据 | 完整编译范围中的清洁正文必须有真实阅读区间记录 | 能发现漏读，不能证明模型理解；不能靠过度清洗缩小义务 |
| 审稿人 | 每批结束新建审核上下文，默认串行、同一配置模型 | 隔开作者历史和自我辩护；不是两个独立事实来源，也不保证消除偏差 |
| 聚合来源 | 保留一份具有实质内容的增量档案，证据定位只保存一处 | 支撑跨材料理解和回查；避免重写原文、候选表和卡片副本 |
| 领域 | 保留轻量领域说明文档，领域之间可联系，归属另存 | 给检索提供问题背景；不为每个文件夹维护一篇综述 |
| 卡片 | 八种多标签，摘要、实质正文、边界、来源为基本结构 | 有质量底线，正文组织仍随知识对象变化 |
| 图像 | 先解决原图保存与卡片打开；图意识别按需 | 保存图片不必先付出视觉理解成本；未解读的图不能当作已读证据 |
| 长任务 | 每批闭环、可审计请求账本、显式继续额度、可恢复队列 | 不必携带整次长会话；“全部”依然可能在一轮额度耗尽时暂停 |

## 2. 当前问题与针对性修正

UNO 当前已经有专用 Agent Loop、历史版本、多标签、七种关系、原文检索和第二轮整理，不必重造引擎。DSH 有真实阅读区间、选定范围、聚合来源、严格卡片规范和版本化恢复，可提取这些能力而不搬回整套旧工作流。

| 观察到的问题 | 证据与边界 | 本方案如何处理 |
|---|---|---|
| 摘要替代了知识正文 | 上一轮 72 张卡中，36 张没有正文小标题，58 张正文少于 300 个 Unicode 字符；没有软件要求卡片不得超过 300 字。标题数量和长度本身都不是质量判据 | 审核“摘要之外新增了什么解释”，保留机制过程、方法操作、案例细节；不设成卡字数配额 |
| 类型说明不足以指导写出好卡 | 现有类型、关系说明有定义和正反例，但完整的“原文片段→成品→过度压缩反例”不足 | 常驻核心规范；按需补充完整类型示范；四张问题卡用作回归样本 |
| 概览结果被收束为原文保留 | 508 篇未制卡中，278 篇有正文判断，230 篇仅概览筛选；“未发现”不能等于“没有知识” | 概览未读、已读未制卡、材料缺失、已有承载分别计数，前者仍可回到待编译队列 |
| 第二轮没有系统补足内容 | 之前重点做命名、分类、关系和少量边界补充；不能据此声称所有正文完整 | 所有本批新增和实质改写卡都接受正文复核，高风险主张回查来源 |
| 程序检查弱而归档联动强 | UNO 某些缺项只是质量提示；当前结束阶段的未解问题可能令整批无法归档 | 对少数基础缺项真正拒绝；对语义问题按卡片/来源依赖结算 |
| 短采购线索和宣传材料容易被一刀切 | 标题金额不是履约证据，但具体需求、组织问题、合同安排仍可能是知识 | 分离消息真实性、证据完整度和沉淀价值；广告中的实质内容不自动排除 |
| 图片问题混入全部完成条件 | PDF、DOCX 的未核验警告不等于每张图都妨碍当前文本制卡 | 资产保存、文字理解和关键图证据分别记状态 |
| 原件移动后目录说明有旧路径 | 本轮报告记录 596 份 catalog 中的旧 Inbox 路径问题，主追溯链有效但目录不同步 | 稳定来源 ID 解析位置；所有目录和引用由同一迁移收据更新 |

上一轮通过 Codex 和脚本处理 689 篇，并非直接运行当前 Web 的完整编译结束机制。该结果可用于内容质量复盘，不能证明或否定 Web Agent Loop 的所有能力。

## 3. A：平等的多知识库目录

两个项目分别使用以下结构；UNO 与 DSH 的知识内容不互相合并：

```text
NEXOGENESIS-UNO/ 或 NEXOGENESIS-DSH/
  packages/、web/、docs/、presets/        程序、契约和项目文档
  .nexogenesis/instances.json            知识库注册与稳定 ID
  knowledge-bases/                       界面显示“知识库”
    <library-id>/
      00-Inbox/
      01-Cards/
        _meta/domains/                  领域说明，不属于八种知识类型
      02-Profile/                       已有档案，保持授权规则
      03-Archive/
        sources/<source-id>/            原件、清洗记录与定位说明
        aggregates/<aggregate-id>.md    聚合来源档案
        assets/<asset-id>/              原图、页面图、来源说明
        card-history/
      04-OutBox/
      05-Buffer/<主题文件夹>/
      06-Journal/
      07-Conversations/
      .nexogenesis/                     该库可重建索引和任务状态
```

保留现有知识库 ID，包括名为 `legacy` 的 ID；它只成为普通库 ID，不再代表项目根目录的特权知识库。显示名称可以改，物理根路径以稳定 ID 为准。当前 UNO 是根目录“主知识库”与 instances 下“辅助知识库”；DSH 是根目录“金融底座”与 instances 下“周期研究”“人工智能”。全部迁到同一层，独立保留各自内容、配置和会话归属。

一个编译任务只写一个明确目标库。项目可以关联多个库用于思考，但关联不授予跨库修改权限。检索结果带库 ID；跨库修改须另行选择目标，不因一个自由提示词而扩大本轮写入范围。

迁移采用专用本地工具，不让模型临时拼接移动命令：暂停目标库写入 → 生成文件/引用/注册表快照 → 复制到新根并核对校验和 → 在临时注册表下验证读卡、检索、图片和恢复 → 原子切换注册表 → 确认新根可用后撤去旧根编号目录。迁移备份放独立备份位置，不注册为第二个活跃知识库。失败恢复旧注册表与快照。

需检查根路径假设、绝对路径、主题指针、导出工具、测试默认库、会话所绑实例。相对位置相同不代表所有绝对引用自动有效。运行中任务不得在路径切换中继续写入；确认工具退出后才迁移。本文未执行上述动作。

## 4. B：持久要求、任务要求与范围快照

知识处理设置新增“编译偏好”自由文本，作用于当前知识库，影响清洗、阅读关注点、聚合、成卡与审核。它与“思维体表达”的回答风格分开：前者决定沉淀什么和怎样组织，后者决定回答怎样表达。

编译弹窗提供“本次补充要求”。默认继承库偏好，也可明确选择“本次不使用库偏好”。相同事项由本次明确要求覆盖长期偏好，未冲突部分保留；不能静默用模型摘要替换用户原话。任务启动冻结两者及规范版本，运行中改设置只影响新任务。恢复原任务继续使用其快照；确需变更时生成要求修订，标出影响哪些尚未处理或已经处理的内容。

建议长期示例：

> 优先保存作者的解释过程、不同立场及关键案例。方法要保留可执行细节，数字保留时间和统计口径。案例可独立成卡并被多张卡引用。清理关注提示、重复宣传语、无信息的活动报名段，但宣传材料中的具体需求与事实不要一起删。正文充分展开，不要把摘要换句话重复。

建议本次示例：

> 这一批重点保留组织如何采用 AI、真实采购需求和实施障碍。带有具体安排的采购案例优先；只有标题和金额的消息保留为检索线索，不推定已中标或已产生收益。

要求进入模型上下文时有明确区块和来源标识：项目规范、该库长期偏好、本次补充、当前批次范围。材料正文始终作为资料，不执行其中“忽略要求”“调用工具”等指令。

用户确认偏好部分扩大到 **3,000 tokens**：长期偏好与本次补充的有效原文合计使用这一预算；关闭长期偏好继承时，只计算本次补充。系统核心规范、工具说明和知识证据另计，不能为了塞入偏好删除它们。不再分别施加 4,000/2,000 字的旧限制。

真实实现以当前编译模型兼容的分词器计量，前后端一致校验；切换模型需要重新计量，不把中文字数固定换算为 tokens。超过合计上限时保留原文，提示用户精简某一部分，不静默裁剪或让模型擅自摘要。没有可靠计量能力的适配器必须标明未计量，不能宣称已精确执行这一上限；本次离线原型只展示 3,000 tokens 规则与实际字数，不伪造 token 计数。

每次请求保持核心要求可见；阶段工具说明按需挂载。重复生成的“偏好摘要”不再单独维护一份事实源。

用户偏好可以改变粒度和取舍，不能伪造来源、覆盖版本冲突、读取未授权库，或把“清理内容”解释为删除原始文件。若用户明确不想沉淀某部分，记作“依用户范围排除”，不要谎称其无价值。任务中发现“保留所有案例”与“删除全部案例”等不可同时满足的要求时，保留冲突内容，暂停相关删除判断并说明冲突；其它无关材料可以继续。

## 5. C：自动识别、清洗与质量标记

Python 先识别格式、目录、正文块、图片和显然重复内容；模型根据这些结果判断材料类别与需要保留的语义部分，再调用确定性工具执行清洗。不会让模型重写一遍全文。

| 材料路径 | 主要处理 | 必须防止误删 |
|---|---|---|
| 图书 | 目录和章节、页眉页脚、断行断词、脚注与参考文献定位；章节级安排阅读 | 序言中的核心问题、章节依赖、批评与限制、作者致谢中的资金或利益关系 |
| 高质量报告 | 执行摘要、正文、图表、方法与附录分块；保留报告期、样本和口径 | 摘要与正文表述相近不等于无意义重复；附录可能含关键方法 |
| 论文 | 摘要、问题、方法、结果、讨论、参考文献；保留编号与图表锚点 | 负结果、局限性、显著性口径、样本和引文归属 |
| 公众号文章 | 正文识别、公众号页脚/关注/相关推荐排除；区分转载与评论 | 推广文里的具体事实、需求、作者观点、案例和时间信息 |
| 一般文章 | 按内容段落清洁，短文整篇保留；新闻线索、观点和长分析区别处理 | 不凭平台或篇幅直接判定“没有知识” |

新提议的初筛每次最多 12 份，给模型每份最多 800 字结构预览，合计不超过 9,600 字材料预览。优先放摘要、目录、开头及结构性代表片段，不能只机械取开头。这里只能做初判；不确定就补读，不能据此登记精读完成。

清洗动作分两层：确定性删除重复页面装饰等；模型提出语义区间排除建议。每个删除区间有原始定位和理由，原件不改。对引文、表格、数字单位、否定词、脚注及无法确认的重复段优先保留。不同来源表达相近只标记可能重复，不全库语义删除。字符完全相同也要保留来源映射与上下文差异。

建议清洗后正文减少超过 20% 时抽检删除区间；超过 50% 或输出为空时完整检查删除清单后才标为就绪。这是误删警报，不是保留比例配额，也不能证明低于阈值就安全。失败只将该来源记为待处理，不拖住其它来源。

质量标记至少拆成：`material_kind`（书/报告/论文等）、`attention`（重点/常规/线索）、`extraction`（完整/部分/需核验）、判断理由与人工覆盖记录。不要把“重点阅读”写成“内容已经可信”。书的关键章节、高质量报告与论文通常优先，但方法缺失的论文不因类别自动优于有实质内容的文章。

当前 UNO 已有格式清洗器，不是完整的上述分流组件；现有限制包括 50 MiB 单文件、约 500 万 Unicode 提取字符和特定 DOCX 解压上限。新版本先保留这些明确资源保护，超限文件单列，不默默截断后宣称全文就绪。更大文件支持作为独立扩展验证。

## 6. C1：图片成为可打开、可追溯的资产

图片保存不以视觉模型已读懂为前提。Markdown/HTML 的本地图片保存原文件；DOCX/EPUB 等可提取的内嵌图保存原图；PDF 优先保留可定位页面，按需生成该页预览，能可靠提取原图再附加原图。没有可靠坐标时不强行裁切，直接提供整页。

每个资产有稳定 ID、原始文件及版本、页码或段落定位、原始图注、文件校验和。保存于库内 `03-Archive/assets/`；卡片“图像与附件”引用资产并提供“查看原图 / 查看来源页”。原件已经在 sources 中，不为了每张图重复存整本 PDF。内容相同的图可共享字节文件，但各个出现位置和图注分别保留。

默认先处理本地可得图片。网络图片另有“尝试保存可公开访问的外链图片”选项；建议并发 2、单图 20 MiB、单次下载 15 秒，失败保留链接与未归档状态，不登录或绕过访问限制，也不无限重试。该下载策略不是本轮实际下载行为。

OCR 和视觉理解只在结论依赖图表内容时启用。没有启用或识别失败，则该主张待核验；已经保存的图片仍能浏览，独立可靠的文字卡仍能完成。图片压根缺失与图片存在但未读懂必须区分。PDF 物理页码与印刷页码分开记，避免图像引用错页。

## 7. D：Buffer 的主题文件夹与原文检索

清洁文本存一份，按模型初判的内容放进主题文件夹，例如“组织与劳动”“技术产业与采购”；每篇/每章保存稳定来源和单元 ID、质量标记、原件定位。一个材料涉及多个主题时只保留一个主放置位置，附加主题标签供检索，不复制正文到多个文件夹。

模型通过受控工具新建、重命名、合并或调整文件夹。文件夹名字不是引用身份；移动通过 ID 解析、旧路径别名与一次原子更新保持引用有效，失败回滚。模型有整理权，但工具限制在目标库 Buffer 内，不能借路径调整越过库边界。

图书按章节切分，短文章可作为一个单元。过长章节按段落拆成阅读块，保留“属于哪章、前后是哪块、必要术语在哪里”；不能把一章内每段都独立写成摘要。新阅读块提议最多 24,000 个 Unicode 字符，特殊长段也需明确拆分，避免名为上限却任意超出。

继续使用本地稀疏检索（现有 BM25 能力），先优化去重、来源分组与定位。它不是已经实现的学习型稀疏向量编码器，不承诺理解所有语义同义词。默认检索展示 8 条、展开最多 30 条沿用现有量级；相邻命中合并，单一来源不占满结果；需要细节时读取有定位的正文。文件夹和重点标签辅助排序，不将其它主题排除出搜索。用户已确认稠密向量检索可在以后加入，不纳入本轮实现范围；未来按真实漏召回样本再评估，不提前建立嵌入模型、向量数据库或额外检索链。

## 8. E：小批次、完整流程和停止方式

全量模式指“继续处理启动时冻结的待编译队列”，不指单次塞进全部文本，也不自动纳入运行期间新放进来的材料。默认一次只运行一个写入批次；同库建构与编译互斥写入，跨任务冲突仍按版本处理。

建议的初始批次目标：一本书的 1–3 个相邻章节，或 1–3 份报告/论文，或不超过 12 篇短文章；清洁正文合计目标不超过 60,000 字。按材料长度取更小范围。这些是调度目标，不是每张卡的产量配额，也不是 60,000 字全部放进一次请求。单个超长章节/论文允许拆成多个完整批次，保留统一背景和未完成依赖。

“本批完成后停止”与“全部待编译材料”共用同一流程。长书本批只完成部分章节时，显示“本书已处理 3/12 章”，不能显示“全书完成”。每批都要走到复核和结算，再开下一批；有未解决对象可按明确待办结算为部分完成，不能伪装为成功，也不必原地无限重试。

请求历史与消耗在整个任务中累计保存，不能清零；默认 120 次表示每次明确开始或继续后应有的可用额度。达到本轮额度时暂停，用户点击继续后只把剩余额度补足到设定值，未发生新请求时重复点击不继续叠加。工具调用不是模型请求，重试、压缩等实际模型请求必须分别计量；若某适配器不能完整统计，界面标明缺口，不能显示成可靠费用上限。“全部”可能在完成若干批后暂停，用户应同时看到历史已用量、本轮剩余范围和继续后的可用额度。

停止提供“完成本批后停止”和“尽快暂停”。后者停止发起新模型请求，等当前不可中断写入获得收据后保存状态；必须区分取消已请求和执行已退出。恢复只装入任务目标、原始要求、当前阶段、待处理 ID、当前卡版本和必要证据，不重放成功写入。

原件完成保全后即可保存到 Archive；物理归档不等于语义完成。Inbox 中已安全接收的文件可移去归档，未编译单元继续出现在“待编译”视图。结算状态与文件位置分离，可避免反复移动原件；导入接收必须有校验和与原子收据，失败原件留在 Inbox。

## 9. F：阅读证据保留，但不制造逐句台账

编译当前选定清洁正文时，工具返回的内容必须覆盖该单元的完整有效区间，并记录来源版本。概览不算；仅得到路径不算；工具返回被截断也不算完整阅读。上下文压缩后，保存了读过的状态也不代表当前模型仍拥有关键证据，写卡所依赖的证据需保留或定点读回。

低价值单元允许读后不成卡，记录具体理由；纯装饰内容在清洗阶段排除。有实质内容但未读完的单元仍待处理，不能用“原文保留”抹去。复用旧卡前读回相关当前正文，说明承载哪项贡献，不强制为这件事再复制整段 carrier quote 到另一张表里。

每个单元的去向记录仅包括：阅读覆盖、贡献简述、卡片/聚合锚点或不成卡理由、未完成问题。真实重要贡献可分多个对象登记；不需要候选表、对象表、覆盖表都重复同一段语义文本。某一对象未完成只牵连相关单元的完成状态。

清洗提高了完整阅读的价值，但“清洗过”不是强制阅读有用的充分证明：如果误删了反例，剩余部分全读也会失真。因此 F 的阅读校验必须关联 C 的清洗版本和删除记录。

## 10. G：有内容、少重复的聚合来源

聚合档案回答“这些材料共同在讨论什么、各自怎样解释、依据与分歧在哪”。按实际主题或同一书的问题建立，而不是每批强制新建一份，也不把一个库的一切写进一篇超长档案。

推荐内容：核心问题；按对象组织的来源主张、解释过程、关键证据和边界；各作者立场；原文锚点与必要短引；已形成的卡片和未完成依赖。对象使用稳定区块 ID。新章节增补相关区块，修订记录避免每轮重新生成全文。

卡片可以直接引用原文单元，也可引用聚合对象；**聚合引用最终必须解析到具体原文和版本**。聚合是组织层，不是新的原始证据，模型不能把自己的综合意见写成某作者的话。允许保存“作者甲与作者乙在某维度不同”的材料整理，不在编译中补造全新理论。

定位、短引和去向共用同一个来源对象记录；卡片不复制整份档案，检索默认只带对象摘要及必要片段。对于极短独立消息，没有跨材料聚合价值时可保留简单来源记录，不为了仪式再改写一遍。对重要跨章问题，档案必须有实质内容，不能只有链接清单。

## 11. H：多标签知识卡与直接注入的写作要求

保留 `概念、观点、机制、模型、方法、现象、案例、实体` 八种可组合类型。主题标签、证据状态和来源质量另外表达，不能将它们混为一组类型。领域不加入这八种类型。

最低正文结构是：**摘要 → 有实质内容的自由组织正文 → 边界与适用条件 → 来源**。摘要只保存一处，界面从元信息渲染，不再要求正文复制同一摘要。边界可以具体注明“本文仅描述某次事件，不据此推断普遍效果”；没有明确作者边界时表达证据范围，禁止空写“原文未提及”。引用位置可自动渲染，但必须能实际打开。

| 类型 | 鼓励使用的语义结构 | 不应发生的坍缩 |
|---|---|---|
| 概念 | 定义、辨析、不同用法、适用范围 | 只有一句词典释义，丢掉作者的特定含义 |
| 观点 | 针对的问题、作者主张、理由、异议 | 把作者意见当共识，或只保存口号 |
| 机制 | 触发条件、主体、传导环节、反馈、失效点 | 把相关性补写成因果过程 |
| 模型 | 构成、维度如何联系、如何理解问题、假设 | 罗列几个词就叫模型 |
| 方法 | 目的、输入、实际操作、判断输出、限制 | 只有“重视、加强、推动”等建议 |
| 现象 | 观察、范围、时间、口径、变动和例外 | 用一次消息概括普遍规律 |
| 案例 | 情境、主体、过程、结果/当前状态、作者用途 | 长期积累在抽象卡里，或把计划当结果 |
| 实体 | 身份、职责/特征、时间变化、与问题的联系 | 仅出现名称就建空卡 |

槽位是写作提示，不是全类型同时填表。模型应直接使用适合知识对象的小标题，例如“如何判断产出”而不一定叫“输出槽”。不设 300 字上限，也不按最少字数填充。

每次制卡请求直接携带以下核心规范，不能因为上下文压缩删除：忠实来源与作者归属；保留解释而不只结论；摘要不替代正文；保留关键案例、条件和异议；计划、报道、宣称与已验证事实区别；所用类型的必要内容提示；基本结构与引用要求。另附最多两份与当前任务相关的完整示范，全文示范按需读取，其核心要点持续可见。这个“两份”是节省示范占用的建议，不限制读原文或卡片数量。

示范库要包含八型成品、多标签对象、跨来源分歧和拆分共享案例；每例含教学原文、良好成品与过度压缩反例。教学假设明确标识，不进入真实知识库。现有四张问题卡另作真实材料回归样本。

**标题：AI 影视项目的制作与运营安排**<br>
**类型：案例**<br>
**摘要：** 宜昌金辉 AI 影视采购公告将内容制作和持续运营放入同一合同安排，并分别规定产出与期限。它说明采购如何组织这两类工作，不能证明项目已经交付或盈利。

## 12. I：程序即时检查，只拒绝相关对象

立即拒绝的项目限于可明确验证的错误：无有效标题/类型、摘要或正文为空、无实质边界内容、来源不存在或定位版本无效、关系端点不存在、越界路径、旧版本覆盖、未授权修改，以及非法写入结构。检查字段存在可以程序完成，判断边界是否真实有用仍属于语义审核。

拒绝后保存候选草稿和精简问题回执；不得把无效候选作为普通可检索卡片。若本来有正式卡，保留旧版可用；通过基础检查的新版也先处于本批待复核版本，思考默认使用上一已审核版本。新卡在批次复核通过后成为普通可检索知识。可以在界面主动查看待复核成果，但状态必须显著显示。

为了不造成首轮频繁重写，首次拒绝允许一次就地修复；同对象本批第二次仍失败就进入待修队列，作者继续其它对象。这个次数是试验默认值，不表示第二次后永久放弃。预算允许时交给审核阶段处理，仍失败则本批部分完成，带具体错误退出。新建关系依赖草稿端点时先保存为候选关系，端点通过后再提交。

原子性落在真实互相依赖的修改组上：例如合并卡与旧卡去向必须一起成功；两张无关卡不因同批而一起回滚。修改组开始前检查当前版本，成功回送 ID、版本、改动字段和问题，默认不重复回送整张正文。程序不按“观点有没有说服力”反复驳回模型。

以上是新提议，比当前 UNO 的缺项提示更严格；落地前须同步修改当前“语义质量写后修订”契约的具体适用范围，不能只改校验器留下相反提示。

## 13. J：每批新上下文实质审核

推荐由独立的审核会话/工作上下文执行，默认串行使用同一模型配置；作者状态已经保存，不真正删除原会话。它可以技术上使用子代理，但不需要逐卡并行开代理，也不复制整个作者历史。跨模型审稿是以后可测选项，不是本次默认建设。

审核输入包括：任务原始要求与规范版本、本批目标、所有新增/实质改写卡当前正文、变更差异、聚合对象、支撑主要结论的短证据与可回查位置、待处理问题。没有作者的自我辩护或隐藏思维链。相关旧卡只在查重、改写或关系核对时读取。

**本批每张新增和实质改写卡都检查实质内容，不只抽样标题。** 检查摘要是否替代正文、解释链是否断裂、关键细节/反例是否遗漏、作者是否混淆、方法是否可理解使用、案例能否独立阅读。主要结论逐项对照相关来源证据；数字、因果措辞、历史卡删改、高注意力材料与关键图表需要定点读回原文。审核不是从头重读整批所有无关原文，也不是只相信作者写的审核摘要。

建议每次审核工作包最多 6 张卡，并以实际上下文可容纳量为先，长卡包可只有一张；没有“每批最多六卡”的生产上限。若来源材料没有足够内容，不让审核人编造细节凑结构，而是缩小命题、调整类型、留作线索或标出缺口。

审核人可以通过相同 Gateway 修改卡片；补充来源、重命名、标签和关系调整按实际依赖提交。每张卡记录审核所对应的正文版本。后续实质修改导致相关审核失效；纯界面显示名不强迫重审无关内容。审核修改仍需机械检查和证据比对，但不再无限新开“审核审核人”的角色。

当前推荐保留这次实质审核。只有同一固定材料样本连续比较显示首轮已能稳定保住内容、二审实质纠错收益很低，才考虑将部分二审缩到命名/标签/关系。不能先缩审稿范围，再假定首轮质量已经解决。

## 14. K：领域说明、案例共享与检索关系

### 领域的价值与维护边界

领域说明是一个高层入口，说明此处常讨论的问题、对象、尺度、典型争议和如何进入下属知识。存入独立的 Markdown 元信息目录，可在界面称“领域卡”，但不成为八种知识类型之一。

成员归属关系单独表达，允许一张卡属于多个领域。领域之间只与领域建立语义导航关系；知识卡间维持知识卡关系，不混接成一套推理图。领域层先复用“补充、对照、类比”三种导航语义；上下级归属另存，不为视觉效果造交叉联系。

例如，假设知识中已经有相关内容，“技术产业”与“组织与劳动”的补充关系可说明：分析技术采购，还需查看组织采用条件与劳动调整。依据应指向下属的实际材料；这是一条查资料路线，不是“技术必然造成劳动变化”的定律。若没有已保存的内容支持，不强行创建。

领域说明初始建议 300–800 字，检索先用 1–2 个候选领域的短说明，再选具体卡片与 Buffer；这只是上下文预算目标，不限制完整 Markdown 的表达。检索保留全库关键词入口和跨领域候选，避免错误领域选择挡掉重要内容。只有发现新的问题轴、显著冲突或归属变化时才更新说明，不因每新增一张卡都重写全文。

用固定问题比较“有领域说明 / 只有标签索引”：是否更准确识别问题、是否召回不同角度、是否增加泛泛背景和成本。如果领域说明只重复卡片目录，则退回轻量索引；无需为维护一张领域卡而创造工作。

### 案例与事实

保留独立案例卡，尤其是作者用来支撑或质疑主张的关键历史例子。案例的身份由事件/对象、时间、情境和过程决定，不由“它属于哪个模型”决定。因此同一案例可以为多张模型或观点卡提供阅读入口。

有实质内容的事实集合可用“案例 / 现象 / 实体”表达，证据状态单独标注。暂不增加泛化的“事实”类型：书中的事实陈述仍可能是报道或作者宣称，不能通过标签把它变成已核验事实。一句旁证无需单独造卡，留在正文或聚合来源；不要走到每个数字一个节点。

抽象卡保留理解所需的两三句案例要点和链接，完整过程存案例卡；不能把全部案例细节抽走后让抽象卡只剩口号。复用关系保存作者用途、比较维度与限制，案例结果不自动证明模型有效。

### 卡片之间的七种关系

| 关系 | 方向和用途 | 明确边界 |
|---|---|---|
| 细分 | 一般 → 更具体的一种；失业 → 结构性失业 | 组成部分、具体事件和领域归属不自动算子类 |
| 补充 | 补充者 → 被补充者；授权条件 → 协商机制 | 必须说清补充哪个条件/维度，不是同题即相关 |
| 对照 | 双向；选举代表与抽签代表的产生方式 | 差异不是反驳，更不自动证明优劣 |
| 质疑 | 反对/限制内容 → 被质疑主张 | 有明确针对性；情境不同先作对照 |
| 类比 | 双向；来源明确比较两个场景的共同结构 | 保留差异；编译不把模型新联想伪装为来源知识 |
| 例证 | 案例 → 所说明的观点/机制 | 说明作者怎样使用它，不声称因此已证明 |
| 应用 | 方法/模型 → 使用案例 | 真正使用与作者建议使用要区分 |

索引支持反向查找，不重复保存相反方向同义边。无“仅相关”边；共同领域和主题由索引表达。图谱动画可以表现检索经过的节点、关系类别和待审核状态，不生成视觉专用假关系，不把无关系节点视为失败。

## 15. L：结算、失败隔离与恢复

每批报告至少分别显示：已读并制卡、已读未制卡、已有知识承载、仅概览待读、待补材料、待修卡片。卡片统计区分新建、实质丰富、仅补来源、修订与退役；不能将 88 篇来源与 72 张卡相加成产出。

完成条件作用于本批真实范围：有效阅读完成、重要贡献有去向、当前卡版本审核通过、来源/资产定位有效。未处理图片只有在某个结论依赖其内容时才阻止该对象通过；一份坏文件不阻止其它来源完成。

本批可“完成”“部分完成”或“暂停”。部分完成明确保留未解对象与材料，继续队列时不自动把它们从总数中抹掉，也不无限在同一错误上循环。到队尾仍有待办则整个任务显示“已处理可执行部分，仍有待办”，绝不显示全部完成。

恢复以稳定 ID、原始要求版本、源文件哈希、当前步骤、成功写入收据和未完列表为依据。源文件或卡片被外部改动，失效的是相关阅读/审核，不是所有历史成果。建构同样采用小范围、真实依赖组和检查点，不继续使用相互割裂的暂停语义。

## 16. M：上下文中保留什么，移走什么

| 借鉴 DSH 的高价值部分 | 在 UNO 中的实现方式 | 避免的成本 |
|---|---|---|
| 当前任务目标与范围始终可见 | 固定任务信封：目标库、范围、要求快照、阶段、剩余预算 | 不从很长历史推测当前要做什么 |
| 规范在实际模型输入里 | 核心内容规范和用户原话常驻；类型补充和完整示范按需 | 不把“文档里写过”当模型当前已知 |
| 来源、计划、成果可回查 | 稳定 ID 和一个贡献去向记录，正文按定位读取 | 不重复运输候选、对象、全量收据 |
| 版本与写入收据 | 返回改动 ID、版本、错误字段及下一步合法操作 | 不为确认成功再完整读写同一张卡 |
| 工作摘要与恢复 | 仅保留公开的任务状态、关键决定和待办，不保留推理过程 | 不依赖长对话复述恢复任务 |
| 同一知识对象可跨章继续 | 简短全书背景＋相关聚合区块＋相邻阅读单元 | 不每章从零，也不每章重发整本书 |
| 角色明确的审稿上下文 | 新工作上下文读取相同规范与本批正文/证据 | 不把作者整个历史转给审稿人 |

建议单次输入分配优先顺序：不可省略的任务与规范、当前证据、正在修改的卡片、相关旧知识、近期操作摘要。实际容量依据所选模型配置与可靠 tokenizer；不将字符数冒充 tokens。正常输入以可用窗口的约 70% 为调度目标，留出输出与工具返回空间，超过时分页或切换工作包，不静默截去首尾规范或关键证据。70% 为试验目标，必须先扣除输出预算和系统实际占用再计算。

不要承诺固定 Token 节省比例。每批记录输入、输出、缓存命中（若供应商提供）、重试、首轮与审核用量。若供应商无可靠 usage，显示估计值及缺口。成本比较要同时记录错误纠正和漏知识，不能只看调用次数。

## 17. N：知识处理设置＋O：编译弹窗

### 知识处理设置：保存这个库的习惯

顶部明确“正在设置：某知识库”，并说明不改变项目关联的其它库。删去旧“先归属再消化”开关和“流程主权”等实现术语。设置不再出现部分即时保存、部分点底部保存的两套行为；统一保存/取消，未保存提示一致。

默认可见内容：

1. **编译偏好。** 一个主要自由文本区域，说明可影响风格、精细度、保留和清理要求。示例按钮是插入可编辑文字，不隐藏额外规则。显示字数限制与“新任务生效”。
2. **材料清理。** 默认去除明确噪声、保留有疑问内容；可强调“保留更多原貌”。无“删除原件”选项。显示原件始终保全，可查看清洗差异。
3. **图像与附件。** 本地图片保存固定启用；可选尝试归档公开外链图片。关键图意需要解读时才使用已配置视觉能力，未配置显示待核验，不阻挡图片浏览。
4. **结果如何保存。** “审核通过后自动保存”或“每批审核后由我确认”。两者都执行同一质量检查；人工确认与质量等级不是一回事。自动保存不等于可以越过权限/来源校验。

高级设置折叠展示继续后可用请求额度、历史累计用量、批次目标和技术计量说明。默认 120 次清楚标明为一轮额度；不暴露一排语义槽开关，不让用户通过关闭检查获得“快速”假象。

### 编译弹窗：决定本次做什么

顺序为：目标知识库与材料 → 单批/全部 → 本次要求 → **开始编译**。全部在一个弹窗内完成，取消独立的“预览计划”页面及其额外确认步骤。常用摘要直接可见，完整材料清单、长期偏好和高级设置可展开查看。

- 材料列表同时包含未接收的 Inbox 文件与已在 Buffer 的待编译单元；状态、类型、重点标记、估计长度可过滤。不要把已归档物理位置等同于无需处理。
- 默认“完成一个批次后停止”；勾选“继续编译全部选定材料”，逐批闭环直到范围完成、预算暂停或用户停止。全选冻结的是列表范围，不默认加入其它库。
- 显示首批预计范围，例如“先处理 10 篇，剩余 37 篇”；估计值与真实解析后的数量分开。
- 本次要求文本框，快捷按钮如“重点保留案例”“展开解释过程”“保留分歧与反例”“重点查漏”，点击直接插入可编辑提示词。
- 可展开“长期偏好与本次要求”，分别显示原文与来源，并注明本次明确要求覆盖同项长期偏好；不能声称模型已完美合并所有歧义。偏好有效原文合计最多 3,000 tokens，计量与超限处理沿用 B；这只是可选查看，不是开始前的必经步骤。
- 显示保存方式、继续后可用请求额度、历史累计用量和是否归档外链图。若要改，作为本次覆盖，不回写长期设置，除非用户明确点击“保存为长期设置”。
- `/编译 + 提示词` 使用同一任务结构：已知当前目标库，文本进入本次要求；未指定材料时按默认一个批次创建可见范围。不能让斜杠入口绕过范围、预算或保存方式。明确指定全部时与面板相同冻结队列。

编译中显示当前批/全部范围、当前阶段、待审核/待修数量、累计用量和暂停控制。用户随时可查看已经审核的卡片，不必等整次全量任务结束。人工确认时只等待当前批，显示差异和待办；没有确认的草稿不当作正式知识。

配套原型仅演示设置保存、要求继承/覆盖、材料选择、单批/全部切换和一次点击提交。点击“开始编译”直接结束弹窗并显示明确的原型演示回执，不进入预览页，不调用真实编译接口。真实产品在相同位置创建经过范围、预算与权限校验的任务，启动失败保留输入供修改。原型的材料条目是虚构样例，不冒充已读取用户文件。

## 18. P：实施顺序、验收与可撤回性

不更换 Agent 引擎，不并行建设另一套事实源。优先按以下可验证切片实施；每一切片同步工具、校验、提示、界面和文档，旧流程仅用于原版本任务恢复。

| 切片 | 具体范围 | 验证 | 成本与撤回 |
|---|---|---|---|
| P1 先修质量与控制 | 用户长期/本次提示、直接规范、完整示例；对象级拒绝；批末新上下文审核；统一设置/弹窗 | 四张问题卡原文回归，空卡/错引用/漏条件测试，按钮与斜杠任务一致 | 增加一次审核成本；功能版本开关退回旧入口，保留新成果历史 |
| P2 清洗与资产 | 分类清洗、删除记录、原件及图片归档、稳定 Buffer ID 与主题整理 | 各类材料含反例、脚注、广告混合内容、表格和图像样本；模拟误删恢复 | 提取维护成本；保留原件与旧提取版本可重建 |
| P3 小批与恢复 | 冻结队列、可审计账本与显式继续额度、贡献去向与聚合、读区间、归档结算分离 | 在读取/写入/审核/归档分别中止，恢复不重复写；坏对象不阻断无关成果 | 对象级状态改造；旧任务按原版本恢复，不现场升级 |
| P4 多库根目录 | 两项目分别将根库和 instances 库迁到 knowledge-bases | 临时副本验证 ID、引用、检索、图片、会话、导出、恢复；迁移后根无编号知识目录 | 路径兼容成本最高；先 UNO 后 DSH，独立快照可退回 |
| P5 领域与思考联动 | 领域短说明、领域间导航、案例共享、搜索来源分组 | 有/无领域上下文同问题对照；检查反例和跨域素材是否真的增多 | 避免手工维护膨胀；无收益领域退为索引 |

P1 也需一个最小的批次边界，以便先验证审核收益；P3 再完善跨批队列和完整恢复。多库目标从现在起约束所有新增路径，P4 才实际搬迁实例。新聚合档案和审核状态会改变现有 UNO 契约，实施时同步更新 AGENTS/现行文档；本方案本身不悄悄替换它们。

内容验证先用固定小样本：四张问题卡对应原文，加图书关键章/普通章、报告、论文、含广告实质文章、缺正文和含图片材料，建议合计 12–16 份。对照当前首轮、强化提示首轮、强化提示＋新上下文审核，记录主要知识点/反例/数字遗漏、错误归因、卡片独立可读性、实质修改次数、Tokens 和耗时。真实模型质量验证需按用户指定执行方式进行，本轮不调用项目模型 API。

硬验收：无幽灵引用、无成功写入重放、无原件丢失、无将概览计为完整阅读；版本回退可用、继续不清空历史账本且能补足一轮额度、图片能从卡片打开、跨库不越界。语义验收由样本原文与人工判断支撑，不用长度、连边率或自动评分假装证明理解。未达到内容收益就调整方案，不为已写代码保留无效机制。

### 可反向优化 DSH 的部分

优先考虑统一设置和本次提示词预览、资产保存与图意核验解耦、精简错误收据、坏对象不阻塞无关对象、来源位置统一解析；多库根目录按用户目标独立迁移。DSH 已有建设方向快照，可复用而非再做第二份偏好真相。

不顺带把 DSH 七型强规范全部改成 UNO 多标签，也不直接取消 DSH 现有阅读/候选校验。借鉴的是内容要求与可追溯能力，需针对 DSH 实际任务分别验证。用户当前允许讨论反向优化，不意味着本次已经修改 DSH 运行规则或服务。
