## 2026-09-14 对话入口与建构修订

思考入口并入新对话，沿用只读知识检索与按需分析，不再先填写重复的思考表单。原有对话和任务可继续访问。超长的最新问答会保留首尾并明确标注节选，避免整个历史窗口被清空；单字概念可参加检索。

新建建构任务记录 `construct_contract=scoped-review-v1`：

- 按标签选择时同时匹配 topics，开始时冻结卡片 ID 范围。范围外卡片可读；修改、关系起点和合并对象必须在所选范围内。此版本围绕既有卡片修订，不开放范围外新卡创建。
- 无草稿的卡片也必须由全新审核上下文读取当前版本，并登记具体保留理由；卡片版本变化会使旧审核失效。理由可在任务面板查看。
- 领域提交失败保留提案，审核疑点和未完成对象计为部分完成，可以从未完成处继续，不再丢弃失败项后宣称全部完成。
- 建构说明与执行阶段使用知识检查、修订和独立审核，不套用材料筛选与消化文案。任务详情不会再因状态同步自动收起，可主动收起返回对话。

没有该标记的历史任务保留创建时的范围与无修改审核规则，不扩大或重解释旧授权。新版前端根据准备接口的能力标记开启新建建构，旧服务需安全重启后启用；已有任务仍可查看和继续。

验证使用临时合成知识库，覆盖越界修改、合并、范围内关系、无修改审核、版本失效、领域失败恢复和长历史检索。程序与界面验证不代表真实模型的语义改善效果。当前运行服务仍在执行既有任务，本轮没有重启或改写真实知识。

本轮验收：后端 327 项、前端 179 项测试通过，前端构建通过。使用 Edge / Playwright 在 1440×960 与 390×844 验证新对话请求、旧服务新建建构保护、主题筛选、开始建构参数、部分完成恢复请求和保留理由展示；无页面异常、无实际写请求，任务接口使用合成响应。浏览器截图及断言记录保存在本机临时目录 `uno-construct-final-aMVxbJ`。构建仍有既有的单包体积提示。

## 当时的工作流（历史协议）

**选材与冻结要求 → 模型浏览全体、按需补读并判断价值 → 自主选择下一组值得消化的材料 → 程序清理与 Buffer → 阅读与聚合 → 候选草稿 → 全新上下文审核 → 发布通过对象 → 结算本批 → 返回自主筛选。**

2026-09-13 新建编译任务增加 `selection_workflow=agent-selection-v1`。筛选排除、暂存直接记录，不进入正式消化和二审；下表全文阅读要求只适用于已接收消化的材料。旧任务无此标记，按保存协议恢复，避免改写用户正在测试的进度。

设置页保存当前知识库的长期偏好、清理方式、外链图片归档、默认预算和审核后的发布方式。编译按钮与 `/编译 + 提示词` 进入同一面板：选材料、补充本次要求、选择是否连续处理，然后直接开始，没有“预览计划”步骤。本次选项不反向覆盖长期设置。运行中的任务保留原始偏好和本次要求快照。

编译和建构都使用原生 Agent Loop。建构从卡片范围开始，无材料预处理步骤；修订同样经过草稿和独立审核。旧版任务保留原协议恢复。

## A–P 的落地与实际边界

| 环节 | 当前行为 | 数值与边界 |
|---|---|---|
| A 多知识库 | `knowledge-bases/<稳定ID>/` 各库平等；项目读库与当前写库分开 | 单任务写一个库；运行任务期间禁止切库 |
| B 要求与偏好 | 按库保存，任务冻结原文，本次明确要求优先 | 合计3000 tokens，核心规范另计，无静默截断 |
| C 清理分流 | Python技术清理后，模型按图书/报告/论文/公众号/一般文章分类、精确删减 | 单文件50 MiB、提取文本500万Unicode字符；模型分类初始为待确认，程序不冒充已判断质量 |
| C1 图像 | 原件保全；PDF嵌图、DOCX媒体、本地图片归档；可选下载外链位图；卡片显示来源图片 | 本地提取合计20 MiB、最多64项；外链最多64项、累计64 MiB、2并发、单图20 MiB、15秒、最多3次跳转；拒绝私网地址；失败保留原件/链接 |
| D Buffer | 主题文件存正文，`_index`稳定引用；BM25细节检索 | 稠密向量未接入；优先呈现不同来源，溢出结果仍可翻页 |
| E 小批范围 | 只接收当前需要的一组原件，每小批完成流程后推进 | 参考1–3个书章/报告/论文单元，或最多12个短文单元；每批≤60000 Unicode字符；长章按段落续块，每块≤24000字符 |
| F 阅读 | 当前正文版本及实际返回区间，完整阅读后才能结算 | 单次默认12000、最多24000 Unicode字符；概览不是全文，回执不证明理解 |
| G 聚合来源 | 可发现、读取、增量改写档案，保留作者、问题、证据、分歧和对象锚点 | 短材料不强制另写档案；修改保留旧版，不逐条复制原文 |
| H 卡片 | 八种类型多选；摘要、实质正文、具体边界、来源；可共享案例 | 不要求每文产卡、不定槽位数量；核心提示直接包含类型、关系及正文示例 |
| I 基础检查 | 草稿隔离；缺摘要/类型/边界/合法来源仅影响当前对象 | 作者失败后可修正一次，再失败交给审核；有效草稿仍不是正式卡片 |
| J 独立审核 | 新会话、新上下文、同一冻结模型，默认串行；读草稿和来源，先核内容再整理名称/TAG/关系 | 每次登记最多6卡；不成卡材料也须在审核阶段全文读取并复核去向；问题可明确留待修 |
| K 领域与关系 | 七种弱卡片关系；独立领域索引、父层导航及领域间三种联系；背景进入思考检索，图上显示导航节点 | 领域不是知识卡片类型；领域只与领域连线，导航不等于论证 |
| L 发布恢复 | 发布对应版本审核通过的对象，替代稿通过前保留旧卡；无关对象独立结算 | 待修草稿关联原文保持待编译；有依赖的卡片同一事务发布；历史可恢复 |
| M 上下文 | 核心规范、工具、原始要求、当前批次和预算；按需读原文，短checkpoint | 默认累计120次原生请求尝试，可设10–2000；新批前至少剩余20次；供应商内部重试/压缩另计 |
| N 设置 | 自由提示词、清理、发布和图片；预算折叠，统一底部保存 | 旧两阶段消化与即时权限开关不控制新版 |
| O 开始面板 | 选材、本次要求、继承偏好、单批/连续；高级选项折叠 | 默认单批；冻结队列，不加入后来文件；选材传输最多10000项 |
| P 验证 | 程序、原生宿主和浏览器分别核对 | 合成接口证明流程接通，不能证明真实知识质量和Token收益 |

## 知识和运行文件

以下路径均相对于单一知识库：

```text
00-Inbox/                         尚未接收或提取失败的原件
01-Cards/                         已发布知识卡片
01-Cards/_meta/domains/           独立领域导航说明
03-Archive/sources/<内容指纹>/     原件、初始提取文本、目录、排除记录
03-Archive/assets/<图片指纹>/      图片及来源说明
03-Archive/aggregates/            聚合来源档案
03-Archive/aggregate-history/     聚合档案历史
03-Archive/card-history/          卡片历史与合并前版本
03-Archive/compile-drafts/<批次>/  候选、基础错误和发布状态
05-Buffer/<主题>/                 整理后的原文
05-Buffer/_index/                 稳定原文引用
.nexogenesis/uno-jobs/            可恢复任务状态及累计调用
.nexogenesis/knowledge-processing.json  本库处理偏好
```

原件归档只表示安全接收。Buffer的pending/completed/source_only、任务延期和未通过草稿分别记录处理状态；不能根据原件已归档宣称知识沉淀完成。不成卡材料也必须说明实际去向。

## 仍需区分的限制

1. 本轮没有用真实模型重编公众号、图书或论文。核心章节理解、删减、案例拆分与关系价值仍需样本评测，不能把测试通过写成质量已提升。
2. 图像归档和显示已接通；OCR、复杂表格重建及图像语义核验没有自动解决。依赖未核验图片的内容仍应保留缺口。
3. 本机准备了DeepSeek V4官方词表计量偏好。未知模型显示估计值，服务端按同口径校验，不冒充供应商账单。词表在应用 `.nexogenesis/tokenizers/`，新部署需另行配置。
4. 暂停等待原生回合退出；每执行时段30分钟会请求暂停。底层中断延迟、供应商内部重试和历史压缩仍有计量及恢复边界。
5. 阅读回执不等于理解保证。新上下文审核减少作者历史信息的继承，但未证明可以消除同一模型的共同偏差。

## 撤回

停止已核对身份的UNO服务后，程序按工作区差异撤回入口；保留全部知识Markdown、草稿、历史和收据。目录按备份 `moves.json` 逐项移回，恢复 `instances.json`；每项核对目标为空且内容一致，不得在新目录已产生知识后直接用旧备份覆盖。

后续以真实样本的来源忠实度、信息保留、回答用途与Token用量作对照，不继续堆叠未经验证的检查环节。

## 前置自主筛选补充（2026-09-13）

新增的是原生 Agent 工具权限与选择范围，不是固定分类调用。每次是否补读、比较什么、排除或接收谁、下一组的顺序由模型决定。程序不按材料后缀或发布时间裁定价值；用户长期偏好、本次要求、材料用途始终进入任务快照。

| 工具/环节 | 实际返回与限制 | 处理边界 |
|---|---|---|
| compile_sources list | 全部本任务选材；默认30、最多60项/页；可按状态、文件名筛选；文本开头180个Unicode字符 | 不预建Buffer，不声称全文精读；图片/PDF等只展示元信息，正文按需提取 |
| compile_sources read | 默认3000、最多6000字符；可翻页或定位关键词；提取目录前40项，正文仍可续读 | PDF/DOCX按需本地提取，缓存可重建；不下载图片、不搬动原件；OCR缺口明确返回 |
| compile_select decide | 每次1–60个明确判断；digest/exclude/defer；理由≤1200字符，实际返回的标题/片段引用≤500字符 | 不用阅读配额判断价值。标题不足就补读。排除必须保全原件及Markdown依据，不要求全文或二次审核 |
| compile_select begin | 模型自主选择1–12份digest材料并排序；可标注材料种类、注意力与主题 | 仅这些材料进入预处理和既有小批消化；长材料仍按章节和24000字符续块，现有60000字符批次保护保留 |
| compile_select finish | 结束本次筛选，程序如实汇总剩余 | 排除是正常筛选结果；未判断、暂存、待消化和未通过对象不算完整消化 |
| 暂停与恢复 | 筛选决定、版本、当前选择和收据落盘；短快照只携带计数、当前包及最近3批摘要 | 预览区间不进入正式阅读回执；恢复不重放已成功接收或已排除的材料 |
| 用户复查 | 面板区分未判断/待消化/正式接收/排除/暂存/恢复；可看依据、原件，暂停后恢复被排除项 | 恢复到待处理供新任务选择，不覆盖同名新文件；不自动重启原任务 |

筛选记录在 `03-Archive/screening/<任务ID>/`，含原件版本、决定、理由、证据摘录和“非全文精读”声明。排除的Inbox原件进入 `03-Archive/sources/<内容指纹>/`，不创建Buffer；已存在的Buffer排除后标为screened_out，可恢复pending。非文本预览缓存位于 `.nexogenesis/selection-cache/`，不是知识事实源。

实现入口：`uno/selection.js`、Gateway负责的 `uno/screening.js`、宿主 `uno-workflow-v3.js`。新增标记只作用于新编译，建构及历史任务不强行迁移。撤回入口时保留原件、筛选记录、草稿和收据；新任务的select状态需要新代码恢复，不能用旧代码冒充兼容。

验证使用合成材料：全部排除时只执行筛选回合，没有清理/制卡/审核；混合案例仅接收模型选中的材料，排除与暂存不参加正式阅读或二审。真实模型的价值判断准确率、遗漏率和Token收益仍待用户样本验证，不由合成流程测试代替。


## Agent 共用基础能力补充（2026-09-13）

执行层和检索层的最新行为见 [Agent 基础能力改进](UNO-Agent基础能力改进.md)。系统提示不再逐步拼入动态快照，改用原生持久化上下文；字段修订保持未提交内容；批量工具、段落定位、旧批待办恢复与导航关系标记已接通。旧段落中逐次重建系统提示、完整正文覆盖、类比仅能由单一来源明确表达的说明被本补充取代。原文知识不扩写的约束仍保留，模型导航不得冒充来源论证。真实服务加载状态与验证边界以当前实现文档为准。
