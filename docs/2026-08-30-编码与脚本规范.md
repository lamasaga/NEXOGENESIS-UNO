# 2026-08-30 编码与脚本规范

> 状态：现行工程约定  
> 核对日期：2026-08-30

## 一、文件编码

- Markdown、JavaScript、TypeScript、JSON、YAML 与脚本统一使用 UTF-8。
- 中文自然语言段落首行使用两个半角空格；标题、列表、表格、代码块和 frontmatter 不缩进。
- 修改已有文件时保留原换行约定，避免只因换行符产生整文件差异。
- 代码读取文本时显式指定 UTF-8；不得依赖 Windows 当前代码页猜测。

## 二、PowerShell 与批处理

- 路径包含中文或空格时使用 `-LiteralPath` 或完整引号。
- 不复用 `$HOME`、`$CODEX_HOME` 等系统变量保存任务路径。
- 删除或递归移动前先解析并显示绝对目标，确认其位于预期仓库。
- 启动后台服务时记录端口和进程；停止服务前确认进程归属。
- 普通脚本失败必须返回非零退出码，不把部分成功写成完成。

## 三、JavaScript 与 Node

- 文件、卡片、来源和请求参数在边界处验证，不能只依赖调用方。
- 需要原子性的知识写入统一经过 HarnessGateway，不直接改 Markdown。
- 外部进程、解压和大文件处理必须有超时、大小与输出上限。
- 结构化数据优先使用成熟解析器和序列化器，不自行拼接 YAML、multipart 或 JSON。
- 新工具的说明、JSON Schema、实际校验、Skill 示例和测试必须一致。

## 四、文档

- 当前开发事实只写入 `docs/README.md` 索引的活文档或 `.agent/reference/`。
- 活文档文件名和一级标题包含核对日期；入口 README、目录 README 和评测资产内部说明除外。
- 已被替代的介绍、调研、SPEC 与计划移入 `docs/history/`，不得直接删除。
- “已实现”必须能对应代码与测试；只有骨架或配置时使用“已有初版”或“尚未验证”。
- 新文档应先确认现有活文档是否能够容纳，避免为一次普通修改创建平行设计稿。
- 专项清单完成后不得继续占用 `docs/` 根目录：先把仍有效的运行事实、规则和未来待办回写到对应活文档，再将原清单整体移入带日期和主题的 `docs/history/` 子目录。
