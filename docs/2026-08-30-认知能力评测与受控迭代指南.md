# 2026-08-30 认知能力评测与受控迭代指南

> 状态：后续实施指南，测评台与自动迭代尚未完整实现  
> 核对日期：2026-08-30  
> 目标：证明知识图谱、Thinking Model 和 GraphOps 是否真正改善分析，而不是只增加工具调用与界面效果。

## 一、核心判断

  DSH 不能用一个“综合分”证明 Agent 变聪明，也不能因为一次输出流畅就自动修改 Thinking Model。可靠的评价必须固定输入、模型、知识快照和预算，分别检查最终答案、证据使用、真实 OPS 轨迹、成本与稳定性，并与明确基线比较。

  近期采用两层循环：任务内 Loop 根据 Observation 纠错；任务外流程聚类重复失败、提出候选、隔离评测、人工批准和小范围晋升。生产任务不能直接改写长期认知资产。

```text
任务内执行
目标 → 选择 TM → 调用 OPS → Observation → 修正 / 询问 / 停止
                                      ↓ Episode
任务外改进
失败聚类 → 归因 → 候选改动 → 固定集与隐藏集 → 人工批准 → 晋升或回滚
```

## 二、评测对象

| 对象 | 核心问题 |
|---|---|
| 知识体 | Card 是否保真、可追溯、可连接，关系是否真正支持推理 |
| 检索与 GraphOps | 是否找到必要证据、反证与边界，而不是多读无关卡 |
| Thinking Model | 是否改变了观察选择和输出结构，并在适用任务上稳定获益 |
| Agent Loop | 新 Observation、拒绝和用户反馈是否真的改变下一步 |
| Harness | 非法写入是否被拒绝，失败是否无副作用且可恢复 |
| 用户体验 | 用户能否看懂正在检查什么、发现什么、为何不写和下一步是什么 |
| 成本 | 读取量、步骤数、延迟和模型费用是否与收益匹配 |

## 三、四层评测结构

### 3.1 第一层：确定性回归

  这层不调用真实模型，先确认基础契约没有坏。任一项失败时，不进入语义评测。

| 编号 | 场景 | 通过标准 |
|---|---|---|
| R1 | 含扩展字段、关系 note 与 Card unit 的卡片往返写入 | 所有合法字段和值保持一致 |
| R2 | 元数据筛选、两卡比较与 1～3 跳遍历 | 只返回真实节点、边、note、plane 和 readiness |
| R3 | 来源追溯 | 只读取 Card 声明的来源，越界路径被拒绝 |
| R4 | 选择每一种 Thinking Model | 所需能力均映射到实际 Operator；缺能力时拒绝启用 |
| R5 | 读取、写入和总步骤达到预算 | 后续操作被阻止，停止原因与状态一致 |
| R6 | 用户停止、回答错误会话或投递失败 | 不留下错误状态；合法 continuation 可恢复 |
| R7 | 新建 Card 的图谱接入 | 三态决定合法，ready 入边或出边能关闭接入任务 |
| R8 | 编译归档与断点 | 成功只归档一次；失败保留 Inbox；继续不重复写 Buffer |
| R9 | 安全边界 | 恶意 Origin、YAML 换行、路径穿越、同名上传和资源超限被安全处理 |

### 3.2 第二层：固定任务集

  第一版保持小而稳定，先覆盖 12～20 个任务，不直接随机抽整库问题。每项保存输入材料、允许范围、知识快照、预期证据锚点、禁止泄漏信息和人工评分记录，但不规定模型必须复现唯一句子。

| 任务类型 | 首批数量 | 观察重点 |
|---|---:|---|
| 编译材料 | 3～4 | 章节、数字、图表、来源锚点、覆盖与归档 |
| 多 Buffer 消化 | 3～4 | 旧卡优先、综合质量、贡献结算和接入决定 |
| 对话与研判 | 3～4 | 证据、反证、边界、关系路径和推断标记 |
| 建构 | 2～3 | 局部范围、写前精读、拒绝改选和写后复核 |
| 来源与权限 | 1～2 | 追溯正确、越界拒绝、失败无副作用 |
| 有状态交互 | 1～2 | 暂停、刷新、回答、恢复和并发隔离 |

### 3.3 第三层：系统基线对比

  每个开放式分析任务至少在相同模型、温度、知识快照和近似预算下运行两次，并比较以下配置：

| 基线 | 配置 | 回答的问题 |
|---|---|---|
| A | 裸模型，不提供项目知识 | 模型预训练本身能做到什么 |
| B | 平面关键词检索 | 文本召回能带来多少增益 |
| C | GraphOps，不强制 TM | 图结构观察是否有独立价值 |
| D | TM + GraphOps | 显式思维策略是否进一步改善结果 |
| E | 候选 TM / OPS | 新版本是否稳定优于当前基线 |

  不能只比较 D 与 A 后就把全部增益归因于 Thinking Model；B、C 用于分离资料、图结构与策略的贡献。

### 3.4 第四层：历史情景回放与长期 holdout

  金融、经济与国际贸易任务采用严格 `as_of` 时间截面，只允许读取当时已经发布的数据和材料。具名历史题容易受模型预训练记忆污染，因此必须同时保留匿名化回放、顺序更新和尚未揭晓结果的 live holdout。

  第一批可继续使用 `docs/金融经济与国际贸易测试资料集/` 中的 1997、2008 和 2014 三个案例。该资料集是评测资产，不是项目运行契约。

## 四、评分结构

### 4.1 硬门槛

  任一硬门槛失败，该次结果不能以其他维度高分抵消。

- 引用不存在的 Card、来源或关系。
- 读取超出允许范围的材料。
- 把事后信息用于 `as_of` 之前的判断。
- 绕过 Harness 写入或失败后留下不一致状态。
- 把候选、推断或情境联系表述为已确认事实。

### 4.2 分项评分

| 维度 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| 证据忠实度 | 无来源、错引或泄漏 | 有来源但条件与反例不完整 | 来源、条件、不确定性完整可追溯 |
| 分析价值 | 复述材料或空泛结论 | 有局部结构但缺少区分度 | 提供机制、反证、边界和可行动判断 |
| 图谱贡献 | 错连、无意义扩展 | 使用关系但没有明显增益 | 关系路径带来必要证据或结构发现 |
| Loop 行为 | 固定步骤或一次失败即停 | 有检索但改选不稳定 | Observation、拒绝和反馈能改变下一步 |
| 运行治理 | 无法停止、恢复或核对影响 | 有记录但状态不清 | 预算、暂停、恢复、写入与收据一致 |
| 用户可读性 | 只有日志和上下文字数 | 有摘要但影响不清 | 能说明检查、发现、未改变和下一步 |
| 成本效率 | 大量无关读取和重复调用 | 成本可接受但有冗余 | 在有限读取和步骤内取得稳定结果 |

### 4.3 稳定性

  开放式任务不要求两次输出文字一致，但两次都应满足证据、权限和结构边界。记录均值之外还要记录方差、失败率和最坏样本，避免平均分掩盖偶发严重错误。

## 五、Episode 与实验记录

  每次实验至少保存以下可审计信息，不保存隐藏思维链：

- 案例 ID、版本、`as_of`、输入与知识体快照指纹。
- 模型、参数、Skill、Thinking Model、可用 OPS 与预算。
- 每次工具调用、参数摘要、Observation、错误与 Harness 收据。
- 最终输出、引用、写入差异、任务状态、耗时和 token/费用。
- 自动硬门槛结果、人工评分、评分者和备注。
- 候选版本、父版本与回滚目标。

  评测数据与生产知识体分离。评分器只能读取实验快照，不得因打分自动改写 Card、TM 或 OPS。

## 六、失败归因

  低分必须定位发生在哪一层，再决定修改对象。

| 失败表现 | 优先检查 | 不应首先做的事 |
|---|---|---|
| 找不到必要证据 | 检索、Card 字段、关系 readiness | 直接加长最终提示词 |
| 读到证据仍误判 | TM、输出契约、模型能力 | 再增加相似检索工具 |
| 候选反复被拒 | 工具 Schema、示例、Harness 反馈 | 放松全部安全规则 |
| 关系路径无价值 | 关系语义、note、plane、存量债务 | 扩大遍历深度 |
| 任务卡死或丢状态 | CognitiveRun、队列、恢复和并发 | 修改知识本体 |
| 用户看不懂过程 | 认知事件投影和结果摘要 | 展示隐藏思维链 |

## 七、受控迭代等级

| 等级 | 改变内容 | 当前态度 |
|---|---|---|
| L0：任务内纠错 | 换参数、补证据、换 OPS、缩小范围 | 应优先做稳 |
| L1：人工修订 | 根据重复失败手工修改 Skill、TM、OPS 或 Harness | 当前可用方式 |
| L2：候选生成 | 系统依据失败聚类提出受限文本或配置候选 | 可在隔离环境试验 |
| L3：自动搜索与晋升 | 自动生成、评测、部署策略或代码 | 暂不开放 |

  Thinking Model、Skill、工具说明和 OPS 实现必须分别归因。一次候选只改变一个主要变量，否则无法判断提升来自哪里。

## 八、候选晋升门槛

1. 重复失败模式至少在多个案例中出现，并有明确证据。
2. 候选改动范围有限，能说明影响层与撤回方式。
3. 固定回归集无退化，安全硬门槛全部通过。
4. 目标任务集稳定改善，不只改善用于生成候选的样本。
5. 隐藏集或盲化成对比较仍保持优势，并允许平局。
6. 成本、延迟和失败方差没有不可接受上升。
7. 人工批准后先小范围试用，保留旧版本与一键回滚。

## 九、近期实施顺序

1. 先完成安全修复与 R1～R9 确定性回归。
2. 从现有真实材料中建立 12～20 项固定任务集与不可变快照。
3. 实现本地实验记录和 A～D 基线运行，不先依赖云测评平台。
4. 建立硬门槛检查、人工评分表和盲化成对比较。
5. 对首轮结果做失败归因，只选择一个重复失分模式改进。
6. 候选通过固定集和隐藏集后，才讨论半自动候选生成。

## 十、明确不宣称的能力

- Episode 已经能让系统自动学习。
- Thinking Model 配置存在就证明策略有效。
- 多调用 GraphOps 等于推理质量更高。
- LLM Judge 的高分等于事实正确或用户价值高。
- 历史题答对等于具备真实预测能力。
- 一次自我反思足以永久修改生产策略。

  当前合理目标是建立可信的比较和归因基础，而不是提前包装“自我进化系统”。

## 十一、把历史案例变成 OPS × TM × Skill 评测

  现有 FT-001～FT-003 已经能用于人工顺序回放，但它们主要测“模型读完固定材料后能否给出合理判断”。要判断 DSH 的 OPS、Thinking Model 和 Skill 是否各自带来价值，还需要补四类可执行约束。

### 11.1 冻结一个小型知识体，而不只冻结输入文档

  每个案例增加 `fixture/`。其中保存本案例专用 Card、来源摘要和一份 `manifest.json`。清单必须声明每个检查点允许出现的 Card、来源和关系；运行器只把当时可见的部分复制到临时知识体。这样 C、D 两组才能真实调用检索和图操作，同时不会读到未来信息或用户的生产知识体。

  不要求复制完整 DSH 仓库。第一版每个案例保留 8～15 张有意义的 Card、2～4 条干扰信息和足够支撑判断的关系即可。图过大只会让资料质量和检索质量混在一起。

### 11.2 把四种运行配置写成机器可读契约

  `case.json` 增加 `execution_profiles`，固定模型参数、Skill、允许的 TM、允许的 OPS、总步骤、读取次数、图遍历深度和是否只读。建议至少保留四组：

| 组别 | 可见信息与能力 | 用途 |
|---|---|---|
| A | 只有题目，不给案例材料 | 测预训练记忆与一般分析能力 |
| B | 固定文本包，可全文阅读，不给图工具 | 测资料本身带来的增益 |
| C | 冻结知识体与 GraphOps，不指定 TM | 测检索和图关系的增益 |
| D | 同一知识体、OPS 和预算，再启用 `nexo-assess` 与指定 TM | 测 Skill 与思考策略是否继续改善判断 |

  C 与 D 必须使用同一知识快照和近似 token 预算。不能让 D 多看一倍材料，再把提升归因于 TM。

### 11.3 要求答案引用“证据位置”，并检查真实工具轨迹

  `output-schema.json` 增加 `evidence_anchors`：每项核心判断至少给出 Card ID 或输入文件中的证据段落标识，并区分支持证据、反证和推断。`evaluator/expected-evidence.json` 保存“允许的关键证据集合”，不规定唯一措辞，也不规定唯一工具调用顺序。

  自动检查 Episode 中是否真的执行了声明的 OPS：读到了哪个节点、沿哪条关系发现了什么、失败后是否换了动作、有没有重复读取。只在答案里声称“比较过机制”不能算使用了 GraphOps。评分关注能力是否发生和证据是否相关，不把固定调用顺序伪装成 Agent Loop。

### 11.4 用结果平衡与负例防止“逢风险必报危机”

  历史案例不能全是危机实际爆发、价格实际暴跌的正例。否则总是预测坏结果的系统也可能得高分。测试集中应同时有危机发生、危机未发生、局部受损但没有系统性危机，以及方向判断正确但幅度错误的案例。

  FT-004 采用 1994—1995 年美国快速加息后的软着陆。它保留债券损失、墨西哥危机和经济放缓这些真实压力，但把“1995 年美国是否进入衰退”设为否定结果，用来检查系统能否把压力、传导渠道和最终事件分开。

### 11.5 最小运行器需要修改什么

  第一版不需要建立测评平台。在 `tools/eval/` 内实现一个本地运行器即可，职责限制为四件事：

1. 读取 `case.json` 和 `fixture/manifest.json`，按检查点建立一次性临时知识体。
2. 按 A～D 配置启动认知 run，关闭网络和写入，只开放清单中的文件、Skill、TM 与 OPS。
3. 保存输入、最终答案、Episode、工具收据、token、耗时和退出原因；每次运行使用新的目录，不能覆盖旧结果。
4. 校验输出 Schema、时间越界、虚构证据、预算、Brier 分数和人工评分表；评分器只能读结果，不能给被测 Agent 暴露答案。

  当前已保持四个小文件：`runner.mjs` 生成顺序运行计划，`materialize-fixture.mjs` 生成临时快照，`score.mjs` 执行 Schema 与通用跨字段检查，`schema.mjs` 校验案例、checksum 与答案。准备命令为：

```powershell
node tools/eval/runner.mjs --case FT-004 --profile E_thinking_body_v1 --variant anonymous --repeat 3 --output tmp/eval-ft004
```

  当前运行器只完成案例校验、隔离快照和计划生成，尚未直接创建 DSH 模型会话。模型适配与结果收集接通前，仍只能人工执行答案阶段，不能宣称已经分离测出了 OPS、TM 或 Skill 的贡献。

### 11.6 四份案例当前已经补齐的部分

  FT-001～FT-004 已统一要求 `previous_checkpoint`、`evidence_anchors`、`update_delta` 和 `limitations`，并分别保留贸易、国家、商品与软着陆案例自己的预测字段。四套案例均已增加 `execution_profiles`、冻结图谱 fixture、预期证据集合和 OPS 能力要求。

  FT-001 的校验和已重新生成；FT-002 已把两项区域事件 Brier 纳入自动指标；FT-003 已增加来源与 Card 证据位置。`tools/eval/check-cases.mjs` 检查案例契约，`tools/eval/score-response.mjs` 处理情景概率和、区间嵌套、排名唯一性、区域概率必要一致性及已有量化结果。

  尚未完成的是自动临时装载、模型调用、Episode 收集、匿名图谱变换和 A～D 批量运行。这些仍属于最小运行器，而不是测试集内容本身。
