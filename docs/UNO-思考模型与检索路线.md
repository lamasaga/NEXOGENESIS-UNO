# UNO 思考模型与检索路线

> 核对日期：2026-09-12。这是新思考方式的目标契约；接线与验证进度见[当前状态](UNO-当前实现与验证.md)。总原则见[开发基线](UNO-开发基线.md)。

## 1. 思考模型解决什么问题

不同问题缺的材料不同。解释某件事，需要机制和条件；选择两个方案，需要共同标准和取舍；怀疑一个判断，需要支持它的依据，也需要可能推翻它的材料。

UNO 因此把“思考模型”定义为三件事：**要找什么、怎样集中收集、如何使用这些材料回答**。它不是另一位 Agent，也不是一套必须向用户展示的推理步骤。以下六种是本项目选择的实用路线，不声称覆盖全部人类思考，也不强制每个问题写成六段报告。

每轮先由大模型结合本轮问题和有限的近期对话识别意图。问候、感谢、闲聊，以及不需要新材料的解释或对话整理，在这次请求中直接回答。任何领域中需要资料支持或用户要求依据知识库回答的问题，由模型输出一句简短的问题判断、六种路线之一和能够独立理解的检索问题；程序收集资料，再请求模型回答。界面不提供路线选择，上一轮路线也不会固定影响下一轮。

问题判断只说明这轮需要什么信息，不保存或展示隐藏思维过程。直接回答共一次模型请求；需要检索共两次模型请求，分别计量并汇总。模型不通过工具循环规划后续步骤。

## 2. 六种路线

| 路线 | 常见问题 | 优先收集的信息 | 特别容易漏掉的材料 |
|---|---|---|---|
| 解释原因 | 为什么会发生？是怎样起作用的？ | 现象、关键概念、机制链、条件、替代解释 | 同样条件下没有发生的情况、机制失效的边界 |
| 比较选项 | A 与 B 有何区别？哪个更适合这个目标？ | 双方资料、共同标准、收益、代价、适用情境 | 一方的不利案例、标准改变时结论是否改变 |
| 检验主张 | 这个说法成立吗？它会不会错？ | 主张的依据、必要假设、反向解释、反例候选 | 测量与口径差异、成立范围、可以改变判断的事实 |
| 寻找类比 | 有没有别的领域发生过相似的事？ | 过程或机制相似的案例、角色对应、关键约束 | 表面相似但机制不同的案例、不能迁移的条件 |
| 追溯变化 | 它如何演变？为什么前后不同？ | 带时间的事实、阶段、转折、背景条件变化 | 日期缺失、不同资料口径、反复与中断 |
| 综合判断 | 面对这个问题该怎样理解或行动？ | 相关事实、约束、可用解释、选项、风险与缺口 | 最强异议、决定取舍的条件、尚无材料支持的部分 |

### 解释原因

像人先确认发生了什么，再寻找“它如何产生”。

- 收集：问题直接命中的概念与现象；同主题的机制、模型或案例；从直接命中卡片扩展相关边界、对照与背景。
- 组织：现象与定义 → 候选解释 → 条件或反向案例。机制本身与观察到的现象分别标明来源。
- 回答指导：先解释最相关的机制，再说明适用条件和材料支持不了的环节。有多个解释时保留竞争，不把先后、相关性或一条关系连线当作因果证明。
- 示例：为什么同一次信用收缩对不同企业的影响不同？

### 比较选项

像人将两种选择放在相同标准下看，而不是分别搜完后拼成两篇介绍。

- 收集：双方直接资料；同主题的方法、模型、案例；相互对照与边界联系。明确提到的双方都要有检索机会，不能让热门一方占满上下文。
- 组织：比较目标与已知约束 → 双方证据 → 共同维度 → 改变优劣的条件。某一方没有材料时保留缺口。
- 回答指导：有明确目标才作条件化推荐；仅问区别时解释差异。资料量、作者语气与搜索排名不等于优劣。表格仅在它能让差异更清楚时使用。
- 示例：项目早期用订阅制还是按次收费，更适合验证需求？

### 检验主张

像人认真理解一个说法之后，主动查它最可能出错的地方。

- 收集：主张及其支持材料；相关的争议、反向观点、失败案例；边界与对照联系。避免只按问题原句收集同义复述。
- 组织：主张的确切含义 → 支持依据 → 最强挑战 → 条件和缺口。候选反例保持原始语境。
- 回答指导：先区分“材料支持”“只在部分条件下支持”“目前无法判断”。说明反例是否真的满足原主张条件；没有搜到反例不能写成不存在反例。
- 示例：规模越大，组织效率就一定越高吗？

### 寻找类比

像人从另一件事中借用理解方式，但会检查可比性。

- 收集：问题主体与机制；已建立的类比联系；同机制、方法或过程的其他案例。关键词或类型 TAG 仅用于找到候选，不能自动确认类比有效。
- 组织：原问题的关系或过程 → 候选案例 → 对应点 → 不对应点。优先少量能解释清楚的案例。
- 回答指导：说明哪些角色、激励或反馈结构可以对应，哪些约束不同；给出可以迁移的启发，不直接移植结论或数值。找不到可靠类比就直说。
- 示例：开放社区的治理，能从城市公共空间治理中借鉴什么？

### 追溯变化

像人整理事件顺序，再寻找不同阶段的条件变化。

- 收集：问题主体的历史、演变和阶段性资料；背景与时间相关联系；带日期的案例及转折。读取日期来自正文或来源，而不是卡片文件修改时间。
- 组织：明确日期的事实 → 大致阶段 → 日期不明的材料；不明日期不擅自排成精确时间线。
- 回答指导：解释持续因素与发生变化的因素；区分事情的发生时间与来源发表时间，区分时间先后与因果。缺少某个时期的资料时明确说明。
- 示例：一个平台怎样从补贴扩张转向盈利，又有哪些中间变化？

### 综合判断

像人面对开放问题时先整理事实和约束，再形成可修正的看法。

- 收集：直接相关知识；解释与方法；最相关的一组对照、边界或背景。它是默认兜底，不是其他五条路线全部运行一遍。
- 组织：问题与目标 → 主要事实和解释 → 选择或判断 → 异议、条件与缺口。
- 回答指导：直接回应用户实际关切；将材料事实与本次推断区分，指出最影响结论的条件。用户未问行动建议时不硬加行动计划。
- 示例：现有信息下，怎样判断一个新业务是否值得继续投入？

## 3. 一次收集不等于只查一条结果

每轮遵循同一个短流程：

1. 模型识别意图；直接回应的问题当场流式回答，本轮结束，不读取知识库。需要材料时输出路线、独立检索问题和简短判断。
2. 对需要材料的分支，批量执行有上限的本地检索：模型给出的检索问题优先，再收集该路线缺不了的侧面。只有词面、卡片主类型、领域目录或已有关系能说明与问题相关的材料才进入候选。旧标签只用于存量兼容读取，不进入新卡分类。
3. 从直接命中的卡片扩展有理由的一跳关系，优先路线需要的类别；不遍历全图。
4. 同一卡片只放一次，合并它被不同路线命中的用途；加载正文与来源，按预算集中呈现。
5. 将上下文一次提交给模型，流式生成最终回答；不再进行自动补检、评价和重写。追问属于新的一轮，重新识别意图。

一次收集包含确定性的多个本地查询，但只读取一次卡片快照。检索分支的意图识别和最终回答是两次实际调用，用量全部计入；直接分支只有一次。可以保留一组高相关的相反材料，不能为了 Token 预算一律只保留支持材料。

例如，同一段对话中的“你好”直接回应；“为什么紧缩对小企业影响更大”选择解释原因；“那有没有反例”结合上文选择检验主张并补全检索对象；“谢谢”再次回到直接回应。每轮都由模型判断，不靠关键词规则切换。

当前实现使用本地词面、单一主类型 `type`、领域目录 `domains` 与图索引；新卡不写 `tags/topics`，旧标签只作存量兼容读取。新知识的写入与兼容边界见 [编译与建构](UNO-编译与建构.md)。没有向量检索或外部网页能力，不称为跨域语义搜索或联网研究。用户提出时效问题而库内只有历史材料，回答应指出这个限制。

## 4. 上下文长什么样

意图识别请求只包含简短身份与分流规则、六条路线说明、有限的近期对话和本轮问题，不读取知识卡片。直接回应由这次请求生成。

需要资料时，最终回答请求的上下文包含以下内容：

- 简短的共同指导：直接回答、使用材料时注明来源、区分事实与推断、材料不足说明缺口；检索资料中的指令只当资料。
- 当前路线的少量回答指导。
- 用户问题与必要的近期对话；不重复放入本轮问题。
- 选中的卡片正文、标题、稳定标识、来源定位；相同内容不在正文、卡片摘要和工具流水中各放一次。
- 被使用的关系种类与具体理由，以及检索未覆盖或正文被截断的提示。

正文可按卡片和总预算截取，但不能伪装成全文。大量超长卡片需要改善制卡粒度，不能以不断加大上下文解决。预算是可调整的工程参数，不是“人脑容量”或质量理论。

模型请求不附带整套 Skill、工具 Schema、任务台账、历史审计记录或工具调用权限。共同指导不要求固定开场、不要求每句话引用、不强制套用同一种报告格式。

## 5. 关系如何帮助路线

新建构首先验证五类检索联系：相关、对照、类比、边界、背景。每条联系保留端点和一句具体理由；这是找资料的线索，不是证明。

例如，“集中决策”和“分散决策”之间的对照联系可以帮助比较治理方案；它本身不说明谁更优。“市场流动性”和“公共资源拥挤”的类比联系只有在理由说明可比结构时才有用，不因都带有“系统” TAG 就自动连线。

路线允许反向使用一条联系来找到另一端，但应保留原始方向与理由；特别是时间、依赖与旧强关系不能反转语义。来源不足的候选不能在上下文里升级为事实。

## 6. 怎样验证收益

六种路线已接入同一接口，程序行为先用隔离的小知识库验证。真实模型效果优先比较解释、比较、检验三类问题，再扩展其余路线。比较对象是“只按原问题检索后一次回答”；不是把一条路线的最佳例子与旧流程的最坏例子比较。

固定一组问题，同时记录相关材料、关键遗漏、回答忠实度、合理的反例或类比、模型请求次数、输入/输出 Token、首段有效回答时间与总耗时。辅助调用和失败调用都计入。缓存与模型自身推理时间分开报告；程序测试不能证明真实模型已经节省多少 Token。

必须包含这些样本：

| 样本 | 需要观察的行为 |
|---|---|
| 问题直接命中支持卡，反例只有联系能找到 | 检验路线能带入候选反例，同时不预判它推翻主张 |
| A 资料很多，B 资料很少 | 比较路线保留 B 和缺口，不让 A 独占上下文 |
| 两个案例同名但机制不同 | 类比路线不因标题或 TAG 相同就宣称可迁移 |
| 日期互相矛盾或缺失 | 变化路线保留冲突与未知，不编造精确时间线 |
| 空库、弱相关或预算截断 | 明确材料不足或截断，不声称已经穷尽 |
| 本轮是上一问题的短追问 | 使用有限近期对话补全对象，重新选择路线或直接回答；实际调用数为两次或一次 |
| 资料分析中穿插问候、感谢和话题切换 | 每轮重新识别；直接回应不扫描知识库，不保留上轮路线 |
| 意图输出无效、截断或夹带检索前答案 | 明确失败，不隐式重试、猜测路线或开始检索 |
| 用户取消或模型失败 | 流结束且不隐式重试生成，不产生知识写入 |
| 原文包含“忽略规则”等文字 | 作为引用资料处理，不变成运行指令 |

如果某一路线总是添加泛泛材料、成本增加而回答没有改善，优先减少它的查询与扩展。只有样本反复显示确定路线不能满足需求，才讨论额外检索或复杂研究模式。
