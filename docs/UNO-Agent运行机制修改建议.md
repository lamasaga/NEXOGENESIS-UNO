# UNO Agent 运行机制修改建议与实施核对

> 2026-09-16。依据当前 UNO 源码、9 月 15 日请求快照和本轮隔离宿主验证修订。适用阶段：独立重建与架构验证。
> 本文区分已经实施的运行修复、程序验证、真实模型证据与尚待实验的方案。保留 DSH 原生引擎，不迁移、删除或重写用户知识。

## 1. 调整后的结论

原建议抓对了工具契约、执行归属和上下文之间的交界，但把已经发生的证据裁剪放在第二优先级，低估了它对重复阅读与验收的影响。修改顺序调整为：**先使返回证据完整可恢复，再统一任务归属与失败处理，最后用对照实验决定工具视图和并行是否值得引入。**

普通问答保留自动判断、按需检索、一次生成的路径；编译与建构保留作者处理、独立审核、通过对象发布的边界。节省用量不能通过放弃反例、来源、版本检查或把未处理事项改成完成来实现。

| 原建议 | 本轮决定 | 当前状态 |
|---|---|---|
| A 工具契约 | 先收紧读卡、编辑与批量嵌套参数；明确恢复类别，保留 Gateway 收据 | 核心入口已实施；其余工具的嵌套 Schema 仍需逐项收紧 |
| B 完成与停止 | 分开模型返回、结束原因和业务完成；增加同一失败空转暂停 | 已实施并回归；不是通用循环检测器 |
| C 请求归属 | 复用原生会话不可变的创建目录，不新增平行快照系统 | 提示、工具和诊断按会话归属；执行仍检查最新任务状态 |
| D 上下文 | 提升为第一优先级；正文在登记阅读前分页，搜索精简，停用知识工具结果首尾裁剪 | 已实施并经原生最终报文验证；高压力历史压缩质量未验证 |
| E 阶段工具视图 | 保留对照实验，不直接切换默认工具集 | 尚未启用，仍是 18 个工具；不是已交付的省 Token 能力 |
| F 只读并行 | 暂缓；读取也会写阅读记录，当前无等待时间收益证据 | 保留顺序执行与逐项提交，不并行写入 |

## 2. 已核对的实际问题

### 2.1 大请求不是一个巨大系统提示词

历史请求 `368b0a91-27aa-44c1-b69f-6b04a3d8c721` 显示 152,117 展示字符，其中工具结果 96,439、工具定义 18,931、系统正文 14,969。10 份搜索结果占 74,628 字符。展示字符不等于 tokens，也不等于未缓存收费输入。

全量授权清单和搜索附带元数据会重复进入后续请求。中文旧卡 ID 被英文数字规则拒绝又促使模型改走检索、重读；中文兼容与授权清单分页在前一轮已经修复，本轮没有把这些重复计为新增改动。

本轮用历史 10 组搜索参数在当前知识库只读重放，结果合计 57,636 字符，较历史可见搜索结果减少约 23%。当前数据状态和渲染形式可能与历史有差异；这是体积诊断，不是固定材料、同模型的成本 A/B，也不能推断回答质量提升。

### 2.2 存在两层不同的裁剪

- 原生 spill 策略按 UTF-8 字节把大结果换成首尾预览与临时文件指针；历史请求中确实出现过。UNO 的工具集中没有它提示的通用 read/grep。
- `uno-compile` 还安装了压力触发的工具结果裁剪器，默认超过 8,192 字符就保留头尾，可能破坏 JSON。它是与 spill 不同的机制，不能混称一次裁剪。

读取工具先登记区间，随后宿主再裁剪，便会出现“台账认为返回完整、模型实际没收到完整”的不一致。解决点必须在交付链路，单改提示词或要求模型记住内容无效。

### 2.3 活动知识库曾参与执行定位

`uno/agent.js` 原先通过订阅当前选中的知识库更新闭包 root，提示装配和工具执行都使用它。原生会话已经有固定 `header.cwd`，没有必要继续把 UI 选择作为旧请求的执行依据。

本轮证实该实现会造成归属漂移风险；没有据此宣称发生过跨库写入。新实现根据会话创建目录和任务记录唯一绑定，切库只影响新入口。已交接的旧会话不能使用当前角色的写权限。

### 2.4 返回不等于完成，重复失败需要停止

原生 `assistant/message` 仅表示形成了模型消息，可能只有工具调用、没有正文或被额度截断。原代码统一记作 completed，诊断会误导。业务是否完成仍须依赖审核、来源去向与发布结果。

压力模拟还复现了重复请求“完成”、不断得到相同未完成事项的空转。这是测试模型的错误行为，但宿主若没有限制，真实模型同样只能靠总预算兜底。

### 2.5 普通对话的片段选择仍可能偏向首次命中

旧摘录优先开头及每个词的第一次后段命中，同一关键词后来出现的限制可能没有机会进入上下文。本轮增加重复命中和明确限制、反例的候选机会，保留真实片段位置。它仍是检索启发式，不证明已经找到所有反证。

## 3. 已实施的具体规则

### 3.1 工具参数与错误

- 卡片 ID 说明与实现一致：支持目录返回的合法中文原 ID，不接受路径；任务标识的限制没有放宽。
- 编辑的 link、merge、edits 以及批量操作外壳使用明确字段。拼错字段被拒绝；批量中的相关操作在任何写入前预检。
- 原生定义与嵌套编辑、读卡、读原文共用参数契约。不同 action 的组合限制仍由业务实现执行。
- 版本冲突和幂等参数冲突携带明确错误码；暂停、旧角色、范围越界有各自类别。错误类别不再通过中文文案正则猜测。
- `HarnessRejected.receipt` 原样保留为结构化收据。未迁移的业务错误仍为 `TOOL_FAILED`，返回原始原因，不编造确定的重试策略。
- 同一操作 ID、同一参数查回原收据；改了参数不能冒充同一次提交。不存在“所有工具都有相同输出结构”的声明，成功结果保持各自最小业务结构。

### 3.2 执行归属和恢复

- 提示装配与工具执行使用同一会话根目录解析器；只从项目与登记知识库中唯一匹配所属任务。
- 原生会话创建目录是定位依据；没有该字段的兼容调用也必须唯一匹配任务，不能静默选中当前 UI 库。
- 每次执行重新读取任务状态、当前 session、结束标记；建构修改继续受当前范围限制，版本由 Gateway 校验。
- 迟到旧角色事件不更新新的角色状态。模型请求诊断也优先归入原生会话拥有的知识库。
- 没有给请求增加永久授权快照；没有重建消息队列、业务任务或调度器。

### 3.3 模型结果与空转暂停

已有 call 记录新增或明确：`session_id`、`turn`、`finish_reason`、`response_kind`、`turn_end_reason`。返回状态为 returned；额度截断为 truncated；text/tool_calls/no_text 区分输出形态。成功返回不会直接设置业务任务 completed。

连续三次相同工具、相同参数、相同失败结果时，任务暂停并保留当前阶段与成果。成功操作重置连续计数，修改参数给模型修正机会；正常重复读取不会被判断为空转。错误循环交替变形、原生参数验证前的失败、语义上毫无增量的成功读取仍可能逃过该规则，不能称为完整防循环。

原子写入、回执和取消边界保持原机制；本轮没有更改事务提交顺序。诊断写入失败不得改变知识提交事实。

### 3.4 正文、搜索与批量返回

- 原文、卡片、聚合来源在登记区间前按完整 JSON 的 32,000 UTF-8 字节预算生成页。`next_offset` 对应真正返回的 Unicode 字符末端，不是原请求 limit。
- 元数据自身过大、连一个正文字符都无法返回时，明确报错且不登记阅读，不通过破坏 JSON 继续运行。
- 批量仍最多 8 项且顺序执行；累计结果达到阈值后停止启动余项，`next_index` 指出未执行项。已成功项不重放，剩余项可以另行提交。
- 搜索输出定位、短摘要、片段、有限关系线索与质量疑点。精确 ID/ref 不缩写；查看完整卡片用读卡工具。大结果按实际返回项数分页。
- pending 目录分页，动态状态只给待处理批次数和入口；已接收补充要求完整保留，现有入口已限制累计 12,000 字符，不引入悄悄截掉旧要求的窗口。
- `uno-compile` 停用通用首尾裁剪器，保留原生历史压缩。该修改只作用 UNO 专用 preset，不修改 DSH 项目或共享运行配置。

32,000 字节是传输保护，不是模型 Token 预算。批次、请求预算与模型上下文窗口仍分别约束。异常庞大元数据、少用工具的所有输出分支尚未全部建立统一上限，不能宣称任意结果绝无 spill。

阅读回执仅证明工具交付过对应版本的区间，不证明模型理解、不证明后来压缩后仍在窗口。恢复时查当前版本、来源与收据；需要精确引用才定位补读，不以窗口变化为理由整书重新处理。

### 3.5 普通对话如何使用知识

保留一次意图判断；需要资料时集中本地检索后一次回答，不添加重排模型、第二审核或隐式重试。

片段选择兼顾首次观点、后续同词命中、明确限制与反例，保留原始 spans 与省略标记，不切断 emoji。质量疑点继续进入检索结果；导航关系继续标注导航身份，不能当成已证实因果或反驳。

知识覆盖、回答质量与本轮是否允许写卡是不同职责。普通问答依现行基线保持只读，本轮没有接通新的涌现写卡流程，也没有用删掉“不能写卡”一句话冒充能力修复。未来显式保存候选需要完整的授权、预览和 Gateway 通路。

## 4. 验证结果与限制

| 验证 | 结果 | 能证明什么 |
|---|---|---|
| 中文旧卡、草稿、版本与审核回归 | 通过 | 原 ID、正文、来源和独立审核边界保持 |
| Unicode 大页与批量余项 | 通过 | 页返回长度与记录区间一致，未执行项不假装成功 |
| 两个临时库切换、旧会话交接 | 通过 | 创建目录固定归属，旧角色被拒绝 |
| 错误码、嵌套字段和失败暂停 | 通过 | 文案变化不改变已分类错误，重复失败可暂停 |
| 原生短材料 | 17 次本地模拟请求、0 工具错误、完成发布 | 真实 DSH Schema、请求、执行、审核链接通 |
| 原生长中文材料 | 26 次本地模拟请求；120 份历史工具消息均可解析；最大 30,130 字节；末尾反例进入请求 | 大页与最终模型报文匹配，未出现 spill 或 JSON 首尾裁剪 |
| 历史搜索参数只读重放 | 返回字符减少约 23% | 结果体积下降；不是费用或质量 A/B |

344 项后端、182 项前端测试及构建通过；诊断归属的最后容错调整另通过 7 项专项测试。

原生模拟使用独立临时库和本地供应商。压力脚本最初遗漏第二个预处理单元，导致反复请求完成；保留了这次失败分析，修正样本处理并加入连续失败暂停。不能把模拟模型当作真实理解质量的评分人。

**本轮验证操作失误记录：** 首次本地供应商配置因思考模式参数不合法被拒绝，手工测试仍启动了临时任务，继承默认真实模型连接。发现后已结束该任务。记录有 9 个原生 step，8 个报告非缓存输入 17,203、缓存读取 99,584、输出 1,696（含推理 621，不另计），另一个无用量；只处理合成材料、没有正式知识写入。已增加配置响应、模型与端点回读验证，任一检查失败就不创建任务。该偶发调用不当作质量实验，也不能称本轮完全没有真实调用。

请求输入只保留最近 60 份，是诊断窗口，不是完整费用账本。未报告用量保持未知；源码测试、健康标记、字符减少和成功发布均不替代真实知识质量验证。

## 5. 保留的后续实验与采用标准

### 阶段工具视图

先保留 18 个工具的可用基线。原生 scoped restriction 不能简单限制同一 scope 自己注册的工具，不能用全局工具注册表切换来影响并发会话。若实验按筛选、作者、审核组织工具，应同时验证真实可见集合、嵌套执行检查和阶段切换；审核人保留必要修订能力。

采用标准是同材料、同模型下误调用、总往返或费用改善且重要内容不丢失；工具定义更小本身不是充分收益。暂不增加工具搜索或 Code Mode。

### 历史压缩

原生基本压缩仍使用面向代码工作的摘要模板。本轮关闭的是破坏工具结构的裁剪，不是重写压缩引擎；未验证高压力下来源归属、反例和用户要求在摘要中的忠实度。后续应先测强制压缩前后的关键证据保留，再决定是否通过正式扩展点定制摘要，不复制一个平行压缩器。

### 并行与知识质量

读卡和读原文会保存阅读区间，不能因知识只读就直接并行。继续保留顺序批量和独立提交，只有真实等待数据说明有收益才拆分读取与登记。

真实模型实验使用隔离知识副本、固定问题和材料版本，分别比较本轮契约改动、摘录选择与阶段工具视图，不同时混改模型。包含长材料后段反例、作者分歧、数字、中文旧卡、无需修改的建构、部分完成恢复和普通问答。逐例看来源忠实度、独立可读性、错漏、有效新建/修订、非缓存/缓存/输出用量与时延，不设“必须多产卡”指标。

付费实验开始前确认模型、样本和费用上限。样本结果足够前，不宣称经济性或语义质量已经全面提升。

## 6. 生效、撤回和核对入口

核心代码：`uno/agent.js`、`uno/execution-contract.js`、`uno/tool-schemas.js`、`uno/workflow-v3.js`、`uno/knowledge.js`、`runtime/tool-result.js`、`runtime/text-edits.js`；宿主的 `uno-request-state.js`、`uno-workflow-v3.js` 与 `prompt-inspector.js`。

测试：`tests/uno-foundation.test.mjs`、现有生命周期/建构/思考测试；原生模拟用 `tools/eval/uno-foundation-native-smoke.mjs` 与带失败即停保护的 `tools/eval/run-uno-native-smoke.mjs`。

源码、前端构建、原生进程与真实模型分别核对。当前生效状态见 [当前实现与验证](UNO-当前实现与验证.md)。不自动继续真实编译或建构任务，不提高旧任务预算。保留所有用户知识、历史和本轮开始前的未提交改动。

撤回可恢复本轮工具投影、分页及 preset 改动，不需要知识迁移；新状态字段为可选诊断字段。若撤回重新启用通用首尾裁剪，证据破坏风险也随之恢复，不能作为“兼容性修复”静默启用。
