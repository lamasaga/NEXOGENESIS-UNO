## 1. 新一轮实测

任务：be347b32-957f-44b2-a137-d47f1f9deeb8。

- 5 份候选：2 份正式消化，3 份筛选排除。
- 2 篇消化材料仍形成 4 个单元，两个为纯元数据。
- 1 批发布 3 张卡片，1 条例证关系，1 个领域索引；批次 pending 为 0，随后任务由用户结束。
- 43 次模型请求：筛选 7、制卡 22、审核 14；86 次工具调用。
- 已报告输入 2,061,145 tokens：未命中 1,765,337，命中 295,808，命中率 14.35%；输出 50,869。
- 12 次工具报错：协议输出错误 5 次（状态 3、检查点 2）、清理定位 3 次、筛选引用 1 次、阅读/审核覆盖 3 次。
- 三个会话分别 7、22、14 次请求，系统提示词分别出现同样数量的不同版本。缓存缺陷继续存在；14.35% 不代表已经实施优化，与上一批材料规模和上下文长度不同。

卡片：future-industry-concept、wim-2024-innovation-conference、dengta-rice-fish-bigdata-center。领域索引实际位于 01-Cards/_meta/domains/ai-industry.md。

### 有效产出与质量边界

三卡保留了概念口径、采购意向与成交价的区别、会议预告与会后结果的区别、宣传性数字的来源。审核补入了部分具体信息，具有实质作用。

审核也存在过度限制：灯塔卡原有与算力基础设施/大模型项目比较的内容被删除，最终甚至写成“材料未提供同期其他项目，故不宜比较”。如果比较来自已读的其他卡片并清楚注明依据，它可以是合法检索导航；不能用单篇材料没有自行比较来禁止跨材料知识组织。

WIM 原文“超过 2000 位行业从业者”和“线下与会者超过 1600 人”被审核记录称为自相矛盾。两者可能是对象/口径不同，且两个下界数值并不构成逻辑矛盾。保存两处口径合理，直接判定矛盾并要求每次引用同时携带两数则过强。更合适的说明是“会前预测数字存在不同表述，范围未明确，不作为实际到场人数”。

### 新确认的关系接口问题

作者在普通卡片写入中提供了 link，但没有 action: link。stageKnowledge 的普通写入分支不消费 link，也没有返回未应用字段提示。WIM 与未来产业的关系后来由审核人单独 link 才保存；灯塔与既有招采卡的对照关系没有落盘。不能把关系少全部归为模型主动不连边。

应采用操作区分清晰的 Schema：不支持的参数组合明确拒绝或报告，不能成功保存正文却静默忽略用户/模型提交的关系。一次“卡片加关系”提交可以设计成明确支持的操作，由程序处理端点依赖；不用要求模型记住隐含调用顺序。

### 领域检查更正

上一份审计用 02-Profile 是否为空判断领域是否存在，路径错误，现已更正。新一轮的 ai-industry 索引实际创建成功。其摘要和代表入口聚焦新建三卡，不能据此宣称整个现有 AI 知识库的领域整理已完成。

## 2. 哪些部分是自建

DeepSeek Harness 的 Agent Loop、原生会话、工具运行与校验框架是复用的开源底座。PDF 读取使用 PyMuPDF，YAML 解析使用现成库，运行环境使用 Node/Python。

UNO 自建的是编译工具参数和包装、Python 分段与清理策略、知识草稿和发布、两轮审核调度、关系与领域规则、动态上下文注入及任务 UI。当前集中暴露的缺陷主要在这些集成与业务代码中，不是开源 Agent Loop 自动产生的必然问题。

## 3. 问题出现时间

Git 最早可核对的 UNO v3 提交为 341a8ad（2026-09-13 15:16:40 +0800）。preprocess.py、drafts.js、专用编译入口及关系指引在该版本已存在；它是代码最早被此仓库记录的时间，不等于精确编写时刻。

- 动态快照置于系统提示前部、全文覆盖缺字段变空、按文本标题把元数据拆成独立单元、来源类比限制：基线版本已有。
- 自主筛选是其后的未提交扩展；selection_reminder 在非筛选阶段为 undefined，新增了稳定触发非法工具输出的条件。
- JSON 规范化没有接入编译专用入口，是更基础的集成遗漏；归档阅读缺失元数据也是潜在触发条件，不能把所有非法输出只归因于筛选字段。
- 自主筛选相关收尾、历史 pending 重入 select 等，属于新路径的问题。
- 早于 20 份材料的 44 次请求任务，原生日志已经有 16 次工具错误，包括清理定位 4 次、领域阶段限制 2 次及阅读/结算错误。本次新 43 次请求任务再次复现。

所以是“部分近期引入，部分基线就有，真实连续编译集中暴露”，不能说直到用户截图时才产生，也不能无证据说很久以前所有版本都有。

## 4. 与 NEXOGENESIS-DSH 对照

本节以 DSH 当前源码和项目内历史真实审计为据，没有对当前 DSH 服务新发编译或声称其当前命中率。

| 问题 | DSH 证据与差异 |
|---|---|
| 非法 JSON 输出 | DSH 已有 json-value.js 的 normalizeJsonValue，多个核心工具入口使用。文件最早可核对提交为 0d32981（2026-09-01）。UNO 仓库也保留此工具，但专用编译入口未接入。不能保证 DSH 所有分支无错，但 UNO 无需为此另建新校验框架。 |
| 局部修改误当全文覆盖 | DSH 的 expandEnrichWrite 从旧正文和元数据构造补丁，支持 add_sources/add_relations；与 UNO 缺字段清空不同。历史 Kimi 编译曾因缺 mode=enrich 连续四次失败，是类似接口摩擦，但当时保护了正式文件。 |
| 缓存前缀 | 当前 DSH 未发现 UNO 这种每步把任务预算拼入系统提示词的入口；工作记忆主要通过工具结果及压缩交接提供。历史 Kimi 恢复记录有大量缓存命中，但不同供应商与工作负载不能和 UNO DeepSeek 直接比较。 |
| 重复登记/恢复成本 | DSH 2026-09-11 十一书复盘已记录先重复分派后发现旧成果、来源去向粒度细、旧队列与覆盖阻塞。此类问题确实不是 UNO 首次出现；相关代码已有针对性修复，但本次未做当前真实模型复验。 |
| 实体与关系 | DSH 已有 characterizes、attributed-to 的实体引用层，以及较严格的论证/情境关系规则。可借鉴实体归属，不能把整套强论证门控搬回 UNO。 |
| 网页尾部清理 | DSH 的来源处理以文本/PDF/EPUB 提取和来源账为核心；普通文本在 materializeSource 中主要规范换行，不能认为已经具备可靠的公众号去广告能力。两项目都需要适合网页/Markdown 的清理方案。 |

关键项目证据：DSH docs/2026-09-11-十一书编译复盘与修复.md，packages/nexogenesis-tools/lib/json-value.js、cards.js、cognition/model-output.js、context-compaction.js、compile/source-ledger.js。

## 5. 适合复用的开源组件

以下已查官方仓库，未在本项目上安装或做样本评测；建议是候选选择，不是已经验证的项目效果。

| 用途 | 候选 | 使用边界 |
|---|---|---|
| HTML 正文、元数据与模板噪声提取 | [Trafilatura](https://github.com/adbar/trafilatura) | 适合有原始 HTML 的输入；支持标题、作者、日期、正文与可选链接/图片。不能保证识别正文内全部营销内容；已转换为 Markdown 的输入不应再为套工具强行重抓网页。 |
| Markdown 结构、链接、图片、标题与头部识别 | [remark](https://github.com/remarkjs/remark) + [remark-frontmatter](https://github.com/remarkjs/remark-frontmatter) | 先把文档解析为结构，再给模型稳定区块。frontmatter 插件识别语法，字段值仍由 YAML/TOML 解析器读取。比正则猜标题和字符位置更适合当前 Markdown 样本。 |
| 复杂 PDF、扫描文档、表格与版面 | [Docling](https://github.com/docling-project/docling) | 可选重型解析路径；需要考虑模型资源、中文样本和处理耗时，不让每篇普通 Markdown 都经过它。保留现有轻量提取作为简单文本路径。 |
| 工具返回值与操作参数 | 先复用 DSH 的 normalizeJsonValue 与现有 Schema | 开源校验器如 [Ajv](https://github.com/ajv-validator/ajv) 可用，但当前已有验证框架，关键是正确接入和操作参数约束，不是再叠一套库。 |

DeepSeek Harness 自身已是开源底座：[官方仓库](https://github.com/deepseek-ai/deepseek-harness)。其官方标记仍是 developer preview，需固定已验证版本；不能以“开源”替代真实兼容性验证。

## 6. 调整后的优先级

1. 复用已存在的 JSON 规范化和局部补丁能力，补齐原生工具链测试；修复 link 参数静默忽略。
2. 修复稳定提示前缀、准确回执、结束/恢复路由。
3. 对当前 Markdown 样本优先采用结构解析和公共尾部处理；HTML、PDF 按格式分流到相应组件。
4. 修订关系依据与审核提示：来源事实保持忠实，跨材料导航可有明确依据地建立；不把不同下界数字自动当矛盾。
5. 在隔离库进行同材料对照，同时测错误率、成本、内容保留和关系检索价值。不能把本轮命中率从 10.84% 变为 14.35% 当成优化收益，因为尚未实施且样本不同。
