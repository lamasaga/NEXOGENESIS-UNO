# 模型接入与自动视觉配置

## 配置方法

在「设置 → 模型连接」选择服务提供方，填写该服务自己的 API Key，选择或填写模型 ID。再按对话需要设置思考模式、思考强度和图像处理方式，点击「保存更改」。编译与建构不会继承这里的对话深度。

| 服务 | 接口与凭据边界 |
| --- | --- |
| DeepSeek | 官方 API；当前通用 ID 为 `deepseek-flash`，旧 V4 Flash 名称只作兼容别名 |
| Kimi 开放平台 | Moonshot 通用 API Key，不能混用 Code Plan Key |
| Kimi Code Plan | 保留 DSH 原生 Anthropic Messages 适配；仅支持已接入的套餐型号 |
| 智谱 GLM | BigModel 通用 API，不是 Coding Plan 专用地址 |
| 阿里云百炼 | 中国内地通用兼容端点；其它地域用自定义接口 |
| 硅基流动 | 使用平台完整模型 ID，不沿用其它平台的同名模型能力假设 |
| 自定义兼容接口 | OpenAI Chat Completions；自行确认工具调用、图片与思考参数支持 |

供应商分别保存型号、思考设置和密钥；切换后不会把另一家的密钥带过去。未保存的密钥在切换供应商时清空。更换自定义地址须重新填写对应密钥。远程端点必须使用 HTTPS，本机调试允许 HTTP。

「已配置」只表示本地保存了凭据，不代表已完成真实连通性或额度验证。实际型号可用性仍由账户和套餐决定。切换模型或强度后建议新建对话。

## 思考设置

能力按「供应商 + 完整模型 ID」匹配，不根据品牌或名称包含某个词猜测。不同模型的档位不强行统一：

- DeepSeek `deepseek-flash` 与 `deepseek-v4-pro`：可关闭思考，支持 low / high / max；`deepseek-flash` 支持图像输入。旧 `deepseek-v4-flash` 与 `deepseek-v4-flash-vision-exp` 按官方兼容关系识别为当前 Flash，不再作为多个预设展示。
- Kimi K3：始终思考，只设置 low / high / max；不会发送它不接受的思考开关。
- Kimi K2.6、K2.5：可切换思考，不显示虚构的深度档位。K2.7 Code 保留始终思考行为。
- GLM-5.2：可切换思考，支持 high / max；GLM-5、GLM-4.7 和目录内 GLM 视觉型号不提供强度档位。
- 百炼和硅基流动目录内可切换的 Qwen 型号使用 `enable_thinking`，不把 `reasoning_effort` 冒充其通用深度参数。

未列出的通用 API 模型 ID 会原样保存，默认不声明图片能力或发送思考参数；用户可明确声明图文能力及参数协议。未知型号不宣称已核实的上下文窗口。原生 Code Plan 型号必须在已接入目录内。界面显示的“实际 ID”就是请求发送给供应商的型号；已登记旧别名会明确显示当前对应型号，不把同一后端模型伪装成多个预设。

用户选择的思考开关与强度只控制普通对话。新建 v3 编译按制卡、审核、返工和复核分别使用固定策略，建构固定使用高强度；两者仍使用用户选定的供应商与模型，但不继承对话深度。

这些设置控制模型推理参数，不改变 NEXO 任务预算、写入权限或 Harness 校验。

## 自动图像处理

默认选择「自动」：主模型已知支持图像输入时，直接复用主模型和它的凭据；主模型不支持图像时，才使用用户已配置的独立视觉服务。不会自动寻找外部供应商，也不会把主模型的密钥交给独立服务。

还可以选择仅使用主模型、仅使用独立服务，或关闭自动处理。未知型号须由用户确认图文能力，不能仅凭型号名称自动发送材料。

当前接入点是 PDF 关键表图复核 `preserve_source_figure`。正文编译与图像语义复核仍然区分；没有可用视觉服务、请求失败、返回不完整或未通过结果校验时，图像保留待处理，不依据图题猜测结论。当前 Codex 实际看图后提供的 `codex_analysis` 仍可使用。

Kimi Code Plan 读图通过 DSH 原生模型与附件服务；其它兼容接口按各自参数协议发送 `image_url`。图片复核不再统一发送可能被思考模型拒绝的 temperature 参数。

## 实现与验证边界

- `packages/nexogenesis-tools/lib/model-providers.js` 集中维护目录、参数能力、验证和视觉选择，前后端共用；设置界面独立放在 `web/src/components/settings/`。
- `packages/nexogenesis-web-host/lib/model-adapter.js` 只转换兼容接口的请求和流式响应。会话、工具执行、重试与恢复仍由 DSH 负责；普通思考回合及工具回合的 `reasoning_content` 均参与回送。
- 设置保存先验证参数再写凭据；读取只返回是否配置和掩码。供应商 HTTP 错误不回显可能夹带敏感内容的响应正文。
- 自动测试覆盖请求参数、思考与工具回送、断流、密钥隔离、保存恢复、视觉路由及真实 DSH 注册和流组装。浏览器在内存设置沙盒验证桌面及窄屏交互，不修改实际设置或知识体。
- 尚未使用用户密钥逐家进行真实付费推理；网络、套餐权限及模型质量不由模拟测试证明。前端构建完成后，后台仍须重启 NEXO 才加载新增适配；旧后台会被界面识别并提示，不能误报新参数已保存。
- 回退时须一起恢复本次设置、目录、适配器和视觉调用改动，并重新构建前端、重启宿主；新字段可留在本地设置中，但旧代码不能使用新路由。回退前把主模型切回旧版支持的 DeepSeek 或 Kimi Code Plan。
