# UNO 语音输入

点击输入栏发送按钮旁的麦克风图标，允许麦克风权限，说完后点击原位置的方形停止图标转写。录音时显示时长，可点击旁边的取消图标放弃；鼠标悬停和屏幕阅读器提供操作说明。文字会追加到当前草稿末尾；检查人名、数字和否定词后，再点击发送。语音输入不会自动发送消息、创建任务或调用聊天模型。常驻说明和成功提示不占据输入栏空间，失败时才显示可关闭的提示。

单次录音最长 60 秒。录音和转写期间可取消；切换对话也会取消当前录音或转写，已有草稿保持不变。可以边转写边修改输入框，识别结果不会覆盖这些修改。没有识别出清晰语音时会提示重新录音。

## 本机安装

本地识别使用 faster-whisper small 的 CPU int8 模型，普通话优先，支持句中英文缩写。模型输出经 OpenCC 转成简体；不使用聊天模型改写口述内容。录音发送到正在运行 UNO 的电脑进行转写，保留在内存中，不上传外部识别服务，不保存到知识库或录音日志。

首次安装需要 Python 3.10–3.12 与网络。依赖放在 UNO 自己的 `.nexogenesis/speech/venv/`，不修改系统 Python。先复用本机对应版本的 Hugging Face 模型缓存；没有时，安装脚本下载约 484 MB 的固定模型版本。录音运行时强制离线，不会自动下载。

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\setup-speech.ps1 -Python "C:\Python312\python.exe"
```

也可以加 `-ModelPath "D:\models\faster-whisper-small"` 指定已经下载的模型目录。安装脚本会真实加载模型验证成功后，才更新配置。安装完刷新页面；首次加入语音功能后需重新启动 UNO 后台。纯净分发包包含代码和安装说明，不携带本机模型、配置或虚拟环境。

## 浏览器与限制

推荐在本机新版 Edge 或 Chrome 中通过 `http://127.0.0.1:3093` 使用。浏览器要求麦克风处于安全上下文；手机用局域网 HTTP 地址访问电脑时，通常无法录音，需要可信 HTTPS。移动尺寸的布局通过验证不等于手机真机麦克风已经验证。Safari 的实际设备表现仍需真机测试。

权限拒绝、没有设备、设备被占用或拔出、上传中断、识别繁忙、超时都有对应提示。后台一次只执行一段识别，不无限排队；取消会终止该段计算。模型懒加载并复用，空闲 5 分钟释放。加载、上传和识别分别有时间限制，不占用知识库切换/写入锁。

ASR 会受口音、噪声、麦克风和说话方式影响。测试样本上的准确率不能代表所有真实录音；识别文本必须可编辑。该版本不做自动翻译、实时字幕或语音播报，也不把一次转写成功当成消息已经送出。

## 2026-09-16 验证记录

本机 CPU int8 实测，一段公开真人中文样本和四段 Windows 中文合成音频，时长 5.6–12.7 秒；模型加载约 1.42 秒，每段转写 1.66–1.96 秒。百分之二点五到百分之一点八、否定词、GDP/ETF、自我纠正都保留；“下降到”被识别成“降到”。一段 3 秒静音和一段随机噪声返回空文本。合成语音只用于复现术语和机制，不代替真实用户口音测试。

公开样本：[SenseVoice 中文测试音频](https://huggingface.co/csukuangfj/sherpa-onnx-sense-voice-zh-en-ja-ko-yue-2024-07-17/blob/main/test_wavs/zh.wav)，参考句为“开放时间早上九点至下午五点”。其余样本原文包括利率下降的否定条件、需求与供给比较、中英缩写，以及长期/短期国债的自我纠正。

识别实现依据：[faster-whisper 官方说明](https://github.com/SYSTRAN/faster-whisper)。浏览器原生 SpeechRecognition 的兼容性和服务依赖见 [MDN](https://developer.mozilla.org/en-US/docs/Web/API/SpeechRecognition)；本实现没有使用该识别服务。

验收完成：后端 364 项检查（分发清单初次失败，改成精确文件白名单后专项通过）、前端 198 项测试、TypeScript 与生产构建通过。构建仍有原来的大包体积提示；未将其当成语音故障。

Browser plugin not available，使用本机 Edge / Playwright。隔离页面在 1280×900 和 390×844 验证页面身份、非空渲染、无框架遮罩、无未处理页面错误，以及录音、取消、草稿编辑、麦克风释放、跨会话迟到结果隔离、权限拒绝和无横向溢出。公开中文 WAV 经过浏览器假麦克风、AudioWorklet、48k→16k 重采样、真实本地识别、草稿追加，全链路暖状态约 1.87 秒。

另做一次完整 60 秒录音边界验证，实际上传 59.94 秒音频，到时自动转写且没有发送消息；全程约 62.87 秒。它验证时长上限与停止机制，不代表 60 秒连续复杂口述的识别质量。60 秒输入的重采样本机约 97–101 毫秒。

正式 `http://127.0.0.1:3093` 已加载 `local_speech_input:1`，语音状态 ready/loaded 均得到实际确认。在 1440×960 和 390×844 页面完成真实本地转写，冷状态全链路 2.86 秒，保留原有草稿，没有发送聊天消息或调用聊天模型。为此创建的一个空白验收会话已通过正常删除接口移出列表；未继续旧任务或改写知识卡片。

## 验收中另发现的旧会话问题

读取旧会话 `session-e036906b-c8da-4d11-b23d-bfd3524e2386` 返回 HTTP 500：原生日志加载器不认识未标为 ignorable 的 `nexo/quick-message` 事件。这一事件由当前普通对话实现写入，语音录音/识别不写该事件。这不只是历史数据问题：当前新发送的普通对话在后续冷启动时也可能触发。新建空白会话的录音与转写已通过，但这不能证明旧普通对话重启恢复正常。

后续已补上 UNO 自定义事件与原生读取器的兼容声明，旧日志保持原样，其他未知事件仍拒绝。原生 zstd 冷启动、恢复追加后再次冷读，以及报错记录副本读取均通过；详见 [当前实现与验证](UNO-当前实现与验证.md)。本地 3093 重启被自动审批策略阻止，仍需手动重启后台加载修复，不能把源码和隔离验证当成正式进程已经生效。
