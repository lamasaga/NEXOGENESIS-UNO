# UNO编译功能重构

> 历史方案说明（2026-09-16）：本文保留早期 `uno-compile-v2` 与两轮整理方案，相关数值和接口用于追溯，不作为新任务默认规范。现行入口为 `unit-cards-v3` / `uno-unit-compile-v3`；已保存 v2 任务仅按旧契约恢复。下文“新建编译沿用 `uno-compile-v3`、`review_policy=harness-first-v1`”只解释该时点。新契约见 [单元编译实施](UNO-单元编译实施.md)。

> 2026-09-13。用户已授权按本文件实施。本文替代旧编译的固定摘要批次、仅标题去重、逐批确认和严格关系门控；历史任务继续使用其保存的版本。本文件是目标与实施契约，验证结果另记于《UNO-当前实现与验证》。

## 目标

面向用户选择的不同领域，把材料中的知识、关键案例、作者立场、矛盾和论证条件整理成可独立阅读、可检索的卡片。模型决定阅读顺序、重点、卡片粒度、合并与改写；程序提供材料准备、持久化、检索、恢复和非阻塞校对。不在编译中增加模型自行发明的理论、解释或类比。

利用宿主已有的原生 Agent Loop，通过专用编译 preset 装配工具和上下文，不另写一套“调用模型—解析摘要”的循环。不将旧固定控制器重命名为 Agent。新协议为 `uno-compile-v2`。

## 用户入口

保留侧栏“编译”按钮：选择 Inbox 材料、填写可选主题、选择倾向并编辑提示词、设置本轮预算，然后开始。倾向包括自由整理、把握主题与论证、保留机制与方法、保留案例与分歧；倾向只往可见的提示词加入文字，不切换隐藏工作流、不规定卡数。

支持 `/编译 + 提示词` 与 `/compile + 提示词`。已有选材通过同一个 start 接口提交；未指定材料时进入选材面板并保留提示词，避免模型私自挑选或扩大材料范围。HTTP 聊天入口也解析命令，返回同样的选材请求或直接创建选定范围任务。不能落入旧 `/compile` 流程或普通意图回答。

## A．Python 预处理

Python 读取 UTF-8 文本、Markdown、HTML、DOCX 与 PDF（PDF 依赖 PyMuPDF）。清除零宽字符、控制噪声、明显页面标记和跨页重复页眉页脚；保守修复英文断词与分页断行。保留有意义引文、数字、脚注和文献引用，不按语义删除相近观点，不删除无法确定为垃圾的段落。

按 Markdown 标题、中文章节标记、PDF 一级目录组织章节；无可靠目录时使用段落或页码分段，明确报告回退。原件与清理记录保留，章节标出原始行号或 PDF 物理页范围；清理后的字符位置不冒充原件字符位置。PDF 图像、OCR、复杂表格不在本切片中自动理解，原件保留并报告待核验。

单文件读取上限 50 MiB，提取文本上限 500 万 Unicode 字符；这是资源上限，不代表上下文窗口。章节文件不按固定卡数或 6,000 字符切割；无目录长文本回退约 20,000 字符边界。模型阅读按字符分页，默认 12,000、单次最多 30,000 UTF-16 字符，并返回续读位置、是否截断与相邻章节入口。

## B．Buffer 与原文检索

`05-Buffer/themes/_sources/<内容哈希>/` 保存整理后的章节 Markdown、来源目录与清理说明。来源哈希区分原件版本，章节保留处理状态与实际去向。主题索引引用章节，避免重复复制正文。

稀疏索引采用 BM25：中文词语与双字片段、英文词及数字参与分词；原文按约 1,200 字符检索单元、160 字符重叠建立索引。返回命中片段、来源位置、章节引用和字符偏移，模型可展开邻近内容。索引位于 `.nexogenesis/`，可从 Markdown 重建；不承担语义事实源职责。

卡片索引覆盖标题、摘要、TAG、领域、正文与关系说明。类型和关系检索、正反向邻居查询都提供工具。思考的集中资料收集中接入 Buffer 搜索，使卡片没有收录的细节也能召回；稀疏检索不承诺自动找到词面完全不同的类比。

## C．第一轮理解与制卡

原生 Agent 阅读总目录和局部原文，自主选择补读、搜索旧卡、查看规则示范、创建或编辑卡片。全部卡片可修改；修改、合并、拆分前保存原文版本，可通过工具恢复。合并保留旧 ID 的退役去向，入链保持可追踪，不物理删除卡片。

新卡保存稳定 ID、准确标题、摘要、多个内容 TAG、主题 TAG、领域归属、来源与自然 Markdown 正文。正文允许灵活组织，不设置“每批两单元六卡”“每张必须几条关系”等语义配额。关键历史案例可独立沉淀，也可作为完整知识对象内部的论据。

类型：概念、观点、机制、模型、方法、现象、案例、实体。关系：细分、补充、对照、质疑、类比、例证、应用。领域保留独立 Markdown 索引与层级，不是卡片类型。详细定义及正反例见 [知识使用说明](design/knowledge-guidance/README.md)，运行时读取同一套文件，不复制另一份词表说明。

模型明确记录每章的处理结果：保存到哪些卡、哪些内容不单独制卡及原因、尚待处理什么。读取不等于完成，不要求每段生成卡片。允许模型为核心章节分配更多预算。

## D．校对与第二轮整理

卡片先保存，程序生成质量事项：摘要缺失、TAG 缺失、来源问题、失效关系和关系说明缺失。不因标题相近或正文栏目不足驳回整批。标题是否重复、命名是否准确由模型第二轮检查，不把程序检查描述为自动语义纠错。

模型在章节间可读取校对清单并修订；严重疑点标为待核实，检索结果携带提示。全部材料已有明确去向后进入第二轮，集中核对命名、分类、正文结构、合并拆分、领域索引与关系。第二轮可按主题分组，不把全库塞进一个窗口。

最终结束要求：指定材料都有处理结果、受影响卡片有针对当前版本的第二轮检查记录、未解决问题明确呈现。只完成第一轮不能显示“编译完成”。未解决来源或提取问题保留为部分完成，不能伪装已核验；原件仅在满足本轮完成边界后归档。

## E．上下文与工具

任务目标、用户提示、当前阶段、已完成/待处理计数、预算、工作摘要和校对摘要作为每次原生请求更新的上下文快照。常驻规则与工具用途精简稳定；详细示范、章节正文和旧卡通过工具按需读取。工作摘要只记录决定与待办，不保存隐藏推理过程。

采用原生历史压缩和工具结果裁剪，但任务快照每次重新生成，不能随历史裁剪消失。工具返回定位、摘要和续读入口；检索默认 8 条、最多 30 条，目录分页默认 30 项。模型可以更改读取范围、章节投入和下一步工具，不增加固定模型复述阶段。

本轮默认 120 次主循环模型请求，用户可设 10–2,000 次；不按章节固定分配。用户可在暂停后增加本轮上限，用量累计、不因恢复清零。时间默认 30 分钟一个执行时段，到时保存并暂停；允许继续，不宣称整书必须半小时完成。用量按主循环事件记录，缺失统计标为未知；供应商重试和原生历史压缩可能额外调用，不将此上限宣称为 API 账单硬上限。编译标题直接使用任务名，省去自动标题生成调用。

## F．程序职责与恢复

Harness 保留路径、版本冲突、原子提交、幂等收据和历史备份这些文件正确性保护；语义质量由写后校对和模型修订处理。写入冲突返回定位与修订建议，已成功成果不重放。

任务状态独立于浏览器；关闭面板不取消后台。暂停等待原生执行退出，不能提前释放写锁。进程重启后任务转为可恢复状态，模型先看任务快照、既有卡片版本与收据。新编译不改写历史任务协议，不操作 DSH 或其他知识库。

## 实施与验收

1. 加入 Python 预处理、章节 Markdown、稀疏索引和版本化编辑工具。
2. 接入原生编译 preset、动态任务上下文、预算与阶段记录，替换新任务默认入口。
3. 统一按钮、快捷提示词和斜杠命令，显示阶段、进度、校对及累计用量。
4. 接入思考检索、类型与关系显示，保留旧关系原意。
5. 用隔离合成材料验证预处理保全、章节、检索数字与细节、卡片修订恢复、关系方向、第二轮与恢复、两个入口、预算暂停；运行后端/前端测试、构建和桌面/窄屏浏览器交互。

真实模型语义质量单独验证，不用模拟模型或文件存在证明理解效果。具体通过项与限制更新到当前状态文档。撤回时停用新 preset 和入口，保留章节、卡片版本与旧协议；不删除已沉淀知识。
