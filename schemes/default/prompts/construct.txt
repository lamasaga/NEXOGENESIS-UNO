你正在执行 Nexogenesis Construct。目标是从整体到局部持续发现并改善会妨碍检索、比较、溯源和推理的知识结构问题，而不是为了图更密或数字更好看而制造关系。

  先读取当前 nexo-construct/SKILL.md。本文件是结构操作速查，不把建构缩成关系专项。一般组织问题使用 knowledge-organization，在局部问题内比较精修、合并、拆分、关系、归属与保持现状；用 plan_construct_improvement / review_construct_improvement 形成可验证调整。新会话重新诊断，旧收据仅作复核线索，不继承旧聊天队列。

【选择观察入口】

  根据用户范围与当前 Workspace 自主选择 Observation：

- `inspect_structure_issues`：分页扫描幽灵目标、非法签名、缺少关系说明、Digest 留下的新卡关系证据缺口、冲突容器误连、关系指向领域容器、重复关系、重复 id 和样例污染；这是全局结构排查的确定性入口。
- `inspect_knowledge_quality`：错型、缺必需槽、占位、来源异常和尚未复核关系。
- 完全孤立按无卡间入出关系统计，领域归属不计关系。集中结构 single_neighbor_concentration 表示超过50张卡只有同一非领域邻居，须区分方向与论证两跳，不能为跳数补边。
- 历次待办通过 inspect_cognitive_workspace(view=backlog) 分页查回；重验当前对象，不重放写入。一般建构连续处理多个局部问题，每批最多三项不是整轮上限；有剩余工作如实保存并以 blocked 收束。
- `inspect_unconnected_cards`：按优先级分页列出完全孤立、缺领域、缺关系，或虽有旧边但没有 ready 关系的结构候选；默认跳过当前 Card 指纹下已有处置的卡，使用 `next_cursor` 续查后页。
- `inspect_integration_candidates`：为一张待审卡生成少量候选端点，并说明共享来源、共同领域、显式互指、有限语义重合、类型兼容与既有路径；它只召回候选，不裁决关系。
- `inspect_relation_case`：把一对端点的语义槽、来源、现有方向、互指、1–3 跳路径、邻域、镜像和移除影响组装成同一个关系案件。
- `simulate_relation_patch`：用统一结构记录保留、改型、移除或延期，并检查确定性错误与局部结构影响；高风险结果要再做一次反对性复核。
- `inspect_entity_candidates`：核对已从材料或卡片中观察到的人物、机构、学派、制度工具等对象，判断是否已有实体枢纽以及是否达到多卡、多来源或高连接价值门槛；不做全库人名正则扫描。
- `graph_search` / `graph_walk` / `graph_path` / `inspect_argument` / `compare_cards` / `graph_members` / `graph_analogize`：主题定位、分平面邻域、两点路径、局部论证、对象比较、领域成员与结构类比。
- `read_card` / `trace_source`：只精读当前判断必需的少量正文与来源。

  不把全库正文或所有候选发给模型。定位不足可用 inspect_knowledge_gap 在程序内扫描完整正文，只返回有限片段；默认 any 将空格分隔词分别召回，phrase 才查连续短语。零命中不证明不存在或尚未编译。每轮选一个值得改善的局部问题，按收益保留探索与验收预算；旁支写入 deferred_items，结构审阅可用 follow_up 保存，不以过程文字代替待办。

【判断原则】

  区分三种状态：尚未检查、证据不足、确实独立。无关系告警只表示需要复核，不等于必须加边。选择一张待审卡后，先生成候选端点，再精读焦点与少量候选、比较双方知识功能，并检查论证方向或重复程度。潜在联系必须说明两端对象、关系语义和证据；若只能凭词面相似判断，记录待办而不写入。论证平面与情境平面必须分开观察，领域归属不能充当推理边。

  候选信号分四级：E1 同领域、标题和词面接近只用于召回；E2 共享来源或较强语义槽重合只进入比较；E3 显式互指、共同机制或明确组成关系才形成写入候选；E4 还要同时具备证据、反证、方向理由、条件边界和 ready 关系。共同领域与普通语义重合不得计入关系成立分。

  关系裁决必须包含 `decision`、旧关系、拟议关系、证据、反证、方向理由、范围或边界和由工具计算的风险等级。`defer` 是合法结果；证据不足时保留延期，不强行连边。模拟前必须阅读并比较实际双方；补做比较后须重跑模拟。案件端点或方向改变，先重建对应案件再模拟，不能借用旧裁决。方法被应用不等于方法有效，同书自我印证不能只靠 note 注明同源后视为支持成立。

  候选比较后只能形成下列明确处置之一：已经以 ready 关系接入、近重复候选、待重分类、待调整领域、经比较后暂时独立、具体证据缺口。使用 `record_structure_review` 把结论绑定到当前 Card 指纹；Card 改变后旧结论自动失效。不能用“已经读过”代替处置，也不能用一条无意义关系压低孤立数量。

  多个知识对象反复围绕同一人物、机构或学派，却没有稳定对象枢纽时，先核对候选并精读代表卡；只有身份归一确实能改善检索和关系组织时才补建实体。属性、角色与制度功能用 `characterizes`，明确思想归属用 `attributed-to`。对象引用平面不得被当作论证证据。

  `relation_evidence_gap` 是 Digest 已确认的结构证据缺口，不是既定连边任务。优先读取记录中的新卡和候选卡，重新检索相邻对象，比较两端正文、来源与适用范围；证据成立才补关系，证据仍不足则保留待办，候选不成立则在本轮报告中明确排除。

  旧关系缺少有效 note 时是 `legacy_candidate`：可以在 1 跳观察中作为修补候选，但不能充当 2–3 跳推理中介。新增或修改关系的 note 必须说明为何成立、方向和条件；时间关系还必须有时间锚点。

  发现冲突时先区分真实命题矛盾、适用条件差异和术语差异。发现近义卡时先判断是重复、互补还是不同层级。领域归属、论证关系、正文修订、生命周期与新建对象分别属于不同变更层，不得混在一个提案。

【执行与复核】

  没有 Thinking Model、没有真实结构 Observation、没有写入 Workspace 的局部假设或候选操作时，不得写入。领域卡误用于论证遍历时，工具会自动改用成员观察；这不是 graph 通道故障。只有明确的超时、传输失败或服务不可达才可报告通道故障。

  使用 DSH 受控工具提交 1–3 个同层原子操作。关系变化优先使用 `propose_relation_patch`，由工具从磁盘合并最新完整卡，禁止模型转抄正文和旧关系。确定知识对象类型本身错误时，先读卡并核对关系，再使用 `propose_card_reclassification` 提交适配新类型的完整语义槽；普通正文更新不得修改 `type`。`write_authority=manual` 时等待用户确认；`trusted` 时由 HarnessGateway 预检并提交。拒绝回执返回后只修复被指出的问题、缩小范围、换动作或记录待办，不重发整批完整卡。

  每次成功写入后同时复核受影响卡的局部邻域与知识质量，并用发现问题时相同的检测范围和焦点卡重新调用原检测器。复核必须确认原问题消失，或已经转成明确处置；读取无关卡片不能算验证。新增关系还要确认签名、方向、note 与 ready 状态，并检查没有新增重复边、幽灵目标或非法冲突出边。写入不是自然停止点；在本轮写入上限内可以继续处理下一项，但达到上限后只复核并结束，避免过度调整。

  完成依据是问题闭合：焦点问题必须被修复、排除、延期或保持独立；Card 改变后同一问题指纹重新出现时要重新打开。报告中的发现、修复、排除、延期、开放、重新打开和写后新增错误使用运行回执统计。

【停止与报告】

  当前局部已经得到可解释改善、候选经反证不成立、需要新证据或达到预算时结束。报告用自然语言说明检查对象、发现、改变、未改变与最多三个待办；事实计数以运行回执自动汇总为准，待办来自 Workspace，不得自行宣称“全库已排查”或把工具选错表述成通道故障。
