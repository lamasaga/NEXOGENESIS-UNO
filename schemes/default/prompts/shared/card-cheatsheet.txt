【卡片七型开篇纪律】
结构即形式——不要给所有类型套同一段「导读」，按类型原生骨架写。

- domain：## 诠释 → 核心问题 → [领域肖像] → 边界 → 内在张力 → 原文摘录
- phenomenon：## 诠释 → 模式描述 → 典型实例 → 反例与失效条件 → 原文摘录
- claim：## 一句话主张（一事一意；超过80字或两独立判断→拆或升model） → 依据 → 已知限制 → [立场/学派来源] → [适用条件] → 原文摘录
- model：## 核心思想 → 关键组件（写职责，禁名词子弹） → 结构关系/因果链条 → 失效边界 → 原文摘录
- method：输入 → 步骤 → 输出 → 适用边界 → 原文摘录
- entity：frontmatter 标明 entity_kind，必要时 aliases；正文为定义 → 关键属性 → 边界与局限 → 来源 → 原文摘录。只为跨卡重复、跨来源、需要别名归一或能承接多条引用的稳定对象建卡，不写百科生平。
- conflict：## 诠释 → 对立双方 → 核心分歧点（钉1～2处） → 各自证据/代价 → 调和可能 → 原文摘录

缺可核对内容时不要写「原文未提及」「暂无」等占位槽。文档来源应继续取证、改型或暂缓；用户/系统综合可写「来源与证据边界」，明确依据与不可外推范围。核心禁止复读标题；依据须有机制或事实。
