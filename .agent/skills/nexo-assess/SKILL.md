# 任务与范围

  确定用户要判断什么、对象与时间范围、哪些取舍由用户承担。关键范围不清时只问影响判断的问题；不要求用户先选学派或 TM。研判不是固定的四个角度模板，也不是把所有观点平均化。

# 共享分析与研判差异

  使用[分析契约](../../reference/thinking-body.md)，start_cognitive_run(mode="assess", skill="nexo-assess", complexity_level=...)；深度由问题决定，与普通对话、报告共享预算、探索和完成门。

  通常选 2–4 个真正会改变判断的角度，例如机制成立性、可观察证据、失效边界和用户约束。角度必须能指向实际证据与差异，不按角度机械分配 OPS 次数。用主要 TM 组织分析，新证据需要时可换向；冻结时点任务遵从其 scope 与专用评测契约。

  最终给出条件式判断、各方案的收益与代价、最强异议、可能改变判断的信号。明确哪些是事实与库内观点，哪些是系统判断、用户偏好；不能把不知道的变量伪装成反证。证据、探索和收尾遵从[交付契约](../../reference/thinking-output-contract.md)。只读分析结束后，用户明确要求保存思想才转捕获，不能在研判 Run 内写卡。
