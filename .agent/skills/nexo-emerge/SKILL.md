# 先保存用户的意思

  用户明确要求保存时，直接进入候选准备，不再重复问“要不要记”。“这个可能有意思”不等于授权；可自然澄清其希望继续讨论还是记录。若用户指代不清，只问需要保存哪项判断，不要求其重写完整卡片。

  读取当前讨论中的明确主张、用户修正、来源线索和未决条件。先结束仍在进行的只读分析 Run；分析的精读可以作定位线索，但捕获须核对当前目标卡版本。不得靠修改分析预算获得写入权限。

# 判断保存什么

  用 retrieve 或必要的高级筛选定位最相近对象，精读后判断 enrich/create/skip/deferred；需要时 compare_cards 比较真实增量。共享主题不等于同一对象，知识库已有框架不因本轮重述而成为新发现。

  系统综合的新命题，至少核对最相近卡与关键依据的当前正文或完整相关单元，可批量读取；不能只凭候选摘要或没有同名卡认定新颖。按新命题做一次有针对性的差异或挑战检查，复用比较、来源或检索工具，不强制完整研究。先区分变量/指标、时期/样本、分析层级和因果方向；口径不同不自动构成矛盾或新机制。反例须针对命题的限定与量词，例如一次同向变化不能反驳“未必同向”。仍无法区分时缩小主张或暂缓。

  依据对象身份、真实增量、独立复用价值和承载负担选择修订或新建，不预设两者优先级；既不重复造卡，也不把独立对象塞入旧卡。最多展示三个紧密相关候选，不把一句零散话拆成多张卡。材料不足以形成有用对象时保留对话并说明待补信息，不强行落卡。候选必须保留用户贡献与系统解释的区别，不把系统综合标为用户立场。

  只读取目标类型的[正文契约](../../reference/card-contracts/body-structure.md)、[类型与关系契约](../../reference/card-contracts/ontology.md)及必要正例；写入前遵守[事务契约](../../reference/write-transaction.md)。不默认加载所有正例、所有共享 prompt 或无关 Profile。

# 提案与确认

  list_domains 取得合法领域；根据实际来源标 origin，system 候选不得自行成为 mature 或 active 理论。候选用白话说明“保存哪项观点、丰富哪张卡、新增什么、哪些仍待验证”，随后 propose_write 生成真实确认卡。新建提交完整记录，丰富使用单层语义补丁，不转抄未改长正文。

  sources 填写真实可回查的对话标识、卡片地址或材料出处，并在正文区分原有证据与本轮推断；来源标题不能替代字段，出处存在也不等于命题已验证。系统综合新卡 sources 为空会被拒绝。关系有真实语义依据才提议，不为消除无关系告警凑边；确认卡已呈现完整正文时，不再重复长篇卡文。

  提案后等待界面确认，确认卡是实际写入授权入口；不能先声称已保存，也不在用户确认后重复提交同一提案。取消后不自动重提。关系、领域与生命周期变化不能夹带在内容精修中；用户明确要求时另用对应提案工具。

  回执成功后简短说明保存位置和实际变化。没有 Profile 提案能力时不声称更新 Profile。若仅有结构缺口可 graph_note 记债，不能自动扩张成建构任务；需要精修指定卡片时转 nexo-refine。

  用户只问“还缺什么”时，直接给出影响命题成立的具体缺口及可查位置；无需为继续说明而强制弹出选择，也不把讨论当成重提授权。
