# 编译

Web、/compile 与 /编译共用材料选择器，新任务创建 `unit-cards-v3 / uno-unit-compile-v3`。历史 v2 任务按保存的旧契约恢复，不能改签为 v3。

Python 按图书章节或文章整体提取 Markdown，每单元不超过 6 万字符。宿主一次给模型完整单元、写作方法、正反例和必要参考，生成知识卡；其余上下文合计不超过 6 万字符。

原始文件保存在 `03-Archive/books/<原件哈希>/`；拆分单元、目录和提取图片保存在 `05-Buffer/books/<原件哈希>/<提取哈希>/`。单元持续保留供卡片溯源，不作为临时缓存删除，不自动加入普通对话全量检索。已有 Archive 单元继续按保存的路径使用，不自动移动；存储位置变化不能作为重新制卡的理由。

每张新卡只有一个主类型 `type`，并可归入零到三个既有领域 `domains`；没有合适领域时留空，编译不能发明领域。`type` 必须按 `conflict → entity → case → concept → method → mechanism → model → claim → phenomenon → undetermined` 顺序逐项检查，只有满足全部最低条件才能命中，取第一个合格类型。`phenomenon` 必须有观察对象与依据，不作无条件兜底；其余九类均不成立但知识单元仍完整可复用时才用 `undetermined`。新卡不写 `tags/topics`。生成和审核提示词都必须包含类型、领域、正文骨架的解释与正反例。

空领域卡写入可重建的未组织池。每 10 个有效单元、20 张新未组织卡或有足够材料的书末边界触发一次批量领域检查；最多处理 20 张，完整正文最多 5 张。既有领域可直接挂靠；新领域形成结构化提案，默认逐项确认。用户在开始任务前明确选择 `domain_approval_mode: automatic` 时，本任务可自动批准通过成员、边界、版本和事务校验的提案。两种方式都通过 Gateway 原子创建领域并挂靠成员。领域治理不进入单卡返工，不重发原书。

生成后程序预检规格、类型、领域、关系和版本，模型检查内容与关系语义；先保存通过卡，只修问题卡，每类最多两次自动返修。卡片问题只提交本卡与具体问题；关系问题只提交本卡、问题中明确且已完整核对的另一端卡片与具体关系问题，并且只能修改本卡 `relations`。关系端点变化后按当前版本重新判断，不能沿用过期问题。两类返工都不带原文、无关卡片或历史。成果经 HarnessGateway 原子保存，原文逐单元继续。没有分页补读工具、历史叠加或子代理。

检查或复核响应格式失败时，宿主先做确定性归一化；仍有歧义时只允许一次局部响应恢复，输入仅含失败返回、错误、预期 ID 和 Schema，不重发原文或卡片。恢复结果必须重过原校验；同一响应失败后熔断，不能循环调用、跳过单元或直接写卡。

未完成或失败不计为完成。原书在整本成功前保留在 Inbox。旧任务只读，不隐式改签或重放。方法见 ../../../../docs/design/book-compile-method.md。
