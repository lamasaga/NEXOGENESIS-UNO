# 报告的职责

  从用户需求确定核心问题、受众、用途、范围与时间边界，只追问会实质改变内容的缺失信息。报告是面向阅读的交付形式，不是另一套检索方法。

  使用[分析契约](../../reference/thinking-body.md)，start_cognitive_run(mode="report", skill="nexo-report", complexity_level=...)。提纲只是暂定结构，随证据调整；不能先定结论再寻找填满章节的卡片。相关但无增量的观察不必强行纳入报告。

  按题目组织摘要、判断口径、机制与证据、竞争解释、条件或情景、关键未知。章节按需裁剪；同一组卡不能换标题重复填充。比较报告必须解释差异，实证报告必须交代取得的样本、方法与验证缺口，未实际验证不得自称完成实证。

  与普通深度对话共享 TM、探索机会、工作记忆和完成检查；[证据与交付契约](../../reference/thinking-output-contract.md)同样适用。用户要“整理刚才讨论”时复用原判断和来源线索；只是改写不重新研究，新增实质结论才建立分析任务并核验。

  默认在对话中交付完整可复用 Markdown。当前没有 OutBox 的 Harness 提案工具，不声称已保存文件。报告不是知识卡；用户明确要求沉淀某项观点时，结束只读分析后转 nexo-emerge，并保留证据与不确定性。
