# 规则放在哪里

> UNO 重建说明：本目录描述现行可执行契约。新知识卡统一使用单一主类型 `type` 与多个既有领域 `domains`；旧多标签字段只读兼容。新默认编译与建构采用独立的 UNO Gateway 方法，批次、来源、分类、检索联系和恢复规则见 [编译与建构](../../docs/UNO-编译与建构.md)。旧聚合、消化和严格建构规则只约束对应历史入口；所有路径仍须通过实际 Gateway 校验。

  项目只保留三类当前规则，避免同一件事在多份文档中重复定义。

| 位置 | 负责什么 |
|---|---|
| `AGENTS.md` | 项目底线、写入权限和文档事实边界 |
| `.agent/skills/*/SKILL.md` | 一类任务的目标、可用工具、完成和停止条件 |
| `.agent/reference/` | 卡片格式、检索、材料处理和写入检查的具体规则 |

  `schemes/default/` 保存历史范例、提示和可选分析指导。新编译的任务契约见 `docs/UNO编译功能重构.md`；`docs/design/knowledge-guidance/` 是唯一一套模型可读的类型与关系约定，运行时直接读取。其他 `docs/` 面向开发者，不自动进入模型上下文。

## 维护原则

- 同一规则只在最接近执行的位置写全，其他文档只链接。
- 旧 Agent Skill 不写死模型的工具调用顺序；UNO 确定性资料路线遵循新基线，不受旧逐步决策假设限制。
- 工具字段以运行时 JSON Schema 和确定性校验为准。
- 历史设计位于 `docs/history/`，不参与当前指令。
- 新概念必须先对应一个已经出现的实际问题，再决定是否进入代码或规则。
