# 当前检索规则

  本文只描述 DSH 当前的 JavaScript 检索，不再保留旧 Python 图模块和向量 RAG 规划。

## 当前实现

  `retrieve` 是普通问答、研判和报告的统一首轮入口。复杂问题由当前对话模型先压缩成一个临时、可见的 `intent`：核心对象、机制、情境、需要比较的分歧与排除项各最多三个短语；这不是额外模型、知识写入或范围裁决，原始问题仍会保留。工具以核心对象和机制作为主召回，以情境和分歧轻量重排，排除项只降权歧义命中；原问题中未被纳入主焦点的强命中还可进入最多四张的低权补召回池，`raw_tail_candidate_total` 会明确显示它是否实际生效。

  首轮先对标题、别名、有限正文语义和元数据进行较宽召回，并沿 ready 的 argument/context 关系扩展最多两跳。随后才从直接命中的非领域卡抽取严格的中文内容锚点，寻找**没有现成 ready 图路径**、但值得精读比较的候选关联。锚点忽略英文模板、Markdown 结构、通用章节标题与高频空词；候选至少需要三个彼此独立、低文档频率的共同锚点，同一概念的嵌套短语不能重复计数。三路候选进入同一阅读计划，但直接召回与 ready 图候选总是先占满预算；候选关联只可占剩余预算中的一个探索位，且小于六张的预算不返回候选关联。

  候选关联场是可重建的索引，不是第二份知识事实：它不新增关系、不继续传播、不触发写入，也不会进入 `structural_frontier` 或触发 `graph_walk` 建议。带 `candidate_status: unverified_association` 的对象只表示“可能值得一起阅读”；返回的 `discovery_frontier` 必须先以 `compare_cards` 对照发现种子和候选，再用 `inspect_argument`、`graph_path` 或来源复核判断，才能进入分析或关系案件。候选关联本身不能作为证据、关系路径或写入理由。

  范围窄、只需要本地依据的 `grounded_quick` 问题在一次 `retrieve` 后使用一次 `read_cards`，最多精读三张并共享正文预算；这条快速路径不建立 CognitiveRun，也不把图候选当成已核验关系。问题出现明显冲突、多阶段结构或三张卡不足以支撑回答时，才升级到分析路径并复用已有候选。

  `graph_search` 与 `retrieve` 共享同一个联合召回、候选关联与上下文计划引擎，只保留类型、成熟度、来源主体、理论状态、学派和适用范围等高级筛选参数，不再形成第二条较弱首轮路径。`graph_walk`、`graph_path`、`inspect_argument`、`compare_cards`、`graph_members` 和 `graph_analogize` 用于进一步核验关系、论证、路径、领域成员或跨领域相似结构。`graph_walk` 通过 `plane=argument|context|reference` 分开论证、情境与对象引用关系，可以受控地走 1～3 跳，并逐层返回真实节点、关系说明、就绪度、来源前沿和完整路径。正式图候选路径必须经过它核验；候选关联则先比较和精读，不能伪装成一条待核验的图边。

  `inspect_structure_issues` 是建构的确定性全局入口。它只扫描元数据，去重后为每项生成稳定问题指纹，并按 P0 确定性错误、P1 关系语义债、P2 接入与类型候选、P3 结构探索排序。模型随后只精读当前页中的少量局部候选。它解决的是结构枚举与续接，不替代正文语义判断。

  `inspect_integration_candidates` 把召回与写入证据分开：E1 同领域、标题与词面接近只负责召回；候选关联场的稀有锚点、语义槽或结构相似信号最多进入 E2 比较；共享来源或较强语义槽重合也只进入比较；E3 显式互指才可进入关系案件。`inspect_relation_case` 再集中提供端点语义、来源、当前方向、路径与局部影响；`simulate_relation_patch` 要求证据、反证、方向和边界，并将达到写入预检的状态标为 E4。

## `graph_walk` 的跳数语义

  新版 conversation-v2 分析的主动性由问题中的隐藏依赖、机制接合、竞争解释或边界传播机会触发，不需要用户先说“走图”。工具返回的是实际候选路径；沿途关键正文/单元要读，关系类型、方向与条件要解释。低收益分支可停止，不以两跳、特殊工具或新增节点配额验收答案。实际路径对判断的影响可在 finish 的可选 relation_findings 中记录；宿主验证路径与阅读出处，不证明语义推断。旧策略与受控测试仍遵从自身规范。

- 1 跳：核对起点的直接支持、依据、扩展、实例、组成与冲突关系。日常回答默认从这里开始。
- 2 跳：寻找中介机制、共同依据、局部反证或同一论证链上的第二层结构。只有一跳不足以回答时使用。
- 3 跳：寻找跨簇桥梁、孤立结构的潜在接点或较长的候选解释链。它用于探索，不直接等于证据成立。
- 每层只从上一层实际返回的节点继续，跨层去重；总返回上限分别默认为 12、18、24，并在各层间分配预算，防止高连接节点吞掉全部深层结果。
- `direction` 与 `relation_types` 在每一层都生效。一跳可呈现待核验旧边，二跳和三跳只沿 ready 关系继续。三跳结果中的关键节点仍须 `read_card` 精读，路径上的关系说明也须进入最终判断。

## 使用顺序

- 普通知识问题先用 `retrieve`。复杂问题在同一轮内先形成精炼 `intent` 再传入；不另开一次模型调用，也不把“对象、机制、情境、分歧、排除项”写成泛词清单。读取上下文计划中的角色覆盖、缺口、阅读槽、图前沿、`retrieval_intent` 和候选关联状态；不要再随机选择 `graph_search`。
- 需要高级元数据筛选时才用 `graph_search`；它和 `retrieve` 使用同一个底层引擎。
- 按计划精读少量入选卡；窄问题可用一次 `read_cards`，复杂分析可组合 `read_card`、`read_cards` 与卡内单元读取。图扩展卡即使排名靠前，也必须用 `graph_walk` 核验实际路径；候选关联卡则必须与其发现种子作语义比较，不能直接进入结论。
- 对数字、历史经验、政策效果或多来源卡片，按 `source_trace_required` 下钻来源。
- 需要关系或领域结构时再使用相应图工具。
- 需要系统性结构排查时用 `inspect_structure_issues`，并通过游标跨轮续查；不要用一次关键词检索声称完成了全库枚举。
- 工具没有结果时应说明检索不足，不能捏造卡片或把模型常识伪装成库内内容。

## 归因

  卡片内容是知识库中的长期内容；Buffer、Inbox、对话和工具推断不是同一事实层。回答中使用已读取卡片时标明卡片 id。模型自行补充的常识必须与库内来源区分。

## 当前限制

  graph_analogize 的 mechanism_query 是受限候选发现：用已读焦点的具体机制线索检索正文，允许同领域或跨 model/claim/method 类型；匹配词片与 ready 关系签名不证明角色对应或因果同构，仍须补读、比较和明确断裂点。省略查询保留原有同型跨领域模式。不要把这个改进描述成完整语义召回或向量检索。

- 没有向量检索和独立 RAG 索引；候选关联场目前以严格中文内容锚点和有限关系结构的可解释信号工作，尚不能可靠覆盖字面完全不同的同义表达。
- `retrieve` 的两跳扩展与重排只是候选编排；结构化论证仍须 `graph_walk` 核验。三跳遍历仍是受控的候选路径发现，不是自动证明。
- 中文检索依赖词片和 n-gram。`intent` 能减少长问题中各词互相干扰，却不能理解完全无词面锚点的隐喻、同义表达或隐含前提。
- 搜索质量尚无稳定黄金测试集。

  只有真实查询反复证明当前检索不足时，才增加新的检索机制。新增机制必须带可比较的测试案例，不能只凭架构设想引入。
