# 思维体输出与沉淀契约

## 一、适用范围

  本契约供 talk、assess、report、emerge 和 refine 共用。它约束证据、结果状态与沉淀边界，不规定固定的工具调用顺序。

## 二、证据等级

| 等级 | 含义 | 能否直接支撑结论 |
|---|---|---|
| 已精读证据 | `read_card` 返回的正文或语义槽，必要时已 `trace_source` | 可以，但必须保留适用范围和归因 |
| 结构证据 | 真实关系、领域成员、冲突或比较 Observation | 可以支撑“结构上存在什么”，不替代卡片正文 |
| 检索候选 | retrieve / graph_search 的命中 | 不可直接作为重要结论，需精读升级 |
| 系统推断 | 模型基于多项已读证据的组合 | 可以作为分析，必须标明是综合判断而非原文事实 |
| 待验证猜想 | 尚缺直接证据的可检验方向 | 不可写成已知结论，可进入未知或候选沉淀 |

  `status: rejected | error | cancelled` 的 Observation 不得计为已完成的证据能力。`partial` 只在它确实返回了可用观察且不含 misuse / error 标记时才可使用，并必须保留其不完整性。

  工具被拒绝意味着未执行，不意味着没有资料；`applicable: false` 意味着未适用，不意味着审计通过。`inspect_knowledge_gap` 是通用只读全文定位，未命中仅说明给定短语未定位；可换别名或查询邻近概念，不能宣称全库不存在。必须先精读候选，再解释它能否回答问题。

## 三、面向用户的结果结构

  简单回答不需要为格式而格式化。复杂分析、研判和报告至少让用户找到下列内容：

1. **结论**：直接回答用户的问题，不以检索过程开场。
2. **依据与机制**：说明哪些事实或观点支撑了什么推断，而不是只列卡片名。
3. **反证与边界**：什么条件会让结论变弱、失效或需要改写。
4. **未知与下一步**：只列出会影响当前判断的缺口，不用泛化的“还需更多研究”填充。
5. **当前状态**：已完成、等待确认、需要补充信息或受阻。

  已读取的卡片使用 `[[card:真实卡片 id|卡片标题]]` 紧跟其支撑的判断；界面只显示标题并可直接打开卡片阅读器。引用只允许指向本轮已精读的真实卡片，不得把候选、图节点或未读卡伪装为证据，也不得伪造不存在的链接。报告仍使用界面可识别的真实路径。

## 四、沉淀决策

  深度分析通过 `hypotheses` 保存少量显式判断：id、statement、status、scope、uncertainty、anchors。status 区分 supported、inference、unresolved、rejected；supported 仅表示本轮材料支持，不能冒充独立验证。scope 保留时期、地域、样本与方法边界。最终三条总结的确定性不得高于正文；历史预测未经事后检验，不能同时写“尚未核验”与“已经正确”。用户要求实证时，没有取得实际验证就明确报告缺口。

  `read_cards` 不再按标题删减章节；预算截断或 slots 读取均记录真实 coverage。完整卡片地址需要全文覆盖，局部证据用已完整返回的 unit 地址；仅有工具名或候选摘要不能通过锚点检查。来源归并只提示原始出处或疑似同源，不能仅凭条目数声称来源独立。

  特殊 OPS 与类比的价值以认知结果判断：是否推翻判断、缩窄适用范围、提出竞争解释或没有有效改变。有候选必须补读；声称改变还需探索后真实的挑战观察。类比必须说明对应结构和断裂点，空结果与暂时无结论均合法。工作记忆只保留这些公开结果和知识锚点，不保存隐藏思维链。

| 情况 | 动作 |
|---|---|
| 与既有对象身份一致且修订后职责仍清晰 | 比较后可 enrich，补机制、证据、反例或边界；不因文字可以容纳就认定落点，不设新建与修订的默认优先级 |
| 形成可独立命名、可被后续推理引用的新命题 | create，并检查近义、领域与关系目标 |
| 只是重述、低信息密度、无法归因或已被完整覆盖 | skip，说明理由 |
| 有价值但缺少决定性证据或用户立场 | deferred，说明需要什么才能继续 |

  emerge 和 refine 的写入始终经用户确认。确认卡存在时，文字说明只摘要修改与影响；确认卡不存在时，不得说“请点击确认”。

## 五、可审计轨迹与隐藏思维链

  界面可展示 Thinking Model 用途、OPS 名称、Observation 摘要、Workspace 变化、证据锚点、Harness 回执和停止原因。不展示或声称展示模型的隐藏思维链。

## 六、复杂问答完成门

  新版试用由宿主返回 conversation-v2 标记时，使用[分析契约的新版章节](thinking-body.md)：执行 closed、真实消息 delivered 和请求覆盖分别记录；证据缺口可随局部答案交付，方法配额不作门槛。未读或失效引用不被核验，未做的实证不能写成已完成。下述完成门只用于旧策略与固定执行测试，不能跨策略套用。

  analytical 对话、研判和报告共用[分析契约](thinking-body.md)。回答前必须选择适用 TM、完成其真实观察义务、检查支持与挑战/边界，并核验最终证据。只有实际需要结构推理时才要求图路径；图不足应明确记录缺口，不制造连接。

  信息是否足够由完成门根据上述状态判断，不由固定检索轮数决定。新增知识观察后必须重新检查；预算或证据不足时以受阻状态保留具体缺口，不能把未闭合运行标记为完成。一个复杂问答 Run 只服务当前用户问题，回答边界仍未结束的 Run 会被隔离，下一问题必须建立新状态。

  预算档位、精读覆盖和挑战未果的记录格式统一见分析契约，不在各 Skill 重复。普通 deep 的严谨不等于必须找到反例：必须挑战并保留局限，未定位反例不能改分类凑通过。固定执行测试仍保留其专用义务。
