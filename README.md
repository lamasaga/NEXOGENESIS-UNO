# NEXOGENESIS-UNO

　　UNO 将图书整理成可以独立阅读、相互连接且能回查来源的知识卡，并支持按问题检索、讨论和局部建构。项目处于独立重建与验证阶段；程序运行、模型理解质量和正式服务加载分别验证。

　　新建编译采用 `unit-cards-v3` / `uno-unit-compile-v3` / `review-publish-repair-v2`：保全整书和提取版本，按完整 Markdown 单元一次生成卡片，审查后先保存通过卡。审核问题明确分为卡片问题和关系问题：卡片问题只携带本卡与具体要求；关系问题只携带待修改卡、已完整核对的关系端点及具体要求，并且只能改 `relations`。每张新卡只有一个主类型 `type`，严格按 `conflict/entity/case/concept/method/mechanism/model/claim/phenomenon/undetermined` 顺序取第一个满足全部最低条件的类型，并可归入零到三个既有领域 `domains`；不再写入 `tags/topics`。新编译与新建构任务都冻结分类版本，旧在途任务继续使用创建时的分类口径。最多发送 3 张完整参考卡与 5 张导航摘要；同一原文单元已产生的旧卡优先进入参考集，冻结参考遗漏但模型再次返回同 ID 时复用旧卡而不覆盖。编译和建构使用固定的环节思考策略，不继承对话思考深度。生成达到输出上限时保留完整候选，恢复只请求剩余内容。历史 v2 任务保留原契约恢复，不改签、不混写。源码健康与准备接口声明同一组标识；正式服务是否已经加载必须另行核验，不能由源码或健康字符串推断。实现说明见 [单元编译实施](docs/UNO-单元编译实施.md) 与 [分类契约](docs/design/knowledge-guidance/card-types.md)。

　　空领域目录不会阻止制卡。`domains: []` 会进入可重建的未组织池；编译在 10 个有效单元、20 张新未组织卡或有足够材料的书末边界进行一次有界领域治理。既有领域可批量挂靠，新领域按本次任务冻结的授权处理：默认逐项确认；勾选“允许编译自行决定领域”后，只有通过成员、边界、版本和事务校验的提案才自动创建并挂靠。两种方式都由同一 Gateway 原子事务提交。领域治理不重发原书，不进入单卡返工，也不把书名、章节或临时关键词变成正式领域。现行设计与实现边界见 [领域治理方案](docs/UNO-领域治理方案.md)。

## 编译、建构与新对话

　　旧编译执行器、旧筛选与消化工具已从源码移除；历史记录只读，不能从普通对话、恢复按钮或旧写入提案重新启动。当前建构仍使用原协议，执行代码独立为 `construction-host.js` / `construction-workflow.js`。清理范围与验证见 [当前实现与验证](docs/UNO-当前实现与验证.md)。

| 入口 | 当前源码行为 |
|---|---|
| 编译 | 选定 Inbox 原件、要求、预算与本次领域建设授权；Python 提取并保全版本，宿主按完整 Markdown 单元生成、检查并保存卡片；每 10 个有效单元批量处理未组织卡。新领域默认逐项确认，也可由用户在开始前授权本任务自动批准合规提案。未读、提取不完整和延期明确保留。 |
| 建构 | 保持现行按方向建构协议：程序安排有限候选，模型局部改善，按具体改动审核；新任务冻结当前分类版本，作者与独立审核读取同一口径；授权范围、历史与退役保护不变。 |
| 新对话 | 默认只读；无需资料时直接回答，需要依据时按现有路线收集卡片与原文细节，再生成回答。项目可明确关联一个或多个知识库。 |

　　编译按钮与 `/编译 + 要求` 进入同一请求和面板；倾向快捷提示只追加可见文字，不切换隐藏工作流。同一知识库同时只执行一项编译或建构，其他会话可继续普通聊天。

　　新编译把用户选定的全部正文作为范围，不能在后台悄悄缩成选读。章节用于切分提交单元，知识对象决定成卡粒度；可以跨单元丰富同一卡片，也可以在完整阅读后说明无需独立成卡。每次保存最多 100 张卡片是事务限制，不是每章产卡指标。方法和正反例见 [判断方法](docs/design/book-compile-method.md) 与 [正反例](docs/design/book-compile-examples.md)。

　　原文单元最多 60,000 Unicode 字符，其余上下文合计最多 60,000 字符，两者独立计数；切分另受 240,000 UTF-8 字节上限约束，优先按段落、句子拆分，并保留连续分块标识。宿主一次提交完整单元，无模型补读工具、无阅读组、无历史正文叠加。

　　运行中可暂停、继续或结束。恢复先核对实际收据、已保存卡片版本和未完成范围；历史请求计数不清零，用户明确点击继续时会获得新一轮可用额度。整本已处理且无延期、提取缺失，归档原件哈希核验通过后，由 Gateway 将原件移出 Inbox；归档支持崩溃恢复，不等待独立的领域提案确认。提取警告需要另行核对，不能仅凭单元处理完毕自动忽略。旧编译任务只保留历史查看，不再恢复旧筛选或二审；需要继续处理剩余材料时明确创建新任务。建构保持自己的协议。

## 知识放在哪里

所有知识库平等位于 `knowledge-bases/<稳定ID>/`，应用根目录只放程序和共享运行设置。

| 目录 | 用途 |
|---|---|
| `00-Inbox/` | 尚未完成处理的原件；整本完成并核验归档后移出 |
| `01-Cards/` | 正式卡片；领域为独立 Markdown 索引 |
| `02-Profile/` | 知识体说明，修改需用户授权 |
| `03-Archive/books/` | 按原件哈希保全上传的原始文件 |
| `03-Archive/card-history/` | 卡片修订前版本 |
| `03-Archive/aggregates/` | 已有聚合来源；新编译不依赖此中间步骤 |
| `04-OutBox/` | 对外交付 |
| `05-Buffer/books/` | 按原件哈希及提取版本保存清洗、拆分后的 Markdown 单元、目录和提取图片；被卡片引用后持续保留 |
| `05-Buffer/_index/`、`05-Buffer/themes/` | 既有整理原文与稳定索引；新编译不生成旧式中间笔记，也不搜索这些索引 |
| `06-Journal/`、`07-Conversations/` | 处理记录与会话侧产物 |

　　Markdown 是唯一语义事实源。实质写入一律经过 HarnessGateway，执行授权、路径、版本、来源、关系端点和事务校验，留下真实收据。新提取版本不会覆盖旧来源；旧卡更新保留历史和旧来源，不能以普通编译复活退役卡。已有 Archive 单元路径仍可读取和续跑，不自动移动或改写；明确授权迁移后，旧来源地址可读取 Buffer 中同版本的文件，卡片引用和来源字节保持不变。`05-Buffer/books/` 不自动加入普通对话的全量检索索引，不能作为临时缓存整体清空。

　　卡片使用稳定 ID、标题、摘要、一个主类型、多个领域、结构化正文、来源和具体关系。主类型按 `conflict/entity/case/concept/method/mechanism/model/claim/phenomenon/undetermined` 严格顺序判断并决定正文骨架；`phenomenon` 需要观察对象与依据，其他九类都不成立但知识单元仍完整可复用时使用 `undetermined`。领域表示跨材料长期成立的问题空间，通常 1–2 个、最多 3 个，没有合适领域时允许留空。模型保存来源只填 `ref`，程序为完整交付的单元生成精确 `source_spans`，模型不手填位置。来源可点击查看真实归档文本、原书页章定位及原书链接。提交不等于理解，写入成功不等于质量合格。已有库的旧标签不自动迁移、清理或重编译。

　　领域记录保存在 `01-Cards/_meta/domains/`，卡片自身 `domains` 是成员归属的唯一事实源。阅读领域时可查看核心问题、纳入与排除范围、代表卡、成员数量和已有正文。领域间支持邻接、对照、桥接的保存与双向阅读入口，需说明使用条件和限制；自动发现与创建关系尚未接入建构，检索不会自动沿领域关系扩展。契约和示例见[领域说明与领域关系](docs/design/knowledge-guidance/domains.md)。`.nexogenesis/domain-governance/state.json` 只保存可重建的未组织项与待审提案，不是第二套知识库。知识卡处理完成与领域组织完成在界面分别显示。

## 查看模型提示词与语音输入

顶部「提示词」提供当前知识库最近 60 次模型调用的只读快照，可检查任务归属、输入、工具与已报告用量。记录保存在各库 `.nexogenesis/prompt-inspector/`，不含连接密钥；旧请求不能从对话文本准确补回。上下文预算和实际外发的差异见 [请求上下文治理](docs/UNO-请求上下文治理.md)。

输入框支持本地中文语音转写：停止录音后检查文字再发送，单次最多 60 秒，取消或切换会话保留原有草稿。安装及验证见 [语音输入](docs/UNO-语音输入.md)。

## 本地启动

需要 Node.js、npm、Python 3 和已安装的 Agent 运行时（`dsh.cmd`）。PDF 提取另需 `python -m pip install pymupdf`。扫描件不自动 OCR；复杂表格和图片的保存不代表完成了视觉理解。

```powershell
powershell -ExecutionPolicy Bypass -File .\prepare-nexogenesis.ps1
.\start-nexogenesis.cmd
```

默认地址为 http://127.0.0.1:3093。在「设置 → 模型连接」配置供应商与型号；连接测试只读模型目录，不发生成请求。详情见 [模型连接](docs/UNO-模型连接.md)。

双击 `start-nexogenesis.cmd` 启动本工作区服务；运行窗口保持打开时可用 `Ctrl+C` 结束。若启动窗口提示服务已经运行并随即关闭，说明 3093 上已有本工作区进程，重复启动不会替换它。此时双击 `stop-nexogenesis.cmd`：脚本会先核对健康接口、workspace ID、进程命令和端口，只停止确认属于当前 UNO 工作区的服务，并停留显示结果。修改后台代码后应先停止再启动，单纯刷新页面或重复双击启动器不会加载新代码。

启动器不停止其他进程。改代码后，源码、构建与当前运行进程分别核对；仅停止已确认属于本工作区的 UNO 进程。自定义 `NEXO_PORT` 不使用保留端口 3080、3083；开发代理指向 3093，改端口需同步核对。

## 开发、验证与分发

以下命令用于完整开发工作区，干净发行包使用准备和启动脚本。

```powershell
npm ci
npm test
npm run test:web
npm run build
powershell -File .\start-nexogenesis.ps1 -CheckOnly
```

　　程序测试使用临时合成实例。当前分类、v3 编译入口和建构分类冻结定向 42/42 通过，前端 36 个测试文件、233 项通过，生产构建通过；扩大后端回归仍有调用已移除旧 Buffer Gateway 的测试债，不能描述为全套回归通过。阶段性验证与边界见 [当前实现与验证](docs/UNO-当前实现与验证.md)。v1 阅读组当时的图书专项 45/45、来源查看 5/5、前端 217/217 及完整后端 715 项数字只属于该时点。v2 没有付费模型实验。

　　v1 真实 Kimi 实验已使用授权预算 11/12 次，在隔离复制的 2,669 张金融卡片底座中处理第三章 7,088 字符，新增 4 卡，未写入正式知识。该实验针对五个 `book_*` 工具，不能外推到本版。完整用量、错误与证据见 [当前实现与验证](docs/UNO-当前实现与验证.md)。

　　源码健康接口声明 `compile_profile=unit-cards-v3`、`compile_version=uno-unit-compile-v3`、`compile_review_policy=review-publish-repair-v2`，分类契约为 `ordered-single-type-and-domains-v2`，失败恢复契约为 `compile-response-recovery-v1`，常规审核治理为 `uno_review_governance=routine-review-governance-v2`，独立待办诊断为 `uno_isolated_repair_diagnosis=isolated-repair-diagnosis-v1`，并包含 `uno_relation_repair=1`、`uno_domain_governance=1`、`uno_domain_auto_approval=1`、`uno_domain_checkpoint=10-units-20-cards-book-end-v1`。准备接口另须声明 `domain_approval_modes=[manual, automatic]`，新版页面才允许开始编译。这些是源码契约标识，不证明正式 3093 已重载，也不证明真实模型提出的领域边界已经通过效果验证。

知识、实例登记、密钥、会话、任务和实验产物不进入核心程序提交。具体知识库整体保留在本地 `knowledge-bases/`；根目录的 `.nexogenesis/`、`artifacts/`、`output/`、`tmp/` 等编译状态、中间产物和验证输出同样不进入发布。默认干净分发使用 `tools/export-clean-agent.ps1`，只有明确迁移知识时才使用便携快照。底层保留原生 Harness 包和协议，不以改名假装替换运行时。

开发任务提到“编译”不会自动开始真实知识处理。实际任务经过统一入口、新协议及 Gateway。文档总入口为 [docs/README.md](docs/README.md)。
