# NEXOGENESIS-UNO

NEXOGENESIS-UNO 是一个在本机运行的知识工作台。它把图书、文章和笔记整理成可以独立阅读、相互连接、回查来源的 Markdown 知识卡，帮助你围绕自己的资料阅读、整理和讨论问题。

你可以从空白知识库开始：导入材料，编译成卡片，按领域浏览，再通过建构整理已有知识，或在对话中检索和使用这些知识。程序与知识库分开保存，分享程序不必附带自己的资料、会话和模型密钥。

UNO 面向 Windows 本机单用户使用，仍处于开发与验证阶段。模型生成和审核都可能出错，重要结论需要回查原文；它不是经过质量认证的知识系统，也不是可直接暴露到公网的多人服务。

## 可以用它做什么

### 把材料整理成知识卡

导入 PDF、EPUB、DOCX、Markdown 或 TXT，选择「编译」。程序提取文本，按图书章节或文章结构组织处理单元；模型从中整理出完整的知识对象，而不是机械地为每一段生成摘要。

每张卡片有稳定标识、标题、摘要、主类型、正文、来源，以及可选的领域和关系。卡片可以独立阅读，也能回到对应的提取文本和原始文件核对。原件、提取版本和卡片修订历史分别保存。

编译会检查候选卡，先保存通过的内容，需要修复的内容单独保留。你可以暂停、继续或结束任务。部分成果不会被当作整本完成，未完成材料仍保留在待处理区。

### 按领域阅读，在图谱中查看联系

领域围绕长期有用的问题组织知识，例如一组需要共同理解的机制、方法或争议，而不只是书名和章节目录。一张卡可以属于多个领域；暂时找不到合适领域的卡也能保存，稍后再整理。

卡片之间可以记录细分、补充、对照、质疑、类比、例证和应用等关系。图谱帮助你查看这些联系，但有连线不等于论证已经成立，图上距离和连通程度也不代表知识质量。

### 对已有知识进行建构

「建构」用于整理已有卡片。你可以侧重发现联系、梳理领域、精炼卡片、比较分歧或综合整理，并分别授权关系调整、卡片修订、已有领域归属调整和重复卡片合并。

处理可以限定到整个知识库、某个领域或指定卡片；取消所有修改权限后，只做诊断。建构不会自动获得新建卡片、生成综合理论或重组领域体系的权限。详细选项见 [建构侧重与允许调整](docs/UNO-建构侧重与允许调整.md)。

### 围绕知识提问和讨论

「新对话」默认只读。无需资料的问题直接交流；需要知识库依据的问题会检索卡片和相关原文，再组织回答。你可以追问某个概念、比较不同观点，或检查一个结论有哪些条件和反例。

多个知识库分别保存。项目可以关联多个知识库供对话检索，编译和建构仍绑定创建任务时的目标库，不会随界面切库转移写入。

顶部「提示词」可以查看当前知识库最近的模型请求快照，了解实际提供了哪些材料。输入框还支持可选的本地中文语音转写，识别文字经你检查后再发送。

## 安装与启动

### 1. 准备环境

- Windows、Node.js 22.12 或更高版本及 npm、Python 3。
- 已安装可在命令行调用的 DeepSeek Harness 运行时，命令为 `dsh.cmd`。本仓库不包含该运行时，准备脚本也不会替你安装它。
- 一个可用的模型服务账户和对应 API Key。生成请求的费用及额度由所选服务决定。
- 处理 PDF 时，在程序使用的 Python 环境中安装 `pymupdf`：`python -m pip install pymupdf`。

运行时可通过 npm 安装，本项目配套依赖使用 `0.1.0-rc.6`：

```powershell
npm install -g @deepseek-ai/dsh@0.1.0-rc.6
```

安装后重新打开 PowerShell，检查 `node --version`、`npm --version`、`python --version` 和 `Get-Command dsh.cmd` 能正常返回。尚未具备运行时的电脑不能仅靠下载本仓库启动。文档提取默认使用 `python`；若设置了 `UNO_PYTHON`，PDF 依赖也应安装到该解释器环境中。

### 2. 获取并准备程序

克隆 [GitHub 仓库](https://github.com/lamasaga/NEXOGENESIS-UNO)，或解压干净发行包，然后在项目根目录运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\prepare-nexogenesis.ps1
.\start-nexogenesis.cmd
```

准备脚本会安装项目依赖、构建网页，并建立当前工作区自己的运行配置和空白知识目录；不会导入其他项目的知识库或凭据。首次准备需要网络。

浏览器打开 [本机工作台](http://127.0.0.1:3093)。后续通常只需双击 `start-nexogenesis.cmd`。

### 3. 配置模型

打开「设置 → 模型连接」，选择供应商、填写密钥和模型，然后保存。可先用「测试连接并读取模型」检查模型目录是否可访问；这个测试不调用生成模型，也不能证明所有生成能力都可用。

供应商、兼容接口、密钥保存和思考选项见 [模型连接](docs/UNO-模型连接.md)。编译和建构要求宿主支持该模型的请求计数；界面提示不可用时，应先解决连接或适配问题。

## 第一次使用

1. 选择或创建一个知识库，确认它是本次资料的保存位置。
2. 点击「导入材料」添加一份短文或小型文档。首次使用建议先核对文本是否能正常提取。
3. 打开「编译」，选择材料、处理要求、质量模式和请求预算。新领域默认需要你确认；只有希望本任务自动建域时才勾选相应授权。
4. 开始处理，查看进度、已保存卡片和待修复内容。打开几张卡核对正文、边界与来源，不只看完成数量。
5. 在领域或图谱中浏览成果；需要整理已有卡片时再启动「建构」。
6. 新建对话，提出一个需要这些资料回答的问题，并回查答案引用的依据。

完整操作、任务恢复、备份和常见问题见 [使用指南](docs/UNO-使用指南.md)。语音识别需单独安装，见 [语音输入](docs/UNO-语音输入.md)。

## 数据保存与知识库分离

具体知识库位于 `knowledge-bases/<知识库ID>/`，不属于通用程序发布内容。

| 位置 | 保存内容 |
|---|---|
| `00-Inbox/` | 尚未完成处理的材料 |
| `01-Cards/` | 正式 Markdown 卡片；领域定义位于 `_meta/domains/` |
| `02-Profile/` | 知识库自身的说明 |
| `03-Archive/` | 原始材料、卡片历史等可追溯记录 |
| `04-OutBox/` | 对外交付内容 |
| `05-Buffer/` | 提取文本、处理单元、图片及相关索引 |
| `06-Journal/`、`07-Conversations/` | 处理记录与会话侧产物 |
| 库内 `.nexogenesis/` | 任务、收据、提示词快照和可重建状态等 |

Markdown 是知识内容的事实源，索引和图谱不是另一套正文。知识写入经过统一的授权、来源、版本和事务校验。`05-Buffer/books/` 中的文本可能已被卡片引用，不能当作临时缓存清空。

应用根目录的 `.nexogenesis/` 还保存工作区运行配置、会话等本机数据。`artifacts/`、`output/`、`tmp/` 等目录可能包含编译、实验或验证产物。它们与具体知识库、凭据、依赖和构建输出一起排除在 Git 提交及干净发行之外；排除不等于删除，本地数据仍保留。

数据在本地保存不等于推理离线：使用在线模型时，当前问题、必要的卡片和原文会发送给你配置的模型服务。提示词快照也可能包含这些正文，备份和分享时应按私有资料处理。

## 停止、备份与分享

停止服务可在启动窗口按 `Ctrl+C`，或运行 `stop-nexogenesis.cmd`。停止脚本会核对工作区和进程身份，不用于关闭其他项目。重复启动不会替换已运行的服务；更新后台代码后需要停止并重新启动。

备份前先暂停任务并停止服务。要保留知识与任务上下文，应备份完整的 `knowledge-bases/` 及根目录 `.nexogenesis/`，妥善保护其中的私有数据；不要仅备份卡片正文，也不要把私有备份当作公开发行包。

从完整 Git 工作区生成空白发行包：

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\export-clean-agent.ps1
```

脚本按白名单打包程序和说明，创建空知识目录，默认输出到项目旁的 `NEXOGENESIS-UNO-distributions/`。发行包不携带已有知识、密钥、会话、任务、语音模型或实验产物。分发规则和本机运行边界见 [运行与分发](deploy/README.md)。

## 开发与进一步阅读

完整开发仓库的检查入口：

```powershell
npm ci
npm test
npm run test:web
npm run build
```

这些命令检查程序，不证明模型理解质量，也不证明运行中的服务已经加载新代码。测试与实际模型效果分别记录在 [当前实现与验证](docs/UNO-当前实现与验证.md)。干净发行包不包含完整测试工程。

[文档目录](docs/README.md) 收录使用说明、工程契约、设计提案和历史资料；首次使用只需从使用说明开始。
